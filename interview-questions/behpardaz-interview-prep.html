نقاط حساس و برگ‌های برنده

Angular را همین امروز به رزومه جاب‌ویژن اضافه کن.مصاحبه‌کننده رزومه را جلویش دارد و Angular جزو الزامات است. یک خط در سوابق ناک یا پارسیان (هر جا که واقعاً Angular کار کردی) و یک تگ در «نرم‌افزارها» با سطح واقعی‌ات. یک پروژه مشخص هم آماده کن که بگویی: چه صفحه‌ای ساختی، Service و HttpClient چطور بود، با API دات‌نت چطور وصل شد.
ارتباط با همراه اول برگ برنده توست.ناک هم از مجموعه همراه اول بود و بهپرداز همراه سامانه اول زیرمجموعه همراه اول است. در معرفی بگو با فضای همراه اول، حجم بالای کاربر و استانداردهایش آشنایی.
Overqualified به نظر نرسی.آگهی سطح Intermediate خواسته و تو الان Team Lead هستی. اگر پرسیدند «چرا از تیم‌لیدی به این نقش؟» جواب آماده داشته باش: علاقه به محیط بزرگ‌تر و پایدارتر، پروژه‌های متنوع‌تر، و اینکه هم کد می‌زنی و هم می‌توانی منتورینگ کنی (آگهی هم «technical guidance» خواسته).
فقط چیزی را بگو که عمیق می‌دانی.Azure و Kubernetes در رزومه هست ولی تجربه کاری عملیاتی‌ات با آن‌ها محدود است. اگر پرسیدند صادقانه بگو «در حد آشنایی و پروژه آموزشی» و سریع برگرد به چیزی که قوی هستی. مصاحبه‌کننده ایرانی معمولاً روی همین‌ها یک سوال عمقی می‌پرسد.
حقوق.در رزومه ۸۰ تا ۱۰۰ میلیون تومان ثبت شده. اگر عدد پرسیدند، از همین بازه دفاع کن و بگو بسته به مزایا قابل صحبت است. عدد پایین‌تر از این بازه نگو.

داستان‌های پروژه فرمت STAR: موقعیت، وظیفه، اقدام، نتیجه

مصاحبه‌گرها روی یکی از خطوط رزومه عمیق می‌شوند. این چهار داستان را با عدد و جزئیات آماده کن.

۱. پاسخ زیر ۱۰۰ میلی‌ثانیه در درگاه پرداخت

  • موقعیت: سرویس تراکنش شتاب در ساعات پیک کند می‌شد و Timeout داشتیم.
  • اقدام: Log و Monitoring گذاشتیم تا گلوگاه پیدا شود؛ Queryهای سنگین را با Execution Plan بررسی و Index مناسب (Covering) ساختیم؛ کارهای غیرضروری مسیر اصلی (نوتیفیکیشن، لاگ تفصیلی) را به RabbitMQ و پردازش Async بردیم؛ داده‌های ثابت را Cache کردیم؛ کل مسیر را async/await کردیم.
  • نتیجه: زمان پاسخ به زیر ۱۰۰ms رسید. اگر عدد قبل را یادت هست (مثلاً ۴۰۰ms) حتماً بگو.

۲. یک Query کند که درستش کردی

  • یک گزارش یا Query پرتکرار مشخص را انتخاب کن. بگو مشکل چه بود: Index Scan، تابع روی ستون در WHERE (Non-SARGable)، Parameter Sniffing، یا Key Lookup.
  • بگو چطور فهمیدی (Execution Plan، SET STATISTICS IO، Query Store) و چه کردی و زمان از چند به چند رسید.

۳. تیم‌لیدی و منتورینگ

  • تیم سه‌نفره روی پروژه کارت پرداخت، منتورینگ پنج مهندس. Code Review، تقسیم کار، تصمیم فنی.
  • یک مثال مشخص: کسی که با Review یا Pair Programming پیشرفت کرد، یا یک تصمیم فنی که با استدلال تیم را قانع کردی.

۴. یک باگ سخت در Production

  • مثلاً تراکنش تکراری یا Race Condition: با Idempotency Key، Redis Lock یا rowversion در SQL Server حلش کردی. نشان بده چطور با Log ریشه‌یابی کردی و چه کردی که تکرار نشود.

سوالات فنی

۰ از ۰ مرور شده

علامت «مرور شد» در همین مرورگر ذخیره می‌شود. موارد مهم را حتماً بلد باش.

C# و OOP

چهار اصل OOP را با مثال توضیح بده.مهم
  • Encapsulation: حالت داخلی پنهان و فقط از طریق متد تغییر می‌کند. مثلاً Balance در BankAccount فقط با Deposit/Withdraw عوض می‌شود.
  • Inheritance: SavingsAccount : BankAccount؛ استفاده مجدد از رفتار مشترک.
  • Polymorphism: متد virtual CalculateFee() که هر نوع حساب override می‌کند؛ کد صدازننده فقط با نوع پایه کار دارد.
  • Abstraction: فقط «چه کاری» دیده شود نه «چطور»؛ مثل IPaymentGateway.
تفاوت abstract class و interface؟مهم

abstract class می‌تواند State (فیلد)، Constructor و پیاده‌سازی پیش‌فرض داشته باشد و کلاس فقط از یکی ارث می‌برد. interface قرارداد است، چندتایی پیاده‌سازی می‌شود و از C# 8 می‌تواند Default Implementation داشته باشد ولی فیلد نه. وقتی «is-a» با کد مشترک داریم abstract، وقتی «can-do» یا قابلیت داریم interface. در عمل برای DI و تست، interface.

SOLID را توضیح بده و یک مثال واقعی از کار خودت بزن.مهم
  • S یک کلاس، یک دلیل برای تغییر (PaymentService کار Log و Email نکند).
  • O باز برای توسعه، بسته برای تغییر: اضافه کردن درگاه جدید با کلاس جدید IPaymentGateway، نه if/else جدید.
  • L زیرکلاس باید جای کلاس پایه بنشیند بدون شکستن رفتار.
  • I interfaceهای کوچک و تخصصی به‌جای یک interface چاق.
  • D وابستگی به Abstraction؛ در ASP.NET Core همان DI Container.
Value Type و Reference Type؟ struct و class؟ record چیست؟

Value Type مقدار خودش را نگه می‌دارد و با کپی منتقل می‌شود (int، struct)؛ Reference Type به آدرسی در Heap اشاره می‌کند (class، string، array). Boxing یعنی تبدیل Value Type به object که هزینه Allocation دارد. record نوع ارجاعی با Equality بر اساس مقدار، Immutable به‌صورت پیش‌فرض و with expression؛ برای DTO و Value Object عالی است.

async/await چطور کار می‌کند؟ چرا در API مهم است؟مهم

کامپایلر متد را به State Machine تبدیل می‌کند. در I/O (دیتابیس، HTTP) Thread آزاد می‌شود و به Thread Pool برمی‌گردد، پس سرور با Thread کمتر درخواست بیشتری جواب می‌دهد (Scalability، نه لزوماً سرعت یک درخواست). خطاهای رایج: .Result و .Wait() که Deadlock یا Thread Starvation می‌سازند، و async void که Exception را گم می‌کند (فقط برای Event Handler). Task.WhenAll برای کارهای موازی مستقل.

IEnumerable، IQueryable، و Deferred Execution در LINQ؟مهم

IQueryable Expression Tree می‌سازد که EF آن را به SQL ترجمه می‌کند، پس فیلتر در دیتابیس اجرا می‌شود. IEnumerable در حافظه کار می‌کند. اگر زود ToList() یا AsEnumerable() کنی، کل جدول به حافظه می‌آید. Deferred Execution: Query تا زمان Enumerate شدن (foreach، ToList، Count) اجرا نمی‌شود؛ اگر دو بار Enumerate کنی دو بار اجرا می‌شود.

Garbage Collector و IDisposable و using؟

GC حافظه Managed را با Generationهای 0، 1، 2 (و LOH برای آبجکت‌های بزرگ) آزاد می‌کند. منابع Unmanaged (Connection، File، Socket) را GC به‌موقع آزاد نمی‌کند، پس IDisposable و using لازم است. برای HttpClient از IHttpClientFactory استفاده می‌کنیم تا Socket Exhaustion نداشته باشیم.

delegate، event، Func و Action؟

delegate نوعی است که به متد اشاره می‌کند. Func<T,TResult> مقدار برمی‌گرداند، Action<T> نه. event یک delegate محافظت‌شده است که بیرون کلاس فقط += و -= می‌شود و فقط خود کلاس آن را Raise می‌کند (الگوی Observer).

Generic و constraint ها؟ چرا Generic Repository بحث‌برانگیز است؟

Generic یعنی Type Safety بدون Boxing و تکرار کد: where T : class, IEntity, new(). Generic Repository روی EF Core اغلب لایه اضافه است چون DbSet خودش Repository و DbContext خودش Unit of Work است؛ Repository اختصاصی با متدهای معنادار دامنه (مثلاً GetPendingTransactions) مفیدتر است.

string و StringBuilder؟ چرا string Immutable است؟

string Immutable است؛ هر تغییر یک آبجکت جدید می‌سازد. در حلقه با الحاق زیاد، StringBuilder یک بافر قابل تغییر دارد. Immutability برای Thread Safety و String Interning و استفاده امن به‌عنوان کلید Dictionary خوب است.

چند Design Pattern که واقعاً استفاده کردی نام ببر.

Repository و Unit of Work، Factory/Builder برای ساخت Entity، Strategy برای انتخاب درگاه یا محاسبه کارمزد، Decorator (مثلاً Caching روی Repository)، Mediator با MediatR در CQRS، Options Pattern، Outbox برای پیام مطمئن. برای هر کدام یک جمله «کجا و چرا» آماده کن.

ASP.NET Core

Middleware Pipeline چیست و ترتیب چرا مهم است؟مهم

زنجیره‌ای از کامپوننت‌ها که Request را به ترتیب ثبت پردازش می‌کنند و Response برعکس برمی‌گردد. هر Middleware می‌تواند next() را صدا بزند یا Short-circuit کند. ترتیب معمول: ExceptionHandler، HTTPS، Static Files، Routing، CORS، Authentication، Authorization، Endpoints. اگر Authorization قبل از Authentication باشد، کاربر شناخته نمی‌شود.

app.Use(async (ctx, next) => {
    var sw = Stopwatch.StartNew();
    await next();
    logger.LogInformation("{Path} {Ms}ms", ctx.Request.Path, sw.ElapsedMilliseconds);
});
Lifetimeهای DI: Singleton، Scoped، Transient؟ Captive Dependency چیست؟مهم

Singleton یک نمونه برای کل برنامه، Scoped یک نمونه برای هر Request (DbContext)، Transient هر بار نمونه جدید. Captive Dependency: تزریق Scoped در Singleton؛ DbContext عملاً Singleton می‌شود و مشکل Thread Safety و داده کهنه می‌دهد. در BackgroundService با IServiceScopeFactory Scope بساز.

Filter ها در MVC چه انواعی دارند و فرقشان با Middleware؟

Authorization، Resource، Action، Exception، Result. Filter به Context کنترلر و Action و Model دسترسی دارد؛ Middleware عمومی‌تر و روی کل Pipeline است. Logging عمومی و Exception سراسری در Middleware، Validation یا منطق مخصوص Action در Filter.

Exception Handling سراسری را چطور پیاده می‌کنی؟

با UseExceptionHandler یا از .NET 8 با IExceptionHandler و خروجی استاندارد ProblemDetails. Exceptionهای دامنه به Status Code مناسب Map می‌شوند (NotFound → 404، Validation → 400) و جزئیات داخلی فقط Log می‌شود، به کاربر نمی‌رود.

Authentication و Authorization؟ JWT چطور کار می‌کند؟مهم

Authentication یعنی «کی هستی»، Authorization یعنی «اجازه داری». JWT سه بخش دارد: Header، Payload (Claims)، Signature. سرور با کلید امضا را چک می‌کند، پس Stateless است. Access Token کوتاه‌عمر و Refresh Token برای تمدید. Policy-based Authorization با [Authorize(Policy="...")] و Role/Claim. در Backoffice که مدیریت دسترسی داشتید، این را به تجربه خودت ربط بده.

Model Validation چطور انجام می‌دهی؟

DataAnnotations یا FluentValidation. با [ApiController] اگر ModelState نامعتبر باشد خودکار 400 با ProblemDetails برمی‌گردد. Validation قواعد کسب‌وکار در لایه Domain یا Application، نه فقط در DTO.

Configuration و Options Pattern؟ IOptions، IOptionsSnapshot، IOptionsMonitor؟

تنظیمات از appsettings، Environment، User Secrets و... لایه‌لایه خوانده می‌شود. IOptions یک بار (Singleton)، IOptionsSnapshot هر Request (Scoped)، IOptionsMonitor با Reload زنده و قابل استفاده در Singleton.

Background Job در ASP.NET Core؟

BackgroundService/IHostedService برای کارهای ساده؛ Hangfire یا Quartz برای زمان‌بندی، Retry و Dashboard. برای کارهای مهم، Queue (RabbitMQ) بهتر است چون با Restart پروسس از بین نمی‌رود.

Controller یا Minimal API؟ تفاوت .NET Framework و .NET Core؟

Minimal API سبک‌تر و کم‌کدتر برای سرویس‌های کوچک؛ Controller برای API بزرگ با Filter و ساختار مرسوم. .NET Core کراس‌پلتفرم، Open Source، سریع‌تر، DI داخلی، Kestrel، و Self-hosted است؛ .NET Framework فقط ویندوز و IIS.

CORS چیست و چرا وقتی Angular به API وصل می‌شود مطرح است؟

مرورگر درخواست از Origin دیگر را بدون اجازه سرور مسدود می‌کند. سرور با Header Access-Control-Allow-Origin اجازه می‌دهد؛ برای درخواست‌های غیرساده Preflight با OPTIONS ارسال می‌شود. در ASP.NET Core با AddCors و Policy مشخص؛ AllowAnyOrigin با Credentials ممنوع است.

REST API

اصول REST و متدهای HTTP؛ کدام Idempotent هستند؟مهم

Resource محور، Stateless، Uniform Interface، Cacheable. GET، PUT، DELETE Idempotent هستند (تکرار، نتیجه را تغییر نمی‌دهد). POST نیست، پس در پرداخت از Idempotency Key در Header استفاده می‌کنیم تا تراکنش تکراری ثبت نشود. این را حتماً به تجربه پرداخت ربط بده.

PUT و PATCH؟

PUT کل Resource را جایگزین می‌کند؛ PATCH بخشی را تغییر می‌دهد (JSON Patch یا Merge Patch).

Status Codeهای مهم را بگو.

200 OK، 201 Created (با Location)، 204 No Content، 400 Bad Request، 401 Unauthorized (احراز نشده)، 403 Forbidden (اجازه ندارد)، 404، 409 Conflict (مثلاً Concurrency)، 422، 429 Too Many Requests، 500، 503.

Versioning و Pagination را چطور طراحی می‌کنی؟

Versioning در URL (/api/v1/)، Header یا Query String؛ URL ساده‌ترین برای کلاینت‌ها. Pagination با page/pageSize (OFFSET/FETCH) یا Keyset/Cursor برای جدول‌های بزرگ که در صفحه‌های عمیق سریع‌تر است.

REST در مقابل gRPC؟

gRPC روی HTTP/2 با Protobuf باینری، سریع‌تر، Contract-first و Streaming؛ مناسب ارتباط داخلی سرویس‌ها. REST با JSON خواناتر و برای مرورگر و کلاینت عمومی. گفته‌ای gRPC کار کرده‌ای؛ یک مثال آماده کن.

SQL Server نقطه قوت اصلی تو؛ اینجا باید بدرخشی

Clustered و Non-Clustered Index؟ Covering Index؟مهم

Clustered ترتیب فیزیکی داده‌ها (Leafها خود داده‌اند)، فقط یکی در هر جدول. Non-Clustered ساختار جدا که به Clustered Key اشاره می‌کند؛ اگر ستون لازم در Index نباشد Key Lookup رخ می‌دهد. Covering Index با INCLUDE همه ستون‌های Query را دارد و Lookup حذف می‌شود. Filtered Index برای زیرمجموعه (مثلاً WHERE Status = 'Pending').

یک Query کند را چطور بررسی می‌کنی؟ مراحلت را بگو.مهم
  • پیدا کردن Query: Query Store، DMVها (sys.dm_exec_query_stats)، Extended Events.
  • SET STATISTICS IO, TIME ON و Actual Execution Plan: Scan به‌جای Seek، Key Lookup، تفاوت Estimated و Actual Rows، Sort و Spill در tempdb، Implicit Conversion.
  • رفع: Index مناسب، بازنویسی SARGable، به‌روزرسانی Statistics، حذف SELECT *، شکستن Query، Temp Table.
SARGable یعنی چه؟ مثال بزن.

شرطی که بتواند از Index Seek استفاده کند. تابع روی ستون آن را خراب می‌کند:

-- Bad: Index Scan
WHERE YEAR(CreatedAt) = 2026
-- Good: Index Seek
WHERE CreatedAt >= '2026-01-01' AND CreatedAt < '2027-01-01'

LIKE '%abc' و مقایسه nvarchar با varchar (Implicit Conversion) هم همین مشکل را دارند.

Parameter Sniffing چیست و چطور حلش می‌کنی؟

SQL Server Plan را بر اساس پارامتر اولین اجرا Cache می‌کند؛ اگر توزیع داده نامتوازن باشد Plan برای پارامترهای دیگر بد است. راه‌ها: OPTION (RECOMPILE)، OPTIMIZE FOR، متغیر محلی، Plan Forcing در Query Store، یا جدا کردن Procedure.

Isolation Levelها و Deadlock؟مهم

Read Uncommitted (Dirty Read)، Read Committed (پیش‌فرض)، Repeatable Read، Serializable، Snapshot و RCSI که با Row Versioning خواننده و نویسنده را بلاک نمی‌کنند. Deadlock: دو تراکنش منابع هم را قفل کرده‌اند و یکی Victim می‌شود. پیشگیری: دسترسی به جدول‌ها با ترتیب ثابت، تراکنش کوتاه، Index مناسب، RCSI، و Retry در کد. برای تحلیل از Deadlock Graph در system_health.

Temp Table، Table Variable و CTE؟

Temp Table در tempdb با Statistics و Index، برای حجم زیاد. Table Variable آمار ندارد (تا قبل از 2019 تخمین ۱ ردیف) و برای حجم کم. CTE فقط خوانایی است و Materialize نمی‌شود؛ اگر دو بار استفاده شود دو بار اجرا می‌شود. Recursive CTE برای سلسله‌مراتب.

Window Functionها: ROW_NUMBER، RANK، DENSE_RANK، LAG، SUM OVER؟
SELECT AccountId, Amount, CreatedAt,
  ROW_NUMBER() OVER (PARTITION BY AccountId ORDER BY CreatedAt DESC) AS rn,
  SUM(Amount)  OVER (PARTITION BY AccountId ORDER BY CreatedAt
                     ROWS UNBOUNDED PRECEDING) AS RunningTotal,
  LAG(Amount)  OVER (PARTITION BY AccountId ORDER BY CreatedAt) AS PrevAmount
FROM Transactions;

RANK با تساوی شماره رد می‌کند (1،1،3)، DENSE_RANK نه (1،1،2).

Stored Procedure یا Query از کد؟ View و Function؟

SP: Plan Reuse، امنیت (فقط Execute)، کاهش رفت‌وبرگشت؛ ولی منطق در دیتابیس پراکنده و تست سخت‌تر می‌شود. Scalar Function قدیمی Row-by-row اجرا می‌شود و کند است (2019 Inlining دارد)؛ Inline Table-Valued Function بهتر است. View برای ساده‌سازی و امنیت؛ Indexed View برای تجمیع از پیش محاسبه‌شده.

DELETE، TRUNCATE، DROP؟ WHERE و HAVING؟ JOIN ها؟

DELETE ردیف‌به‌ردیف و Log کامل با WHERE؛ TRUNCATE همه داده با Log حداقلی و Reset شدن Identity؛ DROP کل جدول. WHERE قبل از Group، HAVING بعد از Group روی Aggregate. INNER، LEFT، RIGHT، FULL، CROSS، و APPLY.

Columnstore Index چه موقع؟

برای جدول‌های بزرگ گزارشی و تحلیلی با Aggregate روی ستون‌های کم؛ فشرده‌سازی بالا و Batch Mode. برای OLTP با Seek تک‌ردیفی مناسب نیست. دوره‌اش را در نیک‌آموز گذرانده‌ای؛ اگر جایی استفاده کردی بگو.

EF Core و Dapper

مشکل N+1 چیست و چطور حل می‌شود؟مهم

یک Query برای لیست و N Query برای هر رابطه (معمولاً با Lazy Loading). راه‌حل: Include (Eager)، Projection با Select به DTO، یا AsSplitQuery برای جلوگیری از Cartesian Explosion.

AsNoTracking و Change Tracker؟

برای Queryهای فقط‌خواندنی AsNoTracking سربار Tracking را حذف می‌کند و سریع‌تر و کم‌حافظه‌تر است. Change Tracker تغییرات Entityهای Track‌شده را در SaveChanges به SQL تبدیل می‌کند.

Concurrency را در EF Core چطور مدیریت می‌کنی؟

Optimistic با [Timestamp]/rowversion یا ConcurrencyToken؛ در صورت تعارض DbUpdateConcurrencyException می‌گیری و Retry یا پیام 409 می‌دهی. Pessimistic با Lock در SQL (UPDLOCK) یا Distributed Lock در Redis. تجربه خودت در پرداخت را بگو.

EF Core یا Dapper؟ کی کدام؟

EF Core برای CRUD و منطق دامنه، Migration، Change Tracking و بهره‌وری. Dapper برای Queryهای سنگین گزارشی و مسیرهای حساس به Performance با SQL دستی. در یک پروژه هر دو با هم: Write با EF، Read سنگین با Dapper (نزدیک به CQRS).

Migration در Production را چطور اجرا می‌کنی؟

اجرای خودکار Database.Migrate() در Startup برای Production ریسکی است. بهتر: تولید اسکریپت Idempotent با dotnet ef migrations script --idempotent یا Migration Bundle، بررسی DBA، و اجرا در Pipeline.

Angular سوالات پایه تا متوسط برای یک Backend Developer

استراتژی:بگو تمرکزت Backend است ولی با Angular صفحه و فرم ساخته‌ای و به API وصل کرده‌ای. سریع پل بزن به قرارداد API، CORS، JWT Interceptor و Pagination که سمت تو هستند.
ساختار یک برنامه Angular: Component، Module، Service، Standalone؟مهم

Component = Template + Class + Style. Service منطق مشترک و فراخوانی API، با @Injectable({providedIn:'root'}) تزریق می‌شود. NgModule روش قدیمی گروه‌بندی بود؛ از Angular 14 به بعد Standalone Component رایج و از 17 پیش‌فرض است.

Observable در مقابل Promise؟ RxJS چند Operator مهم؟مهم

Promise یک مقدار، Eager، غیرقابل لغو. Observable چند مقدار در طول زمان، Lazy (تا Subscribe نشود اجرا نمی‌شود)، قابل لغو با Unsubscribe. Operatorها: map، filter، switchMap (لغو درخواست قبلی، مثلاً در جستجو)، mergeMap، debounceTime، catchError، takeUntil. برای جلوگیری از Memory Leak از async pipe یا takeUntilDestroyed استفاده می‌شود.

ارتباط بین کامپوننت‌ها چطور است؟

Parent به Child با @Input، Child به Parent با @Output و EventEmitter، و بین کامپوننت‌های نامرتبط با Shared Service و BehaviorSubject یا Signal. برای State پیچیده NgRx.

Lifecycle Hookها؟

ngOnChanges (تغییر Input)، ngOnInit (مقداردهی و فراخوانی API)، ngAfterViewInit، ngOnDestroy (Unsubscribe و پاکسازی). Constructor فقط برای تزریق وابستگی.

Data Binding ها؟

Interpolation {{ value }}، Property [src]="url"، Event (click)="save()"، Two-way [(ngModel)].

HttpClient و Interceptor؛ توکن JWT را چطور به همه درخواست‌ها اضافه می‌کنی؟مهم
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).token();
  const authReq = token
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })
    : req;
  return next(authReq);
};
// app.config.ts
provideHttpClient(withInterceptors([authInterceptor]))

Interceptor برای Token، مدیریت سراسری خطا (مثلاً 401 → صفحه Login)، و Loading.

Reactive Form و Template-driven Form؟

Template-driven ساده، منطق در HTML با ngModel. Reactive با FormGroup/FormControl/FormBuilder در کلاس، Validation قوی‌تر، قابل تست؛ برای فرم‌های پیچیده Reactive.

Routing، Lazy Loading و Guard؟

Route با loadComponent/loadChildren Lazy بارگذاری می‌شود و Bundle اولیه کوچک می‌ماند. Guard (canActivate) دسترسی به Route را بر اساس Login یا نقش کنترل می‌کند؛ ولی امنیت واقعی همیشه سمت API است.

Change Detection و OnPush؟ Signals چیست؟

Angular با Zone.js بعد از هر رویداد Async کل درخت را بررسی می‌کند. OnPush فقط وقتی Input مرجعش عوض شود یا Event داخلی رخ دهد بررسی می‌کند و سریع‌تر است. Signals (از Angular 16) مقدار واکنش‌گرا با signal()، computed()، effect() که Change Detection دقیق‌تر و بدون Zone را ممکن می‌کند.

Pipe چیست؟

تبدیل نمایش داده در Template: date، currency، async، و Pipe سفارشی. Pure Pipe فقط با تغییر ورودی دوباره اجرا می‌شود.

Microservices و RabbitMQ

Microservice در مقابل Monolith؛ مزایا و هزینه‌ها؟مهم

مزایا: Deploy و Scale مستقل، مالکیت تیمی، ایزوله شدن خطا، تکنولوژی متفاوت. هزینه: پیچیدگی شبکه، Consistency توزیع‌شده، Monitoring و Tracing، DevOps. برای سیستم کوچک، Modular Monolith اغلب انتخاب بهتری است.

انواع Exchange در RabbitMQ؟مهم

Direct بر اساس Routing Key دقیق؛ Fanout به همه Queueهای متصل (Broadcast)؛ Topic با الگو (payment.*.failed، #)؛ Headers بر اساس Header.

چطور مطمئن می‌شوی پیام گم نمی‌شود؟مهم
  • Queue و پیام Durable/Persistent.
  • Publisher Confirms.
  • Manual Ack در Consumer بعد از پردازش موفق؛ در خطا Nack و Retry.
  • Dead Letter Exchange برای پیام‌های Poison.
  • Outbox Pattern: پیام در همان تراکنش دیتابیس ذخیره و جداگانه Publish می‌شود.
  • Consumer Idempotent (Inbox یا چک MessageId) چون تحویل At-least-once است.
ارتباط Sync و Async بین سرویس‌ها؟ کی کدام؟

Sync (HTTP/gRPC) وقتی جواب فوری لازم است، ولی Coupling زمانی و زنجیره خطا دارد؛ با Timeout، Retry و Circuit Breaker (Polly) محافظت کن. Async (پیام) برای کارهایی که منتظرشان نیستیم: نوتیفیکیشن، گزارش، به‌روزرسانی سرویس دیگر.

تراکنش توزیع‌شده: Saga؟

چون Transaction واحد بین دیتابیس‌ها نداریم، Saga زنجیره‌ای از تراکنش‌های محلی با Compensating Action است. Choreography با Event، Orchestration با یک هماهنگ‌کننده (مثلاً State Machine در MassTransit).

API Gateway، Service Discovery، Observability؟

Gateway (YARP، Ocelot): نقطه ورود واحد، Auth، Rate Limit، Routing. Observability: Log ساخت‌یافته با Serilog به Elasticsearch، Correlation Id، Metrics، و Distributed Tracing با OpenTelemetry.

تست

Unit Test و Integration Test؛ از چه ابزاری استفاده می‌کنی؟مهم

Unit Test یک واحد را جدا از وابستگی‌ها (با Mock) تست می‌کند: xUnit، Moq یا NSubstitute، FluentAssertions. Integration Test چند لایه با دیتابیس واقعی یا Testcontainers و WebApplicationFactory برای تست کامل API. Test Pyramid: Unit زیاد، Integration کمتر، E2E کم.

یک Unit Test ساده بنویس.
public class BankAccountTests
{
    [Fact]
    public void Withdraw_MoreThanBalance_Throws()
    {
        var account = new BankAccount(initialBalance: 100);
        var act = () => account.Withdraw(150);
        Assert.Throws<InvalidOperationException>(act);
    }

    [Theory]
    [InlineData(100, 30, 70)]
    [InlineData(50, 50, 0)]
    public void Withdraw_Valid_DecreasesBalance(decimal start, decimal amount, decimal expected)
    {
        var account = new BankAccount(start);
        account.Withdraw(amount);
        Assert.Equal(expected, account.Balance);
    }
}

الگوی Arrange / Act / Assert و نام‌گذاری Method_Scenario_Expected.

Mock، Stub و Fake؟

Stub فقط داده برمی‌گرداند، Mock علاوه بر آن رفتار و فراخوانی را Verify می‌کند، Fake پیاده‌سازی سبک و واقعی (مثل InMemory Repository).

Git و Agile

merge و rebase؟ cherry-pick؟مهم

merge یک Merge Commit می‌سازد و تاریخچه را حفظ می‌کند؛ rebase کامیت‌ها را روی شاخه مقصد بازنویسی و تاریخچه را خطی می‌کند. روی شاخه مشترک و Push‌شده rebase نکن. cherry-pick یک کامیت خاص را به شاخه دیگر می‌آورد (مثلاً Hotfix). git stash برای کنار گذاشتن موقت تغییرات، git revert برای برگرداندن امن کامیت Push‌شده.

استراتژی Branching تیمتان چه بود؟

Git Flow (develop، feature، release، hotfix) یا Trunk-based با Feature Branch کوتاه‌عمر و Merge Request با Code Review و CI. تجربه GitLab Merge Request و Review خودت را بگو.

Scrum و تجربه Agile تیمتان؟

Sprint دو هفته‌ای، Sprint Planning، Daily Standup، Review و Retrospective؛ Backlog و تخمین با Story Point. حتی اگر رسمی Scrum نبود، بگو چطور کار را تقسیم، تخمین و تحویل می‌دادید. نقش خودت به‌عنوان تیم‌لید در Planning و Review را برجسته کن.

Performance و Scalability

برای بهبود Performance یک API چه کارهایی می‌کنی؟مهم
  • اول اندازه‌گیری: Log زمان، APM، Profiler؛ حدس نزن.
  • دیتابیس: Index، Projection، AsNoTracking، Pagination، حذف N+1.
  • Caching: In-Memory، Redis (Distributed)، Output/Response Caching؛ Cache-aside و Invalidation.
  • async تا انتها، Connection Pooling، IHttpClientFactory.
  • کارهای غیرضروری را Async و به Queue بفرست.
  • Response Compression و کاهش حجم Payload.
Scale Up و Scale Out؟ سرویس Stateless چرا مهم است؟

Scale Up سخت‌افزار قوی‌تر، Scale Out نمونه‌های بیشتر پشت Load Balancer. برای Scale Out سرویس باید Stateless باشد: Session و Cache در Redis، فایل در Storage مشترک.

Redis را برای چه استفاده کردی؟

Distributed Cache، جلوگیری از درخواست تکراری (Deduplication)، Distributed Lock، Rate Limiting. مراقب Cache Stampede و TTL مناسب باش.

Rate Limiting در ASP.NET Core؟

از .NET 7 Middleware داخلی AddRateLimiter با الگوریتم‌های Fixed Window، Sliding Window، Token Bucket و Concurrency؛ خروجی 429.

تمرین کدنویسی محتمل

در مصاحبه‌های ایرانی معمولاً یک یا دو Query و یک مسئله کوچک C# روی کاغذ یا نوت‌پد می‌دهند. اول خودت بنویس، بعد باز کن.

SQL: دومین حقوق بالا (یا N امین).
SELECT Salary FROM (
  SELECT Salary, DENSE_RANK() OVER (ORDER BY Salary DESC) AS rnk
  FROM Employees
) t WHERE rnk = 2;
SQL: رکوردهای تکراری را پیدا و حذف کن (یکی بماند).
;WITH d AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY Email ORDER BY Id) AS rn
  FROM Users
)
DELETE FROM d WHERE rn > 1;
SQL: آخرین تراکنش هر حساب (Top 1 per group).
SELECT * FROM (
  SELECT t.*, ROW_NUMBER() OVER (PARTITION BY AccountId ORDER BY CreatedAt DESC) AS rn
  FROM Transactions t
) x WHERE rn = 1;

یا با CROSS APPLY (SELECT TOP 1 ...) که با Index روی (AccountId, CreatedAt DESC) خیلی سریع است.

SQL: مشتری‌هایی که هیچ سفارشی ندارند.
SELECT c.* FROM Customers c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerId = c.Id);

NOT IN با NULL در زیرQuery نتیجه خالی می‌دهد؛ NOT EXISTS امن‌تر است.

SQL: مجموع تراکنش موفق هر روز در ماه جاری، فقط روزهای بالای ۱۰۰ میلیون.
SELECT CAST(CreatedAt AS date) AS Day, SUM(Amount) AS Total
FROM Transactions
WHERE Status = 'Success'
  AND CreatedAt >= DATEFROMPARTS(YEAR(GETDATE()), MONTH(GETDATE()), 1)
GROUP BY CAST(CreatedAt AS date)
HAVING SUM(Amount) > 100000000
ORDER BY Day;
C#: کاراکترهای تکراری یک رشته و تعدادشان را با LINQ بشمار.
var result = input
    .Where(char.IsLetter)
    .GroupBy(c => char.ToLower(c))
    .Where(g => g.Count() > 1)
    .Select(g => new { Char = g.Key, Count = g.Count() });
C#: بررسی Palindrome و Reverse رشته بدون متد آماده.
static bool IsPalindrome(string s)
{
    int i = 0, j = s.Length - 1;
    while (i < j)
        if (s[i++] != s[j--]) return false;
    return true;
}
C#: دو عدد در آرایه که جمعشان برابر Target است (Two Sum).
static (int, int)? TwoSum(int[] nums, int target)
{
    var seen = new Dictionary<int, int>();
    for (int i = 0; i < nums.Length; i++)
    {
        if (seen.TryGetValue(target - nums[i], out var j)) return (j, i);
        seen[nums[i]] = i;
    }
    return null;
}   // O(n)
C#: خروجی این کد چیست؟ (سوال تله‌ای رایج)
var actions = new List<Action>();
for (int i = 0; i < 3; i++) actions.Add(() => Console.Write(i));
actions.ForEach(a => a());

خروجی 333؛ Closure متغیر i را Capture می‌کند نه مقدارش را. با foreach از C# 5 به بعد هر دور متغیر جدید است و 012 چاپ می‌شود. راه‌حل در for: کپی محلی var x = i;.

طراحی: یک Endpoint انتقال وجه بین دو حساب طراحی کن.
  • POST /api/v1/transfers با Header Idempotency-Key.
  • Validation: مبلغ مثبت، حساب‌ها متفاوت و فعال.
  • Transaction دیتابیس؛ Lock یا rowversion روی حساب‌ها، و قفل گرفتن با ترتیب ثابت (Id کوچک‌تر اول) برای جلوگیری از Deadlock.
  • ثبت Ledger (بدهکار و بستانکار) به‌جای فقط تغییر Balance.
  • رویداد TransferCompleted با Outbox به RabbitMQ برای نوتیفیکیشن.
  • خروجی 201؛ تعارض 409؛ موجودی ناکافی 422.

سوالات رفتاری و منابع انسانی

چرا می‌خواهی از کار فعلی‌ات بروی؟مهم

هیچ‌وقت از شرکت فعلی بد نگو. «سه سال در اوزون پروژه شتاب را از ابتدا تا پایداری رساندیم و یاد گرفتم. حالا دنبال محیط بزرگ‌تر با پروژه‌های متنوع‌تر هستم و همراه اول را از دوره ناک می‌شناسم.»

چرا بهپرداز همراه؟ از شرکت چه می‌دانی؟

قبل از یکشنبه سایت و محصولاتشان را ببین (پرداخت، کیف پول، خدمات دیجیتال همراه اول) و یک جمله بگو که تجربه پرداخت و تراکنش‌های پرترافیکت دقیقاً به کجای کارشان می‌خورد.

نقطه ضعفت چیست؟

یک ضعف واقعی ولی غیرکشنده که روی آن کار می‌کنی. مثال: «قبلاً کارها را خودم انجام می‌دادم و Delegate نمی‌کردم؛ در تیم‌لیدی یاد گرفتم کار را تقسیم کنم و با Code Review کیفیت را نگه دارم.»

با هم‌تیمی اختلاف فنی داشتی؟ چطور حل شد؟
