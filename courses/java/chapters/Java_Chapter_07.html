درس 01 · فصل هفتم

مفهوم Thread و تفاوت start و run

توضیح مفهوم و مقایسه با دات‌نت

هر Thread مسیر اجرای مستقلی در یک Process است. در Java فراخوانی start() اجرای یک Thread جدید را آغاز می‌کند، ولی run() فراخوانی معمولی روی Thread فعلی است. در #C نیز Thread.Start() آغاز اجرای Thread جدید است.

مثال عملی

نمونه کد / Java — ThreadJAVA
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() ->
            System.out.println(Thread.currentThread().getName()));
        t.run();   // typically prints main
        t.start(); // runs in a separate thread
        t.join();
    }
}
سؤال مرور درس 01 — نمایش پاسخ

سؤال: اگر از داخل main متد t.run() را صدا بزنیم چه اتفاقی می‌افتد؟

پاسخ: روی Thread فعلی اجرا می‌شود و معمولاً نام main چاپ خواهد شد.

درس 02 · فصل هفتم

تفاوت Runnable و Callable و مفهوم Future

توضیح مفهوم و مقایسه با دات‌نت

اینترفیس Runnable متد run() بدون مقدار بازگشتی دارد، اما Callable<T> با متد call() نتیجه تولید می‌کند و می‌تواند Checked Exception اعلام کند. نتیجه کار ثبت‌شده در Executor را می‌توان از Future<T> دریافت کرد؛ get() در صورت آماده‌نبودن نتیجه مسدودکننده است.

مثال عملی

نمونه کد / Java — CallableJAVA
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService executor = Executors.newSingleThreadExecutor();
        try {
            Callable<Integer> fee = () -> 100 + 200;
            Future<Integer> result = executor.submit(fee);
            System.out.println(result.get()); // 300
        } finally {
            executor.shutdown();
        }
    }
}
سؤال مرور درس 02 — نمایش پاسخ

سؤال: برای محاسبه کارمزد و دریافت نتیجه کدام ترکیب مناسب‌تر است؟

پاسخ: Callable<Integer> همراه با Future<Integer>؛ گزینه C.

درس 03 · فصل هفتم

مدیریت Thread Pool با ExecutorService

توضیح مفهوم و مقایسه با دات‌نت

ایجاد یک Thread برای هر درخواست هزینه‌بر است. ExecutorService کارها را مدیریت می‌کند. newFixedThreadPool(2) حداکثر دو کار را هم‌زمان روی Threadهای همان Pool اجرا می‌کند؛ بقیه منتظر می‌مانند. shutdown() از پذیرش کار جدید جلوگیری می‌کند، نه اینکه کارهای پذیرفته‌شده را خودکار لغو کند. صف پیش‌فرض این Factory نامحدود است و در فشار زیاد می‌تواند رشد کند.

مثال عملی

نمونه کد / Java — ExecutorServiceJAVA
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) {
        ExecutorService pool = Executors.newFixedThreadPool(2);
        for (int i = 1; i <= 5; i++) {
            int id = i;
            pool.submit(() -> System.out.println("Payment " + id));
        }
        pool.shutdown();
    }
}
سؤال مرور درس 03 — نمایش پاسخ

سؤال: اگر به Pool دو Threadی ده کار بدهیم، حداکثر چند کار هم‌زمان اجرا می‌شوند؟

پاسخ: حداکثر ۲ کار؛ گزینه C.

درس 04 · فصل هفتم

مفهوم Race Condition و synchronized

توضیح مفهوم و مقایسه با دات‌نت

عملیات balance = balance - 100 از خواندن، محاسبه و نوشتن تشکیل شده و بدون هماهنگی ممکن است افزایش یا برداشت از دست برود. synchronized برای Threadهایی که از یک مانیتور یکسان استفاده می‌کنند ورود هم‌زمان به بخش حساس را محدود می‌کند. در #C با lock قابل مقایسه است. این قفل فقط درون یک فرایند معتبر است، نه بین چند Instance سرویس پرداخت.

مثال عملی

نمونه کد / Java — synchronizedJAVA
class Counter {
    private int value = 0;

    public synchronized void increment() {
        value++;
    }

    public synchronized int getValue() {
        return value;
    }
}
// Two threads each call increment() 1000 times on SAME Counter.
// After both threads finish, getValue() is 2000.
سؤال مرور درس 04 — نمایش پاسخ

سؤال: اگر دو Thread روی یک شیء مشترک هرکدام هزار بار increment همگام‌شده را اجرا کنند، نتیجه چیست؟

پاسخ: پس از پایان هر دو Thread دقیقاً 2000؛ گزینه B.

درس 05 · فصل هفتم

مفهوم volatile و تفاوت Visibility با Atomicity

توضیح مفهوم و مقایسه با دات‌نت

کلمه volatile برای خواندن و نوشتن یک فیلد، تضمین‌های Visibility و ترتیب حافظه فراهم می‌کند؛ اما یک عملیات مرکب مانند value++ را اتمیک نمی‌کند. برای افزایش هم‌زمان به ابزارهایی مانند AtomicInteger یا قفل نیاز داریم.

مثال عملی

نمونه کد / Java — volatileJAVA
class PaymentWorker {
    private volatile boolean running = true;
    void stop() { running = false; }
    void process() {
        while (running) { /* independent work */ }
    }
}

class UnsafeCounter {
    private volatile int value = 0;
    void increment() { value++; } // NOT atomic
}
سؤال مرور درس 05 — نمایش پاسخ

سؤال: آیا volatile روی int موجب می‌شود value++ همیشه بدون از دست رفتن افزایش‌ها باشد؟

پاسخ: خیر؛ ممکن است نتیجه کمتر از مقدار مورد انتظار باشد، زیرا افزایش اتمیک نیست؛ گزینه C.

درس 06 · فصل هفتم

مفهوم AtomicInteger و ReentrantLock

توضیح مفهوم و مقایسه با دات‌نت

کلاس AtomicInteger برای عملیات اتمیک مانند incrementAndGet() کاربرد دارد؛ مشابه Interlocked.Increment() در دات‌نت. برای چند دستور وابسته می‌توان از ReentrantLock استفاده کرد و حتماً unlock() را در finally قرار داد.

مثال عملی

نمونه کد / Java — AtomicIntegerJAVA
import java.util.concurrent.atomic.AtomicInteger;

class Counter {
    private final AtomicInteger value = new AtomicInteger(0);
    void increment() { value.incrementAndGet(); }
    int getValue() { return value.get(); }
}
نمونه کد / Java — ReentrantLockJAVA
import java.util.concurrent.locks.ReentrantLock;

class Account {
    private int balance = 1000;
    private final ReentrantLock lock = new ReentrantLock();
    void withdraw(int amount) {
        lock.lock();
        try {
            if (balance >= amount) balance -= amount;
        } finally {
            lock.unlock();
        }
    }
}
سؤال مرور درس 06 — نمایش پاسخ

سؤال: اگر دو Thread هرکدام هزار بار incrementAndGet را اجرا کنند، نتیجه چیست؟

پاسخ: پس از پایان هر دو Thread دقیقاً 2000؛ گزینه C.

درس 07 · فصل هفتم

مفهوم Future و CompletableFuture

توضیح مفهوم و مقایسه با دات‌نت

کلاس CompletableFuture<T> امکان زنجیره‌سازی عملیات پس از آماده‌شدن نتیجه را فراهم می‌کند. supplyAsync() کار نتیجه‌دار شروع می‌کند؛ thenApply() نتیجه را تبدیل می‌کند و thenAccept() از نتیجه استفاده می‌کند. متد join() در صورت تکمیل‌نشدن Future، Thread فراخوان را مسدود می‌کند. این مدل با Task<T> در دات‌نت شباهت دارد اما یکسان با async/await نیست.

مثال عملی

نمونه کد / Java — CompletableFutureJAVA
import java.util.concurrent.CompletableFuture;

public class Main {
    public static void main(String[] args) {
        CompletableFuture<Integer> future =
            CompletableFuture.supplyAsync(() -> 100);
        CompletableFuture<Integer> doubled =
            future.thenApply(x -> x * 2);
        System.out.println(doubled.join()); // 200
    }
}
سؤال مرور درس 07 — نمایش پاسخ

سؤال: خروجی supplyAsync(() -> 100).thenApply(x -> x * 2).join() چیست؟

پاسخ: عدد 200؛ گزینه B.

درس 08 · فصل هفتم

مفهوم Virtual Threads در Java

توضیح مفهوم و مقایسه با دات‌نت

از Java 21، Virtual Threads به‌صورت پایدار در دسترس‌اند. JVM تعداد زیادی Thread سبک‌وزن را مدیریت می‌کند و برای وظایفی با انتظار I/O زیاد مناسب‌اند. آن‌ها سرعت CPU، ظرفیت دیتابیس یا ایمنی هم‌زمانی را خودکار افزایش نمی‌دهند. در دات‌نت async/await برای مقیاس‌پذیری I/O هدف مشابهی دارد اما مدل اجرایی متفاوت است.

مثال عملی

نمونه کد / Java — Virtual Thread (Java 21+)JAVA
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread t = Thread.startVirtualThread(() ->
            System.out.println("Payment started"));
        t.join();
        System.out.println("Finished");
    }
}
سؤال مرور درس 08 — نمایش پاسخ

سؤال: مزیت اصلی Virtual Threads در سرویس‌های منتظر I/O چیست؟

پاسخ: مدیریت تعداد زیاد کار هم‌زمان با هزینه Thread کمتر؛ گزینه D.

درس 09 · فصل هفتم

تفاوت ConcurrentHashMap و HashMap

توضیح مفهوم و مقایسه با دات‌نت

کلاس ConcurrentHashMap برای دسترسی هم‌زمان چند Thread به یک Map مشترک طراحی شده است. اشتراک‌گذاری خودکار رخ نمی‌دهد: همه Threadها باید به همان شیء اشاره کنند. حتی روی این Map، عملیات مرکب get() سپس put() لزوماً اتمیک نیست؛ برای شمارنده از merge() استفاده می‌کنیم. این ابزار حافظه چند Instance مستقل سرویس را مشترک نمی‌کند.

مثال عملی

نمونه کد / Java — ConcurrentHashMapJAVA
import java.util.concurrent.ConcurrentHashMap;

public class Main {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> counts =
            new ConcurrentHashMap<>();
        counts.merge("Success", 1, Integer::sum);
        counts.merge("Success", 1, Integer::sum);
        System.out.println(counts.get("Success")); // 2
    }
}
سؤال مرور درس 09 — نمایش پاسخ

سؤال: دو Thread هرکدام هزار بار merge روی کلید Success انجام دهند؛ نتیجه چیست؟

پاسخ: پس از تکمیل هر دو Thread مقدار 2000؛ گزینه C.

درس 10 · فصل هفتم

مفهوم Deadlock و ترتیب دریافت قفل‌ها

توضیح مفهوم و مقایسه با دات‌نت

اگر Thread اول قفل A را داشته باشد و منتظر B بماند، درحالی‌که Thread دوم B را داشته و منتظر A است، چرخه انتظار یا Deadlock رخ می‌دهد. یک راه پیشگیری این است که همه Threadها قفل‌های مشترک را با ترتیب یکسان دریافت کنند. این وضعیت در هر اجرای کد با ترتیب‌های معکوس لزوماً رخ نمی‌دهد؛ به زمان‌بندی وابسته است.

مثال عملی

نمونه کد / Java — risky orderJAVA
final Object lockA = new Object();
final Object lockB = new Object();

Thread t1 = new Thread(() -> {
    synchronized (lockA) {
        synchronized (lockB) { System.out.println("Pay"); }
    }
});
Thread t2 = new Thread(() -> {
    synchronized (lockB) {
        synchronized (lockA) { System.out.println("Refund"); }
    }
});
t1.start();
t2.start(); // possible deadlock
نمونه کد / Java — consistent lock orderJAVA
// Both operations acquire A before B:
synchronized (lockA) {
    synchronized (lockB) {
        // critical section
    }
}
سؤال مرور درس 10 — نمایش پاسخ

سؤال: بهترین روش کاهش خطر Deadlock این دو قفل چیست؟

پاسخ: همه Threadها قفل‌ها را با ترتیب یکسان دریافت کنند؛ گزینه C.
