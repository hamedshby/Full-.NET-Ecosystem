درس 01 · فصل پنجم

Lambda Expression و Functional Interface

توضیح مفهوم و مقایسه با دات‌نت

در #C از Func<int,int> و عبارت x => x * 2 استفاده می‌کنیم. در Java علامت لامبدا -> است و عبارت لامبدا باید با یک Functional Interface سازگار باشد؛ یعنی اینترفیسی که دقیقاً یک متد abstract داشته باشد.

Annotation @FunctionalInterface اختیاری است، ولی کامپایلر را وادار می‌کند این شرط را بررسی کند. وجود متدهای default و static مانع Functional Interface بودن نیست.

مثال عملی

نمونه کد / JavaJAVA
@FunctionalInterface
interface Calculator {
    int calculate(int x);
}

public class Main {
    public static void main(String[] args) {
        Calculator doubleValue = x -> x * 2;
        System.out.println(doubleValue.calculate(10)); // 20
    }
}
سؤال مرور درس 01 — نمایش پاسخ

سؤال: خروجی Calculator calc = x -> x + 10; calc.calculate(5) چیست؟

پاسخ: 15؛ لامبدا مقدار ورودی را ۱۰ واحد افزایش می‌دهد.

درس 02 · فصل پنجم

اینترفیس‌های Predicate، Function و Consumer

توضیح مفهوم و مقایسه با دات‌نت

کتابخانه java.util.function اینترفیس‌های آماده‌ای دارد. Predicate<T> مانند Func<T,bool> در #C شرط را ارزیابی می‌کند؛ Function<T,R> مانند Func<T,R> تبدیل انجام می‌دهد؛ و Consumer<T> مانند Action<T> عملی انجام می‌دهد ولی خروجی ندارد.

اینترفیسمتدکاربرد
Predicate<T>test()بررسی شرط
Function<T,R>apply()تبدیل داده
Consumer<T>accept()انجام عملیات بدون نتیجه

مثال عملی

نمونه کد / JavaJAVA
import java.util.function.*;

public class Main {
    public static void main(String[] args) {
        Predicate<Integer> valid = amount -> amount > 0;
        Function<Integer, String> formatter = n -> "Amount: " + n;
        Consumer<String> logger = System.out::println;

        System.out.println(valid.test(100)); // true
        logger.accept(formatter.apply(500)); // Amount: 500
    }
}
سؤال مرور درس 02 — نمایش پاسخ

سؤال: اگر شرط amount -> amount > 100 باشد، نتیجه test(100) و test(200) چیست؟

پاسخ: به ترتیب false و true؛ عدد ۱۰۰ بزرگ‌تر از خودش نیست.

درس 03 · فصل پنجم

آشنایی با Stream API و Lazy Execution

توضیح مفهوم و مقایسه با دات‌نت

در #C عملیات LINQ مانند Where() و ToList() آشناست؛ در Java از stream()، filter() و toList() استفاده می‌کنیم. عملیات میانی (Intermediate) مانند filter() و map() تنبل یا Lazy هستند؛ تا یک عملیات نهایی (Terminal) اجرا نشود، پردازش معمولاً آغاز نمی‌شود.

برخلاف پرس‌وجوهای LINQ که می‌توان آن‌ها را مجدداً enumerate کرد، یک Stream مصرف‌شده در Java دوباره قابل استفاده نیست. متد Stream.toList() از Java 16 وجود دارد و نتیجه غیرقابل‌تغییر است.

مثال عملی

نمونه کد / JavaJAVA
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> amounts = List.of(100, 200, 300);

        var stream = amounts.stream().filter(x -> {
            System.out.println("Filter: " + x);
            return x > 100;
        });
        System.out.println("Before");
        System.out.println(stream.toList());
    }
}
سؤال مرور درس 03 — نمایش پاسخ

سؤال: در مثال بالا، عبارت Before قبل از پیام‌های Filter چاپ می‌شود یا بعد از آن‌ها؟

پاسخ: قبل از آن‌ها؛ فیلتر با اجرای عملیات نهایی toList() آغاز می‌شود. خروجی سپس [200, 300] است.

درس 04 · فصل پنجم

تفاوت filter و map در Java

توضیح مفهوم و مقایسه با دات‌نت

متد filter() معادل Where() در LINQ است و عناصر نامنطبق را حذف می‌کند. متد map() معادل Select() است و هر عنصر عبوری را به مقدار دیگری تبدیل می‌کند. این دو عملیات را می‌توان زنجیره کرد.

در Stream ترتیبی، عملیات میانی غالباً به‌صورت عنصر‌به‌عنصر اجرا می‌شوند؛ قرار نیست الزاماً اول یک فهرست کامل از نتایج فیلتر ساخته شود.

مثال عملی

نمونه کد / JavaJAVA
import java.util.List;

public class Main {
    public static void main(String[] args) {
        var result = List.of(100, 200, 300, 400).stream()
            .filter(x -> x >= 200)
            .map(x -> x + 50)
            .toList();

        System.out.println(result); // [250, 350, 450]
    }
}
سؤال مرور درس 04 — نمایش پاسخ

سؤال: خروجی فیلتر اعداد بزرگ‌تر یا مساوی ۲۰۰ و سپس افزودن ۵۰ به هر عنصر چیست؟

پاسخ: [250, 350, 450]؛ ابتدا ۱۰۰ کنار گذاشته می‌شود و سپس سه مقدار باقی‌مانده تبدیل می‌شوند.

درس 05 · فصل پنجم

تفاوت map و flatMap برای داده‌های تو در تو

توضیح مفهوم و مقایسه با دات‌نت

در #C متد SelectMany() یک مجموعه تو در تو را تخت می‌کند. در Java از flatMap() استفاده می‌کنیم. map() هر عنصر را به یک خروجی نگاشت می‌کند، اما flatMap() هر عنصر را به یک Stream تبدیل می‌کند و عناصر Streamهای داخلی را به جریان واحد می‌آورد.

مثال کاربردی: هر فروشگاه فهرستی از تراکنش‌ها دارد و می‌خواهیم همه تراکنش‌ها را به‌صورت یک فهرست واحد پردازش کنیم.

مثال عملی

نمونه کد / JavaJAVA
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<List<Integer>> payments = List.of(
            List.of(10, 20),
            List.of(30, 40)
        );

        var result = payments.stream()
            .flatMap(list -> list.stream())
            .filter(x -> x > 20)
            .toList();

        System.out.println(result); // [30, 40]
    }
}
سؤال مرور درس 05 — نمایش پاسخ

سؤال: نتیجه flatMap() روی دو لیست [10,20] و [30,40] و سپس فیلتر x > 20 چیست؟

پاسخ: [30, 40]؛ ابتدا لیست‌های داخلی تخت و سپس فیلتر می‌شوند.

درس 06 · فصل پنجم

مرتب‌سازی با sorted و Comparator

توضیح مفهوم و مقایسه با دات‌نت

در #C از OrderBy() و OrderByDescending() استفاده می‌کنی. در Java، sorted() مرتب‌سازی طبیعی و sorted(Comparator.reverseOrder()) مرتب‌سازی معکوس را انجام می‌دهد.

برای مرتب‌سازی تراکنش‌ها بر اساس مبلغ می‌توان از Comparator.comparingInt(Payment::amount) استفاده کرد. متد sorted() لیست منبع را تغییر نمی‌دهد و از عملیات میانیِ Stateful است.

مثال عملی

نمونه کد / JavaJAVA
import java.util.*;

record Payment(int id, int amount) {}

public class Main {
    public static void main(String[] args) {
        List<Payment> payments = List.of(
            new Payment(1, 500), new Payment(2, 100),
            new Payment(3, 300)
        );
        var sorted = payments.stream()
            .sorted(Comparator.comparingInt(Payment::amount))
            .toList();
        sorted.forEach(System.out::println);
    }
}
سؤال مرور درس 06 — نمایش پاسخ

سؤال: نتیجه مرتب‌سازی نزولی [400,100,300,200] پس از فیلتر x > 150 چیست؟

پاسخ: [400, 300, 200]؛ مقدار ۱۰۰ فیلتر می‌شود و سایر مقادیر نزولی می‌شوند.

درس 07 · فصل پنجم

عملیات distinct، skip و limit

توضیح مفهوم و مقایسه با دات‌نت

متدهای distinct()، skip(n) و limit(n) به‌ترتیب مشابه Distinct()، Skip() و Take() در LINQ هستند. حذف تکرارها به برابری منطقی عناصر (و قرارداد equals()/hashCode()) وابسته است.

برای صفحه‌بندی مجموعه‌های درون حافظه می‌توان از skip و limit استفاده کرد، اما برای جدول تراکنش‌های بزرگ بهتر است صفحه‌بندی در دیتابیس انجام شود.

مثال عملی

نمونه کد / JavaJAVA
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> numbers =
            List.of(10, 20, 10, 30, 40, 20, 50);

        var result = numbers.stream()
            .distinct()
            .skip(1)
            .limit(2)
            .toList();

        System.out.println(result); // [20, 30]
    }
}
سؤال مرور درس 07 — نمایش پاسخ

سؤال: خروجی distinct().skip(1).limit(2) برای مقادیر بالا چیست؟

پاسخ: [20, 30]؛ پس از حذف تکراری‌ها، ۱۰ حذف و دو عضو بعدی انتخاب می‌شوند.

درس 08 · فصل پنجم

عملیات نهایی count، findFirst و anyMatch

توضیح مفهوم و مقایسه با دات‌نت

این متدها عملیات نهایی Stream هستند: count() تعداد عناصر را از نوع long برمی‌گرداند؛ findFirst() نتیجه‌ای از نوع Optional<T> دارد، چون ممکن است عنصری پیدا نشود؛ و anyMatch() یک boolean تولید می‌کند.

متدهای findFirst() و anyMatch() می‌توانند Short-circuit شوند؛ یعنی پس از یافتن پاسخ، ادامه پیمایش لازم نباشد.

مثال عملی

نمونه کد / JavaJAVA
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> amounts = List.of(100, 200, 300, 400);

        long count = amounts.stream().filter(x -> x > 200).count();
        int first = amounts.stream().filter(x -> x > 150)
            .findFirst().orElse(0);
        boolean exists = amounts.stream().filter(x -> x > 150)
            .anyMatch(x -> x > 350);

        System.out.println(count);  // 2
        System.out.println(first);  // 200
        System.out.println(exists); // true
    }
}
سؤال مرور درس 08 — نمایش پاسخ

سؤال: آیا anyMatch(x -> x > 350) پس از فیلتر کردن اعداد بیشتر از ۱۵۰ نتیجه مثبت می‌دهد؟

پاسخ: بله، true؛ چون عدد ۴۰۰ شرط را برقرار می‌کند.

درس 09 · فصل پنجم

عملیات collect و groupingBy

توضیح مفهوم و مقایسه با دات‌نت

در Java از collect(Collectors.groupingBy(...)) برای گروه‌بندی استفاده می‌کنیم؛ مشابه GroupBy() در LINQ. خروجی پیش‌فرض معمولاً یک Map<K,List<T>> است.

اگر به‌جای فهرست تراکنش‌های هر گروه فقط تعداد آن‌ها را بخواهیم، از Collectors.counting() به‌عنوان Downstream Collector استفاده می‌کنیم. روی ترتیب کلیدها در خروجی پیش‌فرض تکیه نکن.

مثال عملی

نمونه کد / JavaJAVA
import java.util.*;
import java.util.stream.Collectors;

record Payment(int id, String status) {}

public class Main {
    public static void main(String[] args) {
        var payments = List.of(
            new Payment(1, "Success"),
            new Payment(2, "Failed"),
            new Payment(3, "Success"),
            new Payment(4, "Pending"),
            new Payment(5, "Failed")
        );
        Map<String, Long> counts = payments.stream()
            .collect(Collectors.groupingBy(
                Payment::status, Collectors.counting()
            ));
        System.out.println(counts.get("Failed")); // 2
    }
}
سؤال مرور درس 09 — نمایش پاسخ

سؤال: برای داده‌های بالا تعداد تراکنش‌های Failed چند است؟

پاسخ: 2؛ دو رکورد با وضعیت Failed وجود دارد.

درس 10 · فصل پنجم

تفاوت Stream و Parallel Stream

توضیح مفهوم و مقایسه با دات‌نت

جریان معمولی با stream() به‌صورت پیش‌فرض ترتیبی است. parallelStream() اجازه می‌دهد پردازش عناصر به‌صورت موازی انجام شود. هنگام استفاده از forEach() روی جریان موازی، ترتیب اجرا تضمین نمی‌شود؛ در صورت نیاز به رعایت Encounter Order می‌توان از forEachOrdered() استفاده کرد.

پردازش موازی همیشه سریع‌تر نیست: تقسیم کار و هماهنگی سربار دارند. تغییر وضعیت مشترک داخل forEach() می‌تواند باعث Race Condition شود؛ برای تجمیع اعداد از عملیات استاندارد sum() استفاده کن.

نکته سیستم پرداختاز انجام عملیات دارای Side Effect روی موجودی یا وضعیت تراکنش در Parallel Stream بدون طراحی صحیح هم‌زمانی پرهیز کن.

مثال عملی

نمونه کد / JavaJAVA
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> numbers = List.of(1, 2, 3, 4, 5);

        // ترتیب چاپ تضمین نمی‌شود
        numbers.parallelStream().forEach(System.out::println);

        // تجمیع بدون تغییر متغیر مشترک
        int sum = numbers.parallelStream()
            .mapToInt(Integer::intValue)
            .sum();
        System.out.println("Sum: " + sum); // 15
    }
}
سؤال مرور درس 10 — نمایش پاسخ

سؤال: در parallelStream().forEach(System.out::println) آیا عناصر همیشه به ترتیب ۱ تا ۵ چاپ می‌شوند؟

پاسخ: خیر؛ ترتیب چاپ تضمین نمی‌شود. پاسخ تمرین گزینه C است.
