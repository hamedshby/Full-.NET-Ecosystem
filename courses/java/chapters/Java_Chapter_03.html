درس 01 · فصل سوم

Wrapper Classes و Autoboxing

توضیح مفهوم و مقایسه با دات‌نت

انواع int و long در Java از نوع Primitive هستند. برای استفاده از آن‌ها در کدهایی که Object می‌خواهند، کلاس‌های Wrapper مانند Integer و Long وجود دارند.

تبدیل خودکار Primitive به Wrapper را Autoboxing و تبدیل معکوس را Unboxing می‌نامیم. برخلاف int، متغیر Integer می‌تواند null باشد. Unboxing مقدار null در زمان اجرا NullPointerException ایجاد می‌کند.

PrimitiveWrapper
intInteger
longLong
doubleDouble
booleanBoolean
charCharacter

در #C هم مفهوم Boxing و Unboxing را می‌شناسی، اما در Java Wrapperهای اختصاصی برای Primitiveها نقش پررنگی دارند.

مثال عملی

نمونه کد / JavaJAVA
int amount = 500;
Integer boxed = amount; // Autoboxing
int result = boxed;     // Unboxing
System.out.println(result); // 500

Integer absent = null;
// int wrong = absent; // NullPointerException at runtime
سؤال مرور درس 01 — نمایش پاسخ

سؤال: خروجی یا نتیجه کد Integer amount = null; int value = amount; چیست؟

پاسخ: هنگام Unboxing خطای NullPointerException رخ می‌دهد.

درس 02 · فصل سوم

BigDecimal و محاسبات مالی

توضیح مفهوم و مقایسه با دات‌نت

در سیستم‌های پرداخت، دقت اعداد اعشاری بسیار مهم است. نوع double نمی‌تواند همه کسرهای ده‌دهی را به‌صورت دقیق در مبنای دو نمایش دهد؛ مثلاً جمع 0.1 + 0.2 ممکن است 0.30000000000000004 شود.

معادل رایج decimal در #C برای محاسبات ده‌دهی در Java کلاس BigDecimal است. از سازنده رشته‌ای یا BigDecimal.valueOf(...) استفاده کن، نه new BigDecimal(0.1). متدهای add، subtract، multiply و divide مقدار اصلی را تغییر نمی‌دهند، چون این کلاس Immutable است.

برای تقسیم‌هایی که نمایش اعشاری پایانی ندارند، باید دقت یا سیاست گردکردن را تعیین کنی؛ و برای مقایسه عددی معمولاً compareTo() مناسب‌تر از equals() است، چون equals() به Scale هم توجه می‌کند.

مثال عملی

نمونه کد / JavaJAVA
import java.math.BigDecimal;
import java.math.RoundingMode;

BigDecimal balance = new BigDecimal("1000");
balance.subtract(new BigDecimal("300")); // discarded
balance = balance.add(new BigDecimal("200"));
System.out.println(balance); // 1200

BigDecimal price = new BigDecimal("10");
BigDecimal share = price.divide(new BigDecimal("3"), 2, RoundingMode.HALF_UP);
System.out.println(share); // 3.33
سؤال مرور درس 02 — نمایش پاسخ

سؤال: در مثال balance.subtract(300) و بعد ذخیره نتیجه balance.add(200)، خروجی چیست؟

پاسخ: مقدار 1200؛ چون نتیجه subtract ذخیره نشده است.

درس 03 · فصل سوم

آرایه‌ها و Varargs

توضیح مفهوم و مقایسه با دات‌نت

آرایه‌ها در Java مانند #C اندازه ثابتی دارند. تفاوت رایج: طول آرایه با فیلد length (نه Length) گرفته می‌شود.

برای دریافت تعداد متغیری آرگومان، در #C از params استفاده می‌کنی و در Java از ...، مثلاً int... amounts. این پارامتر در بدنه متد مانند آرایه رفتار می‌کند و باید آخرین پارامتر متد باشد.

مثال عملی

نمونه کد / JavaJAVA
public class Main {
    static void printAmounts(String merchant, int... amounts) {
        System.out.println(merchant);
        System.out.println(amounts.length);
        for (int value : amounts) {
            System.out.println(value);
        }
    }
    public static void main(String[] args) {
        int[] payments = {100, 200, 300};
        System.out.println(payments.length); // 3
        printAmounts("Store", 100, 200, 300, 400); // length: 4
    }
}
سؤال مرور درس 03 — نمایش پاسخ

سؤال: در فراخوانی calculate(100, 200, 300, 400) با پارامتر int... amounts مقدار amounts.length چیست؟

پاسخ: عدد 4.

درس 04 · فصل سوم

Null و Optional در Java

توضیح مفهوم و مقایسه با دات‌نت

در Java انواع اولیه مانند int نمی‌توانند null باشند؛ اما کلاس‌هایی مانند Integer و String می‌توانند. کلاس Optional<T> برای نشان دادن صریح احتمال نبودن نتیجه، مخصوصاً در مقدار بازگشتی متدها، مفید است.

متدرفتار
Optional.of(x)مقدار غیر null لازم دارد؛ با null خطا می‌دهد
Optional.ofNullable(x)null را به Optional خالی تبدیل می‌کند
orElse(default)مقدار موجود یا پیش‌فرض را برمی‌گرداند
orElseGet(supplier)پیش‌فرض را فقط هنگام نیاز می‌سازد

در #C برای حالت‌های ساده از ?? و Nullable Reference Types استفاده می‌کنیم؛ ولی Optional در Java یک کلاس واقعی است.

مثال عملی

نمونه کد / JavaJAVA
import java.util.Optional;

Optional<String> merchant = Optional.ofNullable(null);
System.out.println(merchant.orElse("Unknown")); // Unknown

// This throws NullPointerException immediately:
// Optional<String> bad = Optional.of(null);
سؤال مرور درس 04 — نمایش پاسخ

سؤال: اگر Optional.of(null) را اجرا کنیم، آیا orElse() فرصت اجرا دارد؟

پاسخ: خیر؛ در همان Optional.of(null) خطای NullPointerException رخ می‌دهد.

درس 05 · فصل سوم

Exception و try/catch/finally

توضیح مفهوم و مقایسه با دات‌نت

مدیریت استثنا در Java بسیار شبیه #C است: بخش try کد اصلی را اجرا می‌کند، catch استثنای مناسب را می‌گیرد و finally معمولاً در پایان اجرا می‌شود؛ حتی وقتی استثنا رخ دهد.

از throw new IllegalArgumentException(...) برای اعتبارسنجی آرگومان نامعتبر استفاده می‌کنیم. پیام Exception با getMessage() قابل خواندن است. اجرای finally در شرایطی مثل خاتمه اجباری فرآیند تضمین نمی‌شود.

مثال عملی

نمونه کد / JavaJAVA
public class Main {
    public static void main(String[] args) {
        try {
            System.out.println("A");
            throw new RuntimeException("Error");
        } catch (RuntimeException ex) {
            System.out.println("B");
        } finally {
            System.out.println("C");
        }
        System.out.println("D");
    }
}
// A
// B
// C
// D
سؤال مرور درس 05 — نمایش پاسخ

سؤال: ترتیب چاپ حروف در مثال try/catch/finally چیست؟

پاسخ: A → B → C → D.

درس 06 · فصل سوم

Checked و Unchecked Exceptions

توضیح مفهوم و مقایسه با دات‌نت

این مبحث تفاوت بزرگی با #C دارد. در Java برخی استثناها از نوع Checked هستند؛ کامپایلر مجبورمان می‌کند آن‌ها را با try/catch مدیریت کنیم یا در امضای متد با throws اعلام کنیم. برای نمونه IOException و FileNotFoundException.

استثناهای فرزند RuntimeException مانند NullPointerException و IllegalArgumentException از نوع Unchecked هستند و الزام کامپایلری ندارند. وجود واقعی فایل روی دیسک این الزام را تغییر نمی‌دهد.

مثال عملی

نمونه کد / JavaJAVA
import java.io.FileReader;
import java.io.IOException;

public class Main {
    public static void main(String[] args) {
        try (FileReader reader = new FileReader("payments.txt")) {
            System.out.println(reader.read());
        } catch (IOException ex) {
            System.out.println(ex.getMessage());
        }
    }
}

// Alternative: declare throws IOException in main signature.
سؤال مرور درس 06 — نمایش پاسخ

سؤال: اگر new FileReader("payments.txt") را بدون catch یا throws بنویسیم، حتی با وجود فایل، نتیجه چیست؟

پاسخ: خطای کامپایل؛ احتمال Checked Exception مدیریت یا اعلام نشده است.

درس 07 · فصل سوم

ساخت Custom Exception

توضیح مفهوم و مقایسه با دات‌نت

در یک سیستم پرداخت می‌توانیم برای خطای موجودی ناکافی استثنای اختصاصی تعریف کنیم. اگر کلاس ما از RuntimeException ارث ببرد، استثنا Unchecked می‌شود. اگر مستقیماً از Exception ارث ببرد، Checked خواهد بود (مگر اینکه در شاخه RuntimeException باشد).

در پروژه‌های واقعی انتخاب Checked یا Unchecked باید بر اساس قرارداد و سیاست مدیریت خطا انجام شود؛ برای خطاهای دامنه‌ای، Unchecked انتخاب رایجی است.

مثال عملی

نمونه کد / JavaJAVA
class InsufficientBalanceException extends RuntimeException {
    public InsufficientBalanceException(String message) {
        super(message);
    }
}

class PaymentService {
    public void withdraw(int balance, int amount) {
        if (amount > balance) {
            throw new InsufficientBalanceException("Insufficient balance");
        }
        System.out.println("Withdrawal completed");
    }
}

// extends Exception instead? Declare throws or catch it.
سؤال مرور درس 07 — نمایش پاسخ

سؤال: اگر PaymentException extends Exception باشد و متد آن را بدون catch یا throws پرتاب کند، چه می‌شود؟

پاسخ: خطای کامپایل رخ می‌دهد چون Checked Exception مدیریت یا اعلام نشده است.

درس 08 · فصل سوم

Try-with-resources و AutoCloseable

توضیح مفهوم و مقایسه با دات‌نت

در #C از using و IDisposable برای آزادکردن منابع استفاده می‌کنی. در Java، ساختار try-with-resources و قرارداد AutoCloseable همان نقش را انجام می‌دهند: پایان بلوک باعث فراخوانی close() می‌شود.

منابع به ترتیب معکوس تعریف‌شدن بسته می‌شوند. بسته‌شدن حتی هنگام پرتاب استثنا هم انجام می‌شود؛ مگر در شرایط غیرعادی خاتمه اجرا. استثنای خود close() می‌تواند به‌عنوان استثنای suppressed نگهداری شود.

مثال عملی

نمونه کد / JavaJAVA
class PaymentResource implements AutoCloseable {
    public void process() {
        System.out.println("A");
    }
    @Override
    public void close() {
        System.out.println("B");
    }
}

public class Main {
    public static void main(String[] args) {
        try (PaymentResource r = new PaymentResource()) {
            r.process();
        }
        System.out.println("C");
    }
}
// A
// B
// C
سؤال مرور درس 08 — نمایش پاسخ

سؤال: چرا در مثال آخر ترتیب خروجی A → B → C است؟

پاسخ: چون متد close() قبل از اجرای دستورات بعد از بلوک try فراخوانی می‌شود.
