درس 01 · فصل دوم

Class و Object در Java

توضیح مفهوم و مقایسه با دات‌نت

کلاس نقشه ساخت شیء است و هر بار فراخوانی new، یک نمونه مستقل ایجاد می‌کند. در Java مثل #C، متغیر یک کلاس عادی مرجع شیء را نگه می‌دارد.

مثال عملی

نمونه کد / JavaJAVA
class Payment { int amount; }

public class Main {
    public static void main(String[] args) {
        Payment p1 = new Payment();
        Payment p2 = new Payment();
        p1.amount = 100;
        p2.amount = 200;
        System.out.println(p1.amount); // 100
    }
}
سؤال مرور درس 01 — نمایش پاسخ

سؤال: اگر از new Payment() دو بار استفاده کنیم، آیا تغییر مبلغ یکی روی دیگری اثر دارد؟

پاسخ: خیر؛ دو شیء مستقل ایجاد شده‌اند و پاسخ تمرین 100 است.

درس 02 · فصل دوم

Field، Getter و Setter

توضیح مفهوم و مقایسه با دات‌نت

در Java، ویژگی خودکار مشابه { get; set; } در #C نداریم. معمولاً فیلد را private و دسترسی را با متدهای getAmount() و setAmount() فراهم می‌کنیم. Setter می‌تواند قوانین اعتبارسنجی را اعمال کند.

مثال عملی

نمونه کد / JavaJAVA
class Payment {
    private int amount;

    public void setAmount(int amount) {
        if (amount > 0) this.amount = amount;
    }
    public int getAmount() { return amount; }
}

// Payment p = new Payment();
// p.setAmount(500);
// p.setAmount(-100);
// System.out.println(p.getAmount()); // 500
سؤال مرور درس 02 — نمایش پاسخ

سؤال: پس از فراخوانی setAmount(500) و سپس setAmount(-100) چه مقداری برمی‌گردد؟

پاسخ: مقدار 500؛ زیرا Setter مقدار منفی را قبول نمی‌کند.

درس 03 · فصل دوم

Constructor و Constructor Overloading

توضیح مفهوم و مقایسه با دات‌نت

سازنده در Java مانند #C نامی برابر نام کلاس دارد و نوع بازگشتی ندارد. می‌توان چند سازنده با امضای متفاوت تعریف کرد. با this(...) از یک سازنده به سازنده دیگر می‌رویم.

اگر دست‌کم یک سازنده با پارامتر تعریف کنیم، دیگر سازنده بدون پارامتر خودکار تولید نمی‌شود.

مثال عملی

نمونه کد / JavaJAVA
class Payment {
    private int amount;

    Payment() { this(100); }
    Payment(int amount) { this.amount = amount; }
    int getAmount() { return amount; }
}

// new Payment().getAmount() == 100
// new Payment(500).getAmount() == 500
سؤال مرور درس 03 — نمایش پاسخ

سؤال: اگر در کلاس فقط Payment(int amount) داشته باشیم، آیا new Payment() کامپایل می‌شود؟

پاسخ: خیر؛ خطای کامپایل دارد، زیرا سازنده بدون پارامتر وجود ندارد.

درس 04 · فصل دوم

Access Modifiers و Package

توضیح مفهوم و مقایسه با دات‌نت

در Java اعضای بدون Modifier به‌صورت package-private هستند: کلاس‌های همان Package به آن‌ها دسترسی دارند. این با #C که فیلد بدون Modifier در کلاس معمولاً private است فرق دارد.

Modifierدسترسی
publicاز هر جایی که نوع قابل دسترسی باشد
privateدر همان کلاس
protectedدر Package و برای زیرکلاس‌ها با قواعد ارث‌بری
بدون Modifierفقط همان Package

در دات‌نت، internal بر اساس Assembly است؛ اما package-private مرز Package دارد و معادل دقیق نیست.

مثال عملی

نمونه کد / JavaJAVA
// Payment.java
package com.bank.payment;
public class Payment {
    int amount = 1000; // package-private
}

// PaymentService.java (same package)
package com.bank.payment;
public class PaymentService {
    public void print() {
        System.out.println(new Payment().amount); // 1000
    }
}
سؤال مرور درس 04 — نمایش پاسخ

سؤال: اگر ReportService در com.bank.report باشد، آیا به فیلد amount دسترسی مستقیم دارد؟

پاسخ: خیر؛ کامپایل نمی‌شود. در تمرین مجدد، دو کلاس در یک Package بودند و مقدار 1000 چاپ شد.

درس 05 · فصل دوم

Encapsulation و قوانین دامنه

توضیح مفهوم و مقایسه با دات‌نت

کپسوله‌سازی فقط خصوصی کردن فیلد نیست؛ هدف جلوگیری از نقض قوانین شیء است. در پرداخت، نمی‌خواهیم تراکنش با مبلغ نامعتبر ایجاد شود یا هر بخشی از کد مبلغ را بی‌اجازه تغییر دهد.

برای مبالغ مالی واقعی بهتر است سراغ BigDecimal برویم؛ در این مثال فقط برای سادگی از int استفاده شده است.

مثال عملی

نمونه کد / JavaJAVA
class Payment {
    private final int amount;

    public Payment(int amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("Invalid amount");
        }
        this.amount = amount;
    }

    public int getAmount() { return amount; }
}

// Payment p = new Payment(500);
// p.amount = 1000; // Compile Error
سؤال مرور درس 05 — نمایش پاسخ

سؤال: آیا p.amount = 1000 از بیرون کلاس مجاز است؟

پاسخ: خیر؛ چون فیلد private است، خطای کامپایل رخ می‌دهد.

درس 06 · فصل دوم

Inheritance و extends

توضیح مفهوم و مقایسه با دات‌نت

در #C برای ارث‌بری از : استفاده می‌کنی، ولی در Java از extends استفاده می‌شود. Java ارث‌بری چندگانه کلاس‌ها را پشتیبانی نمی‌کند. اعضای private والد از فرزند مستقیماً قابل دسترسی نیستند.

مثال عملی

نمونه کد / JavaJAVA
class Payment {
    private int amount = 1000;
    public int getAmount() { return amount; }
}

class CardPayment extends Payment {
    public void print() {
        System.out.println(getAmount());
    }
}

// new CardPayment().print(); // 1000
سؤال مرور درس 06 — نمایش پاسخ

سؤال: آیا زیرکلاس می‌تواند از متد عمومی getAmount() والد استفاده کند، حتی اگر فیلد خصوصی باشد؟

پاسخ: بله؛ خروجی 1000 است.

درس 07 · فصل دوم

Polymorphism و Method Overriding

توضیح مفهوم و مقایسه با دات‌نت

در Java متدهای نمونه‌ای معمولی (به‌جز مواردی مانند private و final) به‌صورت پیش‌فرض قابل Override هستند؛ بر خلاف #C نیازی به virtual روی آن‌ها نیست. Annotation @Override باعث بررسی درستی بازنویسی توسط کامپایلر می‌شود.

فراخوانی متد Overrideشده بر اساس نوع واقعی شیء در زمان اجرا انجام می‌شود.

مثال عملی

نمونه کد / JavaJAVA
class Payment {
    public void process() { System.out.println("Payment"); }
}

class CardPayment extends Payment {
    @Override
    public void process() { System.out.println("Card"); }
}

// Payment payment = new CardPayment();
// payment.process(); // Card
سؤال مرور درس 07 — نمایش پاسخ

سؤال: در Payment payment = new CardPayment() کدام نسخه process() اجرا می‌شود؟

پاسخ: نسخه کلاس CardPayment اجرا می‌شود و Card چاپ می‌کند.

درس 08 · فصل دوم

Interface و Abstract Class

توضیح مفهوم و مقایسه با دات‌نت

در Java برای پیاده‌سازی Interface از implements و برای ارث‌بری کلاس از extends استفاده می‌کنیم. Interface قرارداد رفتار است و می‌تواند متد default هم داشته باشد. Abstract Class می‌تواند سازنده، وضعیت نمونه و متدهای دارای پیاده‌سازی داشته باشد.

یک کلاس می‌تواند چند Interface را پیاده‌سازی کند، اما فقط از یک کلاس ارث ببرد.

مثال عملی

نمونه کد / JavaJAVA
interface PaymentProcessor {
    void process();
}

class CardPayment implements PaymentProcessor {
    @Override
    public void process() { System.out.println("Card"); }
}

// PaymentProcessor payment = new CardPayment();
// payment.process(); // Card
نمونه کد / JavaJAVA
abstract class Payment {
    public void log() { System.out.println("Started"); }
    public abstract void process();
}

class WalletPayment extends Payment {
    @Override
    public void process() { System.out.println("Wallet"); }
}
سؤال مرور درس 08 — نمایش پاسخ

سؤال: آیا می‌توان متغیری از نوع Interface تعریف کرد و یک شیء پیاده‌ساز را در آن نگه داشت؟

پاسخ: بله؛ متد پیاده‌سازی‌شده شیء واقعی اجرا می‌شود و در تمرین Card چاپ می‌شد.

درس 09 · فصل دوم

Static و Final

توضیح مفهوم و مقایسه با دات‌نت

static در Java مانند #C به معنی متعلق بودن عضو به کلاس است. final روی متغیر جلوی انتساب دوباره را می‌گیرد، اما به‌تنهایی شیء را Immutable نمی‌کند.

final class مشابه sealed class در #C است و یک final method قابل Override شدن نیست.

مثال عملی

نمونه کد / JavaJAVA
class Payment { int amount; }

public class Main {
    public static void main(String[] args) {
        final Payment p = new Payment();
        p.amount = 100;
        p.amount = 500;
        System.out.println(p.amount); // 500
        // p = new Payment(); // Compile Error
    }
}
سؤال مرور درس 09 — نمایش پاسخ

سؤال: آیا تغییر p.amount وقتی p از نوع final است مجاز خواهد بود؟

پاسخ: بله؛ مقدار 500 چاپ می‌شود. تنها انتساب دوباره به متغیر p ممنوع است.

درس 10 · فصل دوم

Record و Enum در Java

توضیح مفهوم و مقایسه با دات‌نت

در Java، record سازنده، متدهای دسترسی مانند amount()، متد equals()، hashCode() و toString() را تولید می‌کند. اجزای آن در سطح مرجع نهایی هستند، اما خود اشیای ارجاعی ممکن است Mutable باشند.

برخلاف Enumهای عددی متداول در #C، مقادیر enum در Java نمونه‌های یک کلاس هستند و Enum می‌تواند فیلد، سازنده و متد داشته باشد.

مثال عملی

نمونه کد / JavaJAVA
record Payment(int id, int amount) {}

// Payment p = new Payment(1, 500);
// System.out.println(p.amount()); // 500

enum PaymentStatus {
    PENDING, SUCCESS, FAILED
}
سؤال مرور درس 10 — نمایش پاسخ

سؤال: خروجی new Payment(1, 500).amount() چیست؟

پاسخ: عدد 500؛ در Java متد دسترسی اجزای record بدون پیشوند get تولید می‌شود.
