درس 01 · فصل ششم

مفهوم Stack و Heap در Java

توضیح مفهوم و مقایسه با دات‌نت

در Java هر Thread یک Stack مخصوص اجرای متدها دارد؛ فریم‌های متد متغیرهای محلی و مراجع محلی را نگهداری می‌کنند. اشیای معمولی غالباً در Heap قرار می‌گیرند. مانند #C، متغیر مرجع و خود شیء یکی نیستند. در کد زیر دو متغیر به یک شیء واحد اشاره می‌کنند. قراردادن p1 = null شیء را حذف نمی‌کند، زیرا p2 همچنان به آن اشاره دارد. این مدل مفهومی است و JVM می‌تواند با بهینه‌سازی، چیدمان فیزیکی را تغییر دهد.

مثال عملی

نمونه کد / JavaJAVA
class Payment { int amount; }

public class Main {
    public static void main(String[] args) {
        Payment p1 = new Payment();
        p1.amount = 300;
        Payment p2 = p1;
        p1 = null;
        System.out.println(p2.amount); // 300
    }
}
سؤال مرور درس 01 — نمایش پاسخ

سؤال: اگر p1 برابر null شود اما p2 به همان شیء اشاره کند، خروجی p2.amount چیست؟

پاسخ: عدد 300؛ شیء هنوز از طریق p2 قابل‌دسترسی است.

درس 02 · فصل ششم

مفهوم Garbage Collection و Reachability

توضیح مفهوم و مقایسه با دات‌نت

Garbage Collector از طریق GC Roots و زنجیره مراجع، اشیای قابل‌دسترسی را تشخیص می‌دهد. اگر هیچ مسیر قابل‌دسترسی‌ای از ریشه‌ها به شیء وجود نداشته باشد، آن شیء واجد شرایط جمع‌آوری است؛ ولی زمان بازیابی حافظه تضمین نمی‌شود. دستور System.gc() فقط درخواست اجرای GC است. مشابه دات‌نت، GC منابع خارجی مانند فایل و اتصال دیتابیس را جایگزینِ بستن صریح آن‌ها نمی‌کند.

مثال عملی

نمونه کد / JavaJAVA
class Payment { int amount; }

public class Main {
    public static void main(String[] args) {
        Payment p1 = new Payment();
        Payment p2 = p1;
        p1 = null;
        p2 = null;
        System.gc(); // درخواست، نه تضمین جمع‌آوری فوری
    }
}
سؤال مرور درس 02 — نمایش پاسخ

سؤال: بعد از null کردن آخرین مراجع و اجرای System.gc() چه چیزی تضمین می‌شود؟

پاسخ: شیء واجد شرایط جمع‌آوری است، ولی زمان جمع‌آوری آن تضمین نمی‌شود.

درس 03 · فصل ششم

مفهوم Young Generation و Old Generation

توضیح مفهوم و مقایسه با دات‌نت

در بسیاری از GCهای نسلی Java، اشیای تازه‌ساخته‌شده ابتدا در Young Generation قرار می‌گیرند و اشیای زنده‌مانده ممکن است به Old Generation منتقل شوند. در برخی پیاده‌سازی‌ها بخش جوان شامل Eden و Survivor است. از نظر مفهومی Young شبیه Gen 0 و Old شبیه Gen 2 در .NET است، اما تطابق یک‌به‌یک وجود ندارد و همه GCهای JVM مدل یکسانی ندارند.

مثال عملی

نمونه کد / JavaJAVA
import java.util.ArrayList;
import java.util.List;

class Payment { int amount; }

class PaymentCache {
    // نگهداری طولانی ممکن است باعث زنده‌ماندن و ارتقای اشیا شود.
    static final List<Payment> payments = new ArrayList<>();
}

// PaymentCache.payments.add(new Payment());
سؤال مرور درس 03 — نمایش پاسخ

سؤال: شیئی که مدت طولانی از طریق Cache قابل‌دسترسی بماند در GC نسلی ممکن است چه شود؟

پاسخ: ممکن است از Young Generation به Old Generation منتقل شود.

درس 04 · فصل ششم

مفهوم Memory Leak و OutOfMemoryError

توضیح مفهوم و مقایسه با دات‌نت

وجود GC مانع Memory Leak منطقی نیست. اگر برنامه اشیای غیرضروری را همچنان در مجموعه‌ای قابل‌دسترسی نگه دارد، GC آن‌ها را پاک نمی‌کند. افزایش بی‌حد مصرف Heap ممکن است به OutOfMemoryError: Java heap space منجر شود. البته هر OutOfMemoryError الزاماً ناشی از Leak نیست؛ محدودیت Heap یا بار کاری بزرگ نیز ممکن است علت باشد. برای داده‌های دائمی تراکنش از دیتابیس و برای Cache از ظرفیت یا TTL مشخص استفاده کن.

مثال عملی

نمونه کد / JavaJAVA
import java.util.ArrayList;
import java.util.List;

class PaymentService {
    private static final List<String> ids = new ArrayList<>();

    void process(String transactionId) {
        ids.add(transactionId); // رشد نامحدود؛ نمونه مشکل‌دار
    }
}
سؤال مرور درس 04 — نمایش پاسخ

سؤال: چرا اشیای ذخیره‌شده در یک static ArrayList قابل‌دسترسی جمع‌آوری نمی‌شوند؟

پاسخ: چون لیست همچنان مرجع آن‌ها را نگه می‌دارد؛ قدیمی بودن شیء به‌تنهایی دلیل جمع‌آوری نیست.

درس 05 · فصل ششم

تنظیم حافظه JVM با Xms و Xmx

توضیح مفهوم و مقایسه با دات‌نت

پارامتر -Xms اندازه اولیه Heap و -Xmx بیشینه Heap را تعیین می‌کند. پارامتر -Xss به Stack مربوط است. حداکثر Heap برابر با حداکثر حافظه کل فرایند نیست؛ Metaspace، Thread Stacks، Direct Buffers و حافظه Native JVM نیز مصرف دارند. در Kubernetes باید برای مصرف خارج از Heap هم جا در Memory Limit در نظر گرفت.

مثال عملی

نمونه کد / BASHBASH
# اجرای سرویس پرداخت با Heap اولیه 256MB و حداکثر 512MB
java -Xms256m -Xmx512m -jar payment-service.jar

# Xmx محدودیت کل RAM فرایند JVM نیست.
سؤال مرور درس 05 — نمایش پاسخ

سؤال: در java -Xms256m -Xmx512m مقادیر چه معنایی دارند؟

پاسخ: اندازه اولیه Heap برابر 256MB و بیشینه آن برابر 512MB است.

درس 06 · فصل ششم

تفاوت StackOverflowError و OutOfMemoryError

توضیح مفهوم و مقایسه با دات‌نت

خطای StackOverflowError عموماً از زیاد شدن عمق فراخوانی متدها در یک Thread، مثلاً بازگشت بی‌پایان، ایجاد می‌شود. در مقابل، OutOfMemoryError هنگام ناتوانی JVM در تأمین حافظه لازم رخ می‌دهد و می‌تواند مربوط به Heap یا بخش‌های دیگر باشد. مشابه خطاهای StackOverflowException و OutOfMemoryException در .NET، این وضعیت‌ها معمولاً نشانه مشکل جدی هستند و نباید با catch عمومی از کنارشان گذشت.

مثال عملی

نمونه کد / JavaJAVA
public class Main {
    static void calculate() {
        calculate(); // بدون شرط توقف
    }

    public static void main(String[] args) {
        calculate(); // معمولاً StackOverflowError
    }
}
سؤال مرور درس 06 — نمایش پاسخ

سؤال: بازگشت بدون شرط توقف در متد calculate معمولاً چه خطایی ایجاد می‌کند؟

پاسخ: StackOverflowError؛ به علت رشد بی‌پایان عمق فراخوانی.

درس 07 · فصل ششم

مفهوم Metaspace و ClassLoader

توضیح مفهوم و مقایسه با دات‌نت

در Java، ClassLoader تعریف کلاس‌ها را بارگذاری می‌کند؛ این کار با ساخت یک نمونه توسط new متفاوت است. در HotSpot اطلاعات ساختاری کلاس‌های بارگذاری‌شده در Metaspace نگهداری می‌شود؛ اشیای معمولی در Heap هستند. اگر بارگذاری پویای کلاس‌ها همراه با باقی‌ماندن ClassLoaderها باعث رشد نامحدود داده‌های کلاس شود، ممکن است OutOfMemoryError: Metaspace رخ دهد. مفهوم AssemblyLoadContext در .NET از بعضی جنبه‌ها قابل مقایسه است، اما معادل کاملاً یکسانی نیست.

مثال عملی

نمونه کد / JavaJAVA
class Payment {
    int amount;
}

public class Main {
    public static void main(String[] args) {
        Payment payment = new Payment();
        System.out.println(payment.getClass().getName());
        // تعریف Payment باید بارگذاری شده باشد.
    }
}
سؤال مرور درس 07 — نمایش پاسخ

سؤال: خطای OutOfMemoryError: Metaspace بیشتر به چه بخش حافظه‌ای مربوط است؟

پاسخ: اطلاعات کلاس‌های بارگذاری‌شده در Metaspace، نه Stack یک Thread.

درس 08 · فصل ششم

ابزارهای عیب‌یابی با Heap Dump و JFR

توضیح مفهوم و مقایسه با دات‌نت

Heap Dump نمایی از اشیای Heap در یک لحظه مشخص است و برای بررسی تعداد اشیا، Retained Size و مسیر مراجع نگهدارنده کاربرد دارد. می‌توان با jcmd Heap Dump تهیه کرد و با ابزارهایی مانند VisualVM یا Eclipse Memory Analyzer آن را بررسی کرد. Java Flight Recorder یا JFR برای ثبت رویدادهای زمان‌دار JVM مانند GC، تخصیص‌ها و Threadها به کار می‌رود. تهیه Heap Dump در Production ممکن است مکث و مصرف منابع داشته باشد و فایل می‌تواند داده‌های حساس تراکنش‌ها را شامل شود.

مثال عملی

نمونه کد / BASHBASH
# PID نمونه است و باید با PID واقعی جایگزین شود
jcmd 12345 GC.heap_dump /tmp/payment-heap.hprof

# سپس فایل را با ابزار تحلیل Heap بررسی کن.
سؤال مرور درس 08 — نمایش پاسخ

سؤال: برای یافتن اشیای نگهداری‌شده توسط static ArrayList کدام روش مناسب است؟

پاسخ: تهیه Heap Dump و بررسی مسیر مراجع با ابزار تحلیل حافظه.
