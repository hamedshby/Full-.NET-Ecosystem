درس 01 · فصل هشتم

Maven و Gradle؛ ابزارهای Build

توضیح و مقایسه با دات‌نت

Maven و Gradle ابزارهای ساخت پروژه Java هستند: علاوه بر دریافت Dependencyها، کامپایل، تست و بسته‌بندی خروجی را مدیریت می‌کنند. Maven مبتنی بر POM و چرخه Build قراردادی است؛ Gradle با Taskها و اسکریپت‌های Groovy یا Kotlin کار می‌کند. در دات‌نت، ترکیبی از قابلیت‌های MSBuild، .NET CLI و NuGet همین نقش‌ها را پوشش می‌دهد.

مثال عملی

نمونه کد / Bash — MavenCODE
mvn compile
mvn test
mvn package
نمونه کد / Bash — GradleCODE
./gradlew build

درس 02 · فصل هشتم

ساختار استاندارد پروژه Maven

توضیح و مقایسه با دات‌نت

Maven به‌صورت قراردادی سورس اصلی را از src/main/java و تست‌ها را از src/test/java می‌خواند. منابع مانند فایل‌های پیکربندی در src/main/resources هستند؛ خروجی پیش‌فرض به target/ می‌رود. ساختار Package معمولاً با مسیر فایل Java هماهنگ است. در دات‌نت این جداسازی اغلب به‌صورت پروژه‌های جداگانه پیاده‌سازی می‌شود.

مثال عملی

نمونه کد / Text — Project layoutCODE
payment-service/
├── pom.xml
├── src/
│   ├── main/
│   │   ├── java/com/example/payment/Main.java
│   │   └── resources/application.properties
│   └── test/java/com/example/payment/PaymentTest.java
└── target/
نمونه کد / Java — Main.javaCODE
package com.example.payment;

public class Main {
    public static void main(String[] args) {
        System.out.println("Payment service");
    }
}

درس 03 · فصل هشتم

فایل pom.xml و Maven Coordinates

توضیح و مقایسه با دات‌نت

POM مخفف Project Object Model است و Maven مشخصات پروژه را از آن دریافت می‌کند. groupId شناسه گروه، artifactId شناسه ماژول و version شماره نسخه است. این سه مقدار Maven Coordinates را تشکیل می‌دهند. packaging به‌طور پیش‌فرض jar است. مقدار maven.compiler.release نسخه Java هدف برای کامپایل را تعیین می‌کند.

مثال عملی

نمونه کد / XML — pom.xmlCODE
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.bank</groupId>
  <artifactId>transaction-service</artifactId>
  <version>2.0.0</version>
  <properties>
    <maven.compiler.release>21</maven.compiler.release>
  </properties>
</project>
نمونه کد / Text — ResultCODE
target/transaction-service-2.0.0.jar
سؤال مرور درس 03 — نمایش پاسخ

سؤال: نام خروجی JAR با artifactId=transaction-service و version=2.0.0 چیست؟

پاسخ: transaction-service-2.0.0.jar؛ گزینه C.

درس 04 · فصل هشتم

مدیریت Dependency و وابستگی غیرمستقیم

توضیح و مقایسه با دات‌نت

کتابخانه‌های موردنیاز زیر عنصر dependencies تعریف می‌شوند. Maven می‌تواند وابستگی‌های غیرمستقیم (Transitive) را نیز بر اساس Metadata کتابخانه دریافت کند. برای بررسی درخت وابستگی‌ها دستور mvn dependency:tree مفید است. Dependency کتابخانه مورد استفاده کد است، اما Plugin وظیفه‌ای در چرخه Build اجرا می‌کند. در دات‌نت PackageReference و NuGet مفاهیم نزدیک هستند.

مثال عملی

نمونه کد / XML — DependencyCODE
<dependencies>
  <dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <version>42.7.4</version>
  </dependency>
</dependencies>
نمونه کد / Bash — Dependency treeCODE
mvn dependency:tree
سؤال مرور درس 04 — نمایش پاسخ

سؤال: اگر کتابخانه A به B وابسته باشد، Maven معمولاً با B چه می‌کند؟

پاسخ: آن را نیز به‌عنوان Transitive Dependency دریافت می‌کند؛ گزینه B.

درس 05 · فصل هشتم

چرخه ساخت Maven: compile، test، package و install

توضیح و مقایسه با دات‌نت

مراحل Default Lifecycle در Maven ترتیب مشخصی دارند. اجرای mvn package مراحل قبلی لازم، از جمله کامپایل و تست را نیز طی می‌کند. اگر تستی با تنظیمات معمول شکست بخورد، Build متوقف می‌شود. mvn install پس از ساخت، Artifact را در Repository محلی نصب می‌کند. clean متعلق به Lifecycle جداگانه‌ای است و خروجی Build قبلی را پاک می‌کند. package به معنای استقرار روی Production نیست.

مثال عملی

نمونه کد / Bash — Maven LifecycleCODE
mvn compile
mvn test
mvn package
mvn install
mvn clean package
نمونه کد / Text — OrderCODE
validate → compile → test → package → verify → install → deploy
سؤال مرور درس 05 — نمایش پاسخ

سؤال: اگر حین mvn package یک Unit Test شکست بخورد، چه رخ می‌دهد؟

پاسخ: Build شکست می‌خورد و مرحله Package با موفقیت کامل نمی‌شود؛ گزینه C.

درس 06 · فصل هشتم

مخازن Maven: Local و Central و Private

توضیح و مقایسه با دات‌نت

Maven معمولاً Artifact موجود را از Repository محلی در ~/.m2/repository استفاده می‌کند و در صورت نیاز از مخازن Remote تنظیم‌شده می‌گیرد. Maven Central مخزن عمومی شناخته‌شده است. کتابخانه‌های محرمانه سازمانی را می‌توان در Nexus یا Artifactory خصوصی منتشر کرد. در حالت -o دسترسی Remote غیرفعال است؛ اگر همه Artifactها و Pluginها محلی باشند، Build همچنان ممکن است.

مثال عملی

نمونه کد / Bash — Offline and localCODE
mvn -o package
# default local repository: ~/.m2/repository
نمونه کد / XML — Maven CoordinateCODE
<groupId>com.company.payment</groupId>
<artifactId>payment-common</artifactId>
<version>1.0.0</version>
سؤال مرور درس 06 — نمایش پاسخ

سؤال: اگر تمام وابستگی‌های لازم از قبل محلی باشند، mvn -o package چه می‌کند؟

پاسخ: Build می‌تواند بدون اتصال اینترنت انجام شود؛ گزینه B.

درس 07 · فصل هشتم

Gradle و Kotlin DSL و Wrapper

توضیح و مقایسه با دات‌نت

Gradle جایگزینی برای Maven است که کارها را به صورت Task مدل می‌کند. فایل build.gradle از Groovy و فایل build.gradle.kts از Kotlin DSL استفاده می‌کند. Gradle Wrapper با gradlew یا gradlew.bat نسخه تنظیم‌شده Gradle را اجرا و در صورت نیاز دریافت می‌کند. معمولاً بهتر است دستورهای پروژه را با Wrapper اجرا کنیم.

مثال عملی

نمونه کد / Kotlin — build.gradle.ktsCODE
plugins {
    java
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("org.postgresql:postgresql:42.7.4")
}
نمونه کد / Shell — Gradle WrapperCODE
./gradlew build
# Windows:
# .\gradlew.bat build
سؤال مرور درس 07 — نمایش پاسخ

سؤال: وجود build.gradle.kts و gradlew نشان‌دهنده چیست؟

پاسخ: پروژه از Gradle استفاده می‌کند و تنظیمات با Kotlin DSL تعریف شده‌اند؛ گزینه C.

درس 08 · فصل هشتم

مقایسه Maven و Gradle در پروژه Backend

توضیح و مقایسه با دات‌نت

Maven تنظیمات XML و چرخه Build قراردادی دارد؛ Gradle تنظیمات Groovy/Kotlin و گراف Taskها را به کار می‌گیرد. Gradle از Build Cache و قابلیت‌های Incremental Build پشتیبانی می‌کند و قابلیت سفارشی‌سازی بالایی دارد. نمی‌توان بدون اندازه‌گیری گفت همیشه از Maven سریع‌تر است. مهاجرت باید با درنظرگرفتن هزینه، نیاز تیم و Benchmark تصمیم‌گیری شود.

مثال عملی

نمونه کد / YAML — CI with MavenCODE
build_maven:
  stage: build
  script:
    - mvn clean verify
نمونه کد / YAML — CI with GradleCODE
build_gradle:
  stage: build
  script:
    - ./gradlew clean build
سؤال مرور درس 08 — نمایش پاسخ

سؤال: آیا برای افزایش قطعی سرعت باید همه پروژه‌های Maven را به Gradle تبدیل کنیم؟

پاسخ: خیر؛ انتخاب به اندازه‌گیری واقعی، نیازها و هزینه مهاجرت بستگی دارد؛ گزینه D.

درس 09 · فصل هشتم

ساخت JAR و تفاوت Executable JAR با Library JAR

توضیح و مقایسه با دات‌نت

JAR یک آرشیو بر پایه ZIP است که می‌تواند کلاس‌های کامپایل‌شده و Resourceها را در خود داشته باشد. Library JAR معمولاً توسط برنامه‌های دیگر استفاده می‌شود. برای اجرای java -jar به Manifest دارای Main-Class مناسب و دسترسی به وابستگی‌ها نیاز داریم؛ mvn package به‌خودی‌خود Executable JAR تضمین نمی‌کند. Fat/Uber JAR معمولاً وابستگی‌ها را نیز بسته‌بندی می‌کند. Spring Boot با تنظیم مناسب می‌تواند JAR اجرایی تولید کند.

مثال عملی

نمونه کد / Java — MainCODE
package com.bank.payment;

public class Main {
    public static void main(String[] args) {
        System.out.println("Payment Service Started");
    }
}
نمونه کد / Text — ManifestCODE
Manifest-Version: 1.0
Main-Class: com.bank.payment.Main
نمونه کد / Bash — Run executable JARCODE
java -jar target/payment-service-1.0.0.jar
سؤال مرور درس 09 — نمایش پاسخ

سؤال: خطای no main manifest attribute معمولاً نشانه چیست؟

پاسخ: نبود مشخصه Main-Class مناسب در Manifest فایل JAR؛ گزینه B.

درس 10 · فصل هشتم

مفهوم Maven Profile و Spring Profile

توضیح و مقایسه با دات‌نت

Maven Profile تنظیمات زمان Build (مثل Properties، Plugins و نحوه بسته‌بندی) را تغییر می‌دهد و با -P فعال می‌شود. Spring Profile مربوط به انتخاب پیکربندی Runtime برنامه Spring Boot است، مانند اجرای برنامه با spring.profiles.active=prod. آن‌ها یکسان نیستند. برای سرویس پرداخت بهتر است در صورت امکان یک Artifact تست‌شده را در محیط‌های مختلف با تنظیمات خارج از فایل JAR اجرا کنیم و رمزها را داخل سورس یا POM قرار ندهیم.

مثال عملی

نمونه کد / XML — Maven ProfilesCODE
<profiles>
  <profile>
    <id>dev</id>
    <properties>
      <build.environment>Development</build.environment>
    </properties>
  </profile>
  <profile>
    <id>prod</id>
    <properties>
      <build.environment>Production</build.environment>
    </properties>
  </profile>
</profiles>
نمونه کد / Bash — Build profileCODE
mvn package -Pprod
نمونه کد / Bash — Spring runtime profileCODE
java -jar payment-service.jar --spring.profiles.active=prod
سؤال مرور درس 10 — نمایش پاسخ

سؤال: برای اجرای همان JAR در Production با تنظیمات مخصوص آن، چه راهی مناسب است؟

پاسخ: فعال‌کردن Spring Profile به نام prod هنگام اجرای برنامه؛ گزینه C.
