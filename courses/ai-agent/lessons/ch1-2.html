PART 1 — LLM Fundamentals

AI & LLM Fundamentals

LLM چیست؟

Large Language Model یا LLM مدلی است که الگوهای زبان را از حجم زیادی Text و Code یاد می‌گیرد و با پیش‌بینی گام‌به‌گام Token بعدی، پاسخ تولید می‌کند. خروجی روان آن می‌تواند بسیار مفید باشد، اما روان‌بودن با درست‌بودن یکسان نیست.

از یک رفتار ساده شروع کنیم

فرض کنید این جمله را می‌بینید:

«کاربر رمز عبور خود را فراموش کرده است، بنابراین باید ...»

احتمالاً ادامه‌هایی مانند «رمز را بازیابی کند» یا «درخواست بازنشانی بدهد» به ذهن شما می‌رسد. دلیلش این است که در تجربه‌های قبلی، میان این واژه‌ها و مفهوم‌ها رابطه دیده‌اید.

یک LLM نیز هنگام تولید Text، با توجه به ورودی و بخش تولیدشده تا آن لحظه، برای ادامهٔ ممکن امتیاز محاسبه می‌کند. سپس یک Token انتخاب می‌شود، به Context اضافه می‌شود و همین فرایند دوباره تکرار می‌شود.

معنای دقیق Large Language Model

نام این مفهوم از سه بخش ساخته شده است:

  • Large: Model از نظر تعداد Parameterها، دادهٔ آموزشی و توان محاسباتی در مقیاس بزرگی ساخته می‌شود. Large بودن دربارهٔ طول پاسخ نیست.
  • Language: Model رابطه‌های آماری موجود در Language را یاد می‌گیرد. Language می‌تواند Text طبیعی، Code یا داده‌ای باشد که به شکل Token نمایش داده می‌شود.
  • Model: مجموعه‌ای از محاسبات و Parameterهای یادگرفته‌شده است که برای ورودی جدید خروجی تولید می‌کند.

Parameter یک مقدار عددی قابل‌یادگیری در Model است. در مرحلهٔ Training این مقدارها تنظیم می‌شوند تا Model بتواند الگوهای داده را بهتر بازنمایی و ادامهٔ مناسب‌تری پیش‌بینی کند.

مدل ذهنی: LLM را یک Database از جمله‌های آماده تصور نکنید. آن را یک تابع عددی بسیار بزرگ در نظر بگیرید که از ورودی فعلی، احتمال ادامه‌های مختلف را محاسبه می‌کند.

Token چه نقشی دارد؟

کامپیوتر Text را مستقیماً مانند انسان نمی‌بیند. ابتدا یک Tokenizer، Text را به واحدهای کوچک‌تری به نام Token تقسیم می‌کند. Token ممکن است یک واژه، بخشی از واژه، نشانه یا فاصله باشد.

سپس هر Token به یک شناسهٔ عددی تبدیل می‌شود. Model با این نمایش عددی کار می‌کند و در خروجی نیز ابتدا Token تولید می‌کند. Tokenهای خروجی در پایان دوباره به Text قابل‌خواندن تبدیل می‌شوند.

تعداد Tokenها لزوماً با تعداد واژه‌ها برابر نیست. جزئیات این فرایند در درس بعدی، Token چیست؟، بررسی می‌شود.

Transformer و Attention به زبان ساده

بسیاری از LLMهای امروزی بر پایهٔ معماری Transformer ساخته می‌شوند. Architecture در اینجا یعنی ساختار کلی محاسبات Model و نحوهٔ عبور اطلاعات میان بخش‌های آن.

یکی از ایده‌های مهم Transformer، سازوکار Attention است. Attention به Model کمک می‌کند هنگام پردازش هر Token، بخش‌های مرتبط Context را با وزن متفاوت در نظر بگیرد.

مثال

در جملهٔ «سارا لپ‌تاپ را خرید چون او به آن نیاز داشت»، برای تفسیر «او» باید ارتباط آن با «سارا» بررسی شود. Attention برای مدل‌کردن چنین وابستگی‌هایی مفید است.

Attention به این معنا نیست که Model مانند انسان توجه یا آگاهی دارد؛ این نام یک عملیات ریاضی است که میزان ارتباط نمایش‌های عددی Tokenها را محاسبه می‌کند.

LLM چگونه آموزش می‌بیند؟

آماده‌کردن یک LLM معمولاً چند مرحله دارد. جزئیات هر Model ممکن است متفاوت باشد، اما این تفکیک برای ساخت مدل ذهنی اولیه مفید است:

  1. Pre-training: Model روی حجم بزرگی از داده آموزش می‌بیند تا الگوهای عمومی Language و رابطه‌های موجود در داده را یاد بگیرد. یکی از هدف‌های رایج، پیش‌بینی Token بعدی است.
  2. Instruction Tuning: نمونه‌های Instruction و پاسخ به Model کمک می‌کنند ساختار درخواست را بهتر دنبال کند و پاسخ مناسب‌تری ارائه دهد.
  3. Alignment: با داده و بازخورد، رفتار Model به سمت پاسخ‌های مفیدتر و رعایت محدودیت‌های موردنظر هدایت می‌شود.

Training با پرسیدن سؤال از Model یکسان نیست. Training، Parameterهای Model را تغییر می‌دهد؛ اما یک Prompt معمولی فقط ورودی همان اجرای فعلی است و Parameterها را آموزش نمی‌دهد.

هنگام ارسال Prompt چه اتفاقی می‌افتد؟

استفاده از Model آموزش‌دیده برای تولید خروجی Inference نام دارد. یک جریان سادهٔ Inference به این شکل است:

  1. Messageها و دادهٔ همراه درخواست به یک ورودی تبدیل می‌شوند.
  2. Tokenizer ورودی را به Token IDها تبدیل می‌کند.
  3. Model برای Token بعدی مجموعه‌ای از Scoreها تولید می‌کند.
  4. روش انتخاب مانند Sampling یا انتخاب محتمل‌ترین گزینه، Token بعدی را مشخص می‌کند.
  5. Token انتخاب‌شده به Context افزوده می‌شود.
  6. فرایند تا رسیدن به شرط توقف تکرار می‌شود.

به همین دلیل پاسخ به‌صورت تدریجی قابل‌نمایش است: Application می‌تواند Tokenهای تولیدشده را با Streaming دریافت کند، به‌جای اینکه تا پایان کل پاسخ منتظر بماند.

یک شبیه‌سازی کوچک با C#

کد زیر LLM نیست. فقط چرخهٔ «انتخاب ادامه، افزودن به Context و تکرار» را با یک جدول کوچک نمایش می‌دهد. یک LLM واقعی به‌جای این جدول، از Parameterهای یادگرفته‌شده و محاسبات شبکهٔ عصبی استفاده می‌کند.

var nextTokenScores = new Dictionary<string, (string Token, double Score)[]>
{
    ["تراکنش"] = [("موفق", 0.72), ("ناموفق", 0.28)],
    ["موفق"] = [("بود", 0.81), ("شد", 0.19)],
    ["بود"] = [(".", 0.96), ("اما", 0.04)]
};

var generatedTokens = new List<string> { "تراکنش" };

for (var step = 0; step < 3; step++)
{
    var currentToken = generatedTokens[^1];
    var candidates = nextTokenScores[currentToken];
    var nextToken = candidates.MaxBy(candidate => candidate.Score).Token;

    generatedTokens.Add(nextToken);
}

Console.WriteLine(string.Join(" ", generatedTokens));

خروجی

تراکنش موفق بود .

در هر تکرار، برنامه آخرین Token را می‌گیرد، Candidateها را پیدا می‌کند و Token دارای بیشترین Score را انتخاب می‌کند. Token تازه به فهرست افزوده می‌شود و مبنای گام بعدی قرار می‌گیرد.

تفاوت مهم این مثال با LLM واقعی آن است که مثال فقط آخرین Token و چند ادامهٔ ازپیش‌نوشته‌شده را می‌بیند. LLM نمایش عددی Context بزرگ‌تری را پردازش می‌کند و Scoreها را با Model آموزش‌دیده محاسبه می‌کند.

LLM چه کارهایی می‌تواند انجام دهد؟

چون بسیاری از مسئله‌ها را می‌توان با Language بیان کرد، یک LLM می‌تواند برای کارهای متنوعی استفاده شود:

  • پاسخ‌گویی و توضیح یک مفهوم با سطح جزئیات متفاوت
  • خلاصه‌سازی سند یا مکالمه
  • ترجمه و بازنویسی Text
  • استخراج دادهٔ ساختاریافته از ورودی بدون قالب ثابت
  • تولید، توضیح و Review کردن Code
  • طبقه‌بندی متن و تشخیص Intent
  • انتخاب Tool و ساخت Argumentهای آن در یک AI Agent

این توانایی‌ها تضمین کیفیت نیستند. برای هر Use Case باید نمونه‌های واقعی، معیار موفقیت و مسیر مدیریت خطا تعریف شود.

LLM با چه چیزهایی یکسان نیست؟

مفهوممسئولیت اصلیتفاوت با LLM
Databaseذخیره و بازیابی دادهٔ مشخصLLM منبع قطعی رکوردهای Business نیست.
Search Engineپیداکردن سند مرتبطLLM خروجی تولید می‌کند؛ Search نتیجه را بازیابی می‌کند.
Chatbotرابط مکالمه با کاربرChatbot ممکن است LLM داشته باشد یا کاملاً Rule-Based باشد.
AI Agentپیگیری Goal و اجرای ActionLLM می‌تواند بخشی از Agent باشد، نه تمام آن.

در معماری واقعی این اجزا معمولاً مکمل یکدیگرند. برای مثال، Agent از Search برای یافتن سند، از Database برای خواندن وضعیت تراکنش و از LLM برای تحلیل درخواست و ساخت پاسخ استفاده می‌کند.

محدودیت‌های مهم LLM

  • تولید محتمل با بازیابی حقیقت یکسان نیست: Model می‌تواند پاسخ روان اما نادرست تولید کند. این رفتار در درس Hallucination دقیق‌تر بررسی می‌شود.
  • Context Window محدود است: Model فقط Tokenهایی را می‌بیند که در درخواست فعلی و محدودهٔ قابل‌پذیرش آن قرار گرفته‌اند. این موضوع در درس Context Window بررسی می‌شود.
  • دانش ممکن است ناقص یا قدیمی باشد: Parameterهای Model جای منبع دادهٔ زنده و قابل‌اعتماد را نمی‌گیرند.
  • همان ورودی همیشه الزاماً همان خروجی را نمی‌دهد: روش Sampling و تنظیمات تولید می‌توانند پاسخ را تغییر دهند.
  • دادهٔ ورودی می‌تواند رفتار را منحرف کند: Instruction ناسازگار یا محتوای مخرب باید با Policy و Validation مدیریت شود.
  • هزینه و Latency وجود دارد: Tokenهای ورودی و خروجی، اندازهٔ Model و زیرساخت بر زمان و هزینه اثر می‌گذارند.
قانون عملی: هرجا پاسخ باید قطعی، قابل‌ممیزی یا دارای اثر مالی باشد، نتیجهٔ LLM را مستقیماً معادل حقیقت یا مجوز اجرای Action ندانید.

جایگاه LLM در AI Agent

در یک Agent، LLM معمولاً نقش تحلیل Language و پیشنهاد گام بعدی را دارد. اجزای دیگر محدودیت و قابلیت عملیاتی سیستم را فراهم می‌کنند:

User Goal
←
Agent Runtime
←
LLM
↔
Tools / Memory
  • Instructions هدف و محدودیت رفتار را تعیین می‌کنند.
  • Tools اجازه می‌دهند Agent اطلاعات واقعی بخواند یا Action انجام دهد.
  • Memory اطلاعات لازم از تعامل‌های قبلی را در اختیار جریان فعلی می‌گذارد.
  • Runtime چرخهٔ اجرا، Timeout، Retry، Stop Condition و Approval را مدیریت می‌کند.

پس جملهٔ «یک LLM می‌سازیم تا تراکنش را Refund کند» معماری دقیقی نیست. LLM می‌تواند پیشنهاد Refund و Argumentهای Tool را تولید کند، اما Authorization، Validation و اجرای واقعی باید در Code کنترل‌شده انجام شوند.

اشتباهات رایج

  • LLM را Database دانستن: Model برای نگهداری رکورد دقیق مشتری یا موجودی حساب طراحی نشده است.
  • پاسخ روان را دلیل فهم کامل دانستن: کیفیت نگارش دربارهٔ صحت استدلال یا داده تضمین ایجاد نمی‌کند.
  • قرار دادن همهٔ داده‌ها در Prompt: Context زیاد می‌تواند هزینه و Latency را بالا ببرد و اطلاعات نامرتبط وارد تصمیم کند.
  • واگذاری Business Rule قطعی به Model: قانون‌هایی مانند سقف Refund باید در Code و Policy enforce شوند.
  • نداشتن Evaluation: چند Demo موفق نشان نمی‌دهد سیستم روی درخواست‌های واقعی قابل‌اعتماد است.

تمرین کوتاه

فرض کنید یک Payment Support Agent باید به سؤال «چرا تراکنش ۸۴۵۲۱ ناموفق شد؟» پاسخ دهد. مسئولیت هر بخش را مشخص کنید:

  1. تشخیص Intent کاربر
  2. خواندن وضعیت واقعی تراکنش
  3. توضیح Error Code به زبان ساده
  4. بررسی مجازبودن Refund
  5. اجرای Refund
مشاهدهٔ پاسخ پیشنهادی
  • LLM می‌تواند Intent را تشخیص دهد و توضیح قابل‌خواندن تولید کند.
  • Tool متصل به Payment API باید وضعیت واقعی را بخواند.
  • Policy و Code قطعی باید مجازبودن Refund را بررسی کنند.
  • یک Write Tool کنترل‌شده، پس از Authorization و Approval لازم، Refund را اجرا می‌کند.

جمع‌بندی

  • LLM یک Large Language Model با Parameterهای یادگرفته‌شده است.
  • Text ابتدا به Token تبدیل می‌شود و پاسخ با تولید گام‌به‌گام Tokenها شکل می‌گیرد.
  • Training Parameterها را تغییر می‌دهد؛ Inference از Model آموزش‌دیده خروجی می‌گیرد.
  • Transformer ساختار رایج LLMها و Attention یک سازوکار عددی برای مدل‌کردن ارتباط Tokenها است.
  • LLM می‌تواند Text و Code را تحلیل یا تولید کند، اما Database، Search Engine یا منبع حقیقت نیست.
  • در AI Agent، LLM در کنار Instructions، Tools، Memory، Runtime و Guardrails قرار می‌گیرد.
