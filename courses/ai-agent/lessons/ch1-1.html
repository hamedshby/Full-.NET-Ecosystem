PART 1 — LLM Fundamentals

AI & LLM Fundamentals

AI، Machine Learning و Generative AI

پیش از ساختن یک AI Agent باید سه مفهوم را از هم جدا کنیم: AI نام یک حوزهٔ گسترده است، Machine Learning روشی برای یادگیری الگو از داده است و Generative AI خانواده‌ای از مدل‌ها است که محتوای تازه تولید می‌کنند.

از یک رفتار قابل‌مشاهده شروع کنیم

فرض کنید در یک سیستم پرداخت، تراکنشی با مبلغ زیاد از دستگاهی ناشناس ثبت می‌شود. سه قابلیت متفاوت می‌توانند روی همین تراکنش کار کنند:

  1. یک سیستم قانون‌محور بررسی می‌کند: «اگر مبلغ از حد مشخص بیشتر بود و دستگاه جدید بود، تراکنش را برای بررسی نگه دار.»
  2. یک Machine Learning Model با توجه به الگوهای تراکنش‌های گذشته، احتمال تقلب را برابر ۸۷٪ پیش‌بینی می‌کند.
  3. یک Generative AI Model برای اپراتور توضیحی قابل‌خواندن تولید می‌کند: «این تراکنش به‌دلیل مبلغ غیرمعمول و دستگاه جدید پرریسک تشخیص داده شد.»

هر سه قابلیت می‌توانند زیر چتر AI قرار بگیرند، اما مسئله و خروجی آن‌ها یکسان نیست: اولی قانون را اجرا می‌کند، دومی پیش‌بینی می‌کند و سومی محتوا می‌سازد.

AI چیست؟

Artificial Intelligence یا AI حوزه‌ای از علوم کامپیوتر است که هدف آن ساخت سیستم‌هایی است که کارهای نیازمند توانایی‌های شناختی را انجام دهند؛ کارهایی مانند تشخیص الگو، تصمیم‌گیری، درک زبان، برنامه‌ریزی یا حل مسئله.

این تعریف نمی‌گوید ماشین «آگاهی» یا «فهم انسانی» دارد. ما دربارهٔ رفتار قابل‌مشاهدهٔ سیستم صحبت می‌کنیم: سیستم چه ورودی‌ای می‌گیرد، چه پردازشی انجام می‌دهد و چه خروجی‌ای می‌دهد.

مدل ذهنی: AI را یک چتر بزرگ در نظر بگیرید. زیر این چتر، روش‌های مختلفی مانند سیستم‌های قانون‌محور، جست‌وجو، برنامه‌ریزی و Machine Learning قرار می‌گیرند.

برای مثال، یک موتور شطرنج می‌تواند با جست‌وجوی حالت‌های ممکن و ارزیابی حرکت‌ها تصمیم بگیرد. چنین سیستمی الزاماً از داده آموزش ندیده است، اما رفتاری را انجام می‌دهد که در حوزهٔ AI مطالعه می‌شود.

Machine Learning چیست؟

Machine Learning زیرمجموعه‌ای از AI است. در این روش به‌جای نوشتن تمام قانون‌ها به‌صورت دستی، الگوریتم از نمونه‌های داده الگو یاد می‌گیرد و یک Model می‌سازد.

Model نتیجهٔ فرایند یادگیری است؛ یعنی ساختاری که رابطه‌های آموخته‌شده را نگه می‌دارد و می‌تواند برای دادهٔ جدید خروجی تولید کند.

دو مرحلهٔ مهم: Training و Inference

  • Training: الگوریتم داده‌های گذشته را بررسی می‌کند و پارامترهای Model را تنظیم می‌کند. مثلاً تراکنش‌های «سالم» و «متقلبانه» را می‌بیند.
  • Inference: Model آموزش‌دیده یک ورودی جدید می‌گیرد و برای آن پیش‌بینی تولید می‌کند. مثلاً احتمال تقلب تراکنش تازه را محاسبه می‌کند.

این دو مرحله را یکی ندانید. برنامهٔ Production معمولاً بارها Inference انجام می‌دهد، درحالی‌که Training در یک فرایند جدا و کنترل‌شده انجام می‌شود.

یک نمونهٔ ساده از Inference در C#

کد زیر یک Model واقعی را آموزش نمی‌دهد. ضرایب از قبل ثابت شده‌اند تا فقط رفتار مرحلهٔ Inference را ببینیم. در یک پروژهٔ واقعی، این ضرایب طی Training از داده یاد گرفته می‌شوند.

public sealed record Transaction(
    decimal Amount,
    bool IsNewDevice,
    int FailedAttempts);

public static double PredictRisk(Transaction transaction)
{
    var amountSignal = Math.Min((double)(transaction.Amount / 10_000_000m), 1);
    var deviceSignal = transaction.IsNewDevice ? 0.35 : 0;
    var attemptsSignal = Math.Min(transaction.FailedAttempts * 0.12, 0.36);

    return Math.Min(amountSignal * 0.45 + deviceSignal + attemptsSignal, 1);
}

var transaction = new Transaction(
    Amount: 8_000_000m,
    IsNewDevice: true,
    FailedAttempts: 2);

var risk = PredictRisk(transaction);

Console.WriteLine($"Risk: {risk:P0}");
Console.WriteLine(risk >= 0.70 ? "Manual review" : "Continue");

متد PredictRisk سه Signal را به یک Score تبدیل می‌کند. مقدار نهایی از یک بیشتر نمی‌شود و اگر حداقل ۷۰٪ باشد، تراکنش برای بررسی دستی ارسال می‌شود.

این مثال عمداً ساده است. Model واقعی باید با دادهٔ معتبر آموزش ببیند، روی داده‌ای مستقل ارزیابی شود و دلیل انتخاب Threshold آن با هزینهٔ خطاهای کسب‌وکار سنجیده شود.

Generative AI چیست؟

Generative AI به مدل‌هایی گفته می‌شود که بر اساس الگوهای آموخته‌شده، محتوای تازه تولید می‌کنند. این محتوا می‌تواند Text، Image، Audio، Video یا Code باشد.

عبارت «تازه» به این معنا نیست که Model مانند انسان قصد یا تجربهٔ شخصی دارد. خروجی از رابطه‌های آماری آموخته‌شده ساخته می‌شود. برای نمونه، یک مدل زبانی با توجه به Context موجود، ادامهٔ مناسب Text را پیش‌بینی و تولید می‌کند.

تفاوت اصلی با بسیاری از کاربردهای کلاسیک Machine Learning در نوع خروجی دیده می‌شود:

  • یک Model طبقه‌بندی ممکن است فقط برچسب Fraud یا Legitimate برگرداند.
  • یک Model رگرسیون ممکن است مقدار فروش ماه بعد را پیش‌بینی کند.
  • یک Generative Model می‌تواند گزارش، پاسخ، تصویر یا Code جدید تولید کند.
نکته: بیشتر سیستم‌های Generative AI مدرن با روش‌های Machine Learning ساخته می‌شوند. پس Generative AI جدا از Machine Learning نیست؛ یک خانوادهٔ تخصصی درون آن است.

پیکان‌ها رابطهٔ زیرمجموعه را نشان می‌دهند: هر Generative AI System مبتنی بر Machine Learning در حوزهٔ AI قرار می‌گیرد، اما هر AI الزاماً Machine Learning نیست و هر Machine Learning Model نیز Generative نیست.

برای هر مسئله کدام رویکرد مناسب است؟

انتخاب Technology باید از شکل مسئله شروع شود، نه از محبوبیت ابزار.

  • قانون‌ها دقیق و پایدارند: یک Rule Engine یا Code معمولی معمولاً ساده‌تر، ارزان‌تر و قابل‌پیش‌بینی‌تر است. محاسبهٔ مالیات نمونهٔ خوبی است.
  • الگو پیچیده است و دادهٔ تاریخی دارید: Machine Learning می‌تواند برای Classification، Forecasting یا Recommendation مناسب باشد.
  • ورودی یا خروجی ساختار ثابتی ندارد: Generative AI برای خلاصه‌سازی، پاسخ‌گویی، استخراج مفهوم و تولید محتوا مفید است.
  • مسئله چند نوع نیاز دارد: یک سیستم Hybrid می‌تواند قانون قطعی، Model پیش‌بینی و Model مولد را کنار هم قرار دهد.

نمونهٔ Hybrid در Payment

قانون قطعی بررسی می‌کند کارت مسدود نباشد؛ Model احتمال Fraud را پیش‌بینی می‌کند؛ Model مولد نتیجه را برای اپراتور توضیح می‌دهد. هر جزء یک مسئولیت مشخص دارد.

این مفاهیم چه ارتباطی با AI Agent دارند؟

یک Model به‌تنهایی Agent نیست. Model ورودی می‌گیرد و خروجی تولید می‌کند؛ اما Agent برای رسیدن به Goal، اجرای چندمرحله‌ای را مدیریت می‌کند.

یک AI Agent معمولاً این اجزا را کنار هم قرار می‌دهد:

  • Model: زبان یا داده را تحلیل می‌کند و برای گام بعدی پیشنهاد می‌دهد.
  • Instructions: هدف، نقش و محدودیت رفتار را مشخص می‌کنند.
  • Tools: امکان خواندن داده یا انجام Action در سیستم‌های واقعی را می‌دهند.
  • Context و Memory: اطلاعات لازم برای تصمیم فعلی و سابقهٔ مرتبط را فراهم می‌کنند.
  • Runtime Loop: تصمیم، اجرای Tool، مشاهدهٔ نتیجه و توقف را هماهنگ می‌کند.
  • Guardrails: دسترسی، Validation، Approval و محدودیت‌های امنیتی را اعمال می‌کنند.

در نتیجه، Generative AI Model می‌تواند موتور استدلال زبانی Agent باشد، اما قابلیت Agentic از ترکیب Model با ابزارها، State، چرخهٔ اجرا و کنترل‌ها به وجود می‌آید.

محدودیت‌هایی که باید از ابتدا بشناسیم

  • دادهٔ ضعیف، نتیجهٔ ضعیف: دادهٔ ناقص، قدیمی یا جانبدارانه روی Model اثر می‌گذارد.
  • پیش‌بینی، حقیقت قطعی نیست: Score برابر ۹۵٪ همچنان احتمال است و باید معنای Business آن مشخص باشد.
  • خروجی مولد می‌تواند نادرست باشد: متن روان تضمین نمی‌کند واقعیت درست باشد؛ خروجی مهم باید Ground، Validate یا Review شود.
  • Privacy و Security مهم‌اند: دادهٔ حساس نباید بدون Policy روشن وارد Model یا Provider خارجی شود.
  • هزینه و Latency واقعی‌اند: فراخوانی Model منابع مصرف می‌کند و ممکن است از Code قطعی کندتر باشد.
  • Evaluation ضروری است: کیفیت باید با Dataset و معیار متناسب با مسئله اندازه‌گیری شود، نه با چند نمونهٔ نمایشی.

اشتباهات رایج

  • یکسان دانستن AI و Chatbot: Chatbot فقط یکی از Interfaceهای ممکن برای یک سیستم AI است.
  • استفاده از Generative AI برای قانون قطعی: اگر پاسخ باید همیشه دقیق و قابل‌ممیزی باشد، Code یا Rule Engine انتخاب مطمئن‌تری است.
  • یکی دانستن Training و Prompting: Prompt ورودی زمان اجرا را هدایت می‌کند؛ Training پارامترهای Model را با داده تغییر می‌دهد.
  • فرض فهم انسانی: Model می‌تواند پاسخ قانع‌کننده بسازد، اما این رفتار اثبات آگاهی یا درک انسانی نیست.
  • نادیده‌گرفتن خطا: هر سیستم AI باید مسیر Failure، Fallback و Human Review داشته باشد.

تمرین کوتاه

برای هر مسئله مشخص کنید راه‌حل مناسب‌تر Rule-Based، Machine Learning، Generative AI یا Hybrid است و دلیل خود را بنویسید:

  1. محاسبهٔ کارمزد تراکنش بر اساس جدول رسمی بانک.
  2. پیش‌بینی احتمال لغو اشتراک مشتری در ماه آینده.
  3. خلاصه‌کردن مکالمهٔ طولانی پشتیبانی.
  4. بررسی تراکنش، پیش‌بینی Fraud و تولید توضیح برای اپراتور.
مشاهدهٔ پاسخ پیشنهادی
  1. Rule-Based، چون قانون رسمی و قطعی است.
  2. Machine Learning، چون هدف پیش‌بینی یک الگو از دادهٔ تاریخی است.
  3. Generative AI، چون خروجی Text جدید و بدون قالب ثابت است.
  4. Hybrid، چون قانون‌های قطعی، پیش‌بینی و تولید توضیح کنار هم لازم‌اند.

جمع‌بندی

  • AI حوزهٔ گستردهٔ ساخت سیستم‌هایی با رفتار هوشمندانه است.
  • Machine Learning زیرمجموعهٔ AI است و الگو را از داده یاد می‌گیرد.
  • Generative AI محتوای تازه مانند Text، Image، Audio یا Code تولید می‌کند.
  • Training Model را می‌سازد و Inference از آن برای ورودی جدید خروجی می‌گیرد.
  • Model به‌تنهایی Agent نیست؛ Agent به Instructions، Tools، Context، Runtime Loop و Guardrails نیاز دارد.
  • راه‌حل خوب ممکن است Rule-Based، Machine Learning، Generative AI یا ترکیبی از آن‌ها باشد.
