درس 01 مطالعه‌شده

Testing چیست و چرا اهمیت دارد؟

مفهوم و کاربرد در مصاحبه

تست خودکار رفتار مورد انتظار نرم‌افزار را با نتیجه واقعی مقایسه می‌کند. هدف کشف زودهنگام باگ و جلوگیری از Regression است، نه اثبات نبودن تمام خطاها.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
public class PaymentService
{
    public bool ValidateAmount(decimal amount) => amount > 0;
}

[Fact]
public void PositiveAmount_IsValid()
{
    var service = new PaymentService();
    Assert.True(service.ValidateAmount(1000m));
}
نکته مصاحبه

برای مرزهای مبلغ مثبت، صفر و منفی تست جداگانه داشته باش. تستی که فقط Exception ندادن متد را چک کند الزاماً درستی خروجی را اثبات نمی‌کند.

سؤال مرور: برای مقدار ۰، خروجی مورد انتظار ValidateAmount چیست؟

پاسخ: false

درس 02 مطالعه‌شده

تفاوت Unit، Integration و E2E

مفهوم و کاربرد در مصاحبه

در Unit Test منطق کوچک را مستقل آزمایش می‌کنیم. Integration Test همکاری چند جزء واقعی مثل Repository و دیتابیس را بررسی می‌کند. E2E مسیر کامل کسب‌وکار را از ورودی تا نتیجه آزمایش می‌کند.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
// Unit: منطق بدون زیرساخت
Assert.False(new PaymentService().ValidateAmount(0));

// Integration (شبه‌کد):
// POST /payments -> read record from test database
// Assert.Equal(PaymentStatus.Pending, saved.Status);

// E2E: API Gateway -> Payment -> Broker -> Ledger
نکته مصاحبه

ارسال HTTP به یک API الزاماً E2E نیست؛ ممکن است تست فقط چند جزء داخل برنامه را یکپارچه کند.

سؤال مرور: برای اثبات ذخیره واقعی در SQL Server چه تستی لازم است؟

پاسخ: Integration Test با دیتابیس تست

مفهوم و کاربرد در مصاحبه

هر سه چارچوب تست دات‌نت هستند. در xUnit از Fact/Theory، در NUnit از Test/TestCase و در MSTest از TestMethod/DataRow استفاده می‌شود. این دوره با xUnit پیش می‌رود.

سؤال مرور: Assert.Equal(6, 2+3) موفق است؟

درس 05 مطالعه‌شده

الگوی Arrange، Act و Assert

مفهوم و کاربرد در مصاحبه

ساختار AAA شامل آماده‌سازی ورودی و وابستگی، اجرای یک عمل، و بررسی خروجی یا اثر قابل مشاهده است. هر تست بهتر است یک رفتار معنادار را پوشش دهد.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
[Fact]
public void Amount_Valid_ReturnsTrue()
{
    // Arrange
    var service = new PaymentService();
    const decimal amount = 5000m;

    // Act
    bool result = service.ValidateAmount(amount);

    // Assert
    Assert.True(result);
}
نکته مصاحبه

چند Assert برای بررسی جنبه‌های یک رفتار واحد می‌تواند منطقی باشد؛ نیازی نیست کورکورانه هر تست فقط یک Assert داشته باشد.

سؤال مرور: اجرای متد اصلی در کدام بخش AAA انجام می‌شود؟

پاسخ: Act

درس 06 مطالعه‌شده

Happy Path، Negative Test و Boundary Value

مفهوم و کاربرد در مصاحبه

فقط سناریوی موفق کافی نیست. برای مبلغی که باید بزرگ‌تر از صفر و حداکثر صد میلیون باشد، مقدار صفر، کمترین مبلغ مجاز، سقف و مقدار بیشتر از سقف را بررسی می‌کنیم.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
public static bool IsValidAmount(decimal amount)
    => amount > 0 && amount <= 100_000_000m;

[Theory]
[InlineData(0, false)]
[InlineData(1, true)]
[InlineData(100_000_000, true)]
[InlineData(100_000_001, false)]
public void AmountBoundaries(int input, bool expected)
    => Assert.Equal(expected, IsValidAmount(input));
نکته مصاحبه

اگر واحد مالی دو رقم اعشار دارد، برای مرز ۰٫۰۱ یا ۱۰۰۰۰۰۰۰۰٫۰۱ از MemberData و decimal استفاده کن.

سؤال مرور: آیا خود سقف ۱۰۰ میلیون معتبر است؟

پاسخ: بله، چون شرط <= است

درس 07 مطالعه‌شده

Fact، Theory و InlineData

مفهوم و کاربرد در مصاحبه

Fact برای یک حالت بدون پارامتر داده‌ای مناسب است؛ Theory یک آزمون پارامتری است که به ازای هر ردیف داده تکرار می‌شود. InlineData فقط آرگومان‌های سازگار با Attribute می‌پذیرد.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
[Theory]
[InlineData(1, true)]
[InlineData(0, false)]
[InlineData(-1, false)]
public void IsPositive(int value, bool expected)
{
    Assert.Equal(expected, value > 0);
}
نکته مصاحبه

برای اشیای پیچیده و decimal از MemberData یا ClassData استفاده کن. سه InlineData معمولاً سه Test Case تولید می‌کند.

سؤال مرور: سه InlineData چند مورد آزمون تولید می‌کند؟

پاسخ: ۳

درس 08 مطالعه‌شده

تست Async و Exception

مفهوم و کاربرد در مصاحبه

تست متد async باید Task برگرداند و عملیات را await کند. برای Exception ناهمگام از Assert.ThrowsAsync استفاده می‌کنیم تا شکست عملیات واقعاً مشاهده شود.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
public async Task<int> GetAmountAsync()
{
    await Task.Yield();
    throw new InvalidOperationException("Payment failed");
}

[Fact]
public async Task GetAmount_Throws()
{
    await Assert.ThrowsAsync<InvalidOperationException>(
        () => GetAmountAsync());
}
نکته مصاحبه

استفاده از async void برای متد تست توصیه نمی‌شود. ThrowsAsync در xUnit نوع دقیق Exception را بررسی می‌کند؛ نوع مشتق لزوماً پذیرفته نمی‌شود.

سؤال مرور: برای تست Exception یک Task از چه ابزاری استفاده می‌کنی؟

پاسخ: await Assert.ThrowsAsync

درس 09 مطالعه‌شده

Test Double: Mock، Stub و Fake

مفهوم و کاربرد در مصاحبه

Test Double جایگزین آزمایشی یک وابستگی است. Stub پاسخ قابل پیش‌بینی می‌دهد، Mock تعاملات را بررسی می‌کند، و Fake پیاده‌سازی ساده ولی فعال دارد (مثلاً ذخیره‌سازی در حافظه).

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
public interface IAccountRepository
{
    Task<decimal> GetBalanceAsync(int accountId);
}

public sealed class StubAccountRepository : IAccountRepository
{
    public Task<decimal> GetBalanceAsync(int accountId)
        => Task.FromResult(5000m);
}
نکته مصاحبه

Mock یک ابزار خاص نیست؛ Moq می‌تواند هم به عنوان Stub و هم Mock به کار رود. Fake جایگزین کاملی برای رفتار Transaction در SQL Server نیست.

سؤال مرور: برای بررسی «SaveAsync دقیقاً یک بار صدا شد» کدام مناسب است؟

پاسخ: Mock + Verify

درس 10 مطالعه‌شده

Moq: تفاوت Setup و Verify

مفهوم و کاربرد در مصاحبه

Setup پاسخ یا رفتار وابستگی را تعریف می‌کند؛ Verify تعداد و آرگومان‌های فراخوانی را می‌سنجد. این دو را با نتیجه واقعی کسب‌وکار اشتباه نگیریم.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
var mock = new Mock<IAccountRepository>();
mock.Setup(x => x.GetBalanceAsync(5))
    .ReturnsAsync(2000m);

var balance = await mock.Object.GetBalanceAsync(5);
Assert.Equal(2000m, balance);

mock.Verify(x => x.GetBalanceAsync(5), Times.Once());
نکته مصاحبه

اگر حساب ۲۰۰۰ موجودی دارد و درخواست پرداخت ۳۰۰۰ باشد، منطق کنترل موجودی باید false بدهد؛ Verify موفق تنها به معنای اجرای وابستگی است.

سؤال مرور: کدام متد Moq تعداد فراخوانی را تأیید می‌کند؟

پاسخ: Verify

درس 11 مطالعه‌شده

State Verification و Behavior Verification

مفهوم و کاربرد در مصاحبه

State Verification خروجی یا وضعیت نهایی را می‌سنجد. Behavior Verification تعامل با وابستگی را ارزیابی می‌کند. تست بیش از حد جزئیات داخلی می‌تواند Refactoring را پرهزینه کند.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
// State: مقدار نهایی
var balance = 5000m;
balance -= 1000m;
Assert.Equal(4000m, balance);

// Behavior: تعامل با سرویس خارجی
notificationMock.Verify(
    x => x.SendAsync(10), Times.Once());
نکته مصاحبه

برای انتقال وجه، وضعیت حساب مبدأ و مقصد معیار اصلی صحت است. برای ارسال فرمان حیاتی به درگاه، Verify تعامل می‌تواند لازم باشد.

سؤال مرور: بررسی موجودی نهایی دو حساب از کدام نوع است؟

پاسخ: State Verification

درس 12 تکمیلی

تست Service با Dependency Injection

مفهوم و کاربرد در مصاحبه

وابستگی‌ها را از طریق سازنده تزریق کنیم تا بتوانیم نسخه آزمایشی آن‌ها را جایگزین کنیم. Interface و تفکیک مسئولیت‌ها Testability را بهبود می‌دهند.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
public interface IFeeCalculator
{
    decimal Calculate(decimal amount);
}
public sealed class PaymentService(IFeeCalculator fees)
{
    public decimal Total(decimal amount)
        => amount + fees.Calculate(amount);
}

[Fact]
public void Total_IncludesFee()
{
    var fee = new Mock<IFeeCalculator>();
    fee.Setup(x => x.Calculate(1000m)).Returns(20m);
    var service = new PaymentService(fee.Object);
    Assert.Equal(1020m, service.Total(1000m));
}
نکته مصاحبه

موقع تست تنها وابستگی‌های بیرونی یا پرهزینه را جایگزین کن؛ برای منطق ساده، Fake/پیاده‌سازی واقعی هم می‌تواند مناسب‌تر باشد.

سؤال مرور: چرا Constructor Injection تست را آسان‌تر می‌کند؟

پاسخ: امکان جایگزین‌کردن وابستگی‌ها

درس 13 تکمیلی

تست وابستگی‌های Database و HTTP

مفهوم و کاربرد در مصاحبه

در Unit Test فراخوانی Repository یا HttpClient را با مرز انتزاعی کنترل می‌کنیم. برای اطمینان از SQL واقعی یا HTTP واقعی باید Integration Test جداگانه داشت.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
public interface IBankGateway
{
    Task<bool> ChargeAsync(decimal amount, CancellationToken ct);
}

var gateway = new Mock<IBankGateway>();
gateway.Setup(x => x.ChargeAsync(1000m, It.IsAny<CancellationToken>()))
       .ReturnsAsync(true);

Assert.True(await gateway.Object.ChargeAsync(
    1000m, CancellationToken.None));
نکته مصاحبه

برای HttpClient می‌توان از HttpMessageHandler آزمایشی یا سرور تست استفاده کرد؛ Mock کردن مستقیم همه متدهای HttpClient معمولاً مناسب نیست.

سؤال مرور: تست با Mock دیتابیس آیا صحت واقعی SQL را اثبات می‌کند؟

درس 14 تکمیلی

اصول FIRST و تست‌های پایدار

مفهوم و کاربرد در مصاحبه

FIRST یعنی Fast، Independent، Repeatable، Self-validating و Timely. تست مستقل نباید وابسته به ترتیب اجرای تست‌های دیگر یا شبکه پرنوسان باشد.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
[Fact]
public void Fee_ForKnownAmount_IsDeterministic()
{

    var fee = amount * 0.01m;
    Assert.Equal(10m, fee);
}
نکته مصاحبه

از DateTime.Now، Random و اشتراک وضعیت mutable بدون کنترل پرهیز کن. ساعت را با TimeProvider یا Interface قابل جایگزینی تزریق کن.

سؤال مرور: کدام اصل FIRST می‌گوید تست نباید به ترتیب تست‌ها وابسته باشد؟

پاسخ: Independent

درس 16 تکمیلی

WebApplicationFactory و تست API

مفهوم و کاربرد در مصاحبه

در ASP.NET Core از WebApplicationFactory برای میزبانی آزمایشی برنامه و ساخت HttpClient استفاده می‌کنیم. با آن Endpoint، Middleware، Routing و Serialization را یکپارچه بررسی می‌کنیم.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
// نیازمند Microsoft.AspNetCore.Mvc.Testing
public class PaymentApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;
    public PaymentApiTests(WebApplicationFactory<Program> factory)
        => _client = factory.CreateClient();

    [Fact]
    public async Task MissingRoute_Returns404()
    {
        var response = await _client.GetAsync("/route-that-does-not-exist");
        Assert.Equal(HttpStatusCode.NotFound, response.StatusCode);
    }
}
نکته مصاحبه

کد نمونه نیازمند usingها، دسترسی به Program، بسته تست و پیکربندی مناسب سرویس‌هاست. خود WebApplicationFactory به معنی اجرای تمام سرویس‌های بیرونی نیست.

سؤال مرور: آیا تست یک Endpoint با WebApplicationFactory الزاماً E2E است؟

درس 18 تکمیلی

تست Authentication و Authorization در API

مفهوم و کاربرد در مصاحبه

تست API باید پاسخ 401 برای کاربر بدون اعتبار، 403 برای کاربر معتبر بدون مجوز، و موفقیت برای مجوز مناسب را تفکیک کند. سیاست‌ها و Claimها را در Test Host تنظیم کن.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
// سناریوها (پیشنهاد تست)
// No Access Token       => 401 Unauthorized
// Valid Access Token, wrong permission => 403 Forbidden
// Valid Access Token, required permission => 200/201
// Expired Access Token  => 401 Unauthorized
نکته مصاحبه

در تست‌ها Access Token و Refresh Token را دقیق نام‌گذاری کن. برای Integration می‌توان Authentication Scheme آزمایشی ثبت کرد؛ تست جداگانه‌ای هم برای پیکربندی اعتبارسنجی واقعی JWT لازم است.

سؤال مرور: کاربر احراز هویت‌شده بدون مجوز معمولاً چه کدی می‌گیرد؟

پاسخ: 403

Code Coverage و Mutation Testing

مفهوم و کاربرد در مصاحبه

Coverage نشان می‌دهد چه میزان از کد در تست‌ها اجرا شده، نه اینکه assertions درست و قوی‌اند. Mutation Testing تغییرات عمدی کوچک در کد ایجاد می‌کند تا حساسیت تست‌ها را بسنجد.

مثال و پیاده‌سازی

نمونه کد / تمرینCSHARP
// dotnet test --collect:"XPlat Code Coverage"

public bool IsValid(decimal amount) => amount > 0;
// Mutation: > تبدیل به >= شود.
// تست مقدار صفر باید mutant را شناسایی کند.
نکته مصاحبه

Coverage بالا تضمین کیفیت نیست؛ تستی بدون Assert هم می‌تواند خطوط زیادی را اجرا کند. Mutation Score نیز باید در کنار هزینه و اهمیت کد تفسیر شود.

سؤال مرور: چرا ۱۰۰٪ Code Coverage تضمین نبودن باگ نیست؟

پاسخ: اجراشدن خطوط، درستی Assertها را اثبات نمی‌کند

اجرای تست‌ها در CI/CD

مفهوم و کاربرد در مصاحبه

تست‌ها در Pipeline پیش از Deploy اجرا می‌شوند. بهتر است Unit Test سریع روی هر تغییر، Integration Test در مرحله مناسب و E2E حیاتی پیش از انتشار اجرا شوند.

مثال و پیاده‌سازی

نمونه کد / تمرینYAML
stages:
  - test
  - deploy

unit_tests:
  stage: test
  image: mcr.microsoft.com/dotnet/sdk:8.0
  script:
    - dotnet restore
    - dotnet test --no-restore --configuration Release

deploy:
  stage: deploy
  script:
    - echo "Deploy application"
  when: manual
نکته مصاحبه

YAML نمونه ساده GitLab CI است و در پروژه واقعی به build، artifact، environment و وابستگی‌ها نیاز دارد. اگر تست‌های مرحله تست شکست بخورند، Deploy وابسته نباید اجرا شود.

سؤال مرور: اگر Unit Test در مرحله test شکست بخورد، Deploy استاندارد باید چه کند؟

پاسخ: متوقف شود
