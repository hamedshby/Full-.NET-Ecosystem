Learning objectives

در پایان فصل باید بتوانید

بخش 03 · ویدئو: 1m 21s

Define cloud computing

تعریف ساده با یک مثال

Cloud Computing یعنی دسترسی به منابعی مانند سرور، شبکه، ذخیره‌سازی و نرم‌افزار از طریق شبکه، معمولاً اینترنت؛ منابع را زمانی می‌گیریم که نیاز داریم و میزان استفاده را می‌توان افزایش یا کاهش داد.

برای مثال، به‌جای خرید سرور برای فروش ویژهٔ سالانه، یک فروشگاه می‌تواند ظرفیت محاسباتی بیشتری را در زمان اوج ترافیک فعال کند و پس از پایان رویداد آن را کاهش دهد. زیرساخت فیزیکی در مرکز دادهٔ ارائه‌دهنده قرار دارد، اما سازمان از راه سرویس به آن دسترسی می‌گیرد.

ویژگیمعنای عملی
On-demandمنبع را هنگام نیاز تهیه یا آزاد می‌کنیم.
دسترسی از شبکهکاربر یا برنامه از مسیر شبکه به سرویس وصل می‌شود.
قابلیت تغییر ظرفیتمنابع متناسب با نیاز قابل افزایش یا کاهش‌اند.
اندازه‌گیری مصرفمصرف منابع قابل پایش و در مدل‌های مربوطه قابل محاسبه است.

Cloud به معنی «همه‌چیز روی اینترنت و بدون مسئولیت مشتری» نیست؛ مشتری هنوز باید دسترسی‌ها، داده‌ها و تنظیمات تحت کنترل خود را مدیریت کند.

سؤال مرور بخش 03 — نمایش پاسخ

سؤال: فروشگاه برای چند ساعت ظرفیت سرور را بالا می‌برد و بعد آن را پایین می‌آورد. کدام ویژگی Cloud این کار را ممکن می‌کند؟

پاسخ: قابلیت تغییر ظرفیت منابع متناسب با تقاضا؛ معمولاً با Elasticity شناخته می‌شود.

بخش 04 · ویدئو: 1m 28s

Describe the shared responsibility model

امنیت بین مشتری و ارائه‌دهنده تقسیم می‌شود

Shared Responsibility Model مرز مسئولیت‌های Cloud Provider و مشتری را مشخص می‌کند. ارائه‌دهنده معمولاً امنیت زیرساخت فیزیکی و اجزایی را که خودش اداره می‌کند بر عهده دارد؛ مشتری نیز مسئول داده، هویت‌ها، دسترسی‌ها و تنظیماتی است که در اختیارش قرار گرفته‌اند.

مرز دقیق مسئولیت به نوع سرویس بستگی دارد. هرچه سرویس مدیریت‌شده‌تر باشد، ارائه‌دهنده بخش بیشتری از زیرساخت را اداره می‌کند؛ اما مسئولیت داده و نحوهٔ دسترسی به آن همچنان برای مشتری مهم است.

نوع مسئولیتنمونهٔ معمول
Cloud Providerامنیت مرکز دادهٔ فیزیکی و سخت‌افزار پایه‌ای که ارائه‌دهنده اداره می‌کند.
مشتریمدیریت حساب‌ها و مجوزها، محافظت از داده و امن‌کردن تنظیماتی که کنترلشان را دارد.
بسته به سرویسمدیریت سیستم‌عامل، Runtime و برنامه؛ این مرز در IaaS، PaaS و SaaS یکسان نیست.

در IaaS مشتری معمولاً کنترل بیشتری بر سیستم‌عامل و تنظیمات ماشین دارد. در PaaS بخشی از مدیریت سیستم‌عامل و Runtime به ارائه‌دهنده سپرده می‌شود. در SaaS ارائه‌دهنده خود برنامه را هم اداره می‌کند، ولی مشتری همچنان باید کاربران، دسترسی‌ها و داده‌های خود را مدیریت کند.

سؤال مرور بخش 04 — نمایش پاسخ

سؤال: آیا استفاده از Cloud Provider مسئولیت محافظت از حساب‌های کاربران و مجوزهای آن‌ها را کاملاً از مشتری می‌گیرد؟

پاسخ: خیر. مدیریت هویت و دسترسی‌هایی که مشتری تعریف می‌کند همچنان از مسئولیت‌های مهم مشتری است.

بخش 05 · ویدئو: 9m 10s

Define cloud models

Public، Private و Hybrid Cloud

Cloud Model در این بخش به شیوهٔ استقرار و استفاده از زیرساخت اشاره دارد. سه مدل اصلی را با این پرسش از هم جدا کنید: زیرساخت کجا و برای چه کسانی فراهم شده و آیا محیط داخلی با Cloud عمومی ترکیب شده است؟

مدلتوضیحنمونهٔ سناریو
Public Cloudسرویس‌ها را ارائه‌دهندهٔ ابری روی زیرساخت خود در اختیار چند مشتری قرار می‌دهد؛ منابع هر مشتری به‌صورت منطقی جدا می‌مانند.راه‌اندازی وب‌سایت روی Azure بدون خرید سرور فیزیکی.
Private Cloudمحیط ابری برای استفادهٔ یک سازمان اختصاص داده شده و می‌تواند داخل مرکز دادهٔ سازمان یا به میزبانی ارائه‌دهنده باشد.سازمان زیرساخت اختصاصی خود را برای نیازهای کنترلی خاص اداره می‌کند.
Hybrid Cloudمحیط محلی یا Private Cloud با Public Cloud یکپارچه می‌شود و داده یا برنامه می‌تواند میان آن‌ها جابه‌جا شود.سامانهٔ قدیمی داخل سازمان می‌ماند و وب‌سایت عمومی در Azure اجرا می‌شود.

Public به معنی عمومی‌بودن داده‌ها نیست؛ واژه به مدل ارائه و استفاده از زیرساخت اشاره دارد. همچنین Hybrid فقط داشتن دو محیط جدا نیست؛ برای این مدل، هماهنگی یا اتصال میان محیط‌ها اهمیت دارد.

سؤال مرور بخش 05 — نمایش پاسخ

سؤال: شرکت بخشی از برنامه را در مرکز دادهٔ خودش نگه می‌دارد و بخشی را در Azure اجرا می‌کند. کدام Cloud Model به این سناریو نزدیک است؟

پاسخ: Hybrid Cloud، چون محیط محلی و Public Cloud در کنار هم استفاده می‌شوند.

بخش 06 · ویدئو: 2m 9s

Consumption-based model

هزینه متناسب با میزان استفاده

در Consumption-based model، هزینه بر اساس منابع یا میزان استفادهٔ اندازه‌گیری‌شده محاسبه می‌شود. سازمان لازم نیست همیشه ظرفیت اوج مصرف را از ابتدا بخرد؛ می‌تواند منابع را متناسب با تقاضا تنظیم کند و مصرف را پایش کند.

خرید و نگهداری سنتیمدل مصرف‌محور
هزینهٔ اولیه برای تهیهٔ سخت‌افزار و ظرفیت آینده.پرداخت بر اساس منابع و واحدهای مصرف‌شده طبق قیمت‌گذاری سرویس.
ظرفیت بلااستفاده هم هزینهٔ خرید و نگهداری داشته است.می‌توان منابع غیرضروری را کاهش داد یا خاموش کرد تا هزینهٔ قابل‌کنترل‌تری داشت.
افزایش ظرفیت به خرید و نصب تجهیزات وابسته است.تغییر ظرفیت معمولاً سریع‌تر انجام می‌شود، اما هزینه همچنان باید پایش شود.

مثلاً اگر سامانه‌ای شب‌ها ترافیک کمی دارد، کاهش اندازه یا خاموش‌کردن منابع غیرضروری می‌تواند مصرف را کم کند. اما اگر منبعی روشن و بلااستفاده بماند، ممکن است همچنان هزینه ایجاد کند؛ پس «پرداخت بر اساس مصرف» به معنی «همیشه ارزان‌تر» یا «بدون نیاز به مدیریت هزینه» نیست.

سؤال مرور بخش 06 — نمایش پاسخ

سؤال: تیمی یک ماشین مجازی را برای آزمایش می‌سازد و پس از پایان کار فراموش می‌کند آن را متوقف کند. آیا مصرف‌محور بودن تضمین می‌کند هزینه‌ای ایجاد نشود؟

پاسخ: خیر. منبع فعال ممکن است طبق واحدهای قیمت‌گذاری هزینه داشته باشد؛ باید مصرف و منابع بلااستفاده را پایش و مدیریت کرد.
