18.9 — KISS

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

KISS — Keep It Simple می‌گوید ساده‌ترین طراحی‌ای را انتخاب کنید که نیاز واقعی را به‌درستی حل می‌کند.

💡
Simple به معنی Primitive یا غیرحرفه‌ای نیست. طراحی ساده یعنی Complexity فقط جایی وجود داشته باشد که مسئله واقعاً آن را لازم دارد.

مثال Overengineering

Text
IPaymentFeeProvider
    -> PaymentFeeProvider
        -> PaymentFeeStrategyFactory
            -> PaymentFeeStrategyResolver
                -> DefaultPaymentFeeStrategy

اگر سیستم فقط یک Fee ثابت دارد، این تعداد Abstraction احتمالاً ارزش ایجاد نمی‌کند.

نسخه ساده

C#
public class PaymentFeeCalculator
{
    public decimal Calculate(decimal amount)
        => amount * 0.01m;
}

اما Simple با Simplistic فرق دارد

اگر واقعاً چند Fee Policy، Rule پیچیده و Variation مستقل داریم، Strategy Pattern ممکن است طراحی را ساده‌تر کند. KISS نمی‌گوید Complexity واقعی را پنهان کنیم.

KISS در .NET

  • از قابلیت Built-in فریم‌ورک قبل از ساخت Framework داخلی استفاده کنید.
  • برای Query ساده، Pipeline چندلایهٔ غیرضروری نسازید.
  • Pattern را برای حل Problem استفاده کنید، نه برای نمایش Pattern.
  • نام‌گذاری و Control Flow را واضح نگه دارید.
⚠️
سادگی را با کوتاه‌ترین کد اشتباه نگیرید. یک One-Liner پیچیده ممکن است از چند خط کد واضح سخت‌تر فهمیده شود.

نکته مصاحبه‌ای

🎤
KISS means choosing the simplest design that correctly satisfies current requirements while keeping the code understandable and maintainable.

جمع‌بندی

Complexity بودجه دارد. آن را فقط برای Requirement یا Constraint واقعی خرج کنید.
