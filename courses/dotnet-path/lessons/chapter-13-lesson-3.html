13.3 — Record

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در C#، record نوعی type است که برای مدل‌کردن داده‌هایی با Value-based Equality بسیار مناسب است. Record به‌خصوص زمانی مفید است که مهم باشد دو object بر اساس مقادیرشان با هم مقایسه شوند، نه صرفاً بر اساس اینکه آیا به یک instance مشترک اشاره می‌کنند یا نه.

💡
اگر فقط record بنویسیم، منظور record class است؛ یعنی همچنان یک Reference Type داریم. تفاوت مهم آن با Class معمولی، رفتارهای تولیدشده توسط Compiler مانند Value Equality، نمایش بهتر داده و پشتیبانی مناسب از with و positional syntax است.

Record چیست؟

یک Record ساده را می‌توان مشابه Class تعریف کرد:

C#
public record Customer
{
    public string FirstName
    {
        get;
        init;
    }

    public string LastName
    {
        get;
        init;
    }
}

و سپس از آن object ساخت:

C#
var customer =
    new Customer
    {
        FirstName = "Hamed",
        LastName = "Ahmadi"
    };

تا اینجا ظاهر آن شبیه Class است؛ تفاوت مهم‌تر هنگام Equality و کار با داده‌ها مشخص می‌شود.

Record یک Reference Type است

record به‌صورت پیش‌فرض همان record class است و Reference Type محسوب می‌شود.

C#
public record Money
{
    public decimal Amount
    {
        get;
        init;
    }

    public string Currency
    {
        get;
        init;
    }
}

پس نباید Record را با Struct اشتباه بگیریم. Record معمولی Reference Type است، در حالی که record struct که در بخش بعدی بررسی می‌کنیم Value Type است.

مهم‌ترین ویژگی Record: Value Equality

Class معمولی به‌صورت پیش‌فرض reference-based equality دارد، اما Recordها به‌صورت پیش‌فرض بر اساس مقادیر اعضای خود مقایسه می‌شوند.

C#
public record Money
{
    public decimal Amount
    {
        get;
        init;
    }

    public string Currency
    {
        get;
        init;
    }
}
C#
var money1 =
    new Money
    {
        Amount = 500_000,
        Currency = "IRR"
    };

var money2 =
    new Money
    {
        Amount = 500_000,
        Currency = "IRR"
    };

Console.WriteLine(
    money1 == money2);
// True

دو instance متفاوت ساخته شده‌اند، اما چون مقادیرشان برابر است، Record آن‌ها را برابر در نظر می‌گیرد.

اما Referenceها یکی نیستند

C#
Console.WriteLine(
    ReferenceEquals(
        money1,
        money2));
// False
🎯
این نکته بسیار مهم است: money1 == money2 می‌تواند true باشد، در حالی که ReferenceEquals(money1, money2) برابر false است. یعنی دو object جدا داریم که از نظر Value برابر هستند.

Positional Record

یکی از جذاب‌ترین قابلیت‌های Record، تعریف بسیار کوتاه آن با Primary Constructor-like syntax است:

C#
public record Money(
    decimal Amount,
    string Currency);

Compiler بخش زیادی از boilerplate موردنیاز را برای ما تولید می‌کند.

C#
var money =
    new Money(
        500_000,
        "IRR");

Console.WriteLine(
    money.Amount);

Console.WriteLine(
    money.Currency);

برای مدل‌های داده‌ای کوچک، این syntax بسیار خوانا و مختصر است.

Record و init

Recordها معمولاً با immutable-style design استفاده می‌شوند. Propertyهای init فقط هنگام initialization قابل مقداردهی هستند.

C#
public record PaymentRequest
{
    public decimal Amount
    {
        get;
        init;
    }

    public string CardNumber
    {
        get;
        init;
    }
}
C#
var request =
    new PaymentRequest
    {
        Amount = 500_000,
        CardNumber = "6037..."
    };

// Compile Error:
// request.Amount = 900_000;
⚠️
Record ذاتاً به معنی «کاملاً Immutable» نیست. می‌توان داخل Record Property با set تعریف کرد. Immutable بودن یک تصمیم طراحی است؛ Record فقط ابزارهای بسیار مناسبی برای این سبک طراحی فراهم می‌کند.

with Expression

وقتی object را immutable طراحی می‌کنیم، به‌جای تغییر object موجود می‌توان نسخهٔ جدیدی با چند مقدار متفاوت ساخت. Record این کار را با with بسیار ساده می‌کند.

C#
public record PaymentRequest(
    decimal Amount,
    string Currency);
C#
var original =
    new PaymentRequest(
        500_000,
        "IRR");

var updated =
    original with
    {
        Amount = 700_000
    };

original تغییر نمی‌کند. یک Record جدید ساخته می‌شود که مقادیر قبلی را دارد، به‌جز Propertyهایی که در with تغییر داده‌ایم.

C#
Console.WriteLine(
    original.Amount);
// 500000

Console.WriteLine(
    updated.Amount);
// 700000

with یک Shallow Copy ایجاد می‌کند

نکتهٔ مهم این است که copy انجام‌شده توسط with برای referenceهای داخلی، shallow است.

C#
public record Order(
    string Number,
    List<string> Items);

var order1 =
    new Order(
        "1001",
        new List<string>
        {
            "Book"
        });

var order2 =
    order1 with
    {
        Number = "1002"
    };

order2.Items.Add(
    "Laptop");

در این مثال، هر دو Record می‌توانند به همان List<string> داخلی اشاره کنند.

⚠️
اگر Record را برای immutable design استفاده می‌کنید، فقط init کافی نیست. باید Mutability اعضای داخلی مانند List<T> را نیز در نظر بگیرید.

Deconstruction

Positional Record به‌صورت خودکار امکان Deconstruction را فراهم می‌کند.

C#
public record Money(
    decimal Amount,
    string Currency);

var money =
    new Money(
        500_000,
        "IRR");

var (amount, currency) =
    money;

Console.WriteLine(amount);
// 500000

Console.WriteLine(currency);
// IRR

این قابلیت در pattern matching و کار با مدل‌های داده‌ای کوچک بسیار مفید است.

نمایش بهتر با ToString()

Recordها یک ToString() مناسب برای نمایش داده‌ها تولید می‌کنند.

C#
var money =
    new Money(
        500_000,
        "IRR");

Console.WriteLine(money);

خروجی چیزی شبیه این خواهد بود:

Text
Money { Amount = 500000, Currency = IRR }

این رفتار هنگام Debugging و Logging می‌تواند بسیار مفید باشد.

Record می‌تواند Method داشته باشد

Record فقط برای نگهداری data نیست و می‌تواند Behavior نیز داشته باشد.

C#
public record Money(
    decimal Amount,
    string Currency)
{
    public Money Add(
        Money other)
    {
        if (Currency !=
            other.Currency)
        {
            throw new InvalidOperationException(
                "Currencies must match.");
        }

        return new Money(
            Amount + other.Amount,
            Currency);
    }
}
C#
var first =
    new Money(
        100_000,
        "IRR");

var second =
    new Money(
        200_000,
        "IRR");

var result =
    first.Add(second);

Console.WriteLine(
    result.Amount);
// 300000

Validation در Record

در Positional Record می‌توان validation را نیز طراحی کرد، اما برای Domain Modelهای دارای invariantهای جدی گاهی syntax صریح‌تر خواناتر است.

C#
public record Money
{
    public decimal Amount
    {
        get;
    }

    public string Currency
    {
        get;
    }

    public Money(
        decimal amount,
        string currency)
    {
        if (amount < 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(amount));
        }

        if (string.IsNullOrWhiteSpace(
            currency))
        {
            throw new ArgumentException(
                "Currency is required.",
                nameof(currency));
        }

        Amount = amount;
        Currency = currency;
    }
}

Record و Inheritance

Record Class از inheritance پشتیبانی می‌کند، اما Record Class فقط می‌تواند از Record Class دیگری ارث ببرد.

C#
public record Payment(
    decimal Amount);

public record CardPayment(
    decimal Amount,
    string CardNumber)
    : Payment(Amount);

Equality در hierarchy مربوط به Recordها نیز type را در نظر می‌گیرد. یعنی صرفاً برابر بودن propertyها کافی نیست که objectهای دو Record Type متفاوت برابر باشند.

Record و Interface

Record می‌تواند مانند Class معمولی Interface پیاده‌سازی کند.

C#
public interface IHasAmount
{
    decimal Amount { get; }
}

public record Payment(
    decimal Amount,
    string Currency)
    : IHasAmount;

Record برای DTO

یکی از کاربردهای بسیار رایج Record، مدل‌کردن Request و Responseهای ساده است.

C#
public record CreatePaymentRequest(
    string CardNumber,
    decimal Amount);

public record CreatePaymentResponse(
    string TransactionId,
    bool IsSuccessful);

این مدل‌ها بیشتر «داده» را منتقل می‌کنند و Identity یا Lifecycle پیچیده‌ای ندارند؛ بنابراین syntax مختصر Record برای آن‌ها بسیار مناسب است.

Record برای Message و Event

در سیستم‌های Event-Driven نیز Record می‌تواند برای پیام‌های immutable-style انتخاب مناسبی باشد.

C#
public record PaymentCompleted(
    Guid TransactionId,
    decimal Amount,
    DateTimeOffset CompletedAt);

Event معمولاً بیانگر چیزی است که اتفاق افتاده و بهتر است بعد از ایجاد تغییر نکند. Record این intent را به شکل خوبی در کد نشان می‌دهد.

Record به‌عنوان Value Object

در Domain-Driven Design، Value Object با مقدارش شناخته می‌شود، نه با Identity. Record به دلیل Value Equality می‌تواند گزینهٔ بسیار مناسبی برای بسیاری از Value Objectها باشد.

C#
public record Money(
    decimal Amount,
    string Currency);
C#
var price1 =
    new Money(
        500_000,
        "IRR");

var price2 =
    new Money(
        500_000,
        "IRR");

Console.WriteLine(
    price1 == price2);
// True

از دید Domain، دو مقدار 500000 IRR یک مفهوم یکسان را بیان می‌کنند؛ مهم نیست دو instance متفاوت در حافظه باشند.

💡
این دقیقاً یکی از دلایلی است که Record برای Value Objectها جذاب است: Compiler بخش زیادی از Equality boilerplate را برای ما تولید می‌کند.

آیا Record برای Entity مناسب است؟

Record از نظر فنی می‌تواند برای مدل‌های مختلف استفاده شود، اما Value Equality پیش‌فرض آن همیشه با مفهوم Entity هماهنگ نیست. Entity معمولاً با Identity شناخته می‌شود، نه با تمام مقادیر Propertyهایش.

C#
public class Transaction
{
    public Guid Id
    {
        get;
    }

    public TransactionStatus Status
    {
        get;
        private set;
    }

    // Entity behavior...
}

برای Entityهای دارای Lifecycle و State متغیر، Class معمولی اغلب intent واضح‌تری دارد. Record بیشتر در DTOها، Commands، Events و Value Objectها می‌درخشد.

Record و Class چه شباهت‌هایی دارند؟

  • Record معمولی Reference Type است.
  • می‌تواند Property و Method داشته باشد.
  • می‌تواند Constructor داشته باشد.
  • می‌تواند Interface پیاده‌سازی کند.
  • می‌تواند inheritance داشته باشد، با قواعد مخصوص Recordها.
  • می‌تواند Mutable یا Immutable-style طراحی شود.

Record و Reference Assignment

با وجود Value Equality، فراموش نکنید که Record Class همچنان Reference Type است.

C#
var payment1 =
    new PaymentRequest(
        500_000,
        "IRR");

var payment2 =
    payment1;

Console.WriteLine(
    ReferenceEquals(
        payment1,
        payment2));
// True

Assignment یک Record Class نیز reference را کپی می‌کند. Value Equality به معنی Value Type بودن نیست.

⚠️
دو مفهوم را با هم اشتباه نکنید: Value Equality دربارهٔ نحوهٔ مقایسه است؛ Value Type دربارهٔ semantics نوع و نحوهٔ assignment/copy است. Record Class Value Equality دارد، اما همچنان Reference Type است.

مثال واقعی: Payment Result

C#
public record PaymentResult(
    bool IsSuccessful,
    string? TransactionId,
    string? ErrorCode)
{
    public static PaymentResult Success(
        string transactionId)
    {
        return new PaymentResult(
            true,
            transactionId,
            null);
    }

    public static PaymentResult Failed(
        string errorCode)
    {
        return new PaymentResult(
            false,
            null,
            errorCode);
    }
}
C#
var success =
    PaymentResult.Success(
        "TX-10001");

var failed =
    PaymentResult.Failed(
        "INVALID_CARD");

این type بیشتر نتیجهٔ یک عملیات را توصیف می‌کند و Identity مستقل ندارد. Record برای چنین مدل‌هایی خوانا، مختصر و مناسب است.

چه زمانی Record انتخاب مناسبی است؟

  • Equality بر اساس داده‌ها برایتان مهم است.
  • مدل بیشتر Data-oriented است.
  • DTO، Request یا Response می‌سازید.
  • Command یا Event مدل می‌کنید.
  • Value Object دارید.
  • Immutable-style design می‌خواهید.
  • استفاده از with برای ساخت نسخهٔ تغییر‌یافته مفید است.

چه زمانی Record را با احتیاط انتخاب کنیم؟

  • Object یک Entity با Identity مستقل است.
  • Lifecycle و تغییر State بخش اصلی مدل است.
  • اعضای mutable داخلی باعث می‌شوند تصور immutability اشتباه شود.
  • Value Equality تولیدشده با semantics واقعی Domain هماهنگ نیست.

اشتباهات رایج

  • تصور اینکه Record یک Value Type است.
  • تصور اینکه Record همیشه کاملاً Immutable است.
  • نادیده گرفتن Shallow Copy در with.
  • استفادهٔ خودکار از Record برای هر Entity فقط به دلیل syntax کوتاه‌تر.
  • اشتباه گرفتن Value Equality با Reference Equality.
  • قرار دادن collectionهای mutable داخل Record و انتظار immutability کامل.
🎯
قاعدهٔ ذهنی خوب: اگر object بیشتر با داده‌هایش تعریف می‌شود تا با Identity، و می‌خواهید دو نمونه با مقادیر یکسان برابر محسوب شوند، Record گزینه‌ای بسیار جدی است.

جمع‌بندی 13.3

Record در C# ابزاری قدرتمند برای مدل‌کردن داده‌های Value-based است. Record معمولی یک Reference Type است، اما برخلاف Class معمولی Value Equality دارد. Positional syntax، with expression، Deconstruction و ToString() مناسب از قابلیت‌های مهم آن هستند. Record به‌خصوص برای DTOها، Messages، Events و Value Objectها کاربرد زیادی دارد.

✅
نکتهٔ کلیدی: record را «Struct جدید» تصور نکنید. Record Class همچنان Reference Type است؛ تفاوت مهم آن با Class معمولی این است که Compiler رفتارهای Value-oriented مانند Equality را برای شما فراهم می‌کند.
