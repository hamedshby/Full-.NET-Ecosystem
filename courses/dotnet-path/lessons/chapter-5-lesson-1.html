مفهوم Inheritance در OOP

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Inheritance یا وراثت یکی از مفاهیم اصلی Object-Oriented Programming است. Inheritance اجازه می‌دهد یک class جدید بر اساس یک class موجود ساخته شود و اعضا و رفتارهای قابل‌ارث آن را دریافت کند. به این ترتیب می‌توان رفتار مشترک را در یک Base Class قرار داد و typeهای تخصصی‌تر را از روی آن ساخت.

💡
ایدهٔ اصلی Inheritance رابطهٔ Is-A است. برای مثال اگر SavingsAccount واقعاً نوعی BankAccount باشد، Inheritance می‌تواند گزینه‌ای قابل بررسی باشد.

یک مثال ساده

فرض کنید چند نوع حساب بانکی داریم که همه شماره حساب و موجودی دارند:

C#
public class BankAccount
{
    public string AccountNumber { get; }

    public decimal Balance { get; protected set; }

    public BankAccount(
        string accountNumber)
    {
        AccountNumber = accountNumber;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(
                nameof(amount));

        Balance += amount;
    }
}

حالا یک نوع تخصصی‌تر از حساب ایجاد می‌کنیم:

C#
public class SavingsAccount
    : BankAccount
{
    public decimal InterestRate { get; }

    public SavingsAccount(
        string accountNumber,
        decimal interestRate)
        : base(accountNumber)
    {
        InterestRate = interestRate;
    }
}

علامت : مشخص می‌کند SavingsAccount از BankAccount ارث‌بری می‌کند.

C#
var account = new SavingsAccount(
    "IR-1001",
    0.05m);

account.Deposit(1_000_000);

Console.WriteLine(account.AccountNumber);
Console.WriteLine(account.Balance);
Console.WriteLine(account.InterestRate);

با اینکه Deposit در SavingsAccount نوشته نشده، این class آن را از BankAccount به ارث برده است.

Base Class و Derived Class

در یک رابطهٔ Inheritance دو اصطلاح مهم داریم:

اصطلاح مثال معنی
Base Class BankAccount Class عمومی‌تر که رفتار و دادهٔ مشترک را تعریف می‌کند.
Derived Class SavingsAccount Class تخصصی‌تر که از Base Class ارث می‌برد.
C#
public class BankAccount
{
}

// SavingsAccount is a BankAccount
public class SavingsAccount
    : BankAccount
{
}

رابطهٔ Is-A

قبل از استفاده از Inheritance باید بتوانیم رابطه را به شکل «X یک Y است» بیان کنیم.

  • SavingsAccount یک BankAccount است.
  • CheckingAccount یک BankAccount است.

اما این رابطه را ببینید:

  • BankAccount یک Logger است؟ خیر.
  • Order یک Database است؟ خیر.

در چنین مواردی Inheritance فقط برای استفادهٔ مجدد از کد انتخاب مناسبی نیست.

⚠️
صرف اینکه دو class چند Method یا Property مشترک دارند دلیل کافی برای Inheritance نیست. رابطهٔ مفهومی و قابلیت جایگزینی Derived Type با Base Type اهمیت بیشتری دارد.

اعضای به‌ارث‌رسیده

Derived Class می‌تواند از اعضای قابل‌دسترسی Base Class استفاده کند. برای مثال اعضای public از طریق object مشتق‌شده قابل استفاده‌اند:

C#
public class BankAccount
{
    public string AccountNumber { get; set; }

    public void PrintAccount()
    {
        Console.WriteLine(AccountNumber);
    }
}

public class SavingsAccount
    : BankAccount
{
}
C#
var account = new SavingsAccount();

account.AccountNumber = "IR-1001";
account.PrintAccount();

private و Inheritance

اعضای private بخشی از پیاده‌سازی Base Class هستند، اما Derived Class نمی‌تواند مستقیماً با نام آن‌ها دسترسی داشته باشد.

C#
public class BankAccount
{
    private decimal _balance;
}

public class SavingsAccount
    : BankAccount
{
    public void Test()
    {
        // Compile Error
        // _balance = 100;
    }
}

اگر Base Class لازم بداند Derived Class به عضوی دسترسی داشته باشد، می‌توان از API مناسب یا در موارد لازم protected استفاده کرد.

protected در Inheritance

عضو protected از بیرون class عمومی نیست، اما Derived Class می‌تواند به آن دسترسی داشته باشد.

C#
public class BankAccount
{
    protected decimal Balance { get; set; }
}

public class SavingsAccount
    : BankAccount
{
    public void AddInterest()
    {
        Balance += Balance * 0.05m;
    }
}

کد بیرونی همچنان نمی‌تواند مستقیماً Balance را تغییر دهد، اما SavingsAccount به آن دسترسی دارد.

استفاده از base

کلمهٔ کلیدی base برای دسترسی به اعضا یا Constructor مربوط به Base Class استفاده می‌شود. یکی از رایج‌ترین کاربردها، فراخوانی Constructor والد است.

C#
public class BankAccount
{
    public string AccountNumber { get; }

    public BankAccount(
        string accountNumber)
    {
        AccountNumber = accountNumber;
    }
}

public class SavingsAccount
    : BankAccount
{
    public decimal InterestRate { get; }

    public SavingsAccount(
        string accountNumber,
        decimal interestRate)
        : base(accountNumber)
    {
        InterestRate = interestRate;
    }
}

عبارت base(accountNumber) Constructor مربوط به BankAccount را فراخوانی می‌کند.

ترتیب اجرای Constructorها

هنگام ساخت Derived Object، ابتدا Constructor مربوط به Base Class اجرا می‌شود و سپس Constructor مربوط به Derived Class.

C#
public class BankAccount
{
    public BankAccount()
    {
        Console.WriteLine(
            "BankAccount Constructor");
    }
}

public class SavingsAccount
    : BankAccount
{
    public SavingsAccount()
    {
        Console.WriteLine(
            "SavingsAccount Constructor");
    }
}
C#
var account =
    new SavingsAccount();

// BankAccount Constructor
// SavingsAccount Constructor

تخصصی‌کردن Derived Class

Derived Class فقط اعضای Base Class را دریافت نمی‌کند؛ می‌تواند قابلیت‌های مخصوص خودش را نیز داشته باشد.

C#
public class SavingsAccount
    : BankAccount
{
    public decimal InterestRate { get; }

    public SavingsAccount(
        string accountNumber,
        decimal interestRate)
        : base(accountNumber)
    {
        InterestRate = interestRate;
    }

    public decimal CalculateInterest()
    {
        return Balance * InterestRate;
    }
}

CalculateInterest رفتاری مخصوص Savings Account است و لازم نیست در همهٔ انواع حساب وجود داشته باشد.

virtual و override

گاهی Base Class یک رفتار عمومی دارد، اما Derived Class باید نسخهٔ تخصصی خودش را ارائه کند. برای این کار می‌توان Method را در Base Class با virtual تعریف و در Derived Class با override بازنویسی کرد.

C#
public class BankAccount
{
    public virtual decimal CalculateFee(
        decimal amount)
    {
        return amount * 0.01m;
    }
}

public class VipBankAccount
    : BankAccount
{
    public override decimal CalculateFee(
        decimal amount)
    {
        return amount * 0.005m;
    }
}
C#
var normal =
    new BankAccount();

var vip =
    new VipBankAccount();

Console.WriteLine(
    normal.CalculateFee(1_000_000));
// 10000

Console.WriteLine(
    vip.CalculateFee(1_000_000));
// 5000

این قابلیت یکی از پایه‌های Runtime Polymorphism است که در فصل Polymorphism با جزئیات بیشتری بررسی می‌شود.

Derived Object به‌عنوان Base Type

چون SavingsAccount یک BankAccount است، می‌توان object آن را در reference از نوع Base Class نگه داشت:

C#
BankAccount account =
    new SavingsAccount(
        "IR-1001",
        0.05m);

account.Deposit(500_000);

این ویژگی بسیار مهم است، چون اجازه می‌دهد کد با abstraction عمومی‌تر کار کند و typeهای تخصصی مختلف را بپذیرد.

Single Inheritance در C#

یک class در C# نمی‌تواند مستقیماً از چند class ارث ببرد. هر class فقط یک Base Class مستقیم دارد.

C#
public class BankAccount
{
}

public class SavingsAccount
    : BankAccount
{
}

چنین چیزی برای classها مجاز نیست:

C#
// Invalid
// public class SpecialAccount
//     : BankAccount, Customer
// {
// }

البته یک class می‌تواند در کنار Base Class چند Interface را implement کند؛ Interface با Multiple Class Inheritance یک مفهوم نیست.

مزایای Inheritance

  • مدل‌کردن رابطه Is-A: ارتباط typeهای عمومی و تخصصی را بیان می‌کند.
  • استفاده از رفتار مشترک: رفتار مناسب می‌تواند در Base Class قرار بگیرد.
  • Polymorphism: Derived Typeها می‌توانند از طریق Base Type استفاده شوند.
  • تخصصی‌سازی: Derived Class می‌تواند قابلیت‌های مخصوص خود را اضافه یا رفتارهای قابل override را تخصصی کند.

مشکلات استفادهٔ نادرست از Inheritance

Inheritance رابطهٔ نسبتاً قوی‌ای میان Base و Derived Class ایجاد می‌کند. اگر طراحی اشتباه باشد، تغییر Base Class می‌تواند تعداد زیادی Derived Class را تحت تأثیر قرار دهد.

  • ایجاد Tight Coupling میان Base و Derived Class
  • ساختن hierarchyهای عمیق و سخت‌فهم
  • وابستگی Derived Class به جزئیات Base Class
  • استفاده از Inheritance فقط برای Code Reuse
  • سخت‌ترشدن تغییر رفتار در آینده
⚠️
Inheritance ابزار قدرتمندی است، اما نباید انتخاب پیش‌فرض برای Code Reuse باشد. در بسیاری از طراحی‌ها Composition انعطاف بیشتری ایجاد می‌کند.

Inheritance یا Composition؟

Inheritance معمولاً رابطهٔ Is-A را مدل می‌کند، در حالی که Composition بیشتر رابطهٔ Has-A را نمایش می‌دهد.

Inheritance Composition
SavingsAccount is a BankAccount Order has a PaymentService
رابطهٔ قوی‌تر میان Typeها معمولاً Coupling کمتر و انعطاف بیشتر
مناسب برای hierarchy واقعی مناسب برای ترکیب رفتارها و dependencyها

مثال کامل

C#
public class BankAccount
{
    public string AccountNumber { get; }

    public decimal Balance { get; protected set; }

    public BankAccount(
        string accountNumber)
    {
        if (string.IsNullOrWhiteSpace(
            accountNumber))
        {
            throw new ArgumentException(
                "Account number is required.",
                nameof(accountNumber));
        }

        AccountNumber = accountNumber;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(amount));
        }

        Balance += amount;
    }

    public virtual decimal CalculateFee(
        decimal amount)
    {
        return amount * 0.01m;
    }
}

public class SavingsAccount
    : BankAccount
{
    public decimal InterestRate { get; }

    public SavingsAccount(
        string accountNumber,
        decimal interestRate)
        : base(accountNumber)
    {
        InterestRate = interestRate;
    }

    public decimal CalculateInterest()
    {
        return Balance * InterestRate;
    }
}

public class VipBankAccount
    : BankAccount
{
    public VipBankAccount(
        string accountNumber)
        : base(accountNumber)
    {
    }

    public override decimal CalculateFee(
        decimal amount)
    {
        return amount * 0.005m;
    }
}
C#
var savings =
    new SavingsAccount(
        "IR-1001",
        0.05m);

savings.Deposit(1_000_000);

Console.WriteLine(
    savings.CalculateInterest());

BankAccount vip =
    new VipBankAccount(
        "IR-2001");

Console.WriteLine(
    vip.CalculateFee(1_000_000));

SavingsAccount و VipBankAccount هر دو نوعی BankAccount هستند. رفتار مشترک مانند Deposit در Base Class قرار دارد، در حالی که هر Derived Class می‌تواند قابلیت یا رفتار تخصصی خودش را داشته باشد.

✅
خلاصه: Inheritance زمانی مناسب است که بین typeها یک رابطهٔ واقعی Is-A وجود داشته باشد. Base Class رفتار و قرارداد عمومی را ارائه می‌کند و Derived Class آن را تخصصی می‌کند. از Inheritance فقط برای حذف چند خط کد تکراری استفاده نکنید؛ ابتدا مطمئن شوید رابطهٔ مفهومی میان typeها واقعاً درست است.
