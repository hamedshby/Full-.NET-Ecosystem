آشنایی با Methods در C#

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در طراحی شی‌گرا، object فقط داده نگه نمی‌دارد؛ باید بتواند رفتارهایی نیز انجام دهد. در C# این رفتارها معمولاً با Method تعریف می‌شوند. برای مثال یک حساب بانکی می‌تواند عملیات واریز، برداشت و محاسبهٔ موجودی را انجام دهد.

💡
اگر Field و Property معمولاً State یک object را نمایش دهند، Method معمولاً Behavior آن object را بیان می‌کند. نام Method بهتر است نشان دهد object چه کاری انجام می‌دهد؛ مانند Deposit، Withdraw یا CalculateFee.

ساختار یک Method

C#
public decimal CalculateFee(decimal amount)
{
    return amount * 0.01m;
}
بخش مثال کاربرد
Access Modifier public سطح دسترسی Method
Return Type decimal نوع مقداری که Method برمی‌گرداند
Method Name CalculateFee نام رفتار
Parameter decimal amount ورودی موردنیاز Method
Body { ... } منطق Method

Instance Method

Instance Method به یک instance مشخص از class تعلق دارد و می‌تواند مستقیماً به State همان object دسترسی داشته باشد. برای فراخوانی آن ابتدا باید یک object داشته باشیم.

C#
public class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}
C#
var account1 = new BankAccount();
var account2 = new BankAccount();

account1.Deposit(100_000);
account2.Deposit(500_000);

Console.WriteLine(account1.Balance); // 100000
Console.WriteLine(account2.Balance); // 500000

متد Deposit روی object مشخص اجرا می‌شود؛ بنابراین فراخوانی آن روی account1، State مربوط به account2 را تغییر نمی‌دهد.

Static Method

Static Method به خود class تعلق دارد، نه به یک instance مشخص. بنابراین معمولاً آن را با نام class فراخوانی می‌کنیم.

C#
public class BankAccount
{
    public static bool IsValidAmount(decimal amount)
    {
        return amount > 0;
    }
}
C#
bool result = BankAccount.IsValidAmount(100_000);

Console.WriteLine(result); // True

Static Method نمی‌تواند بدون داشتن یک instance به اعضای instance دسترسی مستقیم داشته باشد.

Instance Method Static Method
به یک object تعلق دارد. به خود class تعلق دارد.
به Instance State دسترسی مستقیم دارد. به Instance State دسترسی مستقیم ندارد.
account.Deposit(...) BankAccount.IsValidAmount(...)

Method Parameters

Parameter اطلاعاتی است که Method برای انجام کار خود دریافت می‌کند. یک Method می‌تواند بدون Parameter، با یک Parameter یا با چند Parameter تعریف شود.

C#
public void Transfer(
    BankAccount destination,
    decimal amount,
    string description)
{
    // Transfer logic
}

هنگام فراخوانی Method، مقادیر واقعی ارسال‌شده Argument نامیده می‌شوند:

C#
sourceAccount.Transfer(
    destinationAccount,
    500_000,
    "Invoice payment");
💡
در تعریف Method به amount می‌گوییم Parameter؛ در فراخوانی، مقدار 500_000 یک Argument است.

Return Value

اگر Method قرار است نتیجه‌ای به فراخواننده برگرداند، نوع نتیجه قبل از نام Method مشخص می‌شود و معمولاً از return برای بازگرداندن آن استفاده می‌کنیم.

C#
public decimal CalculateFee(decimal amount)
{
    decimal fee = amount * 0.01m;

    return fee;
}
C#
decimal fee = account.CalculateFee(1_000_000);

Console.WriteLine(fee); // 10000

اگر Method چیزی برنمی‌گرداند، Return Type آن void است:

C#
public void Deposit(decimal amount)
{
    Balance += amount;
}

Method Overloading

در C# می‌توان چند Method با نام یکسان اما Parameter List متفاوت تعریف کرد. به این قابلیت Method Overloading گفته می‌شود.

C#
public class BankAccount
{
    public void Deposit(decimal amount)
    {
        // Deposit
    }

    public void Deposit(decimal amount, string description)
    {
        // Deposit with description
    }

    public void Deposit(decimal amount, string description, DateTime date)
    {
        // Deposit with description and date
    }
}
C#
account.Deposit(100_000);

account.Deposit(
    100_000,
    "Salary");

account.Deposit(
    100_000,
    "Salary",
    DateTime.UtcNow);
⚠️
تفاوت فقط در Return Type برای Overloading کافی نیست. Compiler باید بتواند نسخهٔ مناسب Method را از روی Parameterها تشخیص دهد.

Optional Parameters

می‌توان برای Parameter مقدار پیش‌فرض تعریف کرد. در این صورت هنگام فراخوانی Method، ارسال آن Argument اختیاری است. Optional Parameterها باید بعد از Parameterهای اجباری قرار بگیرند.

C#
public void Deposit(
    decimal amount,
    string description = "Deposit")
{
    // Deposit logic
}

هر دو فراخوانی معتبر هستند:

C#
account.Deposit(500_000);

account.Deposit(
    500_000,
    "Salary");

در فراخوانی اول مقدار پیش‌فرض "Deposit" برای description استفاده می‌شود.

Named Parameters

به‌طور معمول Argumentها بر اساس ترتیب Parameterها ارسال می‌شوند. با Named Argument می‌توان نام Parameter را هنگام فراخوانی مشخص کرد.

C#
public void Transfer(
    decimal amount,
    string description,
    bool sendNotification)
{
    // Transfer logic
}
C#
account.Transfer(
    amount: 500_000,
    description: "Invoice payment",
    sendNotification: true);

Named Arguments مخصوصاً برای Parameterهای Boolean یا Methodهایی با چند ورودی می‌توانند خوانایی فراخوانی را بیشتر کنند.

ref

به‌طور معمول Parameterهای Value Type مانند int و decimal به‌صورت value ارسال می‌شوند. با ref می‌توان اجازه داد Method مستقیماً متغیر فراخواننده را تغییر دهد.

C#
public static void AddBonus(
    ref decimal amount)
{
    amount += 10_000;
}
C#
decimal amount = 100_000;

AddBonus(ref amount);

Console.WriteLine(amount); // 110000

متغیری که با ref ارسال می‌شود باید قبل از فراخوانی Method مقداردهی شده باشد و کلمهٔ ref هم در تعریف و هم در فراخوانی نوشته شود.

out

out نیز اجازه می‌دهد Method مقداری را از طریق Parameter به بیرون منتقل کند؛ اما برخلاف ref لازم نیست متغیر قبل از فراخوانی مقدار داشته باشد. Method موظف است قبل از پایان، برای out Parameter مقدار تعیین کند.

C#
public static bool TryGetFee(
    decimal amount,
    out decimal fee)
{
    if (amount <= 0)
    {
        fee = 0;
        return false;
    }

    fee = amount * 0.01m;

    return true;
}
C#
if (TryGetFee(1_000_000, out decimal fee))
{
    Console.WriteLine(fee);
}

الگوی Try... یکی از کاربردهای شناخته‌شدهٔ out در .NET است؛ نمونهٔ معروف آن int.TryParse است.

in

Parameter با in به‌صورت reference ارسال می‌شود، اما Method اجازه ندارد آن Parameter را به مقدار دیگری assign کند. بنابراین in یک reference ورودیِ فقط‌خواندنی برای Parameter ایجاد می‌کند.

C#
public readonly struct TransferRequest
{
    public decimal Amount { get; init; }
    public int DestinationId { get; init; }
}

public static void Validate(
    in TransferRequest request)
{
    Console.WriteLine(request.Amount);

    // Compile Error
    // request = new TransferRequest();
}

in به‌خصوص برای structهای بزرگ می‌تواند مفید باشد؛ چون امکان ارسال با reference را فراهم می‌کند بدون اینکه Method اجازهٔ assign کردن مقدار جدید به Parameter داشته باشد.

تفاوت ref، out و in

ویژگی ref out in
نیاز به مقداردهی قبل از فراخوانی بله خیر بله
Method می‌تواند مقدار جدید assign کند بله بله، و باید مقداردهی کند خیر
هدف اصلی خواندن و تغییر مقدار موجود برگرداندن مقدار از Method ارسال Reference فقط‌خواندنی
⚠️
از ref و out فقط زمانی استفاده کنید که واقعاً طراحی Method به آن نیاز دارد. تغییر متغیر فراخواننده از داخل Method می‌تواند دنبال‌کردن جریان داده را سخت‌تر کند. در بسیاری از سناریوها Return Value یا یک Result Object خواناتر است.

مثال کامل

C#
public class BankAccount
{
    public decimal Balance { get; private set; }

    // Instance Method
    public void Deposit(
        decimal amount,
        string description = "Deposit")
    {
        if (!IsValidAmount(amount))
            throw new ArgumentOutOfRangeException(
                nameof(amount));

        Balance += amount;

        Console.WriteLine(description);
    }

    // Return Value
    public decimal CalculateFee(decimal amount)
    {
        return amount * 0.01m;
    }

    // Method Overloading
    public void Withdraw(decimal amount)
    {
        Withdraw(amount, "Withdrawal");
    }

    public void Withdraw(
        decimal amount,
        string description)
    {
        if (amount > Balance)
            throw new InvalidOperationException(
                "Insufficient balance.");

        Balance -= amount;

        Console.WriteLine(description);
    }

    // Static Method
    public static bool IsValidAmount(
        decimal amount)
    {
        return amount > 0;
    }
}
C#
var account = new BankAccount();

account.Deposit(1_000_000);

account.Deposit(
    amount: 500_000,
    description: "Salary");

decimal fee =
    account.CalculateFee(500_000);

account.Withdraw(200_000);

account.Withdraw(
    100_000,
    "Online purchase");

Console.WriteLine(account.Balance);
Console.WriteLine(fee);
✅
یک Method خوب فقط مجموعه‌ای از دستورات نیست؛ باید یک رفتار مشخص و قابل‌فهم را بیان کند. Parameterها ورودی رفتار را مشخص می‌کنند، Return Value نتیجه را برمی‌گرداند و قابلیت‌هایی مانند Overloading، Optional و Named Parameters کمک می‌کنند API کلاس خواناتر و مناسب‌تر طراحی شود.
