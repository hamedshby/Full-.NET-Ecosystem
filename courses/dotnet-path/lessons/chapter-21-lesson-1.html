🧠 Domain-Driven Design

Domain Model

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Domain Model نمایش مفاهیم، Ruleها، رفتارها و رابطه‌های اصلی Business در کد است. در DDD هدف فقط ساخت Classهایی شبیه Tableهای Database نیست؛ هدف این است که زبان واقعی Business در مدل دیده شود.

💡
در Payment Domain، مفاهیمی مثل Payment، Money، Merchant، Refund، Settlement و PaymentStatus اجزای طبیعی Domain Model هستند.

مدل ضعیف

C#
public class Payment
{
    public Guid Id { get; set; }
    public decimal Amount { get; set; }
    public string Status { get; set; }
}

این Class فقط Data حمل می‌کند و Business Rule را نشان نمی‌دهد.

مدل غنی‌تر

C#
public class Payment
{
    public Guid Id { get; }
    public Money Amount { get; }
    public PaymentStatus Status { get; private set; }

    public void MarkAsPaid()
    {
        if (Status != PaymentStatus.Pending)
            throw new InvalidOperationException();

        Status = PaymentStatus.Paid;
    }
}

Domain Model چه چیزی را شامل می‌شود؟

  • Entity
  • Value Object
  • Aggregate
  • Domain Service
  • Domain Event
  • Invariant

Domain Model و Database Model

⚠️
DDD نمی‌گوید هر Table الزاماً یک Entity و هر Column الزاماً یک Property در Domain باشد.

نکته مصاحبه‌ای

🎤
A domain model represents business concepts, rules, and behaviors rather than merely mirroring database tables.

جمع‌بندی

Domain Model باید زبان Business را در Code بیان کند و محل اصلی Business Ruleهای پیچیده باشد.
