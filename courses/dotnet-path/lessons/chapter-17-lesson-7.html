🧩 Coupling و Cohesion

17.7 — چگونه Coupling را کاهش دهیم؟

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

کاهش Coupling یعنی Dependencyهای غیرضروری را حذف و Dependencyهای ضروری را از طریق مرزهای واضح مدیریت کنیم.

💡
هدف Zero Coupling نیست؛ هدف محدود کردن اثر تغییرات است.

1. وابستگی به Abstraction

C#
// Tight
SqlPaymentRepository repository;

// Better boundary
IPaymentRepository repository;

2. Dependency Injection

C#
public PaymentService(
    IPaymentRepository repository)
{
    _repository = repository;
}

3. Interfaceهای متمرکز

Client فقط به Capability مورد نیاز خودش وابسته باشد؛ این همان ایده ISP است.

4. Separation of Concerns

Text
PaymentService
 ├─ Validation
 ├─ SQL
 ├─ RabbitMQ
 └─ Email

       ↓

PaymentValidator
PaymentRepository
EventPublisher
PaymentNotifier

5. Encapsulation

جزئیات داخلی Component را مخفی کنید و فقط API لازم را expose کنید.

6. Event-Driven در جای مناسب

Text
Payment → PaymentCompleted
              ├─► Reporting
              └─► Notification
⚠️
Messaging Coupling را صفر نمی‌کند و Complexityهایی مثل Retry، Idempotency و Eventual Consistency دارد.

7. Shared Database را محدود کنید

Ownership داده را واضح نگه دارید تا Schema Change یک Service، Consumerهای دیگر را نشکند.

8. Stable Contract

Contract باید نیاز Consumer را بیان کند و Detailهای Provider را Leak نکند.

9. DTO مستقل در Boundary

Entity داخلی یا EF Model را بی‌دلیل به API Consumerها expose نکنید.

10. Interface Count معیار نیست

⚠️
ساخت Interface برای هر Class به‌صورت خودکار Coupling را کاهش نمی‌دهد.

Checklist

  • آیا Business Logic Concrete Detail را می‌شناسد؟
  • آیا تغییر Infrastructure Business Logic را تغییر می‌دهد؟
  • آیا Client Method غیرضروری می‌بیند؟
  • آیا Contract Detail Provider را Leak می‌کند؟
  • آیا Dependency قابل جایگزینی و تست است؟

نکته مصاحبه‌ای

🎤
To reduce coupling, use clear boundaries, focused abstractions, Dependency Injection, encapsulation, stable contracts, and asynchronous messaging where appropriate.

جمع‌بندی

کاهش Coupling نتیجه طراحی درست Dependencyها و Boundaryهاست، نه صرفاً اضافه کردن Interface.
