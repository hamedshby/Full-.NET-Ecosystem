21.11 — Invariant چیست؟

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Invariant Business Ruleای است که باید همیشه در یک Consistency Boundary معتبر بماند.

💡
مثال: مجموع Refundهای یک Payment نباید از Amount اصلی بیشتر شود.

Invariantهای Payment

  • Amount باید مثبت باشد.
  • Refund ≤ Payment Amount
  • Settled Payment قابل Cancel نیست.
  • Capture فقط بعد از Authorization مجاز است.

مثال Refund

C#
public void RequestRefund(
    Money amount)
{
    var refundedAmount =
        _refunds.Sum(
            x => x.Amount.Amount);

    if (refundedAmount + amount.Amount
        > Amount.Amount)
    {
        throw new InvalidOperationException(
            "Refund exceeds payment amount.");
    }

    _refunds.Add(
        Refund.Create(
            Guid.NewGuid(),
            amount));
}

Validation vs Invariant

Validation Invariant
ممکن است Input-level باشد Business Rule اصلی
مثلاً فرمت Mobile Refund ≤ Payment Amount
ممکن است در API باشد باید داخل Domain محافظت شود
⚠️
FluentValidation جای Invariant داخل Domain را نمی‌گیرد. Domain باید بدون توجه به مسیر ورود داده معتبر بماند.

جمع‌بندی

Aggregate را طوری طراحی می‌کنیم که Invariantهایش قابل دور زدن نباشند.
