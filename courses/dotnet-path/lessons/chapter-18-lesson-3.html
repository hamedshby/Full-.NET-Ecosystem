🏗️ اصول طراحی Object-Oriented

18.3 — Favor Immutability

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Favor Immutability یعنی وقتی Object بعد از ساخته‌شدن نیازی به تغییر ندارد، ترجیح بدهیم State آن ثابت بماند.

💡
Immutable Object بعد از ایجاد، State قابل مشاهدهٔ خود را تغییر نمی‌دهد. این موضوع Reasoning دربارهٔ کد را ساده‌تر می‌کند.

Mutable Object

C#
public class Money
{
    public decimal Amount { get; set; }
    public string Currency { get; set; } = string.Empty;
}

هر بخش از برنامه که Reference این Object را داشته باشد می‌تواند State آن را تغییر دهد.

نسخه Immutable با Record

C#
public sealed record Money(
    decimal Amount,
    string Currency);

ایجاد مقدار جدید به‌جای تغییر مقدار قبلی

C#
var price =
    new Money(100_000, "IRR");

var discountedPrice =
    price with
    {
        Amount = 90_000
    };

price تغییر نمی‌کند؛ یک Value جدید ساخته می‌شود.

مزایا

  • کاهش Side Effect
  • Reasoning ساده‌تر
  • اشتراک امن‌تر داده بین بخش‌ها
  • مناسب برای Value Objectها
  • کاهش برخی مشکلات Concurrency

مثال Payment Request

C#
public sealed record PaymentRequest(
    Guid TransactionId,
    decimal Amount,
    string MerchantId);

Request پس از ساخته‌شدن نباید در میانهٔ Pipeline توسط Componentهای مختلف تغییر کند.

Immutability همیشه مطلق نیست

Entityهای Domain معمولاً State دارند و رفتارشان State را تغییر می‌دهد؛ مثلاً Payment می‌تواند از Pending به Succeeded برود. در چنین مواردی Encapsulation تغییر State مهم‌تر از Immutable کردن اجباری Entity است.

C#
public class Payment
{
    public PaymentStatus Status { get; private set; }

    public void MarkAsSucceeded()
    {
        if (Status != PaymentStatus.Pending)
            throw new InvalidOperationException();

        Status = PaymentStatus.Succeeded;
    }
}
⚠️
Favor Immutability به معنی «همه چیز را record کن» نیست. Value Object، Message، Configuration و Snapshotها معمولاً کاندیدای بهتری هستند؛ Entityهای Stateful ممکن است Mutation کنترل‌شده داشته باشند.

نکته مصاحبه‌ای

🎤
Immutability reduces uncontrolled state changes and side effects, which makes code easier to reason about and safer in many concurrent scenarios.

جمع‌بندی

اگر State نیازی به تغییر ندارد، آن را قابل تغییر نکنید. اگر تغییر لازم است، Mutation را از طریق Behaviorهای کنترل‌شده انجام دهید.
