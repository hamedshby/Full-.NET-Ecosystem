🏭 Creational Design Patterns

Abstract Factory

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Abstract Factory یکی از Creational Design Patternهای کلاسیک GoF است. این Pattern برای ساخت یک خانواده از Objectهای مرتبط استفاده می‌شود، بدون اینکه Consumer Concrete Classهای آن خانواده را بشناسد.

💡
Factory Method معمولاً روی ساخت یک Product تمرکز دارد؛ Abstract Factory برای ساخت چند Product مرتبط و سازگار با هم استفاده می‌شود.

سناریوی Payment System

فرض کنید سیستم پرداخت با دو Provider کار می‌کند: Bank A و Bank B. هر Provider سه قابلیت مرتبط دارد:

  • Payment Gateway
  • Refund Gateway
  • Settlement Gateway
Text
Bank A Family
    ├── BankAPaymentGateway
    ├── BankARefundGateway
    └── BankASettlementGateway

Bank B Family
    ├── BankBPaymentGateway
    ├── BankBRefundGateway
    └── BankBSettlementGateway

مشکل بدون Abstract Factory

C#
public class PaymentOperationService
{
    public async Task ExecuteAsync()
    {
        var paymentGateway =
            new BankAPaymentGateway();

        var refundGateway =
            new BankARefundGateway();

        var settlementGateway =
            new BankASettlementGateway();

        // ...
    }
}

Consumer حالا همه Concrete Productهای Bank A را می‌شناسد.

ترکیب اشتباه Familyها

C#

    new BankAPaymentGateway();

    new BankBRefundGateway();

    new BankASettlementGateway();
⚠️
Abstract Factory کمک می‌کند Productهای متعلق به یک Provider به‌صورت یک Family سازگار ساخته شوند و احتمال ترکیب ناسازگار کاهش پیدا کند.

تعریف Abstract Factory

C#
public interface IPaymentProviderFactory
{
    IPaymentGateway CreatePaymentGateway();

    IRefundGateway CreateRefundGateway();

    ISettlementGateway CreateSettlementGateway();
}

این Interface همان Abstract Factory است. هر Method یک Product از همان Family می‌سازد.

Concrete Factory برای Bank A

C#
public class BankAProviderFactory
    : IPaymentProviderFactory
{
    public IPaymentGateway CreatePaymentGateway()
        => new BankAPaymentGateway();

    public IRefundGateway CreateRefundGateway()
        => new BankARefundGateway();

    public ISettlementGateway CreateSettlementGateway()
        => new BankASettlementGateway();
}

Concrete Factory برای Bank B

C#
public class BankBProviderFactory
    : IPaymentProviderFactory
{
    public IPaymentGateway CreatePaymentGateway()
        => new BankBPaymentGateway();

    public IRefundGateway CreateRefundGateway()
        => new BankBRefundGateway();

    public ISettlementGateway CreateSettlementGateway()
        => new BankBSettlementGateway();
}

ساختار Pattern

Text
                IPaymentProviderFactory
                  /                 \
                 /                   \
     BankAProviderFactory     BankBProviderFactory
            |                       |
    +-------+-------+       +-------+-------+
    |       |       |       |       |       |
    v       v       v       v       v       v
Payment  Refund Settlement Payment Refund Settlement
Gateway  Gateway  Gateway  Gateway Gateway  Gateway

Each factory creates one compatible family.

استفاده در Application Service

C#
public class PaymentOperationService
{
    private readonly IPaymentProviderFactory
        _factory;

    public PaymentOperationService(
        IPaymentProviderFactory factory)
    {
        _factory = factory;
    }

    public async Task ExecuteAsync(
        PaymentRequest paymentRequest,
        RefundRequest refundRequest,
        SettlementRequest settlementRequest,
        CancellationToken cancellationToken)
    {
        var paymentGateway =
            _factory.CreatePaymentGateway();

        var refundGateway =
            _factory.CreateRefundGateway();

        var settlementGateway =
            _factory.CreateSettlementGateway();

        await paymentGateway.PayAsync(
            paymentRequest,
            cancellationToken);

        await refundGateway.RefundAsync(
            refundRequest,
            cancellationToken);

        await settlementGateway.SettleAsync(
            settlementRequest,
            cancellationToken);
    }
}
🎯
Abstract Factory = Create a family of related products without exposing their concrete classes.

چرا Family در Payment مهم است؟

Productهای یک Provider معمولاً Configuration و Integration Contractهای مشترک دارند:

  • Base URL
  • Authentication
  • Certificate / API Key
  • Timeout و Retry Policy
  • Error Mapping
  • Serialization Format

مثال Configuration مشترک

C#
public sealed class BankAOptions
{
    public required string BaseUrl { get; init; }

    public required string ApiKey { get; init; }
}
C#
public class BankAProviderFactory
    : IPaymentProviderFactory
{
    private readonly BankAOptions _options;

    public BankAProviderFactory(
        BankAOptions options)
    {
        _options = options;
    }

    public IPaymentGateway CreatePaymentGateway()
        => new BankAPaymentGateway(_options);

    public IRefundGateway CreateRefundGateway()
        => new BankARefundGateway(_options);

    public ISettlementGateway CreateSettlementGateway()
        => new BankASettlementGateway(_options);
}

Factory Method vs Abstract Factory

Factory Method Abstract Factory
معمولاً یک Product یک Family از Productهای مرتبط
اغلب با Inheritance/Override اغلب با Composition و چند Creation Method
تمرکز بر اینکه چه Productی ساخته شود تمرکز بر سازگاری Productهای یک Family
CreatePaymentGateway() Payment + Refund + Settlement

نکته مهم

خود Abstract Factory معمولاً شامل چند Factory Method است:

C#
public interface IPaymentProviderFactory
{
    IPaymentGateway CreatePaymentGateway();

    IRefundGateway CreateRefundGateway();

    ISettlementGateway CreateSettlementGateway();
}

سناریوی Multi-Tenant

هر Merchant می‌تواند یک Family کامل از Integrationهای Provider خودش داشته باشد.

مزایا

  • کاهش Coupling به Concrete Productها
  • حفظ Consistency بین Productهای Family
  • تعویض کل Family با Factory دیگر
  • هماهنگی با OCP و DIP
  • متمرکز شدن Creation و Configuration هر Provider

معایب

  • افزایش تعداد Interface و Class
  • Complexity بیشتر نسبت به Factory ساده
  • اضافه کردن Product Type جدید به تمام Familyها پرهزینه است

Trade-off مهم

C#
public interface IPaymentProviderFactory
{
    IPaymentGateway CreatePaymentGateway();
    IRefundGateway CreateRefundGateway();
    ISettlementGateway CreateSettlementGateway();

    // New product type
    IChargebackGateway CreateChargebackGateway();
}

با اضافه شدن Chargeback، همه Concrete Factoryها باید تغییر کنند.

⚠️
Abstract Factory اضافه کردن Family جدید را آسان می‌کند، اما اضافه کردن Product Type جدید به همه Familyها معمولاً هزینه‌بر است.

چه زمانی استفاده کنیم؟

  • چند Provider داریم.
  • هر Provider چند Product مرتبط دارد.
  • Productهای هر Provider باید با هم سازگار باشند.
  • می‌خواهیم کل Family قابل تعویض باشد.

چه زمانی استفاده نکنیم؟

  • فقط یک Product داریم.
  • فقط یک Implementation ثابت داریم.
  • Productها Family واقعی تشکیل نمی‌دهند.
  • DI ساده مسئله را حل می‌کند.

پاسخ کوتاه مصاحبه‌ای

🎤
Abstract Factory provides an interface for creating families of related objects without exposing their concrete classes. In a payment system, one factory can create the payment, refund, and settlement gateways for Bank A, while another factory creates the compatible family for Bank B.

جمع‌بندی 20.2

Abstract Factory زمانی مناسب است که چند Family از Productهای مرتبط داریم. در Payment System، هر Bank می‌تواند Family مخصوص خودش شامل Payment، Refund و Settlement Gateway داشته باشد.

✅
نکته کلیدی: Factory Method روی ساخت یک Product تمرکز دارد؛ Abstract Factory روی ساخت یک Family of Related Products.
