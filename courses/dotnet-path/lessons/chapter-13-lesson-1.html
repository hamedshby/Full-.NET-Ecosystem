13.1 — Class

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در C#، class یکی از اصلی‌ترین ابزارها برای مدل‌کردن مفاهیم در برنامه‌های شی‌گرا است. Class یک Reference Type است و می‌تواند State و Behavior یک مفهوم را در کنار هم قرار دهد. برای مثال در یک سیستم بانکی، مفاهیمی مانند Customer، BankAccount و Transaction می‌توانند با Class مدل شوند.

💡
Class را می‌توان یک تعریف یا Blueprint در نظر گرفت و Object را instance ساخته‌شده از آن Class. یک Class می‌تواند مشخص کند object چه اطلاعاتی دارد و چه رفتارهایی می‌تواند انجام دهد.

Class چیست؟

Class یک User-Defined Reference Type است که می‌تواند اعضایی مانند Field، Property، Method و Constructor داشته باشد.

C#
public class BankAccount
{
    public string AccountNumber
    {
        get;
        set;
    }

    public decimal Balance
    {
        get;
        private set;
    }

    public void Deposit(
        decimal amount)
    {
        Balance += amount;
    }
}

در این مثال BankAccount یک Class است که هم اطلاعات حساب را نگهداری می‌کند و هم رفتار مربوط به حساب را ارائه می‌دهد.

ساخت Object از Class

تعریف Class به‌تنهایی به معنی ساخت object نیست. برای ساخت یک instance معمولاً از new استفاده می‌کنیم.

C#
var account =
    new BankAccount();

اکنون account یک متغیر Reference Type است که به یک instance از BankAccount اشاره می‌کند.

C#
account.AccountNumber =
    "100-200-300";

account.Deposit(
    500_000);

Console.WriteLine(
    account.Balance);
// 500000

State و Behavior در Class

یکی از مهم‌ترین کاربردهای Class این است که State و Behavior مرتبط را در یک واحد منطقی کنار هم قرار دهد.

State

State وضعیت فعلی object را نشان می‌دهد و معمولاً با Fieldها و Propertyها نگهداری می‌شود.

C#
public string AccountNumber
{
    get;
    set;
}

public decimal Balance
{
    get;
    private set;
}

Behavior

Behavior کارهایی است که object می‌تواند انجام دهد و معمولاً با Methodها مدل می‌شود.

C#
public void Deposit(
    decimal amount)
{
    Balance += amount;
}

در طراحی شی‌گرای مناسب، Methodها فقط عملیات تصادفی نیستند؛ آن‌ها معمولاً رفتار مرتبط با State همان object را بیان می‌کنند.

Class یک Reference Type است

یکی از مهم‌ترین ویژگی‌های Class در C# این است که Classها Reference Type هستند. متغیری که یک object را نگه می‌دارد، در واقع reference مربوط به آن object را در اختیار دارد.

C#
var account1 =
    new BankAccount();

account1.AccountNumber =
    "1001";

var account2 =
    account1;

در اینجا object جدیدی برای account2 ساخته نشده است. هر دو متغیر به همان instance اشاره می‌کنند.

C#
account2.Deposit(
    500_000);

Console.WriteLine(
    account1.Balance);
// 500000
⚠️
Assignment یک Class باعث clone شدن object نمی‌شود. مقدار reference کپی می‌شود؛ بنابراین چند متغیر می‌توانند به یک object مشترک اشاره کنند.

Reference Assignment

مثال زیر را دقیق بررسی کنید:

C#
var customer1 =
    new Customer
    {
        Name = "Hamed"
    };

var customer2 =
    customer1;

customer2.Name =
    "Ali";

Console.WriteLine(
    customer1.Name);
// Ali

چون customer1 و customer2 به یک object اشاره می‌کنند، تغییر State از طریق یکی از referenceها از طریق reference دیگر نیز قابل مشاهده است.

Text
customer1 ──────┐
                │
                ▼
          ┌──────────────┐
          │   Customer   │
          │ Name = "Ali" │
          └──────────────┘
                ▲
                │
customer2 ──────┘

هر new می‌تواند یک Instance جدید بسازد

C#
var customer1 =
    new Customer
    {
        Name = "Hamed"
    };

var customer2 =
    new Customer
    {
        Name = "Hamed"
    };

با وجود یکسان بودن مقادیر، اینجا دو instance مستقل ساخته شده‌اند.

C#
Console.WriteLine(
    ReferenceEquals(
        customer1,
        customer2));
// False

Constructor در Class

Class می‌تواند Constructor داشته باشد تا هنگام ساخت object، State اولیه معتبر ایجاد شود.

C#
public class BankAccount
{
    public string AccountNumber
    {
        get;
    }

    public decimal Balance
    {
        get;
        private set;
    }

    public BankAccount(
        string accountNumber,
        decimal initialBalance)
    {
        if (string.IsNullOrWhiteSpace(
            accountNumber))
        {
            throw new ArgumentException(
                "Account number is required.",
                nameof(accountNumber));
        }

        if (initialBalance < 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(initialBalance));
        }

        AccountNumber =
            accountNumber;

        Balance =
            initialBalance;
    }
}
C#
var account =
    new BankAccount(
        "100-200-300",
        1_000_000);

Constructor کمک می‌کند object از همان لحظهٔ ساخته‌شدن در وضعیت معتبر قرار بگیرد.

Mutable Class

اگر State یک object بعد از ساخته‌شدن قابل تغییر باشد، آن object Mutable است.

C#
public class Customer
{
    public string Name
    {
        get;
        set;
    }
}
C#
var customer =
    new Customer
    {
        Name = "Hamed"
    };

customer.Name =
    "Ali";

در بسیاری از Domain Modelها تغییر State طبیعی است؛ مثلاً وضعیت یک Order یا Balance یک Account می‌تواند در طول زمان تغییر کند.

Immutable Class

می‌توان Class را طوری طراحی کرد که State آن پس از construction مستقیماً قابل تغییر نباشد.

C#
public sealed class Money
{
    public decimal Amount
    {
        get;
    }

    public string Currency
    {
        get;
    }

    public Money(
        decimal amount,
        string currency)
    {
        Amount = amount;
        Currency = currency;
    }
}

در این طراحی Setter عمومی نداریم. بعد از ساخته‌شدن Money، مصرف‌کننده نمی‌تواند Amount یا Currency آن را مستقیماً تغییر دهد.

💡
Reference Type بودن به معنی Mutable بودن نیست. یک Class همچنان Reference Type است، حتی اگر آن را به‌صورت Immutable طراحی کنیم.

Class و Encapsulation

Class فقط ظرفی برای Propertyها نیست. یکی از اهداف مهم آن محافظت از invariants و قرار دادن رفتار کنار داده است.

طراحی ضعیف

C#
public class BankAccount
{
    public decimal Balance
    {
        get;
        set;
    }
}

هر بخش برنامه می‌تواند Balance را به هر مقداری تغییر دهد:

C#
account.Balance =
    -10_000_000;

طراحی بهتر

C#
public class BankAccount
{
    public decimal Balance
    {
        get;
        private set;
    }

    public void Withdraw(
        decimal amount)
    {
        if (amount <= 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(amount));
        }

        if (amount > Balance)
        {
            throw new InvalidOperationException(
                "Insufficient balance.");
        }

        Balance -= amount;
    }
}

حالا تغییر Balance از طریق یک Behavior معنادار انجام می‌شود و Class می‌تواند قوانین خودش را enforce کند.

Equality پیش‌فرض در Class

برای Classهای معمولی، Equality پیش‌فرض معمولاً بر اساس reference identity است، مگر اینکه Equality را override یا overload کنیم.

C#
public class Customer
{
    public string Name
    {
        get;
        init;
    }
}
C#
var customer1 =
    new Customer
    {
        Name = "Hamed"
    };

var customer2 =
    new Customer
    {
        Name = "Hamed"
    };

Console.WriteLine(
    customer1 == customer2);
// False

با اینکه Propertyها مقدار یکسان دارند، دو object مستقل هستند. این نکته یکی از تفاوت‌های مهمی است که بعداً هنگام مقایسهٔ class و record خواهیم دید.

Class در مدل‌سازی Entity

Class انتخاب طبیعی و رایجی برای Entityهایی است که Identity و Lifecycle دارند. برای مثال یک Transaction ممکن است در طول زمان Stateهای مختلفی داشته باشد، اما همچنان همان Transaction باقی بماند.

C#
public class Transaction
{
    public Guid Id
    {
        get;
    }

    public decimal Amount
    {
        get;
    }

    public TransactionStatus Status
    {
        get;
        private set;
    }

    public Transaction(
        Guid id,
        decimal amount)
    {
        Id = id;
        Amount = amount;
        Status =
            TransactionStatus.Pending;
    }

    public void Complete()
    {
        if (Status !=
            TransactionStatus.Pending)
        {
            throw new InvalidOperationException(
                "Only pending transactions can be completed.");
        }

        Status =
            TransactionStatus.Completed;
    }
}

این object دارای Identity، State و Behavior است و Class ابزار مناسبی برای مدل‌کردن چنین مفهومی است.

مثال استفاده

C#
var transaction =
    new Transaction(
        Guid.NewGuid(),
        500_000);

Console.WriteLine(
    transaction.Status);
// Pending

transaction.Complete();

Console.WriteLine(
    transaction.Status);
// Completed

به جای اینکه کد بیرونی مستقیماً Status را تغییر دهد، خود Transaction رفتار Complete() را ارائه می‌دهد و قانون تغییر State را کنترل می‌کند.

اشتباهات رایج

  • تصور اینکه assignment یک Class باعث کپی کامل object می‌شود.
  • فرض اینکه هر Class الزاماً Mutable است.
  • استفاده از Class فقط به‌عنوان مجموعه‌ای از Getter و Setter بدون Behavior.
  • قرار دادن Setter عمومی روی Stateهایی که باید توسط Business Rule کنترل شوند.
  • فرض اینکه دو Class با Propertyهای یکسان به‌صورت پیش‌فرض برابر هستند.
🎯
در طراحی Domain، اگر یک مفهوم Identity دارد، Lifecycle آن مهم است و State آن از طریق Behaviorهای مشخص تغییر می‌کند، Class معمولاً یکی از اولین گزینه‌هایی است که باید بررسی کنید.

جمع‌بندی 13.1

Class در C# یک Reference Type است که برای مدل‌کردن objectهای دارای State و Behavior استفاده می‌شود. ساخت objectهای مختلف از یک Class امکان‌پذیر است و چند reference نیز می‌توانند به یک instance مشترک اشاره کنند. Class می‌تواند Mutable یا Immutable باشد، از Constructor، Encapsulation، Inheritance و Polymorphism پشتیبانی کند و برای مدل‌کردن Entityهای دارای Identity و Lifecycle بسیار مناسب است.

✅
نکتهٔ کلیدی این بخش: class را فقط به‌عنوان «قالب ساخت object» نبینید. در طراحی شی‌گرا، Class ابزاری برای قرار دادن State، Behavior و Business Ruleهای مرتبط در یک abstraction منسجم است.
