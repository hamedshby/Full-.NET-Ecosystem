18.7 — Separation of Concerns

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Separation of Concerns (SoC) یعنی سیستم را به بخش‌هایی تقسیم کنیم که هر بخش روی یک Concern مشخص تمرکز داشته باشد.

همه‌چیز در Controller

C#
[HttpPost]
public async Task<IActionResult> Pay(
    PaymentRequest request)
{
    // Validate request
    // Calculate fee
    // Execute SQL
    // Call bank API
    // Publish RabbitMQ message
    // Send email
    // Build HTTP response

    return Ok();
}

HTTP، Business Logic، Persistence، Integration و Messaging همگی در یک محل جمع شده‌اند.

تفکیک Concernها

Text
PaymentController
      |
      v
ProcessPaymentHandler
      |
      +--> Payment Domain
      +--> IPaymentRepository
      +--> IPaymentGateway
      +--> IEventPublisher

نمونه در ASP.NET Core

  • Controller: HTTP concerns
  • Application Handler: Use Case orchestration
  • Domain: Business rules
  • Repository: Persistence concern
  • Gateway: External integration
  • Middleware: Cross-cutting HTTP behavior

SoC و Layering

Layering یکی از روش‌های اعمال Separation of Concerns است، اما SoC محدود به Layer نیست. حتی داخل یک Layer نیز می‌توان Concernهای متفاوت داشت.

Cross-Cutting Concerns

Logging، Authentication، Metrics و Exception Handling معمولاً در چند Use Case حضور دارند. Middleware، Decorator یا Pipeline Behavior می‌توانند آن‌ها را از Business Logic جدا کنند.

⚠️
Separation بیش از حد نیز هزینه دارد. شکستن یک رفتار ساده به تعداد زیادی Class کوچک و رفت‌وآمد زیاد بین Layerها می‌تواند خوانایی را کاهش دهد.

نکته مصاحبه‌ای

🎤
Separation of Concerns keeps different responsibilities such as business rules, persistence, transport, and infrastructure in appropriate boundaries.

جمع‌بندی

هدف SoC این است که تغییر یک Concern، کمترین اثر ممکن را بر Concernهای دیگر داشته باشد و محل هر نوع Logic برای توسعه‌دهنده قابل پیش‌بینی باشد.
