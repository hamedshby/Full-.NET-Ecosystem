🧠 Domain-Driven Design

21.9 — Anemic Domain Model

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Anemic Domain Model مدلی است که Entityها بیشتر Data دارند و Business Logic در Serviceهای بیرونی قرار گرفته است.

مثال

C#
public class Payment
{
    public Guid Id { get; set; }
    public decimal Amount { get; set; }
    public string Status { get; set; }
}
C#
public class PaymentService
{
    public void Complete(Payment payment)
    {
        if (payment.Status != "Pending")
            throw new InvalidOperationException();

        payment.Status = "Paid";
    }
}

مشکل در Domain پیچیده

  • Entity از State خودش محافظت نمی‌کند.
  • Rule در Serviceها پخش می‌شود.
  • Duplication افزایش می‌یابد.
  • Encapsulation ضعیف می‌شود.

Refactor

C#
public void Complete()
{
    if (Status != PaymentStatus.Pending)
        throw new InvalidOperationException();

    Status = PaymentStatus.Paid;
}
⚠️
Anemic Model همیشه بد نیست. برای CRUD ساده یا Reporting ممکن است کاملاً کافی باشد؛ Rich Model زمانی ارزش بیشتری دارد که Domain Logic پیچیده باشد.

جمع‌بندی

در Domain پیچیده، Anemic Model معمولاً Business Logic را از Objectهای اصلی جدا می‌کند.
