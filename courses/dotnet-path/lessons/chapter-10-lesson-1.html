فصل 10 — Object Equality در C#

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در C# وقتی می‌گوییم دو object «برابر» هستند، باید مشخص کنیم منظورمان چیست: آیا هر دو متغیر به همان instance اشاره می‌کنند، یا دو instance جدا هستند که مقادیر معادل دارند؟ درک این تفاوت برای طراحی Value Objectها و استفاده صحیح از Dictionary و HashSet بسیار مهم است.

💡
سؤال کلیدی Equality این است: «Identity مهم است یا Value؟» Reference Equality دربارهٔ هویت object است؛ Value Equality دربارهٔ داده‌هایی است که از نظر برنامه دو object را معادل می‌کنند.

10.1 Reference Equality

Reference Equality بررسی می‌کند آیا دو reference دقیقاً به یک instance اشاره می‌کنند.

C#
public class Customer
{
    public string Name { get; set; }
}

var customer1 =
    new Customer { Name = "Hamed" };

var customer2 = customer1;

Console.WriteLine(
    ReferenceEquals(
        customer1,
        customer2));
// True

اما دو object جدا، حتی با دادهٔ یکسان، Reference Equality ندارند:

C#
var customer1 =
    new Customer { Name = "Hamed" };

var customer2 =
    new Customer { Name = "Hamed" };

Console.WriteLine(
    ReferenceEquals(
        customer1,
        customer2));
// False

10.2 Value Equality

Value Equality به جای هویت object، مقادیر مهم آن را مقایسه می‌کند. مثلاً در Domain ممکن است دو Money زمانی برابر باشند که Amount و Currency یکسان داشته باشند.

C#
var money1 =
    new Money(100_000, "IRR");

var money2 =
    new Money(100_000, "IRR");

این دو instance متفاوت‌اند، اما می‌توانیم Equality را طوری تعریف کنیم که از نظر Value برابر باشند.

Reference Equality Value Equality
همان instance؟ همان مقادیر مهم؟
Identity مهم است. Content/Value مهم است.
مثلاً Entity instance مثلاً Money یا Value Object

10.3 Equals()

تمام typeها از System.Object قابلیت Equals() را دریافت می‌کنند. برای classهای معمولی می‌توان آن را override کرد تا semantics مربوط به Value Equality را تعریف کنیم.

C#
public class Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(
        decimal amount,
        string currency)
    {
        Amount = amount;
        Currency = currency;
    }

    public override bool Equals(
        object? obj)
    {
        return obj is Money other
            && Amount == other.Amount
            && Currency == other.Currency;
    }
}
C#
var money1 =
    new Money(100_000, "IRR");

var money2 =
    new Money(100_000, "IRR");

Console.WriteLine(
    money1.Equals(money2));
// True

قواعد مهم Equality

  • Reflexive: هر object با خودش برابر است.
  • Symmetric: اگر A با B برابر است، B نیز با A برابر باشد.
  • Transitive: اگر A=B و B=C باشد، A=C باشد.
  • Consistent: تا وقتی داده‌های مؤثر تغییر نکرده‌اند، نتیجه ثابت بماند.
  • یک object غیر-null با null برابر نیست.

10.4 GetHashCode()

اگر Value Equality سفارشی تعریف می‌کنیم، GetHashCode() نیز باید با همان تعریف سازگار باشد. Collectionهایی مانند Dictionary و HashSet از Hash Code استفاده می‌کنند.

⚠️
اگر a.Equals(b) برابر true باشد، Hash Code هر دو نیز باید یکسان باشد. برعکس آن الزامی نیست؛ دو object متفاوت ممکن است Hash Code یکسان داشته باشند.
C#
public override int GetHashCode()
{
    return HashCode.Combine(
        Amount,
        Currency);
}

بهتر است همان اعضایی که در Equality شرکت دارند، در محاسبهٔ Hash Code نیز استفاده شوند.

10.5 Operator ==

رفتار == به type بستگی دارد. برای بسیاری از classهای معمولی که این operator را overload نکرده‌اند، مقایسهٔ reference انجام می‌شود.

C#
var customer1 =
    new Customer { Name = "Hamed" };

var customer2 =
    new Customer { Name = "Hamed" };

Console.WriteLine(
    customer1 == customer2);
// False

برای type سفارشی می‌توان == و != را با semantics مربوط به Value Equality تعریف کرد:

C#
public static bool operator ==(
    Money? left,
    Money? right)
{
    return EqualityComparer<Money>
        .Default
        .Equals(left, right);
}

public static bool operator !=(
    Money? left,
    Money? right)
{
    return !(left == right);
}
💡
اگر == را overload می‌کنید، رفتار آن را با Equals() هماهنگ نگه دارید و != را نیز همراه آن تعریف کنید.

10.6 ReferenceEquals

object.ReferenceEquals() بدون توجه به Value Equality بررسی می‌کند آیا دو reference به همان object اشاره می‌کنند.

C#
var money1 =
    new Money(100_000, "IRR");

var money2 =
    new Money(100_000, "IRR");

var money3 = money1;

Console.WriteLine(
    money1.Equals(money2));
// True

Console.WriteLine(
    ReferenceEquals(
        money1,
        money2));
// False

Console.WriteLine(
    ReferenceEquals(
        money1,
        money3));
// True

money1 و money2 می‌توانند از نظر Value برابر باشند، اما همچنان دو object مستقل هستند.

10.7 Equality در Recordها

Recordها به‌صورت پیش‌فرض Value Equality تولیدشده توسط Compiler دارند و برای مدل‌های data-centric و بسیاری از Value Objectهای ساده بسیار مناسب‌اند.

C#
public record Money(
    decimal Amount,
    string Currency);

var money1 =
    new Money(100_000, "IRR");

var money2 =
    new Money(100_000, "IRR");

Console.WriteLine(
    money1 == money2);
// True

Console.WriteLine(
    money1.Equals(money2));
// True

Console.WriteLine(
    ReferenceEquals(
        money1,
        money2));
// False

دو record می‌توانند دو instance جدا باشند، ولی چون مقادیرشان یکسان است از نظر Value برابر محسوب شوند.

⚠️
Record به‌تنهایی طراحی Domain را حل نمی‌کند. Validation، invariants و اینکه کدام داده‌ها واقعاً هویت یا Value یک مفهوم را می‌سازند همچنان باید آگاهانه طراحی شوند.

10.8 پیاده‌سازی IEquatable<T>

برای typeهایی با Equality سفارشی می‌توان IEquatable<T> را پیاده‌سازی کرد تا یک Equals strongly typed داشته باشیم.

C#
public sealed class Money
    : IEquatable<Money>
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(
        decimal amount,
        string currency)
    {
        Amount = amount;
        Currency = currency;
    }

    public bool Equals(
        Money? other)
    {
        if (other is null)
            return false;

        if (ReferenceEquals(
            this,
            other))
        {
            return true;
        }

        return Amount == other.Amount
            && Currency == other.Currency;
    }

    public override bool Equals(
        object? obj)
    {
        return obj is Money other
            && Equals(other);
    }

    public override int GetHashCode()
    {
        return HashCode.Combine(
            Amount,
            Currency);
    }

    public static bool operator ==(
        Money? left,
        Money? right)
    {
        if (ReferenceEquals(left, right))
            return true;

        if (left is null || right is null)
            return false;

        return left.Equals(right);
    }

    public static bool operator !=(
        Money? left,
        Money? right)
    {
        return !(left == right);
    }
}

در این پیاده‌سازی Equals(Money?)، Equals(object?)، GetHashCode() و operatorها همگی از یک تعریف منطقی برای Equality پیروی می‌کنند.

10.9 مشکلات Equality در Dictionary و HashSet

Collectionهای Hash-based ابتدا از Hash Code برای پیدا کردن محل احتمالی object استفاده می‌کنند و سپس Equality را بررسی می‌کنند. بنابراین قرارداد صحیح بین Equals() و GetHashCode() حیاتی است.

HashSet و Duplicateها

C#
var money1 =
    new Money(100_000, "IRR");

var money2 =
    new Money(100_000, "IRR");

var set =
    new HashSet<Money>();

set.Add(money1);
set.Add(money2);

Console.WriteLine(set.Count);
// 1

چون دو Money از نظر Equality برابر هستند و Hash Code سازگار دارند، HashSet آن‌ها را duplicate تشخیص می‌دهد.

Dictionary و Equality کلید

C#
var prices =
    new Dictionary<Money, string>();

var key1 =
    new Money(100_000, "IRR");

prices[key1] = "Payment";

var key2 =
    new Money(100_000, "IRR");

Console.WriteLine(
    prices[key2]);
// Payment

key1 و key2 یک reference نیستند، اما Dictionary به کمک Value Equality آن‌ها را keyهای معادل می‌داند.

مشکل خطرناک: Mutable Key

اگر مقداری که در GetHashCode() شرکت دارد بعد از اضافه‌شدن object به collection تغییر کند، object ممکن است دیگر از bucket مورد انتظار پیدا نشود.

C#
public class CustomerKey
{
    public int Id { get; set; }

    public override bool Equals(
        object? obj)
    {
        return obj is CustomerKey other
            && Id == other.Id;
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
C#
var key =
    new CustomerKey { Id = 10 };

var set =
    new HashSet<CustomerKey>();

set.Add(key);

// Hash Code تغییر می‌کند
key.Id = 20;

Console.WriteLine(
    set.Contains(key));
// False می‌تواند نتیجهٔ مشاهده‌شده باشد
🚨
اعضایی که در Equality و Hash Code یک Key شرکت می‌کنند بهتر است هنگام حضور object در Dictionary یا HashSet تغییر نکنند. Immutable Value Objectها معمولاً Keyهای امن‌تری هستند.

مثال واقعی: TransactionId

در یک سیستم پرداخت می‌توان Transaction ID را به‌جای string خام، به شکل Value Object مدل کرد:

C#
public sealed record TransactionId
{
    public string Value { get; }

    public TransactionId(string value)
    {
        if (string.IsNullOrWhiteSpace(value))
        {
            throw new ArgumentException(
                "Transaction ID is required.",
                nameof(value));
        }

        Value = value;
    }
}
C#
var id1 =
    new TransactionId("TX-1001");

var id2 =
    new TransactionId("TX-1001");

Console.WriteLine(id1 == id2);
// True

var processedTransactions =
    new HashSet<TransactionId>();

processedTransactions.Add(id1);

Console.WriteLine(
    processedTransactions.Contains(id2));
// True

دو TransactionId با مقدار یکسان از دید Domain برابرند؛ بنابراین HashSet نیز می‌تواند از همان Equality برای تشخیص Transaction تکراری استفاده کند.

جمع‌بندی ابزارهای Equality

ابزار کاربرد
Equals() تعریف یا بررسی Equality منطقی
GetHashCode() پشتیبانی صحیح از Hash-based Collectionها
== Equality Operator؛ رفتار آن به type بستگی دارد.
ReferenceEquals() بررسی یکسان بودن instance
IEquatable<T> Equality strongly typed
record Value Equality تولیدشده توسط Compiler
✅
خلاصه: ابتدا مشخص کنید Equality در type شما بر اساس Identity است یا Value. اگر Value Equality سفارشی تعریف می‌کنید، Equals() و GetHashCode() را هماهنگ نگه دارید. برای typeهای مناسب از IEquatable<T> یا record استفاده کنید و برای Keyهای Dictionary و اعضای HashSet از تغییر مقادیر مؤثر در Hash Code جلوگیری کنید.
