🏭 Creational Design Patterns

Factory Method

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Factory Method یکی از Creational Design Patternهاست. هدف آن جدا کردن منطق ساخت Object از کدی است که آن Object را مصرف می‌کند.

💡
در Payment System، Factory Method زمانی مفید است که چند Payment Gateway داشته باشیم و نخواهیم Business Logic مستقیماً Concrete Gatewayها را بشناسد.

مسئله در Payment System

فرض کنید سیستم ما با Bank A، Bank B و Wallet Provider کار می‌کند. نسخه ساده ممکن است این‌طور باشد:

C#
public class PaymentService
{
    public async Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        IPaymentGateway gateway;

        if (request.Provider == "BankA")
            gateway = new BankAPaymentGateway();
        else if (request.Provider == "BankB")
            gateway = new BankBPaymentGateway();
        else
            gateway = new WalletPaymentGateway();

        return await gateway.PayAsync(
            request,
            cancellationToken);
    }
}

مشکلات طراحی بالا

  • PaymentService همه Concrete Gatewayها را می‌شناسد.
  • Creation Logic با Business Logic ترکیب شده است.
  • اضافه شدن Provider جدید نیازمند تغییر PaymentService است.
  • Coupling بالا می‌رود.

Product Contract

C#
public interface IPaymentGateway
{
    Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken);
}

Concrete Productها

C#
public class BankAPaymentGateway
    : IPaymentGateway
{
    public Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        return Task.FromResult(
            PaymentResult.Success("BANK-A-123"));
    }
}

public class BankBPaymentGateway
    : IPaymentGateway
{
    public Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        return Task.FromResult(
            PaymentResult.Success("BANK-B-456"));
    }
}

تعریف Factory Method

C#
public abstract class PaymentGatewayFactory
{
    public abstract IPaymentGateway
        CreateGateway();
}

متد CreateGateway همان Factory Method است.

Concrete Creator برای Bank A

C#
public class BankAPaymentGatewayFactory
    : PaymentGatewayFactory
{
    public override IPaymentGateway CreateGateway()
    {
        return new BankAPaymentGateway();
    }
}

Concrete Creator برای Bank B

C#
public class BankBPaymentGatewayFactory
    : PaymentGatewayFactory
{
    public override IPaymentGateway CreateGateway()
    {
        return new BankBPaymentGateway();
    }
}

استفاده در PaymentService

C#
public class PaymentService
{
    private readonly PaymentGatewayFactory
        _factory;

    public PaymentService(
        PaymentGatewayFactory factory)
    {
        _factory = factory;
    }

    public async Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        var gateway =
            _factory.CreateGateway();

        return await gateway.PayAsync(
            request,
            cancellationToken);
    }
}
🎯
Factory Method = Encapsulate Object Creation. Business Logic باید روی استفاده از Object تمرکز کند، نه روی نحوه ساخت آن.

Factory Method و OCP

اگر Bank C اضافه شود، Product و Creator جدید اضافه می‌کنیم:

C#
public class BankCPaymentGateway
    : IPaymentGateway
{
    public Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        throw new NotImplementedException();
    }
}

public class BankCPaymentGatewayFactory
    : PaymentGatewayFactory
{
    public override IPaymentGateway CreateGateway()
    {
        return new BankCPaymentGateway();
    }
}

Business Flow اصلی نیاز به تغییر ندارد.

Factory Method و Polymorphism

C#
PaymentGatewayFactory factory =
    new BankAPaymentGatewayFactory();

IPaymentGateway gateway =
    factory.CreateGateway();

Consumer با Typeهای انتزاعی کار می‌کند، ولی Object واقعی در Runtime می‌تواند متفاوت باشد.

Factory Method و Dependency Injection

C#
builder.Services.AddScoped
    <PaymentGatewayFactory,
     BankAPaymentGatewayFactory>();

builder.Services.AddScoped
    <PaymentService>();

در این حالت Composition Root مشخص می‌کند چه Concrete Factoryای تزریق شود.

Runtime Factory در پروژه‌های واقعی .NET

گاهی Provider در Runtime از روی Request انتخاب می‌شود:

C#
public enum PaymentProvider
{
    BankA,
    BankB,
    Wallet
}
C#
public interface IPaymentGatewayFactory
{
    IPaymentGateway Create(
        PaymentProvider provider);
}
C#
public class PaymentGatewayFactory
    : IPaymentGatewayFactory
{
    private readonly IReadOnlyDictionary
        <PaymentProvider, IPaymentGateway>
        _gateways;

    public PaymentGatewayFactory(
        IEnumerable<IPaymentGateway> gateways)
    {
        _gateways =
            gateways.ToDictionary(
                x => x.Provider);
    }

    public IPaymentGateway Create(
        PaymentProvider provider)
    {
        if (!_gateways.TryGetValue(
            provider,
            out var gateway))
        {
            throw new NotSupportedException();
        }

        return gateway;
    }
}
⚠️
این Runtime Factory در پروژه‌های .NET بسیار رایج است، اما با تعریف کلاسیک GoF Factory Method کاملاً یکسان نیست. Factory Method کلاسیک معمولاً بر Override شدن Creation Method توسط Subclass تکیه دارد.

مزایا

  • جدا شدن Creation Logic از Business Logic
  • کاهش Coupling به Concrete Typeها
  • افزایش Extensibility
  • هماهنگی خوب با OCP و Polymorphism
  • تست‌پذیری بهتر

معایب

  • افزایش تعداد Classها
  • احتمال Overengineering در سناریوی ساده
  • Hierarchy بیشتر برای Creatorها

چه زمانی استفاده کنیم؟

  • نوع Concrete Object از قبل ثابت نیست.
  • Creation Logic پیچیده است.
  • چند Provider یا Product داریم.
  • می‌خواهیم Consumer Concrete Product را نشناسد.

چه زمانی استفاده نکنیم؟

اگر فقط یک Object ساده و ثابت داریم و Creation هیچ Variation واقعی ندارد، Factory معمولاً ارزش خاصی ایجاد نمی‌کند.

⚠️
Factory را فقط برای حذف keywordِ new نسازید. Factory باید یک مشکل واقعی در Creation یا Coupling را حل کند.

Factory Method vs Simple Factory

Factory Method Simple Factory
GoF Pattern یک Idiom رایج
معمولاً با Inheritance و Override معمولاً یک Factory Class با if/switch
Subclass نوع Product را تعیین می‌کند Factory مرکزی Product را انتخاب می‌کند

Factory Method vs Abstract Factory

Factory Method معمولاً یک Product ایجاد می‌کند؛ Abstract Factory یک Family از Productهای مرتبط می‌سازد.

Text
BankAFactory
    ├── CreatePaymentGateway()
    ├── CreateRefundGateway()
    └── CreateSettlementGateway()

نکته مصاحبه‌ای

🎤
Factory Method defines a creation method that allows specialized creators to decide which concrete product should be instantiated. In a payment system, it can create different payment gateways without coupling the payment use case to specific bank implementations.

جمع‌بندی 20.1

Factory Method یک Creational Pattern برای Encapsulate کردن Object Creation است. در Payment System می‌توان ساخت Bank Gatewayها را از PaymentService جدا کرد تا Business Logic به Concrete Providerها وابسته نباشد.

✅
نکته کلیدی: Business Logic باید بداند Object چه کاری انجام می‌دهد، نه اینکه دقیقاً چگونه ساخته می‌شود.
