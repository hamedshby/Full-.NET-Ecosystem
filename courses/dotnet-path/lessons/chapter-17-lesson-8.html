17.8 — Interface و DI برای کاهش Coupling

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Interface Contract مورد نیاز Consumer را تعریف می‌کند و Dependency Injection Implementation را از بیرون به Consumer می‌دهد.

قبل از Refactoring

C#
public class PaymentService
{
    private readonly SqlPaymentRepository _repository;

    public PaymentService()
    {
        _repository = new SqlPaymentRepository();
    }
}

1. تعریف Interface

C#
public interface IPaymentRepository
{
    Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken);
}

2. Constructor Injection

C#
public class PaymentService
{
    private readonly IPaymentRepository _repository;

    public PaymentService(
        IPaymentRepository repository)
    {
        _repository = repository;
    }
}

3. Concrete Implementation

C#
public class SqlPaymentRepository
    : IPaymentRepository
{
    public Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken)
    {
        // SQL Server
        return Task.CompletedTask;
    }
}

4. DI Container

C#
builder.Services.AddScoped
    <IPaymentRepository,
     SqlPaymentRepository>();

builder.Services.AddScoped
    <PaymentService>();

Dependency Direction

Text
PaymentService
      │
      ▼
IPaymentRepository
      ▲
      │
SqlPaymentRepository

جایگزینی Implementation

C#
public class InMemoryPaymentRepository
    : IPaymentRepository
{
    public Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken)
        => Task.CompletedTask;
}

PaymentService بدون تغییر می‌تواند Implementation دیگری دریافت کند.

Interface، DI و DIP یکی نیستند

مفهومنقش
Interfaceتعریف Contract
Dependency Injectionتأمین Dependency از بیرون
DI Containerساخت و Resolve کردن Object Graph
DIPاصل طراحی درباره جهت Dependencyها
⚠️
Interface و DI به‌تنهایی Loose Coupling را تضمین نمی‌کنند. Contract باید در Boundary درست و بر اساس نیاز Consumer طراحی شود.

چه زمانی Interface ارزشمند است؟

  • Infrastructure Boundary
  • External API
  • چند Implementation واقعی
  • Variation و Extension
  • تست مستقل از External Dependency

چه زمانی لازم نیست؟

برای بسیاری از Entityها، DTOها، Value Objectها و Classهای داخلی پایدار، Interface اضافی فقط Complexity ایجاد می‌کند.

مثال نهایی

Text
ProcessPaymentHandler
 ├─► IPaymentRepository ◄─ SqlPaymentRepository
 ├─► IPaymentGateway    ◄─ BankAGateway
 └─► IEventPublisher    ◄─ RabbitMqPublisher

DI Container wires implementations.

نکته مصاحبه‌ای

🎤
Interfaces define stable contracts, while Dependency Injection provides implementations from outside the consumer. Used at meaningful boundaries, they reduce coupling and improve testability.

جمع‌بندی

Interface Contract را مشخص می‌کند و DI ساخت Concrete Dependency را از Business Logic خارج می‌کند. ارزش اصلی آن‌ها در Boundaryهای واقعی سیستم است.
