21.5 — Aggregate Root

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Aggregate Root Entity اصلی Aggregate و تنها Entry Point معتبر برای تغییر State داخلی آن است.

💡
در Payment Aggregate، خود Payment می‌تواند Root باشد و Refund فقط از طریق Payment ایجاد یا مدیریت شود.

مثال

C#
public class Payment
{
    private readonly List<Refund>
        _refunds = new();

    public IReadOnlyCollection<Refund>
        Refunds => _refunds.AsReadOnly();

    public void RequestRefund(Money amount)
    {
        ValidateRefund(amount);

        _refunds.Add(
            Refund.Create(
                Guid.NewGuid(),
                amount));
    }
}

Repository برای Root

C#
public interface IPaymentRepository
{
    Task<Payment?> GetAsync(
        Guid id,
        CancellationToken cancellationToken);

    Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken);
}

معمولاً Repository را برای Aggregate Root تعریف می‌کنیم، نه برای هر Entity داخلی.

چرا Root مهم است؟

  • از Invariantها محافظت می‌کند.
  • API تغییر State را محدود می‌کند.
  • مرز Persistence را روشن می‌کند.

نکته مصاحبه‌ای

🎤
An aggregate root is the only entry point for modifying an aggregate and protects its invariants.
