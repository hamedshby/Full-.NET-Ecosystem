18.8 — DRY

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

DRY — Don't Repeat Yourself می‌گوید هر دانش یا Rule مهم سیستم بهتر است یک Source of Truth مشخص داشته باشد.

💡
DRY عمیق‌تر از حذف Code Duplication ظاهری است؛ مسئلهٔ اصلی جلوگیری از تکرار یک Knowledge یا Business Rule در چند محل است.

تکرار Business Rule

C#
// API
var fee = amount * 0.01m;

// Background Worker
var fee = amount * 0.01m;

// Settlement Job
var fee = amount * 0.01m;

اگر Fee به 1.5% تغییر کند باید چند محل را پیدا و اصلاح کنیم.

یک Source of Truth

C#
public class PaymentFeeCalculator
{
    public decimal Calculate(decimal amount)
        => amount * 0.01m;
}

DRY و Abstraction اشتباه

دو قطعه کد ممکن است امروز شبیه باشند ولی به دلایل متفاوت تغییر کنند. ادغام زودهنگام آن‌ها می‌تواند Coupling ایجاد کند.

⚠️
Duplication is sometimes cheaper than the wrong abstraction. قبل از Extract کردن، بررسی کنید آیا دو بخش واقعاً یک مفهوم مشترک دارند یا فقط شکل کدشان مشابه است.

مثال Validation

اگر MerchantReferenceCode در چند Use Case دقیقاً یک Rule مشترک دارد، Rule می‌تواند در Value Object یا Validator مشترکِ معنادار متمرکز شود. اما Validationهای متفاوت را صرفاً به خاطر شباهت ظاهری یکی نکنید.

DRY در سطح داده و Contract

تکرار Configuration، Business Constant، Schema Definition و Mapping Rule نیز می‌تواند نوعی Duplication دانش باشد.

نکته مصاحبه‌ای

🎤
DRY is about avoiding duplicated knowledge, not blindly removing every repeated line of code.

جمع‌بندی

دانشی که باید همیشه با هم تغییر کند بهتر است یک محل معتبر داشته باشد؛ اما Similarity به‌تنهایی دلیل ساخت Abstraction نیست.
