آشنایی با Fields در C#

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در یک class معمولاً لازم است اطلاعاتی را نگه داریم که وضعیت یا State یک object را تشکیل می‌دهند. یکی از ابزارهای اصلی C# برای نگهداری این اطلاعات Field است. Field متغیری است که مستقیماً در بدنهٔ class تعریف می‌شود و می‌تواند به هر instance تعلق داشته باشد یا میان همهٔ instanceها مشترک باشد.

💡
Field را می‌توان حافظهٔ داخلی یک object در نظر گرفت. برای مثال موجودی داخلی یک حساب بانکی می‌تواند در یک Field نگهداری شود.

Instance Field

Instance Field فیلدی است که به یک object مشخص تعلق دارد. وقتی چند object از یک class ساخته می‌شوند، هر object مقدار مستقل خودش را برای Instance Fieldها نگه می‌دارد.

C#
public class BankAccount
{
    private decimal _balance;

    public void Deposit(decimal amount)
    {
        _balance += amount;
    }

    public decimal GetBalance()
    {
        return _balance;
    }
}

در این مثال _balance یک Instance Field است. بنابراین هر حساب بانکی موجودی مستقل خودش را دارد.

C#
var account1 = new BankAccount();
var account2 = new BankAccount();

account1.Deposit(100_000);
account2.Deposit(700_000);

Console.WriteLine(account1.GetBalance()); // 100000
Console.WriteLine(account2.GetBalance()); // 700000

با اینکه account1 و account2 هر دو از یک class ساخته شده‌اند، هرکدام نسخهٔ جداگانه‌ای از _balance دارند.

چرا Fieldها معمولاً private هستند؟

اگر Field داخلی را public کنیم، هر قسمت برنامه می‌تواند بدون کنترل مقدار آن را تغییر دهد. این کار Encapsulation را ضعیف می‌کند.

C#
// طراحی نامناسب
public class BankAccount
{
    public decimal Balance;
}

var account = new BankAccount();

account.Balance = -5_000_000;

در این طراحی هیچ قانونی از منفی‌شدن موجودی جلوگیری نمی‌کند. معمولاً بهتر است Field داخلی باشد و تغییر آن از طریق Method یا Property کنترل‌شده انجام شود.

⚠️
Public Field معمولاً انتخاب مناسبی برای مدل‌های دامنه نیست. در بیشتر مواقع State داخلی را با private نگه می‌داریم و API مناسبی برای دسترسی به آن طراحی می‌کنیم.

Static Field

Instance Field به هر object تعلق دارد؛ اما Static Field به خود class تعلق دارد و میان تمام instanceهای آن class مشترک است. برای تعریف آن از کلمهٔ کلیدی static استفاده می‌کنیم.

C#
public class BankAccount
{
    private static int _accountCount;

    public BankAccount()
    {
        _accountCount++;
    }

    public static int GetAccountCount()
    {
        return _accountCount;
    }
}

هر بار که یک BankAccount ساخته می‌شود، مقدار مشترک _accountCount افزایش پیدا می‌کند.

C#
var account1 = new BankAccount();
var account2 = new BankAccount();
var account3 = new BankAccount();

Console.WriteLine(BankAccount.GetAccountCount()); // 3

برای دسترسی به عضو static معمولاً از نام class استفاده می‌کنیم، نه از یک object:

C#
BankAccount.GetAccountCount();
Instance Field Static Field
به هر object تعلق دارد. به خود class تعلق دارد.
هر object مقدار مستقل دارد. مقدار میان همهٔ objectها مشترک است.
با instance استفاده می‌شود. معمولاً با نام class استفاده می‌شود.

const چیست؟

گاهی مقداری داریم که باید همیشه ثابت باشد و در طول اجرای برنامه تغییر نکند. برای چنین مقادیری می‌توان از const استفاده کرد.

C#
public class BankAccount
{
    public const int MaxDailyTransactions = 100;
}

بعد از تعریف مقدار ثابت، امکان تغییر آن وجود ندارد:

C#
Console.WriteLine(BankAccount.MaxDailyTransactions);

// Compile Error
// BankAccount.MaxDailyTransactions = 200;

مقدار یک const باید در زمان Compile مشخص باشد و همان موقع مقداردهی شود.

C#
public const int MaxRetryCount = 3;
public const string Currency = "IRR";
public const decimal MinimumAmount = 10_000m;
💡
اعضای const به‌صورت ضمنی static هستند؛ بنابراین برای استفاده از آن‌ها نیازی به ساخت object نداریم.

readonly چیست؟

readonly نیز برای جلوگیری از تغییر یک Field استفاده می‌شود، اما برخلاف const لازم نیست مقدار آن حتماً در زمان Compile مشخص باشد. یک readonly Field می‌تواند هنگام تعریف یا داخل Constructor مقداردهی شود.

C#
public class BankAccount
{
    private readonly Guid _accountId;

    public BankAccount()
    {
        _accountId = Guid.NewGuid();
    }
}

مقدار Guid.NewGuid() هنگام اجرای برنامه تولید می‌شود؛ بنابراین نمی‌توانیم آن را const تعریف کنیم، اما readonly برای این سناریو مناسب است.

مقداردهی readonly در Constructor

C#
public class BankAccount
{
    private readonly string _accountNumber;

    public BankAccount(string accountNumber)
    {
        _accountNumber = accountNumber;
    }
}

هر object می‌تواند مقدار متفاوتی برای _accountNumber داشته باشد؛ اما بعد از اجرای Constructor، آن Field دیگر قابل انتساب مجدد نیست.

C#
public class BankAccount
{
    private readonly string _accountNumber;

    public BankAccount(string accountNumber)
    {
        _accountNumber = accountNumber;
    }

    public void ChangeAccountNumber()
    {
        // Compile Error
        // _accountNumber = "IR-2000";
    }
}

تفاوت const و readonly

ویژگی const readonly
زمان مشخص‌شدن مقدار Compile Time Runtime نیز ممکن است
مقداردهی در Constructor خیر بله
تغییر پس از مقداردهی خیر پس از مقداردهی اولیه/Constructor خیر
Static بودن به‌صورت ضمنی static است به‌صورت پیش‌فرض instance است
مناسب برای مقادیر ثابت واقعی مقادیر ثابت‌شونده در Runtime

چه زمانی const استفاده کنیم؟

C#
public const int MaxRetryCount = 3;
public const string DefaultCurrency = "IRR";

این مقادیر از قبل مشخص‌اند و برای ساختن آن‌ها به Runtime یا Constructor نیازی نداریم.

چه زمانی readonly استفاده کنیم؟

C#
public class BankAccount
{
    private readonly Guid _id;
    private readonly DateTime _createdAt;

    public BankAccount()
    {
        _id = Guid.NewGuid();
        _createdAt = DateTime.UtcNow;
    }
}

مقادیر _id و _createdAt تا زمان اجرای برنامه مشخص نیستند، اما پس از ساخته‌شدن object نمی‌خواهیم reference/value این Fieldها دوباره انتساب داده شود.

static readonly

گاهی یک مقدار باید میان همهٔ objectها مشترک باشد، در Runtime ساخته شود و پس از مقداردهی تغییر نکند. در این حالت ترکیب static readonly کاربرد دارد.

C#
public class BankAccount
{
    public static readonly DateTime ApplicationStartedAt =
        DateTime.UtcNow;
}

این مقدار یک‌بار برای type ایجاد می‌شود و همهٔ instanceها همان مقدار مشترک را مشاهده می‌کنند.

مثال کامل

C#
public class BankAccount
{
    // Instance Field
    private decimal _balance;

    // Static Field
    private static int _accountCount;

    // Constant
    public const int MaxDailyTransactions = 100;

    // Readonly Field
    private readonly Guid _accountId;

    public BankAccount()
    {
        _accountId = Guid.NewGuid();
        _accountCount++;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount));

        _balance += amount;
    }

    public decimal GetBalance()
    {
        return _balance;
    }

    public static int GetAccountCount()
    {
        return _accountCount;
    }
}

در این class چهار نوع استفادهٔ مهم از Field را می‌بینیم: _balance متعلق به هر حساب است، _accountCount میان همهٔ حساب‌ها مشترک است، MaxDailyTransactions یک مقدار ثابت Compile-Time است و _accountId هنگام ساخت object مشخص می‌شود و بعد از آن دوباره مقداردهی نمی‌شود.

✅
قاعدهٔ ساده: اگر مقدار برای هر object متفاوت است از Instance Field استفاده کنید؛ اگر میان همهٔ objectها مشترک است Static Field مطرح می‌شود؛ اگر مقدار یک ثابت واقعی Compile-Time است const مناسب است؛ و اگر مقدار در Runtime تعیین می‌شود اما پس از مقداردهی نباید دوباره assign شود، readonly انتخاب مناسبی است.
