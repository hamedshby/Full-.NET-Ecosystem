آشنایی با Primary Constructors در C#

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در Constructorهای معمولی، ابتدا class را تعریف می‌کنیم و سپس Constructor را داخل بدنهٔ آن می‌نویسیم. در نسخه‌های جدید C# قابلیت Primary Constructor اجازه می‌دهد Parameterهای اصلی ساخت object را مستقیماً کنار نام class یا struct تعریف کنیم و در نتیجه بعضی classهای ساده را کوتاه‌تر و خواناتر بنویسیم.

💡
Primary Constructor از C# 12 برای class و struct در دسترس است. هدف آن حذف Constructorهای تکراری و ساده‌ترکردن initialization است؛ نه اینکه در همهٔ classها جای Constructor معمولی را بگیرد.

Primary Constructor چیست؟

در Primary Constructor، Parameterهای Constructor بعد از نام type نوشته می‌شوند:

C#
public class BankAccount(
    string accountNumber,
    string ownerName)
{
}

در این مثال accountNumber و ownerName پارامترهای Primary Constructor هستند. برای ساخت object باید مقادیر موردنیاز را ارسال کنیم:

C#
var account = new BankAccount(
    "IR-1001",
    "Hamed");

ظاهر تعریف کوتاه‌تر شده است، اما همچنان هنگام ساخت BankAccount دو Argument موردنیاز هستند.

مقایسه با Constructor معمولی

ابتدا همان class را با Constructor معمولی ببینیم:

C#
public class BankAccount
{
    public string AccountNumber { get; }
    public string OwnerName { get; }

    public BankAccount(
        string accountNumber,
        string ownerName)
    {
        AccountNumber = accountNumber;
        OwnerName = ownerName;
    }
}

با Primary Constructor می‌توان بخشی از این کد را کوتاه‌تر کرد:

C#
public class BankAccount(
    string accountNumber,
    string ownerName)
{
    public string AccountNumber { get; } =
        accountNumber;

    public string OwnerName { get; } =
        ownerName;
}
Constructor معمولی Primary Constructor
داخل بدنهٔ class تعریف می‌شود. Parameterها کنار نام class قرار می‌گیرند.
دارای بدنهٔ Constructor مشخص است. بدنهٔ Constructor جداگانه‌ای ندارد.
برای منطق initialization پیچیده واضح‌تر است. برای initialization ساده کد را کوتاه‌تر می‌کند.

استفاده از Parameterها در Property

Parameterهای Primary Constructor را می‌توان در initializer اعضای instance استفاده کرد:

C#
public class BankAccount(
    string accountNumber,
    string ownerName)
{
    public string AccountNumber { get; } =
        accountNumber;

    public string OwnerName { get; } =
        ownerName;

    public decimal Balance { get; private set; }
}

اکنون هنگام ساخت object، اطلاعات اصلی حساب دریافت و Propertyها مقداردهی می‌شوند:

C#
var account = new BankAccount(
    "IR-1001",
    "Hamed");

Console.WriteLine(
    account.AccountNumber);

Console.WriteLine(
    account.OwnerName);

Parameter با Property فرق دارد

یکی از نکات مهم این است که Parameterهای Primary Constructor در یک class معمولی، به‌صورت خودکار به Property عمومی تبدیل نمی‌شوند.

C#
public class BankAccount(
    string accountNumber)
{
}

کد زیر معتبر نیست، چون Propertyای به نام accountNumber ایجاد نشده است:

C#
var account =
    new BankAccount("IR-1001");

// Compile Error
// Console.WriteLine(
//     account.accountNumber);

اگر مقدار باید بخشی از API عمومی object باشد، باید Property را صریحاً تعریف کنیم:

C#
public class BankAccount(
    string accountNumber)
{
    public string AccountNumber { get; } =
        accountNumber;
}
⚠️
Primary Constructor در class معمولی با positional record یکسان نیست. در recordهای positional، Parameterها می‌توانند Propertyهای متناظر ایجاد کنند؛ اما Parameterهای Primary Constructor یک class معمولی خودشان Property عمومی نیستند.

استفاده از Parameterها داخل Method

Parameterهای Primary Constructor در اعضای instance نیز قابل استفاده‌اند:

C#
public class BankAccount(
    string accountNumber)
{
    public void PrintAccountNumber()
    {
        Console.WriteLine(accountNumber);
    }
}
C#
var account =
    new BankAccount("IR-1001");

account.PrintAccountNumber();
// IR-1001

اگر Parameter در اعضای instance مورد استفاده قرار گیرد، Compiler در صورت نیاز دادهٔ لازم برای نگهداری آن را مدیریت می‌کند. اما این موضوع به معنی ایجاد یک Field یا Property قابل دسترسی با همان نام برای کد بیرونی نیست.

Validation در Primary Constructor

چون Primary Constructor بدنهٔ مستقل مانند Constructor معمولی ندارد، برای validation باید طراحی مناسبی انتخاب کنیم. یکی از روش‌های ساده، استفاده از helper method هنگام مقداردهی Property است:

C#
public class BankAccount(
    string accountNumber)
{
    public string AccountNumber { get; } =
        ValidateAccountNumber(
            accountNumber);

    private static string ValidateAccountNumber(
        string accountNumber)
    {
        if (string.IsNullOrWhiteSpace(
            accountNumber))
        {
            throw new ArgumentException(
                "Account number is required.",
                nameof(accountNumber));
        }

        return accountNumber;
    }
}
C#
var account =
    new BankAccount("IR-1001");

// Exception
// var invalidAccount =
//     new BankAccount("");
💡
اگر initialization و validation بسیار پیچیده شد، Constructor معمولی یا Factory Method ممکن است خواناتر از تلاش برای فشرده‌کردن همهٔ منطق در Primary Constructor باشد.

Primary Constructor و Dependency Injection

یکی از کاربردهای جذاب Primary Constructor در classهایی است که فقط چند dependency از Dependency Injection دریافت می‌کنند. برای مثال یک Application Service:

C#
public class PaymentService(
    IPaymentGateway paymentGateway,
    ILogger<PaymentService> logger)
{
    public async Task PayAsync(
        decimal amount)
    {
        logger.LogInformation(
            "Payment started.");

        await paymentGateway.PayAsync(
            amount);
    }
}

نسخهٔ سنتی همین class معمولاً به Field و Constructor جداگانه نیاز دارد:

C#
public class PaymentService
{
    private readonly IPaymentGateway
        _paymentGateway;

    private readonly ILogger<PaymentService>
        _logger;

    public PaymentService(
        IPaymentGateway paymentGateway,
        ILogger<PaymentService> logger)
    {
        _paymentGateway = paymentGateway;
        _logger = logger;
    }

    public async Task PayAsync(
        decimal amount)
    {
        _logger.LogInformation(
            "Payment started.");

        await _paymentGateway.PayAsync(
            amount);
    }
}

در classهای کوچک و Serviceهایی که Constructor عمدتاً dependencyها را دریافت و ذخیره می‌کند، Primary Constructor می‌تواند Boilerplate را کاهش دهد.

Primary Constructor همراه Constructorهای دیگر

یک class دارای Primary Constructor می‌تواند Constructorهای دیگری نیز داشته باشد. Constructorهای instance اضافی باید در نهایت Primary Constructor را از طریق this(...) فراخوانی کنند.

C#
public class BankAccount(
    string accountNumber,
    decimal initialBalance)
{
    public string AccountNumber { get; } =
        accountNumber;

    public decimal Balance { get; private set; } =
        initialBalance;

    public BankAccount(
        string accountNumber)
        : this(accountNumber, 0)
    {
    }
}
C#
var account1 =
    new BankAccount(
        "IR-1001",
        500_000);

var account2 =
    new BankAccount(
        "IR-1002");

Constructor دوم مقدار موجودی اولیه را صفر در نظر می‌گیرد و با this(accountNumber, 0) به Primary Constructor متصل می‌شود.

Primary Constructor در struct

Primary Constructor فقط مخصوص class نیست و برای struct نیز قابل استفاده است:

C#
public readonly struct Money(
    decimal amount,
    string currency)
{
    public decimal Amount { get; } =
        amount;

    public string Currency { get; } =
        currency;

    public override string ToString()
    {
        return $"{Amount} {Currency}";
    }
}
C#
var money =
    new Money(
        500_000,
        "IRR");

Console.WriteLine(money);
// 500000 IRR

چه زمانی Primary Constructor مناسب است؟

  • وقتی Constructor فقط چند مقدار یا dependency ساده دریافت می‌کند.
  • وقتی می‌خواهیم Boilerplate مربوط به Constructor را کاهش دهیم.
  • برای Serviceهای کوچک که dependencyهای مشخصی دارند.
  • برای class یا structهای ساده با initialization روشن.

چه زمانی Constructor معمولی خواناتر است؟

  • وقتی initialization چند مرحله دارد.
  • وقتی Validation پیچیده است.
  • وقتی Constructor دارای منطق قابل‌توجهی است.
  • وقتی Primary Constructor باعث مبهم‌شدن محل ذخیره یا استفادهٔ داده‌ها می‌شود.
⚠️
کوتاه‌ترشدن کد همیشه به معنی طراحی بهتر نیست. Primary Constructor زمانی ارزشمند است که Intent کلاس را واضح‌تر کند؛ نه زمانی که صرفاً تعداد خطوط را کاهش دهد.

مثال کامل

C#
public class BankAccount(
    string accountNumber,
    string ownerName,
    decimal initialBalance)
{
    public string AccountNumber { get; } =
        ValidateAccountNumber(
            accountNumber);

    public string OwnerName { get; } =
        ownerName;

    public decimal Balance { get; private set; } =
        initialBalance >= 0
            ? initialBalance
            : throw new ArgumentOutOfRangeException(
                nameof(initialBalance));

    public BankAccount(
        string accountNumber,
        string ownerName)
        : this(
            accountNumber,
            ownerName,
            0)
    {
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(amount));
        }

        Balance += amount;
    }

    private static string ValidateAccountNumber(
        string accountNumber)
    {
        if (string.IsNullOrWhiteSpace(
            accountNumber))
        {
            throw new ArgumentException(
                "Account number is required.",
                nameof(accountNumber));
        }

        return accountNumber;
    }
}
C#
var account =
    new BankAccount(
        "IR-1001",
        "Hamed");

account.Deposit(500_000);

Console.WriteLine(
    account.AccountNumber);

Console.WriteLine(
    account.Balance);

در این مثال Primary Constructor داده‌های اصلی object را دریافت می‌کند، Propertyها از Parameterها مقدار می‌گیرند، Validation انجام می‌شود و یک Constructor اضافی نیز از طریق this(...) به Primary Constructor متصل شده است.

✅
خلاصه: Primary Constructor راهی مختصر برای دریافت داده‌ها و dependencyهای اصلی یک type است. Parameterها کنار نام class یا struct تعریف می‌شوند، اما در class معمولی خودبه‌خود Property عمومی ایجاد نمی‌کنند. از آن زمانی استفاده کنید که باعث ساده‌تر و واضح‌ترشدن طراحی شود.
