🧩 Coupling و Cohesion

17.5 — High Cohesion

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

High Cohesion یعنی اعضای یک Class یا Module حول یک هدف مشخص و منسجم کار کنند.

💡
یک Component با High Cohesion را معمولاً می‌توان با یک Responsibility روشن توضیح داد.

مثال

C#
public class PaymentValidator
{
    public void ValidateAmount(decimal amount) { /* ... */ }
    public void ValidateMerchant(string merchantId) { /* ... */ }
    public void ValidateReference(string reference) { /* ... */ }
}

تمام Methodها درباره Payment Validation هستند.

مزایا

  • Readability بهتر
  • Unit Test ساده‌تر
  • تغییرات متمرکزتر
  • نام‌گذاری واضح‌تر
  • Reuse بهتر

High Cohesion یعنی یک Method؟

⚠️
خیر. یک Class می‌تواند چند Method داشته باشد، اگر همه آن‌ها به یک Responsibility منسجم مربوط باشند.

مثال واقعی Fee

C#
public class PaymentFeeCalculator
{
    public decimal CalculatePurchaseFee(decimal amount)
        => amount * 0.01m;

    public decimal CalculateRefundFee(decimal amount)
        => amount * 0.005m;

    public decimal CalculateSettlementFee(decimal amount)
        => amount * 0.002m;
}

نشانه‌های High Cohesion

  • Methodها روی یک مفهوم مشترک کار می‌کنند.
  • Class نام دقیق دارد.
  • Dependencyهای آن با Responsibility اصلی مرتبط‌اند.
  • تغییرات یک نوع Rule در همان Component متمرکز می‌شوند.

نکته مصاحبه‌ای

🎤
High cohesion means a class contains closely related responsibilities that work toward a focused purpose.

جمع‌بندی

High Cohesion یعنی رفتارهای مرتبط را کنار هم نگه داریم؛ نه اینکه Class را صرفاً کوچک کنیم.
