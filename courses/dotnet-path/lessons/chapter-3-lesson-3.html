آشنایی با Static Constructor در C#

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در درس قبل با Constructorهای معمولی آشنا شدیم؛ Constructorهایی که هنگام ساخت یک object با new اجرا می‌شوند. اما گاهی لازم است قبل از اولین استفاده از یک type، اطلاعات مشترک و static آن فقط یک‌بار آماده شود. در C# برای این کار از Static Constructor استفاده می‌کنیم.

💡
Static Constructor برای مقداردهی و آماده‌سازی اعضای static یک type استفاده می‌شود و توسط Runtime به‌صورت خودکار اجرا می‌شود؛ آن را مستقیماً فراخوانی نمی‌کنیم.

Static Constructor چیست؟

Static Constructor یک Constructor ویژه است که به خود type مربوط می‌شود، نه به یک object مشخص. این Constructor معمولاً زمانی کاربرد دارد که مقدار اولیهٔ یک Static Field را نتوانیم با یک مقدار ثابت ساده تعیین کنیم یا برای آماده‌سازی آن به چند دستور نیاز داشته باشیم.

C#
public class BankAccount
{
    public static string BankName { get; }

    static BankAccount()
    {
        BankName = "DotNet Bank";
    }
}

در این مثال BankName متعلق به خود BankAccount است و Static Constructor مقدار اولیهٔ آن را تعیین می‌کند.

C#
Console.WriteLine(
    BankAccount.BankName);

قبل از اولین استفاده‌ای که نیازمند initialize شدن type باشد، Runtime اطمینان حاصل می‌کند Static Constructor اجرا شده است.

ساختار Static Constructor

C#
static BankAccount()
{
    // Static initialization
}

Static Constructor چند قانون مهم دارد:

  • نام آن دقیقاً با نام Class یکسان است.
  • قبل از نام Constructor از static استفاده می‌شود.
  • Access Modifier مانند public یا private ندارد.
  • هیچ Parameterی دریافت نمی‌کند.
  • Return Type ندارد.
  • برای هر type فقط یک Static Constructor می‌توان تعریف کرد.
  • به‌صورت مستقیم توسط برنامه‌نویس فراخوانی نمی‌شود.
⚠️
این تعریف معتبر نیست: public static BankAccount(). Static Constructor نباید Access Modifier داشته باشد.

Static Constructor چه زمانی اجرا می‌شود؟

اجرای Static Constructor را CLR مدیریت می‌کند. این Constructor حداکثر یک‌بار برای هر type اجرا می‌شود و قبل از اولین استفاده‌ای که به initialization آن type نیاز دارد، اجرا خواهد شد.

C#
public class BankAccount
{
    public static string BankName { get; }

    static BankAccount()
    {
        Console.WriteLine(
            "Static Constructor executed");

        BankName = "DotNet Bank";
    }
}
C#
Console.WriteLine(
    BankAccount.BankName);

Console.WriteLine(
    BankAccount.BankName);

با وجود دو بار استفاده از BankName، Static Constructor فقط یک‌بار اجرا می‌شود.

مثال با Static Field

فرض کنید سیستم بانکی هنگام شروع استفاده از BankAccount باید یک شناسهٔ مشترک ایجاد کند:

C#
public class BankAccount
{
    private static readonly Guid _systemId;

    static BankAccount()
    {
        _systemId = Guid.NewGuid();

        Console.WriteLine(
            "BankAccount initialized.");
    }

    public static Guid GetSystemId()
    {
        return _systemId;
    }
}
C#
Guid id1 =
    BankAccount.GetSystemId();

Guid id2 =
    BankAccount.GetSystemId();

Console.WriteLine(id1 == id2);
// True

مقدار _systemId یک‌بار ساخته می‌شود و برای تمام استفاده‌های بعدی همان مقدار باقی می‌ماند.

Static Constructor و static readonly

یکی از کاربردهای رایج Static Constructor مقداردهی Static Readonly Fieldهایی است که مقدارشان در Runtime مشخص می‌شود.

C#
public class PaymentSettings
{
    public static readonly DateTime StartedAt;

    static PaymentSettings()
    {
        StartedAt = DateTime.UtcNow;
    }
}

چون DateTime.UtcNow در Compile Time مشخص نیست، نمی‌توان آن را const کرد؛ اما static readonly برای این سناریو مناسب است.

Static Constructor و Instance Constructor

یک class می‌تواند هم Static Constructor و هم Instance Constructor داشته باشد. این دو مسئولیت متفاوتی دارند.

C#
public class BankAccount
{
    public static string BankName { get; }

    public string AccountNumber { get; }

    static BankAccount()
    {
        BankName = "DotNet Bank";

        Console.WriteLine(
            "Static Constructor");
    }

    public BankAccount(
        string accountNumber)
    {
        AccountNumber = accountNumber;

        Console.WriteLine(
            "Instance Constructor");
    }
}
C#
var account1 =
    new BankAccount("IR-1001");

var account2 =
    new BankAccount("IR-1002");

Static Constructor فقط یک‌بار برای type اجرا می‌شود، اما Instance Constructor برای هر object جدید اجرا می‌شود.

ویژگی Static Constructor Instance Constructor
مربوط به Type / Class Object / Instance
تعداد اجرا حداکثر یک‌بار برای Type برای هر Object
Parameter ندارد می‌تواند داشته باشد
Access Modifier ندارد می‌تواند داشته باشد
فراخوانی توسط Runtime معمولاً هنگام new
هدف اصلی آماده‌سازی Static State آماده‌سازی Instance State

آیا Static Constructor را می‌توان Overload کرد؟

خیر. Static Constructor هیچ Parameterی نمی‌گیرد؛ بنابراین امکان تعریف چند نسخه با Parameter Listهای متفاوت وجود ندارد. هر type حداکثر یک Static Constructor دارد.

C#
public class BankAccount
{
    static BankAccount()
    {
    }

    // Invalid
    // static BankAccount(string name)
    // {
    // }
}

Exception در Static Constructor

باید در Static Constructor با عملیات خطاپذیر با احتیاط برخورد کرد. اگر Static Constructor با Exception شکست بخورد، type ممکن است برای ادامهٔ اجرای برنامه قابل استفاده نباشد و دسترسی‌های بعدی با خطای initialization مواجه شوند.

C#
public class PaymentService
{
    public static string ApiKey { get; }

    static PaymentService()
    {
        ApiKey = LoadApiKey();

        if (string.IsNullOrWhiteSpace(ApiKey))
        {
            throw new InvalidOperationException(
                "API key is not configured.");
        }
    }

    private static string LoadApiKey()
    {
        // Load configuration...
        return "secret-key";
    }
}
⚠️
Static Constructor جای مناسبی برای کارهای سنگین، طولانی یا وابسته به منابع ناپایدار مانند Network Call نیست. شکست initialization یک type می‌تواند اثر گسترده‌ای روی برنامه داشته باشد.

چه زمانی از Static Constructor استفاده کنیم؟

  • مقداردهی پیچیدهٔ Static Fieldها
  • مقداردهی static readonly با مقادیر Runtime
  • آماده‌سازی داده‌ای که فقط یک‌بار برای کل type لازم است
  • اجرای initialization قبل از استفاده از اعضای static مربوط به type

اگر مقداردهی ساده باشد، معمولاً نیازی به Static Constructor نیست:

C#
public class BankAccount
{
    public static readonly string BankName =
        "DotNet Bank";
}

در این مثال مقداردهی مستقیم ساده‌تر و خواناتر است.

مثال کامل

C#
public class BankAccount
{
    private static int _accountCount;

    public static string BankName { get; }

    public static readonly Guid SystemId;

    public string AccountNumber { get; }

    static BankAccount()
    {
        BankName = "DotNet Bank";
        SystemId = Guid.NewGuid();

        Console.WriteLine(
            "BankAccount type initialized.");
    }

    public BankAccount(
        string accountNumber)
    {
        AccountNumber = accountNumber;
        _accountCount++;
    }

    public static int GetAccountCount()
    {
        return _accountCount;
    }
}
C#
Console.WriteLine(
    BankAccount.BankName);

var account1 =
    new BankAccount("IR-1001");

var account2 =
    new BankAccount("IR-1002");

Console.WriteLine(
    BankAccount.SystemId);

Console.WriteLine(
    BankAccount.GetAccountCount());
// 2

Static Constructor اطلاعات مشترک type مانند BankName و SystemId را یک‌بار آماده می‌کند. در مقابل، Instance Constructor برای هر حساب اجرا می‌شود و اطلاعات مربوط به همان object را مدیریت می‌کند.

✅
خلاصه: Static Constructor برای initialize کردن State مشترک یک type است، Parameter و Access Modifier ندارد، مستقیماً فراخوانی نمی‌شود و Runtime اجرای آن را مدیریت می‌کند. برای State هر object همچنان از Instance Constructor استفاده می‌کنیم.
