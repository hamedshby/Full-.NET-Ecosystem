🔗 Coupling در طراحی نرم‌افزار

17.3 — Loose Coupling

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Loose Coupling یعنی Componentها با کمترین knowledge لازم از جزئیات یکدیگر همکاری کنند. Dependency حذف نمی‌شود؛ بلکه از طریق Contractهای مشخص کنترل می‌شود.

💡
Loose Coupling = Controlled Dependency, not Zero Dependency.

Refactoring

C#
public interface IPaymentRepository
{
    Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken);
}

public class PaymentService
{
    private readonly IPaymentRepository _repository;

    public PaymentService(IPaymentRepository repository)
    {
        _repository = repository;
    }
}

Service فقط Contract را می‌شناسد.

Infrastructure Implementation

C#
public class SqlPaymentRepository
    : IPaymentRepository
{
    public Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken)
    {
        // SQL Server
        return Task.CompletedTask;
    }
}

Dependency Injection در ASP.NET Core

C#
builder.Services.AddScoped
    <IPaymentRepository,
     SqlPaymentRepository>();

builder.Services.AddScoped
    <PaymentService>();

جایگزینی Implementation

C#
public class InMemoryPaymentRepository
    : IPaymentRepository
{
    public Task SaveAsync(
        Payment payment,
        CancellationToken cancellationToken)
    {
        // In-memory implementation
        return Task.CompletedTask;
    }
}

PaymentService بدون تغییر می‌تواند Implementation دیگری دریافت کند.

مزایا

  • Change Impact محدودتر
  • Unit Test ساده‌تر
  • جایگزینی Infrastructure آسان‌تر
  • Extension بهتر
  • مرزهای معماری واضح‌تر

مثال Payment Gateway

C#
public interface IPaymentGateway
{
    Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken);
}

public class BankAGateway : IPaymentGateway
{
    public Task<PaymentResult> PayAsync(
        PaymentRequest request,
        CancellationToken cancellationToken)
    {
        // Bank A
        return Task.FromResult(
            PaymentResult.Success());
    }
}

Business Service فقط IPaymentGateway را می‌شناسد و به API بانک خاص گره نمی‌خورد.

Loose Coupling در Microservices

Text
Payment Service
      │
      ▼
PaymentCompleted
      ├──► Notification Service
      ├──► Reporting Service
      └──► Loyalty Service

Event-driven communication در بعضی سناریوها می‌تواند Direct/Temporal Coupling را کاهش دهد.

⚠️
Event-Driven معماری Coupling را صفر نمی‌کند. Event Schema، Semantic Contract و Broker همچنان Dependency هستند.

ارتباط با SOLID

  • DIP: وابستگی High-Level به Abstraction
  • OCP: افزودن Implementation جدید بدون تغییر Consumer
  • ISP: Contractهای کوچک و Client-focused
  • LSP: Implementationهای قابل جایگزینی

Tight vs Loose Coupling

Tight CouplingLoose Coupling
Concrete DetailStable Contract
Change Impact بیشترChange Impact محدودتر
Test سخت‌ترTest ساده‌تر
جایگزینی سختجایگزینی آسان‌تر

آیا Interface همیشه Loose Coupling می‌سازد؟

خیر. اگر Interface جزئیات Provider خاص را Leak کند یا Consumer به رفتار خاص Implementation وابسته باشد، Coupling همچنان بالا می‌ماند.

🎯
Loose Coupling بیشتر از اینکه درباره Keywordهای C# باشد، درباره طراحی Dependency و Contract است.

آیا Loose Coupling همیشه بهتر است؟

نه به هر قیمتی. Abstraction غیرضروری و Interfaceهای بی‌معنی می‌توانند Over-Engineering ایجاد کنند. در Boundaryها و نقاط واقعی Change/Variation از آن استفاده کنید.

نکته مصاحبه‌ای

🎤
Loose coupling means components depend on stable contracts rather than unnecessary implementation details. In .NET, abstractions and Dependency Injection are common techniques for achieving it.

جمع‌بندی

Loose Coupling باعث می‌شود اجزای سیستم با knowledge کمتری از جزئیات یکدیگر همکاری کنند و تغییر، تست و جایگزینی Dependencyها ساده‌تر شود.

✅
Depend on what a component does, not unnecessarily on how it does it.
