🔗 Coupling در طراحی نرم‌افزار

17.1 — Coupling چیست؟

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Coupling میزان وابستگی بین اجزای یک سیستم نرم‌افزاری است؛ یعنی یک Class یا Module چقدر برای کار کردن به Component دیگر و جزئیات آن وابسته است.

💡
هدف طراحی خوب حذف کامل Dependency نیست؛ هدف کنترل Dependencyها و جلوگیری از سرایت غیرضروری تغییرات است.

مثال ساده

C#
public class PaymentService
{
    private readonly PaymentRepository _repository;

    public PaymentService(PaymentRepository repository)
    {
        _repository = repository;
    }

    public Task PayAsync(Payment payment)
    {
        return _repository.SaveAsync(payment);
    }
}

بین PaymentService و PaymentRepository یک Dependency وجود دارد؛ بنابراین این دو Component Coupled هستند.

آیا Coupling همیشه بد است؟

خیر. سیستم واقعی بدون ارتباط بین اجزا ساخته نمی‌شود. مسئله این است که وابستگی چقدر شدید و شکننده باشد.

Coupling بالا چه مشکلاتی دارد؟

  • Change Impact بیشتر
  • Unit Test سخت‌تر
  • جایگزینی Infrastructure دشوارتر
  • Reuse کمتر
  • شکنندگی بیشتر سیستم

مثال در Payment System

C#
public class PaymentService
{
    private readonly SqlPaymentRepository _repository;
    private readonly RabbitMqPublisher _publisher;
    private readonly SmtpEmailSender _emailSender;
}

Business Service مستقیماً سه Detail فنی را می‌شناسد. تغییر SQL Server، RabbitMQ یا Email Provider می‌تواند روی آن اثر بگذارد.

مدل Change برای تشخیص Coupling

🎯
اگر Component A تغییر کند، آیا Component B هم مرتب مجبور به تغییر می‌شود؟ اگر بله، Coupling را بررسی کنید.

High Cohesion + Low Coupling یکی از مدل‌های ذهنی مهم در طراحی نرم‌افزار است.

ارتباط با SOLID

  • SRP مسئولیت‌ها را متمرکز می‌کند.
  • OCP دامنه تغییر را محدود می‌کند.
  • ISP Dependencyهای غیرضروری را کم می‌کند.
  • DIP وابستگی به Concrete Detail را کاهش می‌دهد.

نکته مصاحبه‌ای

🎤
Coupling describes the degree of dependency between software components. Good design aims for lower and controlled coupling, not zero dependency.

جمع‌بندی

Coupling یعنی میزان وابستگی اجزای سیستم. Dependency طبیعی است؛ مهم این است که تغییرات غیرمرتبط به بخش‌های دیگر سرایت نکنند.
