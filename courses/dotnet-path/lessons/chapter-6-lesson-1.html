فصل 6 — Polymorphism

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Polymorphism یا چندریختی یکی از مهم‌ترین مفاهیم Object-Oriented Programming است. ایدهٔ اصلی آن این است که یک قرارداد یا نوع عمومی داشته باشیم، اما objectهای مختلف بتوانند رفتار متفاوتی در پاسخ به همان درخواست نشان دهند. این قابلیت کمک می‌کند کد به‌جای وابستگی به typeهای مشخص، با abstractionها کار کند.

💡
Polymorphism یعنی «یک interface یا base type، چند رفتار متفاوت». مثلاً همهٔ روش‌های پرداخت می‌توانند عملیات Pay() داشته باشند، اما پرداخت با کارت، کیف پول یا درگاه خارجی هرکدام پیاده‌سازی متفاوتی دارند.

6.1 Polymorphism چیست؟

فرض کنید سیستم ما چند نوع حساب بانکی دارد. همهٔ حساب‌ها عملیاتی به نام محاسبهٔ کارمزد دارند، اما نحوهٔ محاسبه می‌تواند برای هر نوع حساب متفاوت باشد.

C#
public class BankAccount
{
    public virtual decimal CalculateFee(
        decimal amount)
    {
        return amount * 0.01m;
    }
}

public class VipBankAccount
    : BankAccount
{
    public override decimal CalculateFee(
        decimal amount)
    {
        return amount * 0.005m;
    }
}

هر دو object متدی با نام یکسان دارند، اما رفتارشان متفاوت است:

C#
BankAccount normal =
    new BankAccount();

BankAccount vip =
    new VipBankAccount();

Console.WriteLine(
    normal.CalculateFee(1_000_000));
// 10000

Console.WriteLine(
    vip.CalculateFee(1_000_000));
// 5000

هر دو متغیر از نوع BankAccount هستند، اما Runtime با توجه به object واقعی تصمیم می‌گیرد کدام implementation اجرا شود.

6.2 Compile-Time Polymorphism

در Compile-Time Polymorphism، Compiler هنگام Compile مشخص می‌کند کدام Method باید فراخوانی شود. یکی از رایج‌ترین نمونه‌های آن در C#، Method Overloading است.

Method Overloading

Method Overloading یعنی چند Method با نام یکسان ولی Parameter List متفاوت داشته باشیم.

C#
public class PaymentService
{
    public void Pay(decimal amount)
    {
        Console.WriteLine(
            $"Pay: {amount}");
    }

    public void Pay(
        decimal amount,
        string description)
    {
        Console.WriteLine(
            $"{description}: {amount}");
    }

    public void Pay(
        decimal amount,
        string description,
        bool sendNotification)
    {
        Console.WriteLine(
            $"{description}: {amount}");

        if (sendNotification)
        {
            Console.WriteLine(
                "Notification sent.");
        }
    }
}
C#
var service =
    new PaymentService();

service.Pay(100_000);

service.Pay(
    100_000,
    "Invoice");

service.Pay(
    100_000,
    "Invoice",
    true);

Compiler با توجه به تعداد و نوع Argumentها انتخاب می‌کند کدام overload باید اجرا شود. به همین دلیل تصمیم‌گیری قبل از Runtime انجام شده است.

⚠️
تفاوت فقط در Return Type برای Overloading کافی نیست. Parameter List باید طوری متفاوت باشد که Compiler بتواند overload مناسب را تشخیص دهد.

6.3 Runtime Polymorphism

در Runtime Polymorphism، Method نهایی بر اساس type واقعی object در زمان اجرا انتخاب می‌شود. در C# این رفتار معمولاً با virtual، override و Base Reference دیده می‌شود.

virtual

Base Class با virtual اعلام می‌کند که Derived Class اجازه دارد implementation این Method را تغییر دهد.

C#
public class Payment
{
    public virtual void Process()
    {
        Console.WriteLine(
            "Processing payment...");
    }
}

override

Derived Class با override نسخهٔ تخصصی رفتار را ارائه می‌کند:

C#
public class CardPayment
    : Payment
{
    public override void Process()
    {
        Console.WriteLine(
            "Processing card payment...");
    }
}

public class WalletPayment
    : Payment
{
    public override void Process()
    {
        Console.WriteLine(
            "Processing wallet payment...");
    }
}

Base Reference

یک reference از نوع Base Class می‌تواند به object از Derived Class اشاره کند:

C#
Payment payment =
    new CardPayment();

payment.Process();

نوع متغیر Payment است، اما object واقعی از نوع CardPayment است.

Dynamic Dispatch

وقتی یک Method مجازی را از طریق Base Reference فراخوانی می‌کنیم، Runtime implementation مناسب را با توجه به نوع واقعی object انتخاب می‌کند. به این فرآیند Dynamic Dispatch گفته می‌شود.

C#
Payment[] payments =
[
    new CardPayment(),
    new WalletPayment()
];

foreach (Payment payment in payments)
{
    payment.Process();
}

خروجی:

Text
Processing card payment...
Processing wallet payment...

حلقه فقط type عمومی Payment را می‌شناسد، اما هر object رفتار واقعی خودش را اجرا می‌کند. این همان قدرت اصلی Runtime Polymorphism است.

چرا Base Reference مهم است؟

بدون Base Reference یا abstraction مشترک، کد معمولاً مجبور می‌شود typeهای واقعی را یکی‌یکی بشناسد. Polymorphism اجازه می‌دهد Client Code فقط قرارداد عمومی را بداند.

C#
public void ExecutePayment(
    Payment payment)
{
    payment.Process();
}

اکنون تمام Derived Typeها قابل ارسال هستند:

C#
ExecutePayment(
    new CardPayment());

ExecutePayment(
    new WalletPayment());

6.4 Method Hiding

Method Hiding با Method Overriding متفاوت است. در Method Hiding، Derived Class عضوی با همان نام Base Class تعریف می‌کند و معمولاً با کلمهٔ کلیدی new اعلام می‌کند که قصد پنهان‌کردن عضو Base Class را دارد.

new

C#
public class Payment
{
    public void PrintStatus()
    {
        Console.WriteLine(
            "Payment status");
    }
}

public class CardPayment
    : Payment
{
    public new void PrintStatus()
    {
        Console.WriteLine(
            "Card payment status");
    }
}

برخلاف override، انتخاب Method در این حالت به نوع reference وابسته است.

C#
CardPayment card =
    new CardPayment();

card.PrintStatus();
// Card payment status

Payment payment = card;

payment.PrintStatus();
// Payment status

object در هر دو حالت همان CardPayment است، اما چون Method مجازی نیست و فقط hide شده، نوع reference روی انتخاب Method اثر می‌گذارد.

تفاوت new و override

ویژگی override new
هدف تخصصی‌کردن رفتار مجازی Base Class پنهان‌کردن عضو Base Class
نیاز به virtual در Base بله، یا عضو abstract/override مناسب خیر
انتخاب Method بر اساس نوع واقعی object در Runtime بیشتر بر اساس نوع reference در Compile Time
Runtime Polymorphism بله خیر، به معنای overriding

مثال مقایسه‌ای

C#
public class Payment
{
    public virtual void Process()
    {
        Console.WriteLine(
            "Base Process");
    }

    public void Print()
    {
        Console.WriteLine(
            "Base Print");
    }
}

public class CardPayment
    : Payment
{
    public override void Process()
    {
        Console.WriteLine(
            "Card Process");
    }

    public new void Print()
    {
        Console.WriteLine(
            "Card Print");
    }
}
C#
Payment payment =
    new CardPayment();

payment.Process();
// Card Process

payment.Print();
// Base Print
💡
اگر هدف شما Runtime Polymorphism است، معمولاً virtual/override همان چیزی است که می‌خواهید. new رفتار متفاوتی دارد و باید آگاهانه استفاده شود.

6.5 مثال واقعی Polymorphism — Payment Processing

فرض کنید سیستم پرداخت سه روش پرداخت دارد:

  • Card Payment
  • Wallet Payment
  • Bank Transfer

یک طراحی ابتدایی ممکن است از if یا switch بزرگ استفاده کند:

C#
public void ProcessPayment(
    string paymentType,
    decimal amount)
{
    if (paymentType == "card")
    {
        Console.WriteLine(
            "Process card payment");
    }
    else if (paymentType == "wallet")
    {
        Console.WriteLine(
            "Process wallet payment");
    }
    else if (paymentType == "bank")
    {
        Console.WriteLine(
            "Process bank transfer");
    }
}

با اضافه‌شدن هر روش پرداخت جدید، این Method باید تغییر کند. اگر همین شرط‌ها در چند نقطه وجود داشته باشند، نگهداری سیستم سخت‌تر می‌شود.

⚠️
وجود هر if یا switch بد نیست. مشکل زمانی است که تصمیم‌گیری بر اساس type در نقاط متعدد تکرار شود و هر رفتار جدید مجبورمان کند کدهای موجود زیادی را تغییر دهیم.

طراحی با Polymorphism

ابتدا یک قرارداد عمومی تعریف می‌کنیم:

C#
public interface IPaymentMethod
{
    void Pay(decimal amount);
}

پرداخت با کارت

C#
public class CardPayment
    : IPaymentMethod
{
    public void Pay(decimal amount)
    {
        Console.WriteLine(
            $"Card payment: {amount}");
    }
}

پرداخت با کیف پول

C#
public class WalletPayment
    : IPaymentMethod
{
    public void Pay(decimal amount)
    {
        Console.WriteLine(
            $"Wallet payment: {amount}");
    }
}

انتقال بانکی

C#
public class BankTransferPayment
    : IPaymentMethod
{
    public void Pay(decimal amount)
    {
        Console.WriteLine(
            $"Bank transfer: {amount}");
    }
}

Payment Processor بدون دانستن نوع واقعی

C#
public class PaymentProcessor
{
    public void Process(
        IPaymentMethod paymentMethod,
        decimal amount)
    {
        paymentMethod.Pay(amount);
    }
}

PaymentProcessor نمی‌داند پرداخت Card است یا Wallet یا Bank Transfer. فقط قرارداد IPaymentMethod را می‌شناسد.

C#
var processor =
    new PaymentProcessor();

processor.Process(
    new CardPayment(),
    500_000);

processor.Process(
    new WalletPayment(),
    250_000);

processor.Process(
    new BankTransferPayment(),
    1_000_000);

اضافه‌کردن روش پرداخت جدید

حالا فرض کنید Crypto Payment اضافه می‌شود:

C#
public class CryptoPayment
    : IPaymentMethod
{
    public void Pay(decimal amount)
    {
        Console.WriteLine(
            $"Crypto payment: {amount}");
    }
}

برای اضافه‌کردن این رفتار نیازی نیست PaymentProcessor تغییر کند:

C#
processor.Process(
    new CryptoPayment(),
    700_000);

این طراحی به اصل Open/Closed نیز نزدیک است: سیستم برای extension باز است، اما برای بسیاری از تغییرات نیازی به دست‌کاری Client Code موجود نداریم.

پردازش مجموعه‌ای از روش‌های پرداخت

C#
List<IPaymentMethod> methods =
[
    new CardPayment(),
    new WalletPayment(),
    new BankTransferPayment(),
    new CryptoPayment()
];

foreach (IPaymentMethod method in methods)
{
    method.Pay(100_000);
}

حلقه هیچ اطلاعی از implementationهای واقعی ندارد؛ فقط می‌داند همهٔ objectها قرارداد IPaymentMethod را پیاده‌سازی کرده‌اند.

قبل و بعد از Polymorphism

طراحی مبتنی بر شرط طراحی Polymorphic
Client باید نوع پرداخت را بشناسد. Client فقط abstraction را می‌شناسد.
افزودن type جدید ممکن است switch را تغییر دهد. معمولاً implementation جدید اضافه می‌شود.
Business Logic ممکن است در شرط‌ها پخش شود. رفتار هر type در class خودش قرار دارد.
Coupling به concrete typeها بیشتر است. وابستگی به قرارداد مشترک است.

مثال کامل Payment Processing

C#
public interface IPaymentMethod
{
    PaymentResult Pay(decimal amount);
}

public record PaymentResult(
    bool IsSuccess,
    string TransactionId);

public class CardPayment
    : IPaymentMethod
{
    public PaymentResult Pay(
        decimal amount)
    {
        Console.WriteLine(
            $"Card: {amount}");

        return new PaymentResult(
            true,
            Guid.NewGuid().ToString());
    }
}

public class WalletPayment
    : IPaymentMethod
{
    public PaymentResult Pay(
        decimal amount)
    {
        Console.WriteLine(
            $"Wallet: {amount}");

        return new PaymentResult(
            true,
            Guid.NewGuid().ToString());
    }
}

public class BankTransferPayment
    : IPaymentMethod
{
    public PaymentResult Pay(
        decimal amount)
    {
        Console.WriteLine(
            $"Bank Transfer: {amount}");

        return new PaymentResult(
            true,
            Guid.NewGuid().ToString());
    }
}

public class PaymentProcessor
{
    public PaymentResult Process(
        IPaymentMethod paymentMethod,
        decimal amount)
    {
        if (amount <= 0)
        {
            throw new ArgumentOutOfRangeException(
                nameof(amount));
        }

        return paymentMethod.Pay(amount);
    }
}
C#
IPaymentMethod paymentMethod =
    new CardPayment();

var processor =
    new PaymentProcessor();

PaymentResult result =
    processor.Process(
        paymentMethod,
        500_000);

Console.WriteLine(
    result.TransactionId);

PaymentProcessor فقط با IPaymentMethod کار می‌کند. اگر بعداً روش پرداخت جدیدی اضافه شود، کافی است قرارداد را پیاده‌سازی کند؛ Processor برای اجرای رفتار جدید نیازی به شناخت concrete type ندارد.

✅
خلاصه: Polymorphism اجازه می‌دهد با یک قرارداد مشترک، objectهای مختلف رفتارهای متفاوت اجرا کنند. Method Overloading نمونه‌ای از Compile-Time Polymorphism است، در حالی که virtual/override و پیاده‌سازی Interfaceها امکان Runtime Polymorphism را فراهم می‌کنند. در طراحی واقعی، این مفهوم می‌تواند شرط‌های وابسته به type را کاهش دهد و توسعهٔ سیستم را ساده‌تر کند.
