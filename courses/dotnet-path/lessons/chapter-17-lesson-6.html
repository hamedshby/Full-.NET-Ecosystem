🧩 Coupling و Cohesion

17.6 — Low Cohesion

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Low Cohesion یعنی یک Class یا Module مجموعه‌ای از Responsibilityهای کم‌ارتباط یا نامرتبط داشته باشد.

مثال اشتباه

C#
public class PaymentManager
{
    public decimal CalculateFee(decimal amount) => amount * 0.01m;
    public void SaveToDatabase() { }
    public void SendEmail() { }
    public void ExportExcel() { }
    public void WriteLog() { }
}

Fee، Persistence، Email، Excel و Logging دلایل تغییر متفاوتی دارند.

مشکلات

  • چند Reason to Change
  • Test پیچیده‌تر
  • Dependencyهای نامرتبط
  • Readability پایین‌تر
  • احتمال God Class

Refactoring

Text
PaymentManager
      ↓
PaymentFeeCalculator
PaymentRepository
PaymentNotifier
PaymentExporter
ApplicationLogger

چطور تشخیص دهیم؟

  • Class را با چند «و همچنین» توصیف می‌کنیم.
  • Methodها Fieldهای کاملاً متفاوتی مصرف می‌کنند.
  • Dependencyها به Domainهای مختلف مربوط‌اند.
  • تیم‌ها به دلایل مستقل همان Class را تغییر می‌دهند.

آیا Class بزرگ همیشه Low Cohesion است؟

🎯
خیر. معیار اصلی ارتباط مفهومی Responsibilityها است، نه تعداد Line یا Method.

نکته مصاحبه‌ای

🎤
Low cohesion means a class contains weakly related or unrelated responsibilities.

جمع‌بندی

Low Cohesion معمولاً با چند Reason to Change و God Class همراه می‌شود و با تفکیک Responsibilityهای نامرتبط Refactor می‌شود.
