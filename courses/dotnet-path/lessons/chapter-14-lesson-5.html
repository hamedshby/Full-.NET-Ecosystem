14.5 — Generics و Polymorphism

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

Generics و Polymorphism دو قابلیت متفاوت در C# هستند، اما وقتی در کنار هم استفاده شوند می‌توانند طراحی‌های بسیار قدرتمند، reusable و type-safe ایجاد کنند. Generics به ما اجازه می‌دهند یک الگوریتم یا ساختار را برای Typeهای مختلف بنویسیم؛ Polymorphism نیز اجازه می‌دهد objectهای متفاوت را از طریق یک قرارداد مشترک استفاده کنیم.

💡
به زبان ساده: Generics می‌گویند «این کد می‌تواند با Typeهای مختلف کار کند»، و Polymorphism می‌گوید «Typeهای مختلف می‌توانند از طریق یک Base Type یا Interface رفتار متفاوت خودشان را اجرا کنند».

مرور کوتاه Polymorphism

فرض کنید چند روش پرداخت داریم که همگی یک قرارداد مشترک را پیاده‌سازی می‌کنند:

C#
public interface IPaymentMethod
{
    void Pay(
        decimal amount);
}

public class CardPayment
    : IPaymentMethod
{
    public void Pay(
        decimal amount)
    {
        Console.WriteLine(
            $"Card payment: {amount}");
    }
}

public class WalletPayment
    : IPaymentMethod
{
    public void Pay(
        decimal amount)
    {
        Console.WriteLine(
            $"Wallet payment: {amount}");
    }
}

اکنون می‌توانیم هر دو implementation را از طریق IPaymentMethod استفاده کنیم:

C#
IPaymentMethod payment =
    new CardPayment();

payment.Pay(
    500_000);

payment =
    new WalletPayment();

payment.Pay(
    500_000);

این Runtime Polymorphism است؛ متدی که اجرا می‌شود به object واقعی بستگی دارد.

Generics کجای این طراحی قرار می‌گیرد؟

حالا فرض کنید می‌خواهیم یک Processor داشته باشیم که با انواع مختلف Payment Method کار کند. می‌توانیم آن را Generic کنیم:

C#
public class PaymentProcessor<T>
    where T : IPaymentMethod
{
    private readonly T
        _paymentMethod;

    public PaymentProcessor(
        T paymentMethod)
    {
        _paymentMethod =
            paymentMethod;
    }

    public void Process(
        decimal amount)
    {
        _paymentMethod.Pay(
            amount);
    }
}

Constraint زیر به Compiler می‌گوید T حتماً باید IPaymentMethod را implement کند:

C#
where T : IPaymentMethod

به همین دلیل داخل Generic Class می‌توانیم با اطمینان متد Pay() را فراخوانی کنیم.

استفاده با Implementationهای مختلف

C#
var cardProcessor =
    new PaymentProcessor<CardPayment>(
        new CardPayment());

cardProcessor.Process(
    500_000);

var walletProcessor =
    new PaymentProcessor<WalletPayment>(
        new WalletPayment());

walletProcessor.Process(
    250_000);

یک Generic Class داریم، اما می‌تواند با چند implementation مختلف از abstraction مشترک کار کند.

🎯
در این طراحی Generics باعث Reusability و Type Safety شده است، در حالی که Interface قرارداد مشترکی را برای رفتار polymorphic مشخص می‌کند.

Generic Constraint و Polymorphism

Generic Constraint پلی مهم بین Generics و OOP است. بدون Constraint، Compiler اطلاعات زیادی دربارهٔ T ندارد.

C#
public class Processor<T>
{
    public void Process(
        T item)
    {
        // Compile Error:
        // item.Pay();
    }
}

اما اگر Constraint تعریف کنیم:

C#
public class Processor<T>
    where T : IPaymentMethod
{
    public void Process(
        T item)
    {
        item.Pay(
            500_000);
    }
}

Compiler اکنون می‌داند هر Typeای که جایگزین T شود، قرارداد IPaymentMethod را دارد.

Generics با Base Class

Polymorphism فقط با Interface نیست. Generic Constraint می‌تواند یک Base Class نیز باشد.

C#
public abstract class Payment
{
    public decimal Amount
    {
        get;
    }

    protected Payment(
        decimal amount)
    {
        Amount = amount;
    }

    public abstract void Process();
}

public class CardPayment
    : Payment
{
    public CardPayment(
        decimal amount)
        : base(amount)
    {
    }

    public override void Process()
    {
        Console.WriteLine(
            "Processing card payment");
    }
}

Generic Processor را می‌توان به تمام Derived Typeهای Payment محدود کرد:

C#
public class PaymentHandler<T>
    where T : Payment
{
    public void Handle(
        T payment)
    {
        payment.Process();
    }
}

اگر T یک Derived Class باشد، فراخوانی Process() همچنان می‌تواند از Runtime Polymorphism استفاده کند.

Dynamic Dispatch داخل Generic Code

فرض کنید دو نوع Payment داریم:

C#
public class CardPayment
    : Payment
{
    public CardPayment(
        decimal amount)
        : base(amount)
    {
    }

    public override void Process()
    {
        Console.WriteLine(
            "Card payment");
    }
}

public class CryptoPayment
    : Payment
{
    public CryptoPayment(
        decimal amount)
        : base(amount)
    {
    }

    public override void Process()
    {
        Console.WriteLine(
            "Crypto payment");
    }
}
C#
var cardHandler =
    new PaymentHandler<CardPayment>();

cardHandler.Handle(
    new CardPayment(
        500_000));

var cryptoHandler =
    new PaymentHandler<CryptoPayment>();

cryptoHandler.Handle(
    new CryptoPayment(
        700_000));

Generic Handler یک الگوریتم مشترک دارد، اما رفتار واقعی Payment توسط implementation مربوط به همان Type اجرا می‌شود.

Generics جایگزین Polymorphism نیست

این دو مفهوم مسئله‌های متفاوتی را حل می‌کنند. برای مثال، اگر فقط بخواهیم مجموعه‌ای از Payment Methodهای مختلف داشته باشیم، ممکن است اصلاً Generic لازم نباشد:

C#
List<IPaymentMethod>
    paymentMethods =
    [
        new CardPayment(),
        new WalletPayment()
    ];

foreach (
    IPaymentMethod paymentMethod
    in paymentMethods)
{
    paymentMethod.Pay(
        500_000);
}

در اینجا خود List<T> Generic است، اما polymorphic behavior از طریق IPaymentMethod اتفاق می‌افتد.

⚠️
فقط به این دلیل که چند implementation داریم، لازم نیست Service خودمان را Generic کنیم. گاهی وابستگی مستقیم به یک Interface ساده‌تر، خواناتر و مناسب‌تر است.

Generic Processor یا Interface Dependency؟

این طراحی را ببینید:

C#
public class PaymentService
{
    private readonly IPaymentMethod
        _paymentMethod;

    public PaymentService(
        IPaymentMethod paymentMethod)
    {
        _paymentMethod =
            paymentMethod;
    }

    public void Process(
        decimal amount)
    {
        _paymentMethod.Pay(
            amount);
    }
}

این Service بدون Generic نیز polymorphic است و در بسیاری از Business Serviceها همین طراحی کافی است.

نسخه Generic:

C#
public class PaymentService<T>
    where T : IPaymentMethod
{
    private readonly T
        _paymentMethod;

    public PaymentService(
        T paymentMethod)
    {
        _paymentMethod =
            paymentMethod;
    }
}

نسخه Generic زمانی ارزش بیشتری دارد که خود Type مشخص T بخشی از API یا رفتار طراحی باشد، یا لازم باشد type-specific information را در Compile Time حفظ کنیم.

مثال واقعی: Generic Repository و Polymorphism

فرض کنید تمام Entityها یک Base Class مشترک دارند:

C#
public abstract class Entity
{
    public Guid Id
    {
        get;
        protected set;
    }
}

public class Customer
    : Entity
{
    public string Name
    {
        get;
        set;
    }
}

public class Transaction
    : Entity
{
    public decimal Amount
    {
        get;
        set;
    }
}

می‌توانیم Repository را Generic طراحی کنیم:

C#
public class Repository<TEntity>
    where TEntity : Entity
{
    private readonly List<TEntity>
        _items = new();

    public void Add(
        TEntity entity)
    {
        _items.Add(entity);
    }

    public TEntity? Find(
        Guid id)
    {
        return _items.FirstOrDefault(
            x => x.Id == id);
    }
}

حالا یک implementation مشترک برای تمام Entityها داریم، اما Type Safety هر Entity حفظ می‌شود:

C#
var customerRepository =
    new Repository<Customer>();

var transactionRepository =
    new Repository<Transaction>();

Generic Constraint اجازه می‌دهد Repository از اعضای Base Class مانند Id استفاده کند.

Generic Interface و Polymorphism

یکی از کاربردهای مهم ترکیب Generics و Polymorphism، Generic Interfaceها هستند.

C#
public interface IHandler<TRequest>
{
    Task HandleAsync(
        TRequest request,
        CancellationToken cancellationToken);
}

برای هر Request می‌توان implementation متفاوتی داشت:

C#
public class CreatePaymentHandler
    : IHandler<CreatePaymentRequest>
{
    public Task HandleAsync(
        CreatePaymentRequest request,
        CancellationToken cancellationToken)
    {
        Console.WriteLine(
            "Create payment");

        return Task.CompletedTask;
    }
}

public class RefundPaymentHandler
    : IHandler<RefundPaymentRequest>
{
    public Task HandleAsync(
        RefundPaymentRequest request,
        CancellationToken cancellationToken)
    {
        Console.WriteLine(
            "Refund payment");

        return Task.CompletedTask;
    }
}

هر Handler همان abstraction عمومی را پیاده‌سازی می‌کند، اما رفتار مخصوص Request خودش را دارد.

مثال نزدیک به CQRS

این الگو در معماری‌هایی مانند CQRS بسیار رایج است:

C#
public interface ICommandHandler
    <TCommand, TResult>
{
    Task<TResult> HandleAsync(
        TCommand command,
        CancellationToken cancellationToken);
}

یک Handler برای Purchase:

C#
public class PurchaseHandler
    : ICommandHandler
        <PurchaseCommand,
         PurchaseResult>
{
    public Task<PurchaseResult>
        HandleAsync(
            PurchaseCommand command,
            CancellationToken cancellationToken)
    {
        // Purchase logic

        return Task.FromResult(
            new PurchaseResult());
    }
}

و Handler دیگری برای Reversal:

C#
public class ReversalHandler
    : ICommandHandler
        <ReversalCommand,
         ReversalResult>
{
    public Task<ReversalResult>
        HandleAsync(
            ReversalCommand command,
            CancellationToken cancellationToken)
    {
        // Reversal logic

        return Task.FromResult(
            new ReversalResult());
    }
}

Generic Interface شکل قرارداد را reusable کرده است و Polymorphism اجازه می‌دهد هر Handler implementation متفاوت خودش را داشته باشد. این ترکیب در بسیاری از Frameworkها و معماری‌های مدرن .NET دیده می‌شود.

Compile-Time Type Safety + Runtime Behavior

یکی از جذاب‌ترین ویژگی‌های ترکیب Generics و Polymorphism این است که می‌توانیم Type Safety را در Compile Time داشته باشیم و در عین حال رفتار متفاوت objectها را در Runtime اجرا کنیم.

C#
public static void Execute<T>(
    T payment,
    decimal amount)
    where T : IPaymentMethod
{
    payment.Pay(
        amount);
}
C#
Execute(
    new CardPayment(),
    500_000);

Execute(
    new WalletPayment(),
    250_000);

Compiler تضمین می‌کند argument قرارداد موردنظر را دارد و implementation واقعی رفتار خودش را اجرا می‌کند.

تفاوت Generic Dispatch و Runtime Polymorphism

مهم است Generics را خودِ Runtime Polymorphism تصور نکنیم. Generic Type Argument معمولاً در Compile Time مشخص و type-safe است؛ اما virtual/interface dispatch تعیین می‌کند کدام implementation در Runtime اجرا شود.

Generics Polymorphism
تمرکز روی Type Parameterها دارد. تمرکز روی رفتار چندشکلی دارد.
Reusability و Type Safety ایجاد می‌کند. جایگزینی implementationها را ممکن می‌کند.
مثل Repository<T> مثل IPaymentMethod.Pay()
Type Argument مشخص می‌شود. رفتار واقعی می‌تواند در Runtime انتخاب شود.
با Constraint می‌تواند قابلیت‌های T را محدود کند. با Interface یا virtual/override قرارداد رفتاری می‌سازد.

مثال کامل: Notification Pipeline

فرض کنید چند نوع Notification داریم:

C#
public interface INotification
{
}

public record PaymentCompleted(
    Guid TransactionId)
    : INotification;

public record PaymentFailed(
    Guid TransactionId,
    string ErrorCode)
    : INotification;

یک Generic Handler تعریف می‌کنیم:

C#
public interface INotificationHandler<T>
    where T : INotification
{
    Task HandleAsync(
        T notification,
        CancellationToken cancellationToken);
}

هر Notification Handler رفتار خودش را دارد:

C#
public class PaymentCompletedHandler
    : INotificationHandler
        <PaymentCompleted>
{
    public Task HandleAsync(
        PaymentCompleted notification,
        CancellationToken cancellationToken)
    {
        Console.WriteLine(
            "Payment completed.");

        return Task.CompletedTask;
    }
}

public class PaymentFailedHandler
    : INotificationHandler
        <PaymentFailed>
{
    public Task HandleAsync(
        PaymentFailed notification,
        CancellationToken cancellationToken)
    {
        Console.WriteLine(
            $"Payment failed: {notification.ErrorCode}");

        return Task.CompletedTask;
    }
}

در این طراحی:

  • Generics قرارداد Handler را reusable کرده است.
  • Constraint مشخص می‌کند فقط Notificationها مجاز هستند.
  • هر Handler implementation متفاوتی دارد.
  • Compiler ارتباط Request و Handler را type-safe نگه می‌دارد.
  • Polymorphism امکان کار از طریق abstraction را فراهم می‌کند.

Generics و Dependency Injection

Generic abstractionها در ASP.NET Core DI نیز بسیار رایج‌اند. برای مثال می‌توان یک Open Generic registration داشت:

C#
public interface IRepository<T>
{
}

public class Repository<T>
    : IRepository<T>
{
}
C#
builder.Services.AddScoped(
    typeof(IRepository<>),
    typeof(Repository<>));

سپس DI Container می‌تواند هنگام نیاز Type بستهٔ مناسب را ایجاد کند:

C#
public class PaymentService
{
    private readonly IRepository<Payment>
        _repository;

    public PaymentService(
        IRepository<Payment> repository)
    {
        _repository =
            repository;
    }
}

اینجا Generic Interface یک abstraction type-safe ایجاد کرده و implementation از طریق Dependency Injection جایگزین‌پذیر است.

چه زمانی Generics و Polymorphism را ترکیب کنیم؟

  • وقتی یک قرارداد مشترک برای چند Type داریم.
  • وقتی باید Type دقیق در Compile Time حفظ شود.
  • وقتی الگوریتم یا infrastructure مشترک است ولی implementationها متفاوت‌اند.
  • در Handlerها، Repositoryها، Pipelineها و Strategyهای type-specific.
  • وقتی Generic Constraint یک abstraction واقعی Domain یا Application را بیان می‌کند.

چه زمانی ترکیب آن‌ها بیش از حد پیچیده می‌شود؟

Generics می‌توانند طراحی را قدرتمند کنند، اما abstractionهای چندلایه و Type Parameterهای زیاد ممکن است خوانایی را کاهش دهند.

C#
// خواندن چنین طراحی‌هایی
// می‌تواند سخت شود:

Processor
    <TRequest,
     TResponse,
     THandler,
     TValidator,
     TStrategy>
⚠️
Generic abstraction را فقط زمانی اضافه کنید که یک الگوی واقعی و تکرارشونده وجود دارد. هدف، طراحی واضح‌تر و reusableتر است؛ نه نمایش پیچیدگی Type System.

اشتباهات رایج

  • تصور اینکه Generics و Polymorphism یک مفهوم هستند.
  • Generic کردن Service فقط چون چند implementation از یک Interface وجود دارد.
  • فراموش کردن Constraint و در نتیجه ناتوانی در استفاده از رفتار موردنیاز روی T.
  • استفاده از Type Parameterهای زیاد و ایجاد abstraction پیچیده.
  • جایگزین کردن inheritance یا interface ساده با Genericهای غیرضروری.
  • تصور اینکه Generic بودن به‌تنهایی Runtime Polymorphism ایجاد می‌کند.

جمع‌بندی 14.5

Generics و Polymorphism دو قابلیت مکمل هستند. Generics امکان نوشتن کد reusable و type-safe برای Typeهای مختلف را فراهم می‌کند، در حالی که Polymorphism اجازه می‌دهد implementationهای متفاوت از طریق یک Base Class یا Interface رفتار مخصوص خودشان را اجرا کنند. Generic Constraints نیز به Generic Code اجازه می‌دهند به abstractionهای OOP تکیه کند.

✅
نکتهٔ کلیدی: Repository<TEntity>، IHandler<TRequest> و ICommandHandler<TCommand, TResult> نمونه‌های خوبی از ترکیب Generics با abstraction و polymorphism هستند. اما اگر یک Interface ساده مسئله را حل می‌کند، Generic کردن طراحی الزاماً آن را بهتر نمی‌کند.
