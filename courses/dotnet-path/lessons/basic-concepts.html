مفاهیم پایه Object-Oriented Programming

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

قبل از اینکه سراغ Encapsulation، Inheritance یا Polymorphism برویم، باید چند مفهوم پایه را کاملاً درک کنیم. تقریباً تمام مباحث شی‌گرایی روی همین مفاهیم ساخته می‌شوند: class، object، State، Behavior، Instance و Reference Type.

💡
اگر تفاوت class و object را خوب بفهمید، بخش بزرگی از OOP برایتان ساده‌تر می‌شود. Class نقشه است؛ Object نمونهٔ واقعی ساخته‌شده از آن نقشه است.

Object چیست؟

Object یک موجودیت در زمان اجرای برنامه است که معمولاً هم داده دارد و هم رفتار. به زبان ساده، object چیزی است که می‌تواند یک وضعیت مشخص داشته باشد و عملیاتی روی آن انجام شود.

فرض کنید در یک سیستم بانکی یک حساب داریم. این حساب می‌تواند شماره حساب و موجودی داشته باشد و عملیات‌هایی مثل واریز و برداشت انجام دهد. چنین حسابی در برنامه می‌تواند یک object باشد.

C#
var account = new BankAccount("IR-1001", 1_000_000);

account.Deposit(500_000);

Console.WriteLine(account.Balance);

در این مثال، متغیر account به یک object از نوع BankAccount اشاره می‌کند. این object موجودی مخصوص خودش را دارد و متد Deposit رفتار آن را مشخص می‌کند.

Class چیست؟

Class یک تعریف یا Blueprint برای ساخت objectها است. Class مشخص می‌کند objectهایی که از آن ساخته می‌شوند چه داده‌هایی دارند و چه رفتارهایی می‌توانند انجام دهند.

برای مثال، اگر قرار باشد صدها حساب بانکی در برنامه داشته باشیم، برای تک‌تک آن‌ها ساختار جدا تعریف نمی‌کنیم. یک class به نام BankAccount می‌سازیم و سپس هر تعداد object که نیاز داریم از روی آن ایجاد می‌کنیم.

C#
public class BankAccount
{
    public string AccountNumber { get; }
    public decimal Balance { get; private set; }

    public BankAccount(string accountNumber, decimal initialBalance)
    {
        AccountNumber = accountNumber;
        Balance = initialBalance;
    }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}

در این class، دو داده به نام‌های AccountNumber و Balance داریم و یک رفتار به نام Deposit. هر object ساخته‌شده از این class همین ساختار را دارد، اما مقدار داده‌های آن می‌تواند متفاوت باشد.

State و Behavior چیست؟

یکی از مهم‌ترین ایده‌های OOP این است که object معمولاً دو بخش اصلی دارد:

  • State: وضعیت فعلی object؛ یعنی داده‌ها و مقادیری که در یک لحظه در object نگهداری می‌شوند.
  • Behavior: کارهایی که object می‌تواند انجام دهد؛ معمولاً از طریق methodها بیان می‌شوند.

State

در مثال حساب بانکی، شماره حساب و موجودی بخشی از State هستند:

C#
public string AccountNumber { get; }
public decimal Balance { get; private set; }

Behavior

عملیات‌هایی مانند واریز یا برداشت Behavior حساب هستند:

C#
public void Deposit(decimal amount)
{
    Balance += amount;
}

public void Withdraw(decimal amount)
{
    Balance -= amount;
}
✅
در طراحی شی‌گرای خوب، State و Behavior مرتبط کنار هم قرار می‌گیرند. یعنی object فقط یک کیسهٔ داده نیست؛ خودش مسئول رفتار مرتبط با داده‌هایش نیز هست.

Instance چیست؟

Instance یعنی یک نمونهٔ واقعی از یک class. وقتی با استفاده از new از یک class object می‌سازیم، در واقع یک instance از آن class ایجاد کرده‌ایم.

C#
var account1 = new BankAccount("IR-1001", 1_000_000);
var account2 = new BankAccount("IR-2002", 5_000_000);

اینجا account1 و account2 دو instance متفاوت از class BankAccount هستند. هر دو از یک class ساخته شده‌اند، اما State مستقل دارند.

Instance AccountNumber Balance
account1 IR-1001 1,000,000
account2 IR-2002 5,000,000

بنابراین عبارت‌های object و instance در بسیاری از گفتگوهای روزمره تقریباً به‌جای هم استفاده می‌شوند. بااین‌حال وقتی می‌گوییم «instance of BankAccount»، روی این موضوع تأکید داریم که آن object از یک class مشخص ساخته شده است.

Reference Type چیست؟

در C#، یک class از نوع Reference Type است. یعنی متغیری که برای یک object تعریف می‌کنیم معمولاً خود object را نگه نمی‌دارد؛ بلکه یک reference به آن object را نگه می‌دارد.

C#
var account1 = new BankAccount("IR-1001", 1_000_000);
var account2 = account1;

account2.Deposit(500_000);

Console.WriteLine(account1.Balance); // 1500000

در این مثال، object جدیدی برای account2 ساخته نشده است. هر دو متغیر به همان object اشاره می‌کنند. بنابراین وقتی از طریق account2 موجودی را تغییر می‌دهیم، این تغییر از طریق account1 نیز دیده می‌شود.

⚠️
عبارت var account2 = account1; برای یک class به معنی کپی‌کردن کامل object نیست؛ فقط reference کپی می‌شود.

مقایسه کوتاه Reference Type و Value Type

موضوع Reference Type Value Type
نمونه‌ها class، string، array int، bool، decimal، struct
Assignment reference کپی می‌شود خود مقدار کپی می‌شود
تغییر از طریق متغیر دوم ممکن است همان object را تغییر دهد روی مقدار قبلی اثری ندارد

ارتباط Class و Object

ساده‌ترین تشبیه این است که Class را نقشهٔ ساخت و Object را چیزی بدانیم که بر اساس آن نقشه ساخته شده است.

مثلاً نقشهٔ یک ساختمان مشخص می‌کند ساختمان چند اتاق دارد، درها کجا هستند و ساختار آن چگونه است؛ اما خود نقشه ساختمان واقعی نیست. از روی یک نقشه می‌توان چند ساختمان ساخت. در OOP نیز class تعریف می‌کند object چه ساختاری دارد و از روی آن می‌توان چند object مستقل ایجاد کرد.

C#
// Class
public class Customer
{
    public string Name { get; set; }
}

// Objects / Instances
var customer1 = new Customer { Name = "Ali" };
var customer2 = new Customer { Name = "Sara" };
var customer3 = new Customer { Name = "Reza" };
مفهوم توضیح ساده مثال
Class تعریف و نقشهٔ ساخت object BankAccount
Object یک موجودیت واقعی در Runtime حساب IR-1001
State وضعیت فعلی object Balance = 1,000,000
Behavior کاری که object انجام می‌دهد Deposit()
Instance نمونه‌ای ساخته‌شده از یک class new BankAccount(...)
Reference Type متغیر به object اشاره می‌کند class

یک مثال کامل

C#
public class BankAccount
{
    public string AccountNumber { get; }
    public decimal Balance { get; private set; }

    public BankAccount(string accountNumber, decimal initialBalance)
    {
        AccountNumber = accountNumber;
        Balance = initialBalance;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount));

        Balance += amount;
    }
}

var account = new BankAccount("IR-1001", 1_000_000);
account.Deposit(250_000);

Console.WriteLine(account.AccountNumber);
Console.WriteLine(account.Balance);

در این مثال، BankAccount یک class است؛ account یک instance یا object است؛ AccountNumber و Balance State هستند؛ و Deposit() Behavior است. چون BankAccount یک class است، object ساخته‌شده از آن نیز Reference Type محسوب می‌شود.

🎯
جمع‌بندی: Class تعریف می‌کند چه چیزی می‌توان ساخت؛ Object نمونهٔ واقعی ساخته‌شده است؛ Instance همان نمونه از یک Class مشخص است؛ State وضعیت object را نگه می‌دارد؛ Behavior عملیات آن را بیان می‌کند؛ و objectهای ساخته‌شده از class در C# از نوع Reference Type هستند.
