14.1 — Generic Class

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در C#، Generic Class کلاسی است که به‌جای وابستگی به یک Type مشخص، می‌تواند با Typeهای مختلف کار کند. به این ترتیب یک بار ساختار و رفتار Class را طراحی می‌کنیم و هنگام استفاده مشخص می‌کنیم که آن Class دقیقاً با چه Typeای کار کند.

💡
Generics به ما کمک می‌کنند کدی بنویسیم که هم Reusable باشد و هم Type-Safe. یعنی بدون تکرار یک منطق برای Typeهای مختلف، همچنان کنترل Typeها را در Compile Time حفظ کنیم.

مشکل قبل از Generic Class

فرض کنید می‌خواهیم یک Class ساده داشته باشیم که یک مقدار را نگهداری کند. اگر فقط با int کار کنیم، می‌توانیم چنین Classی بنویسیم:

C#
public class IntBox
{
    public int Value
    {
        get;
        set;
    }
}

اگر برای string هم همین قابلیت را بخواهیم، ممکن است Class دیگری بسازیم:

C#
public class StringBox
{
    public string Value
    {
        get;
        set;
    }
}

و برای decimal دوباره:

C#
public class DecimalBox
{
    public decimal Value
    {
        get;
        set;
    }
}

این Classها تقریباً یک کار انجام می‌دهند و فقط Type آن‌ها متفاوت است. این یعنی Code Duplication.

راه‌حل با Generic Class

با Generic Class می‌توانیم Type را به یک Parameter تبدیل کنیم:

C#
public class Box<T>
{
    public T Value
    {
        get;
        set;
    }
}

در اینجا T یک Type Parameter است. هنگام تعریف Class هنوز نمی‌دانیم T دقیقاً چه Typeای خواهد بود.

T چیست؟

T یک نام قراردادی برای Type Parameter است. حرف T معمولاً مخفف Type در نظر گرفته می‌شود، اما اجباری نیست.

C#
public class Box<T>
{
    public T Value
    {
        get;
        set;
    }
}

وقتی از Class استفاده می‌کنیم، Type واقعی را مشخص می‌کنیم:

C#
var numberBox =
    new Box<int>();

numberBox.Value =
    100;

var nameBox =
    new Box<string>();

nameBox.Value =
    "Hamed";

در Box<int>، تمام جاهایی که T استفاده شده به int مربوط می‌شوند. در Box<string> نیز T به string مربوط است.

Generic Class و Type Safety

یکی از مزیت‌های مهم Generics این است که Type مورد انتظار در Compile Time مشخص است.

C#
var box =
    new Box<int>();

box.Value = 100;

// Compile Error:
// box.Value = "Hamed";

چون این object از نوع Box<int> است، Property مربوط به Value فقط مقدار int می‌پذیرد.

🎯
Generic به معنی «هر چیزی را قبول کن» نیست. برعکس، Generic یعنی Class را برای Typeهای مختلف قابل استفاده کنیم، اما هر بار Type دقیق آن را مشخص و کنترل کنیم.

Generic Class با Constructor

Generic Class می‌تواند Constructor داشته باشد و مقدار Generic را هنگام ساخت object دریافت کند.

C#
public class Box<T>
{
    public T Value
    {
        get;
    }

    public Box(
        T value)
    {
        Value = value;
    }
}
C#
var idBox =
    new Box<int>(
        1001);

var nameBox =
    new Box<string>(
        "Hamed");

استفاده از T در Method

Type Parameter تعریف‌شده روی Class را می‌توان در Propertyها، Fieldها، Constructorها و Methodهای همان Class استفاده کرد.

C#
public class Storage<T>
{
    private T? _value;

    public void Save(
        T value)
    {
        _value = value;
    }

    public T? Get()
    {
        return _value;
    }
}
C#
var storage =
    new Storage<string>();

storage.Save(
    "Payment completed");

string? message =
    storage.Get();

Generic Class با Collection

یکی از کاربردهای طبیعی Generic Class، نگهداری مجموعه‌ای از objectها با Type مشخص است. خود .NET نیز collectionهایی مانند List<T> را بر همین اساس ارائه می‌دهد.

C#
public class MemoryStore<T>
{
    private readonly List<T>
        _items = new();

    public void Add(
        T item)
    {
        _items.Add(item);
    }

    public IReadOnlyList<T> GetAll()
    {
        return _items;
    }
}

اکنون می‌توانیم همان Class را برای Customer استفاده کنیم:

C#
var customerStore =
    new MemoryStore<Customer>();

customerStore.Add(
    new Customer());

و همان Class را برای Transaction:

C#
var transactionStore =
    new MemoryStore<Transaction>();

transactionStore.Add(
    new Transaction());

منطق ذخیره‌سازی را یک بار نوشته‌ایم، اما برای Typeهای مختلف از آن استفاده می‌کنیم.

Generic Class با چند Type Parameter

یک Generic Class محدود به یک Type Parameter نیست. می‌توان چند Type Parameter تعریف کرد.

C#
public class Pair<TKey, TValue>
{
    public TKey Key
    {
        get;
    }

    public TValue Value
    {
        get;
    }

    public Pair(
        TKey key,
        TValue value)
    {
        Key = key;
        Value = value;
    }
}
C#
var transaction =
    new Pair<string, decimal>(
        "TX-1001",
        500_000);

Console.WriteLine(
    transaction.Key);

Console.WriteLine(
    transaction.Value);

در این مثال:

  • TKey با string جایگزین شده است.
  • TValue با decimal جایگزین شده است.

نام‌گذاری Type Parameterها

اگر فقط یک Type Parameter ساده داریم، T معمولاً کافی است. اما وقتی چند Type Parameter یا نقش مشخص داریم، نام‌های معنادار خوانایی را بهتر می‌کنند.

C#
public class Repository<TEntity>
{
}

public class Result<TData>
{
}

public class Cache<TKey, TValue>
{
}

نام‌هایی مثل TEntity، TKey و TValue intent طراحی را بهتر نشان می‌دهند.

Generic Class در .NET

Generics فقط قابلیتی برای Classهای خودمان نیستند. بخش بزرگی از APIهای .NET بر پایه Generics طراحی شده‌اند.

C#
List<string> names =
    new();

Dictionary<string, decimal>
    balances =
        new();

HashSet<Guid> transactionIds =
    new();

Task<PaymentResult> result;

در تمام این مثال‌ها Type داخل <...> مشخص می‌کند Generic Type با چه داده‌ای کار خواهد کرد.

Generic Class و Reusability

فرض کنید برای Responseهای API یک ساختار مشترک داریم:

C#
public class ApiResponse<T>
{
    public bool IsSuccess
    {
        get;
        init;
    }

    public T? Data
    {
        get;
        init;
    }

    public string? Error
    {
        get;
        init;
    }
}

برای دریافت Customer:

C#
ApiResponse<Customer>
    customerResponse =
        new()
        {
            IsSuccess = true,
            Data = customer
        };

برای دریافت Transaction:

C#
ApiResponse<Transaction>
    transactionResponse =
        new()
        {
            IsSuccess = true,
            Data = transaction
        };

نیازی نیست CustomerApiResponse، TransactionApiResponse و ده‌ها Class مشابه بسازیم.

مثال واقعی: Generic Repository

یکی از مثال‌های شناخته‌شده برای درک Generic Class، Repository است. فرض کنید چند Entity مختلف داریم و عملیات پایه برای آن‌ها مشابه است.

C#
public class Repository<TEntity>
{
    private readonly List<TEntity>
        _items = new();

    public void Add(
        TEntity entity)
    {
        _items.Add(entity);
    }

    public IReadOnlyList<TEntity> GetAll()
    {
        return _items;
    }
}

Repository مربوط به Customer:

C#
var customerRepository =
    new Repository<Customer>();

customerRepository.Add(
    new Customer());

Repository مربوط به Payment:

C#
var paymentRepository =
    new Repository<Payment>();

paymentRepository.Add(
    new Payment());

منطق پایهٔ Repository فقط یک بار نوشته شده است و Type واقعی Entity هنگام استفاده مشخص می‌شود. در پروژه‌های واقعی Repository معمولاً dependencyهایی مانند DbContext نیز دارد و طراحی آن می‌تواند پیچیده‌تر باشد؛ این مثال صرفاً برای درک Generic Class است.

Generic Class و OOP

Generics جایگزین OOP نیستند. آن‌ها می‌توانند در کنار Encapsulation، Abstraction و Polymorphism استفاده شوند.

C#
public class Result<T>
{
    public bool IsSuccess
    {
        get;
    }

    public T? Value
    {
        get;
    }

    public string? Error
    {
        get;
    }

    private Result(
        bool isSuccess,
        T? value,
        string? error)
    {
        IsSuccess = isSuccess;
        Value = value;
        Error = error;
    }

    public static Result<T> Success(
        T value)
    {
        return new Result<T>(
            true,
            value,
            null);
    }

    public static Result<T> Failure(
        string error)
    {
        return new Result<T>(
            false,
            default,
            error);
    }
}

در این مثال Generic بودن باعث Reusability شده و Encapsulation نیز اجازه نمی‌دهد object در وضعیت نامعتبر ساخته شود.

Generic Typeهای مختلف، Typeهای متفاوت هستند

نکتهٔ مهم این است که Box<int> و Box<string> یک Type یکسان نیستند. هرکدام یک constructed generic type متفاوت هستند.

C#
Box<int> numberBox =
    new(100);

Box<string> textBox =
    new("Hello");

// Compile Error:
// numberBox = textBox;

Generic بودن Type Safety را حذف نمی‌کند؛ بلکه Type Safety را همراه با Reusability فراهم می‌کند.

Generic Class و object

قبل از Generics ممکن بود برای عمومی‌کردن یک Class از object استفاده شود:

C#
public class ObjectBox
{
    public object? Value
    {
        get;
        set;
    }
}

مشکل این طراحی این است که تقریباً هر چیزی می‌تواند داخل آن قرار بگیرد:

C#
var box =
    new ObjectBox();

box.Value = 100;

box.Value = "Hamed";

box.Value =
    new Customer();

هنگام خواندن نیز ممکن است Cast لازم باشد:

C#
int number =
    (int)box.Value!;

اگر Type واقعی اشتباه باشد، خطا ممکن است در Runtime رخ دهد.

نسخه Generic

C#
var box =
    new Box<int>(
        100);

int number =
    box.Value;
💡
Generics معمولاً نسبت به استفادهٔ عمومی از object، Type Safety بهتر و نیاز کمتر به Cast ایجاد می‌کنند. برای Value Typeها نیز می‌توانند از Boxingهای غیرضروری در بسیاری از سناریوها جلوگیری کنند.

آیا داخل Generic Class هر کاری با T می‌توانیم انجام دهیم؟

خیر. وقتی Compiler فقط می‌داند یک مقدار از نوع T است، نمی‌تواند فرض کند آن Type Method یا Property خاصی دارد.

C#
public class Printer<T>
{
    public void Print(
        T value)
    {
        // Compiler cannot assume:
        // value.Pay();
        // value.Save();
    }
}

برای اینکه Compiler دربارهٔ قابلیت‌های T اطلاعات بیشتری داشته باشد، از Generic Constraints استفاده می‌کنیم که در بخش 14.4 به‌صورت کامل بررسی خواهد شد.

مثال Payment Processing

فرض کنید نتیجهٔ عملیات مختلف Payment System ساختار یکسانی دارد، اما Data آن‌ها متفاوت است.

C#
public class OperationResult<TData>
{
    public bool IsSuccessful
    {
        get;
        init;
    }

    public TData? Data
    {
        get;
        init;
    }

    public string? ErrorCode
    {
        get;
        init;
    }
}

نتیجهٔ Purchase:

C#
var purchaseResult =
    new OperationResult<PurchaseResponse>
    {
        IsSuccessful = true,
        Data =
            new PurchaseResponse()
    };

نتیجهٔ Balance Inquiry:

C#
var balanceResult =
    new OperationResult<BalanceResponse>
    {
        IsSuccessful = true,
        Data =
            new BalanceResponse()
    };

ساختار Result ثابت مانده، اما نوع Data متناسب با هر operation تغییر کرده است. این یکی از کاربردهای بسیار رایج Generic Class در پروژه‌های واقعی است.

مزایای Generic Class

  • کاهش Code Duplication
  • افزایش Reusability
  • Type Safety در Compile Time
  • کاهش نیاز به Cast
  • امکان طراحی APIهای عمومی و در عین حال strongly typed
  • استفادهٔ مجدد از یک الگوریتم یا ساختار برای Typeهای مختلف

چه زمانی Generic Class مناسب است؟

وقتی رفتار یا ساختار اصلی برای چند Type یکسان است و فقط Type داده تغییر می‌کند، Generic Class ارزش بررسی دارد.

مثال‌های رایج

  • Result<T>
  • ApiResponse<T>
  • Repository<TEntity>
  • Cache<TKey, TValue>
  • Queue<T>
  • List<T>

چه زمانی Generic نسازیم؟

صرف اینکه دو Class کمی شبیه هم هستند دلیل کافی برای Generic کردن آن‌ها نیست. اگر رفتار Domain آن‌ها متفاوت است، Generic abstraction ممکن است طراحی را پیچیده و مبهم کند.

⚠️
هدف Generics حذف هر نوع تکرار نیست. Generic زمانی مفید است که یک abstraction واقعی و مشترک وجود داشته باشد و تفاوت اصلی Type داده باشد. Genericهای بیش از حد پیچیده می‌توانند خوانایی کد را کاهش دهند.

ویژگی‌های مهم Generic Class

مفهوم توضیح
Type Parameter Typeای مانند T که هنگام تعریف هنوز مشخص نشده است.
Type Argument Type واقعی مانند int یا Customer هنگام استفاده
Type Safety Typeها در Compile Time بررسی می‌شوند.
Reusability یک Class برای Typeهای مختلف قابل استفاده است.
Multiple Type Parameters مانند Dictionary<TKey, TValue>
Constraints می‌توان Typeهای مجاز برای T را محدود کرد.

اشتباهات رایج

  • تصور اینکه T یعنی object.
  • تصور اینکه Generic باعث حذف Type Safety می‌شود.
  • Generic کردن Classهایی که abstraction مشترک واقعی ندارند.
  • استفاده از نام‌های نامفهوم برای چند Type Parameter.
  • فرض اینکه می‌توان هر Method دلخواهی را روی T صدا زد.
  • پیچیده‌کردن طراحی فقط برای جلوگیری از چند خط تکرار.
🎯
قاعدهٔ ذهنی خوب: اگر می‌توانید جملهٔ «این Class یک رفتار ثابت دارد، اما باید با چند Type مختلف کار کند» را دربارهٔ طراحی خود بگویید، Generic Class احتمالاً گزینهٔ مناسبی است.

جمع‌بندی 14.1

Generic Class به ما اجازه می‌دهد Classهایی reusable و type-safe طراحی کنیم که با Typeهای مختلف کار می‌کنند. Type Parameterهایی مانند T هنگام تعریف نقش placeholder دارند و هنگام استفاده با Type واقعی جایگزین می‌شوند. این قابلیت در بسیاری از APIهای اصلی .NET مانند List<T>، Dictionary<TKey, TValue> و Task<T> استفاده شده است.

✅
نکتهٔ کلیدی: Generics ترکیبی از Reusability + Type Safety را فراهم می‌کنند. به‌جای ساخت چند Class مشابه یا استفادهٔ بی‌رویه از object، می‌توان یک Generic Class طراحی کرد و Type واقعی را هنگام استفاده مشخص کرد.
