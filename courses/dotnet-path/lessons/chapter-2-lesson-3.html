آشنایی با Properties در C#

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در کلاس‌های C# معمولاً نمی‌خواهیم Fieldهای داخلی را مستقیماً در اختیار کد بیرونی قرار دهیم. Property راهی کنترل‌شده برای خواندن یا تغییر State یک object فراهم می‌کند و یکی از مهم‌ترین ابزارهای Encapsulation در C# است.

💡
Property از بیرون شبیه یک متغیر استفاده می‌شود، اما پشت آن می‌توان منطق خواندن، نوشتن، اعتبارسنجی یا محدودیت دسترسی قرار داد.

Property چیست؟

فرض کنید کلاس BankAccount یک Field خصوصی برای موجودی دارد. اگر بخواهیم کد بیرون کلاس بتواند موجودی را بخواند، لازم نیست Field را public کنیم؛ می‌توانیم یک Property ارائه کنیم.

C#
public class BankAccount
{
    private decimal _balance;

    public decimal Balance
    {
        get
        {
            return _balance;
        }
    }
}

اکنون کد بیرون می‌تواند Balance را بخواند، اما نمی‌تواند مستقیماً مقدار _balance را تغییر دهد. این همان چیزی است که Property را برای Encapsulation مفید می‌کند.

Getter و Setter

یک Property می‌تواند دو accessor اصلی داشته باشد: get برای خواندن مقدار و set برای تغییر مقدار.

C#
public class Customer
{
    private string _name;

    public string Name
    {
        get
        {
            return _name;
        }

        set
        {
            _name = value;
        }
    }
}

در Setter، کلمهٔ کلیدی value همان مقداری است که هنگام assignment به Property ارسال شده است.

C#
var customer = new Customer();

customer.Name = "Hamed";

Console.WriteLine(customer.Name);

در customer.Name = "Hamed"، مقدار "Hamed" داخل Setter از طریق value در دسترس است.

محدود کردن Setter

Getter و Setter می‌توانند سطح دسترسی متفاوتی داشته باشند. این قابلیت برای محافظت از State بسیار کاربردی است.

C#
public class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}

کد بیرونی می‌تواند موجودی را بخواند، اما فقط خود کلاس اجازه دارد آن را تغییر دهد.

C#
var account = new BankAccount();

account.Deposit(500_000);

Console.WriteLine(account.Balance);

// Compile Error
// account.Balance = 10_000_000;

Auto Property

اگر Getter و Setter منطق خاصی نداشته باشند، می‌توان از Auto-Implemented Property استفاده کرد. در این حالت C# Field پنهان موردنیاز را خودش ایجاد می‌کند.

C#
public class Customer
{
    public string Name { get; set; }
    public string Email { get; set; }
}

برای Auto Property می‌توان مقدار اولیه هم تعریف کرد:

C#
public class BankAccount
{
    public string Currency { get; set; } = "IRR";
    public decimal Balance { get; private set; } = 0;
}
💡
وقتی هیچ منطق خاصی برای Getter یا Setter ندارید، Auto Property معمولاً خواناتر و ساده‌تر از تعریف دستی backing field است.

Read-only Property

گاهی Property باید از بیرون فقط قابل خواندن باشد. یکی از روش‌ها تعریف Property با Getter و بدون Setter عمومی است.

C#
public class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}

از دید مصرف‌کنندهٔ کلاس، Balance فقط قابل خواندن است؛ اما خود BankAccount می‌تواند آن را تغییر دهد.

یک Getter-only Property نیز می‌تواند به شکل زیر تعریف شود:

C#
public class BankAccount
{
    public string AccountNumber { get; }

    public BankAccount(string accountNumber)
    {
        AccountNumber = accountNumber;
    }
}
نوع Property خواندن از بیرون تغییر از بیرون کاربرد
{ get; set; } بله بله Read/Write Property
{ get; private set; } بله خیر تغییر کنترل‌شده داخل Class
{ get; } بله خیر Getter-only Property

Init-only Property

با init می‌توان Property را هنگام ایجاد object مقداردهی کرد، اما بعد از پایان initialization دیگر اجازهٔ تغییر آن را نداد.

C#
public class Customer
{
    public string NationalCode { get; init; }
    public string Name { get; init; }
}
C#
var customer = new Customer
{
    NationalCode = "1234567890",
    Name = "Hamed"
};

// Compile Error
// customer.NationalCode = "9999999999";

این قابلیت برای objectهایی که پس از ایجاد نباید به‌راحتی تغییر کنند بسیار مناسب است.

Property Validation

Setter می‌تواند قبل از پذیرفتن مقدار جدید، آن را بررسی کند. این ویژگی اجازه می‌دهد object از State نامعتبر جلوگیری کند.

C#
public class Customer
{
    private string _name;

    public string Name
    {
        get => _name;

        set
        {
            if (string.IsNullOrWhiteSpace(value))
                throw new ArgumentException(
                    "Name cannot be empty.",
                    nameof(value));

            _name = value;
        }
    }
}
C#
var customer = new Customer();

customer.Name = "Hamed";

// Exception
// customer.Name = "";

Setter اجازه نمی‌دهد یک نام خالی وارد State شیء شود. بنابراین خود object بخشی از قوانین معتبر بودن State را کنترل می‌کند.

⚠️
همهٔ قوانین Domain را داخل Setter قرار ندهید. اگر تغییر یک مقدار یک رفتار مهم کسب‌وکار است، Methodی مثل ChangeAccountNumber() ممکن است مفهوم و Intent روشن‌تری داشته باشد.

Expression-bodied Property

اگر Getter فقط یک عبارت ساده را برمی‌گرداند، می‌توان آن را با syntax کوتاه => نوشت.

C#
public class BankAccount
{
    private decimal _balance;

    public decimal Balance => _balance;
}

این شکل کوتاه‌ترِ همان Getter معمولی است:

C#
public decimal Balance
{
    get
    {
        return _balance;
    }
}

Computed Property

Expression-bodied Property برای مقادیری که از Stateهای دیگر محاسبه می‌شوند بسیار مناسب است.

C#
public class Customer
{
    public string FirstName { get; set; }
    public string LastName { get; set; }

    public string FullName => $"{FirstName} {LastName}";
}

مقایسه انواع Property

نوع Syntax کاربرد
Auto Property { get; set; } خواندن و نوشتن ساده
Private Setter { get; private set; } تغییر State فقط توسط خود Class
Read-only { get; } فقط خواندن
Init-only { get; init; } مقداردهی هنگام initialization
Expression-bodied => expression Getter یا مقدار محاسباتی ساده

مثال کامل

C#
public class BankAccount
{
    private string _ownerName;

    public Guid Id { get; init; }

    public string AccountNumber { get; init; }

    public decimal Balance { get; private set; }

    public string OwnerName
    {
        get => _ownerName;

        set
        {
            if (string.IsNullOrWhiteSpace(value))
                throw new ArgumentException(
                    "Owner name is required.");

            _ownerName = value;
        }
    }

    public bool HasBalance => Balance > 0;

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount));

        Balance += amount;
    }
}
C#
var account = new BankAccount
{
    Id = Guid.NewGuid(),
    AccountNumber = "IR-1001",
    OwnerName = "Hamed"
};

account.Deposit(500_000);

Console.WriteLine(account.Balance);
Console.WriteLine(account.HasBalance);

در این مثال Id و AccountNumber فقط هنگام initialization مقدار می‌گیرند، Balance فقط توسط رفتارهای داخل class تغییر می‌کند، OwnerName Validation دارد و HasBalance یک Expression-bodied Property محاسباتی است.

✅
Property فقط syntax زیباتری برای Field نیست؛ ابزاری برای طراحی مرز دسترسی به State است. مشخص می‌کند چه چیزی قابل خواندن است، چه چیزی قابل تغییر است، چه زمانی قابل تغییر است و هنگام تغییر چه قوانینی باید رعایت شوند.
