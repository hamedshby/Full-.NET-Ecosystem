🧠 Domain-Driven Design

21.6 — Domain Service

📅 به‌روزرسانی: ۱۴۰۵/۰۶/۱۵
⏱️ زمان مطالعه: ۱۲ دقیقه
👤 تیم فنی

Domain Service برای Business Behaviorای استفاده می‌شود که متعلق به Domain است اما به‌طور طبیعی روی یک Entity یا Value Object خاص قرار نمی‌گیرد.

💡
Domain Service باید Business Meaning داشته باشد؛ SaveToSql یا CallHttp به‌تنهایی Domain Service نیستند.

مثال Payment Fee

C#
public class PaymentFeeService
{
    public Money CalculateFee(
        Merchant merchant,
        PaymentChannel channel,
        Money amount)
    {
        var rate =
            merchant.IsVip
                ? 0.005m
                : 0.01m;

        return new Money(
            amount.Amount * rate,
            amount.Currency);
    }
}

چه زمانی مناسب است؟

  • Rule چند Entity یا Value Object را درگیر می‌کند.
  • Behavior متعلق به یک Object خاص نیست.
  • Business Concept مستقلی دارد.

Domain Service vs Application Service

Domain Service Application Service
Business Rule Use Case orchestration
Domain Layer Application Layer
ترجیحاً بدون Infrastructure detail Repository/Gateway را هماهنگ می‌کند

نکته مصاحبه‌ای

🎤
A domain service models domain behavior that does not naturally belong to a single entity or value object.

جمع‌بندی

Domain Service محل Business Behavior بی‌صاحب است، نه محل ریختن Logicهای پراکنده.
