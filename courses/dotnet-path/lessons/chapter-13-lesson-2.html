13.2 — Struct

📅 به‌روزرسانی: ۱۴۰۵/۰۵/۲۳
⏱️ زمان مطالعه: ۱۸ دقیقه
👤 تیم فنی

در C#، struct برای تعریف یک Value Type سفارشی استفاده می‌شود. Structها برای مدل‌کردن داده‌های کوچک و منسجمی مناسب‌اند که معمولاً با «مقدارشان» معنا پیدا می‌کنند، نه با Identity مستقل. نمونه‌های رایج در .NET شامل DateTime، Guid و decimal هستند.

💡
مهم‌ترین تفاوت ذهنی Struct و Class این است که Struct Value Semantics دارد. در assignment یا passing معمولی، مقدار Struct کپی می‌شود؛ در حالی که برای Class معمولاً reference کپی می‌شود.

Struct چیست؟

Struct یک User-Defined Value Type است و می‌تواند مانند Class اعضایی مثل Property، Method و Constructor داشته باشد.

C#
public struct Money
{
    public decimal Amount
    {
        get;
        set;
    }

    public string Currency
    {
        get;
        set;
    }

    public void Print()
    {
        Console.WriteLine(
            $"{Amount} {Currency}");
    }
}

می‌توان از Struct نیز با new مقدار ساخت:

C#
var money =
    new Money
    {
        Amount = 500_000,
        Currency = "IRR"
    };

money.Print();

Struct یک Value Type است

وقتی یک Struct را به متغیر دیگری assign می‌کنیم، مقدار آن کپی می‌شود.

C#
var money1 =
    new Money
    {
        Amount = 100_000,
        Currency = "IRR"
    };

var money2 =
    money1;

money2.Amount =
    500_000;

Console.WriteLine(
    money1.Amount);
// 100000

Console.WriteLine(
    money2.Amount);
// 500000

برخلاف Class، تغییر money2 باعث تغییر money1 نمی‌شود، چون دو مقدار مستقل داریم.

Text
money1

│ Amount = 100000    │
│ Currency = "IRR"   │
└────────────────────┘

          copy

money2
┌────────────────────┐
│ Amount = 500000    │
│ Currency = "IRR"   │
└────────────────────┘

Struct و Class در Assignment

Class Struct
Reference Type است. Value Type است.
Assignment معمولاً reference را کپی می‌کند. Assignment مقدار را کپی می‌کند.
دو متغیر ممکن است به یک object اشاره کنند. دو متغیر معمولاً مقدار مستقل دارند.

Struct و Methodها

Struct می‌تواند Behavior هم داشته باشد و فقط یک container برای data نیست.

C#
public struct Money
{
    public decimal Amount
    {
        get;
        set;
    }

    public string Currency
    {
        get;
        set;
    }

    public Money Add(
        Money other)
    {
        if (Currency != other.Currency)
        {
            throw new InvalidOperationException(
                "Currencies must match.");
        }

        return new Money
        {
            Amount =
                Amount + other.Amount,

            Currency =
                Currency
        };
    }
}
C#
var money1 =
    new Money
    {
        Amount = 100_000,
        Currency = "IRR"
    };

var money2 =
    new Money
    {
        Amount = 200_000,
        Currency = "IRR"
    };

var result =
    money1.Add(money2);

Console.WriteLine(
    result.Amount);
// 300000

Constructor در Struct

Struct می‌تواند Constructor داشته باشد و از نسخه‌های جدید C# امکان تعریف parameterless constructor نیز وجود دارد. اما Struct همیشه یک حالت default نیز دارد که در آن Fieldها و Propertyهای ذخیره‌شده مقدار پیش‌فرض type خود را می‌گیرند.

C#
public struct Money
{
    public decimal Amount
    {
        get;
    }

    public string Currency
    {
        get;
    }

    public Money(
        decimal amount,
        string currency)
    {
        Amount = amount;
        Currency = currency;
    }
}
C#
var money =
    new Money(
        500_000,
        "IRR");

مقدار default

C#
Money money = default;

Console.WriteLine(
    money.Amount);
// 0

Console.WriteLine(
    money.Currency is null);
// True
⚠️
برای Struct باید همیشه به حالت default فکر کنید. اگر type شما فقط زمانی معتبر است که حتماً Constructor خاصی اجرا شود، Struct ممکن است نیازمند طراحی دقیق‌تری باشد.

Mutable Struct

Struct می‌تواند Mutable باشد، اما Mutable Structها در کد واقعی می‌توانند رفتارهای گیج‌کننده‌ای ایجاد کنند؛ چون در نقاط مختلف کپی می‌شوند.

C#
public struct Counter
{
    public int Value
    {
        get;
        set;
    }

    public void Increment()
    {
        Value++;
    }
}

در ظاهر ساده است، اما وقتی این Struct از property، collection یا APIهای مختلف عبور کند، کپی شدن آن می‌تواند باعث شود تغییر روی نسخه‌ای انجام شود که انتظارش را نداریم.

💡
به همین دلیل برای بسیاری از Structهای Domain، طراحی immutable یا readonly struct معمولاً انتخاب امن‌تر و قابل‌فهم‌تری است.

readonly struct

با readonly struct می‌توان اعلام کرد که instance بعد از ساخته‌شدن نباید State قابل‌تغییر داشته باشد.

C#
public readonly struct Money
{
    public decimal Amount
    {
        get;
    }

    public string Currency
    {
        get;
    }

    public Money(
        decimal amount,
        string currency)
    {
        Amount = amount;
        Currency = currency;
    }
}

این طراحی برای Value Typeهایی مثل Money معمولاً طبیعی‌تر است.

Struct و Equality

Value Typeها رفتار Equality متفاوتی از Classهای معمولی دارند. برای Structها، ValueType.Equals() به‌صورت پیش‌فرض بر اساس Fieldهای instance عمل می‌کند.

C#
public readonly struct Coordinate
{
    public double X
    {
        get;
    }

    public double Y
    {
        get;
    }

    public Coordinate(
        double x,
        double y)
    {
        X = x;
        Y = y;
    }
}
C#
var point1 =
    new Coordinate(
        10,
        20);

var point2 =
    new Coordinate(
        10,
        20);

Console.WriteLine(
    point1.Equals(point2));
// True

با این حال، برای typeهای performance-sensitive یا semantics خاص، می‌توان Equality را صریح‌تر با IEquatable<T> پیاده‌سازی کرد.

Struct و Operator ==

برای Struct سفارشی، operator == به‌صورت خودکار برای همهٔ structها وجود ندارد. اگر بخواهیم از آن استفاده کنیم باید در صورت نیاز خودمان تعریفش کنیم، یا از record struct استفاده کنیم.

C#
public readonly struct Money
{
    public decimal Amount { get; }

    public Money(decimal amount)
    {
        Amount = amount;
    }

    public static bool operator ==(
        Money left,
        Money right)
    {
        return
            left.Amount ==
            right.Amount;
    }

    public static bool operator !=(
        Money left,
        Money right)
    {
        return !(left == right);
    }

    public override bool Equals(
        object? obj)
    {
        return obj is Money other
            && Amount == other.Amount;
    }

    public override int GetHashCode()
    {
        return Amount.GetHashCode();
    }
}

Struct و Inheritance

Struct نمی‌تواند از Class یا Struct دیگری ارث‌بری کند و نمی‌تواند Base Class برای Struct یا Class دیگری باشد. اما می‌تواند Interface پیاده‌سازی کند.

C#
public interface IPrintable
{
    string Print();
}

public readonly struct Money
    : IPrintable
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(
        decimal amount,
        string currency)
    {
        Amount = amount;
        Currency = currency;
    }

    public string Print()
    {
        return
            $"{Amount} {Currency}";
    }
}

Struct و Boxing

وقتی یک Value Type باید به object یا بعضی interfaceها تبدیل شود، ممکن است Boxing اتفاق بیفتد. در Boxing، مقدار داخل یک object روی managed heap قرار می‌گیرد.

C#
int number = 10;

object boxed =
    number;

برای Struct سفارشی نیز همین مفهوم وجود دارد:

C#
Money money =
    new Money(
        500_000,
        "IRR");

object boxedMoney =
    money;

Unboxing

C#
Money original =
    (Money)boxedMoney;
⚠️
Boxing می‌تواند allocation و هزینهٔ اضافی ایجاد کند. معمولاً نباید فقط به خاطر «سریع‌تر بودن» سراغ Struct برویم؛ اندازهٔ type، الگوی استفاده، کپی شدن و Boxing همگی در performance واقعی اهمیت دارند.

Struct کجا ذخیره می‌شود؟

عبارت معروف «Struct روی Stack است» بیش از حد ساده است. Struct یک Value Type است، اما محل فیزیکی داده به context بستگی دارد.

C#
public class Payment
{
    public Money Amount
    {
        get;
        set;
    }
}

در این مثال Money به‌عنوان بخشی از object مربوط به Payment نگهداری می‌شود. بنابراین مفهوم Value Type را نباید با «همیشه Stack» یکی بدانیم.

Passing Struct to Methods

Struct به‌صورت پیش‌فرض By Value پاس داده می‌شود؛ یعنی یک کپی از مقدار به Method می‌رسد.

C#
static void ChangeAmount(
    Money money)
{
    money.Amount =
        900_000;
}

var money =
    new Money
    {
        Amount = 100_000,
        Currency = "IRR"
    };

ChangeAmount(money);

Console.WriteLine(
    money.Amount);
// 100000

Method روی یک کپی کار کرده است. برای Structهای بزرگ، در سناریوهای performance-sensitive می‌توان از in برای ارسال read-only reference استفاده کرد.

C#
static decimal ReadAmount(
    in Money money)
{
    return money.Amount;
}

چه زمانی Struct انتخاب مناسبی است؟

Struct معمولاً گزینهٔ خوبی است وقتی:

  • type کوچک است.
  • مفهوم آن Value-based است.
  • Identity مستقل ندارد.
  • بهتر است immutable باشد.
  • معمولاً به polymorphic class hierarchy نیاز ندارد.
  • کپی شدن مقدار از نظر معنایی طبیعی است.

مثال‌های مناسب

  • Coordinate
  • Range
  • Percentage
  • Small Measurement Value
  • بعضی Value Objectهای کوچک

چه زمانی Struct انتخاب خوبی نیست؟

  • Object دارای Identity و Lifecycle مستقل است.
  • State بزرگ و سنگین دارد و زیاد کپی می‌شود.
  • نیاز به Class Inheritance داریم.
  • Shared reference semantics موردنیاز است.
  • Mutable بودن type باعث کپی‌های گیج‌کننده می‌شود.

مثال واقعی: Percentage

Percentage نمونه‌ای مناسب از یک Value Type کوچک و immutable است:

C#
public readonly struct Percentage
    : IEquatable<Percentage>
{
    public decimal Value
    {
        get;
    }

    public Percentage(
        decimal value)
    {
        if (value < 0 ||
            value > 100)
        {
            throw new ArgumentOutOfRangeException(
                nameof(value));
        }

        Value = value;
    }

    public decimal ApplyTo(
        decimal amount)
    {
        return amount *
            (Value / 100m);
    }

    public bool Equals(
        Percentage other)
    {
        return Value ==
            other.Value;
    }

    public override bool Equals(
        object? obj)
    {
        return obj is Percentage other
            && Equals(other);
    }

    public override int GetHashCode()
    {
        return Value.GetHashCode();
    }

    public override string ToString()
    {
        return $"{Value}%";
    }
}
C#
var feePercent =
    new Percentage(2.5m);

decimal fee =
    feePercent.ApplyTo(
        1_000_000);

Console.WriteLine(fee);
// 25000

Percentage Identity مستقلی ندارد؛ مقدار 2.5% در هر جای برنامه همان مفهوم را دارد. این type کوچک، immutable و Value-based است و بنابراین Struct می‌تواند انتخاب مناسبی برای آن باشد.

اشتباهات رایج

  • گفتن اینکه Struct همیشه روی Stack ذخیره می‌شود.
  • انتخاب Struct فقط به امید performance بهتر.
  • ساخت Mutable Struct بزرگ.
  • فراموش کردن اینکه assignment و parameter passing می‌تواند باعث copy شود.
  • نادیده گرفتن حالت default.
  • استفاده از Struct برای Entity دارای Identity و Lifecycle.
  • نادیده گرفتن Boxing در APIهایی که با object یا interface کار می‌کنند.
🎯
قاعدهٔ ذهنی خوب: اگر مفهوم شما بیشتر شبیه «یک مقدار» است تا «یک شیء دارای هویت»، کوچک است و copy شدن آن طبیعی است، Struct ارزش بررسی دارد. اگر Identity، Lifecycle و shared reference behavior مهم‌اند، Class معمولاً گزینهٔ طبیعی‌تری است.

جمع‌بندی 13.2

Struct در C# یک Value Type سفارشی است. هنگام assignment و passing معمولی، مقدار آن کپی می‌شود. Struct می‌تواند Property، Method، Constructor و Interface داشته باشد، اما Class Inheritance ندارد. برای typeهای کوچک، Value-based و ترجیحاً immutable بسیار مناسب است. در عین حال باید هزینهٔ copy، Boxing، حالت default و مشکلات Mutable Structها را در طراحی در نظر گرفت.

✅
نکتهٔ کلیدی: تفاوت واقعی Struct و Class فقط «Stack در برابر Heap» نیست. تفاوت مهم‌تر، Value Semantics در برابر Reference Semantics است. Struct را زمانی انتخاب کنید که کپی شدن مقدار و نبود Identity مستقل با مفهوم Domain شما سازگار باشد.
