Generic Type در CLR چگونه ساخته و اجرا می‌شود؟

پاسخ کوتاه مصاحبه‌ای

Genericها در CLR reified هستند؛ definition و type argumentهای ساخته‌شده در metadata و Runtime قابل‌شناسایی‌اند. JIT می‌تواند برای Reference Typeها code را share و برای Value Typeها code تخصصی تولید کند، اما جزئیات به Runtime وابسته است.

مدل ذهنی ساده

List<int> و List<string> فقط نام‌های حذف‌شونده پس از Compile نیستند؛ Runtime می‌داند هرکدام چه type argumentی دارند. با Reflection می‌توان definition یعنی List<> و argument یعنی int یا string را دید. این شناخت اجازه می‌دهد type safety تا Runtime و metadata حفظ شود.

توضیح کامل

Compiler کد C# را همراه Generic metadata به IL تبدیل می‌کند. هنگام استفاده از یک constructed type، CLR layout و constraintها را می‌شناسد و JIT machine code لازم را تولید می‌کند. Reference Type instantiationها اغلب representation مشابه دارند و امکان code sharing بیشتر است؛ Value Typeها layout متفاوت دارند و specialization می‌تواند Boxing را حذف کند. این توضیح یک الگوی رایج است نه تضمین تعداد دقیق native bodyها در تمام نسخه‌ها و modeهای AOT/JIT.

C#
static int SizeOfList<T>(List<T> items) => items.Count;
var a = SizeOfList(new List<string>());
var b = SizeOfList(new List<int>());
// هر دو constructed generic type در runtime قابل مشاهده‌اند.

رفتار مثال: Reflection روی Dictionary<string,int> دو Generic Argument واقعی را برمی‌گرداند. method Count<T> برای List<string> و List<object> ممکن است machine code مشترک داشته باشد، درحالی‌که List<int> به‌دلیل layout value به code متفاوت نیاز پیدا کند. semantics هر سه همچنان type-safe و یکسان با قرارداد source است.

نکات کلیدی

  • Generic type argumentها در CLR حذف نمی‌شوند.
  • metadata definition و constructed type را نگه می‌دارد.
  • code sharing و specialization جزئیات Runtime هستند.

اشتباهات رایج

  • گفتن اینکه generics فقط syntax compiler است
  • تضمین کد جدا برای هر نوع reference.

جزئیات عمیق‌تر

از reification نتیجه نگیرید که برای هر T حتماً native code کاملاً جدا ساخته می‌شود. Tiered Compilation، ReadyToRun و Native AOT تصویر را تغییر می‌دهند. برای تصمیم Performance، allocation، code size و throughput را در target runtime واقعی اندازه بگیرید.

در پروژهٔ واقعی

در reflection می‌توان generic definition و arguments را دید؛ در performance از benchmark استفاده کنید.

جمع‌بندی برای مصاحبه

reification، metadata، JIT و تفاوت احتمالی reference/value instantiation را با احتیاط توضیح دهید.
