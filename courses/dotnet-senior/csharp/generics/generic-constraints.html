متوسطزمان مطالعه: ۶ دقیقه

Constraintهای Generic چه هستند و چگونه طراحی API را بهتر می‌کنند؟

پاسخ کوتاه مصاحبه‌ای

Generic Constraint به Compiler می‌گوید T چه قراردادی دارد؛ مانند class، struct، notnull، base class، interface یا new(). در نتیجه implementation می‌تواند memberهای تضمین‌شده را بدون cast فراخوانی کند.

مدل ذهنی ساده

بدون constraint، درباره T تقریباً هیچ چیز جز قواعد مشترک typeها نمی‌دانیم. اگر algorithm باید CompareTo را صدا بزند، قرارداد where T : IComparable<T> همان capability موردنیاز را اعلام می‌کند. constraint برای محدودکردن تصادفی caller نیست؛ باید دلیل واقعی implementation را بیان کند.

توضیح کامل

constraintها هم Compile Time validation می‌دهند و هم surface قابل‌استفاده در بدنه Generic را تعیین می‌کنند. می‌توان چند interface و یک base constraint را ترکیب کرد، اما ترتیب syntax قواعد مشخص دارد. new() constructor بدون parameter عمومی را تضمین می‌کند. notnull بیشتر با nullable analysis مرتبط است. constraintهای unmanaged، enum و delegate سناریوهای خاص را پوشش می‌دهند. constraint بیش‌ازحد reuse را کاهش و evolution API را سخت می‌کند.

C#
static T Max<T>(T left, T right) where T : IComparable<T>
    => left.CompareTo(right) >= 0 ? left : right;

static T Create<T>() where T : new() => new T();

رفتار مثال: در Max<T> where T : IComparable<T>، call به CompareTo ایمن است و استفاده با type فاقد این interface در Compile Time رد می‌شود. اگر فقط خواندن property Id لازم است، یک IHasId کوچک بهتر از مجبورکردن T به ارث از base class سنگین است. new() تنها construction بدون argument را تضمین می‌کند.

نکات کلیدی

  • constraint قابلیت‌های T را برای Compiler تضمین می‌کند.
  • کمترین قرارداد لازم انعطاف بیشتری حفظ می‌کند.
  • constraint جای validation داده‌های Runtime را نمی‌گیرد.

اشتباهات رایج

  • استفاده از new() وقتی factory بهتر است
  • constraint بیش‌ازحد و کاهش reuse.

جزئیات عمیق‌تر

where T : class و where T : notnull معنای یکسان ندارند؛ اولی Reference Type بودن را محدود می‌کند و دومی nullability contract را. static abstract memberهای interface امکان Generic Math را فراهم کرده‌اند و algorithm می‌تواند operatorهای type-safe را از constraint دریافت کند. در طراحی public API اثر هر constraint بر سازگاری آینده را بسنجید.

در پروژهٔ واقعی

الگوریتم مرتب‌سازی به IComparable نیاز دارد؛ persistence شاید به interface دامنه‌ای روشن‌تر نیاز داشته باشد.
