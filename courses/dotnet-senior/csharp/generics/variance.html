Covariance و Contravariance در C# چیست؟

پاسخ کوتاه مصاحبه‌ای

Covariance با out برای producer است: IEnumerable<Dog> را می‌توان به IEnumerable<Animal> داد. Contravariance با in برای consumer است: مصرف‌کننده Animal می‌تواند جای مصرف‌کننده Dog استفاده شود.

مدل ذهنی ساده

قانون حفظی روشن است: producer خروجی می‌دهد، پس out؛ consumer ورودی می‌گیرد، پس in. فهرستی که فقط Dog تولید می‌کند با خیال راحت Animal هم تولید می‌کند. عملی که هر Animal را می‌پذیرد حتماً می‌تواند Dog را نیز بپذیرد. اگر type هم می‌خواند و هم می‌نویسد، معمولاً Invariant است.

توضیح کامل

variance روی Generic Interface و delegate declaration تعریف می‌شود و conversion آن فقط برای Reference Type argumentها کاربرد دارد. parameter covariant نباید در موقعیت ورودی مصرف شود، جز قواعد خاص delegate؛ parameter contravariant نباید به‌عنوان خروجی بازگردد. IEnumerable<out T> فقط T تولید می‌کند و IComparer<in T> T را مصرف می‌کند. این محدودیت‌ها همان چیزی است که conversion را type-safe نگه می‌دارد.

C#
IEnumerable<string> names = new List<string>();
IEnumerable<object> objects = names; // covariance

Action<object> logObject = x => Console.WriteLine(x);
Action<string> logText = logObject; // contravariance

رفتار مثال: IEnumerable<string> به IEnumerable<object> تبدیل می‌شود چون sequence فقط string بیرون می‌دهد و هر string یک object است. Action<object> می‌تواند در متغیر Action<string> قرار گیرد چون functionی که هر object را می‌پذیرد string را هم می‌پذیرد. جهت دوم هر دو conversion ایمن نیست.

نکات کلیدی

  • producer با `out` Covariant است.
  • consumer با `in` Contravariant است.
  • type خواندنی‌ونویشتنی معمولاً Invariant می‌ماند.

اشتباهات رایج

  • حفظ‌کردن جملهٔ «جهت بالا/پایین» بدون producer/consumer
  • انتظار variance برای List.

جزئیات عمیق‌تر

variance conversion با Inheritance خود Generic Type متفاوت است؛ List<T> همچنان Invariant است. Value Type argumentها variance conversion نمی‌گیرند، چون conversion reference موردنیاز وجود ندارد. هنگام طراحی interface، parameter را فقط وقتی variant اعلام کنید که تمام memberها واقعاً جهت producer یا consumer را رعایت می‌کنند.

در پروژهٔ واقعی

event handler یا comparer نمونهٔ consumer است؛ stream نتایج نمونهٔ producer.
