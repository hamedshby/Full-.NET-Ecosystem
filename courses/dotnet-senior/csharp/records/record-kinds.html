ارشدزمان مطالعه: ۸ دقیقه

record class، record struct و readonly record struct چه تفاوتی دارند؟

پاسخ کوتاه مصاحبه‌ای

record و record class Reference Type هستند؛ record struct Value Type است؛ readonly record struct نیز Value Type است و تغییر propertyهای instance را محدود می‌کند. هرکدام Value Equality تولیدشده دارند، اما copy semantics آن‌ها متفاوت است.

مدل ذهنی ساده

واژه record شکل equality و data-oriented syntax را انتخاب می‌کند؛ واژه class یا struct خانواده type و رفتار assignment را. بنابراین ابتدا Reference Type یا Value Type بودن را تصمیم بگیرید، سپس از مزایای record استفاده کنید. record بدون واژه دوم همان record class است.

توضیح کامل

record class با assignment reference را کپی می‌کند و with object بیرونی تازه‌ای می‌سازد. record struct در assignment خود value را کپی می‌کند و به‌صورت پیش‌فرض می‌تواند mutable باشد. readonly record struct برای value کوچک و immutable مناسب است و Compiler از mutation اعضای instance جلوگیری می‌کند. positional syntax برای هر سه constructor و propertyهای اصلی را می‌سازد، ولی نوع property تولیدشده و امکان set/init طبق شکل declaration تفاوت دارد.

C#
public record class CustomerDto(int Id, string Name);
public record struct Pixel(byte R, byte G, byte B);
public readonly record struct Coordinate(double X, double Y);

رفتار مثال: PersonRecord که record class است با assignment مشترک می‌ماند، اما PointRecord که record struct است در assignment مستقل کپی می‌شود. readonly record struct Money(decimal Amount, string Currency) اجازه نمی‌دهد پس از ساخت Amount تغییر کند و برای یک value کوچک intent واضحی دارد.

نکات کلیدی

  • record بدون qualifier همان record class است.
  • record struct رفتار کپی Value Type دارد.
  • readonly record struct برای value کوچک و immutable مناسب است.

اشتباهات رایج

  • فرض immutable بودن record struct
  • استفاده از struct بزرگ در API پرتردد.

جزئیات عمیق‌تر

بزرگ‌کردن record struct هزینه کپی را بالا می‌برد و memberهای reference داخل آن همچنان به object مشترک اشاره می‌کنند. readonly فقط خود fieldها و propertyهای instance را محدود می‌کند و objectهای nested را immutable نمی‌سازد. انتخاب نهایی باید با semantics و سپس اندازه‌گیری Performance انجام شود.

در پروژهٔ واقعی

Coordinate کوچک و immutable مناسب readonly record struct است؛ DTO با graph ارجاعی record class باقی می‌ماند.
