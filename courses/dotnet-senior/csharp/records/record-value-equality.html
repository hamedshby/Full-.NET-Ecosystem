Value Equality Recordها چگونه پیاده‌سازی می‌شود؟

پاسخ کوتاه مصاحبه‌ای

Value Equality در record یعنی دو instance وقتی برابرند که Runtime Type سازگار و componentهای equality آن‌ها برابر باشند. Compiler Equals، == و GetHashCode هماهنگ تولید می‌کند.

مدل ذهنی ساده

به‌جای پرسیدن «آیا این دو متغیر به یک object اشاره می‌کنند؟»، record می‌پرسد «آیا داده‌ای که این value را تعریف می‌کند برابر است؟». مثل دو اسکناس دیجیتال با Currency و Amount یکسان. بااین‌حال اگر component داخلی خودش Reference Equality داشته باشد، record آن را خودکار به deep equality تبدیل نمی‌کند.

توضیح کامل

برای positional record، propertyهای اصلی وارد equality می‌شوند و memberهای instance مرتبط نیز طبق قواعد تولیدشده مشارکت دارند. EqualityContract کمک می‌کند recordهای derived با type متفاوت صرفاً به‌خاطر componentهای مشابه برابر نشوند. GetHashCode باید با equality سازگار بماند؛ تغییر member مؤثر در equality پس از قراردادن record در Dictionary یا HashSet می‌تواند lookup را خراب کند. memberهای collection نیز equality خودشان را به record منتقل می‌کنند.

C#
public record Point(int X, int Y);
var a = new Point(2, 3);
var b = new Point(2, 3);
Console.WriteLine(a == b); // True

رفتار مثال: دو Point(2, 3) برابر و hash آن‌ها سازگار است. اما دو record که هرکدام یک List<int> جدا با عناصر یکسان دارند، الزاماً برابر نیستند چون List به‌صورت پیش‌فرض reference-based مقایسه می‌شود. همچنین mutation یک property پس از افزودن به HashSet ممکن است object را در bucket اشتباه باقی بگذارد.

نکات کلیدی

  • equality تولیدشده به componentها و Runtime Type وابسته است.
  • componentهای nested رفتار equality خود را حفظ می‌کنند.
  • member مؤثر در hash نباید هنگام عضویت در hash collection تغییر کند.

اشتباهات رایج

  • قرار دادن record mutable در HashSet و سپس تغییر عضو
  • انتظار مقایسهٔ محتوایی Listها.

جزئیات عمیق‌تر

اگر deep structural equality برای collectionها لازم است، یک type مناسب immutable یا comparer صریح طراحی کنید. override کردن equality record ممکن است، اما باید Equals و GetHashCode هماهنگ بمانند. برای امنیت طراحی، recordهای استفاده‌شده به‌عنوان key را immutable نگه دارید.

در پروژهٔ واقعی

کلید cache باید immutable و دارای اجزای equality پایدار باشد؛ record برای این سناریو مناسب است.

جمع‌بندی برای مصاحبه

تولید Equals/GetHashCode/operator را بگویید و دربارهٔ اعضای reference و mutation هشدار دهید.
