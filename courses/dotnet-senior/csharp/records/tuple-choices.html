تفاوت ValueTuple، Tuple و نوع اختصاصی برای بازگرداندن چند مقدار چیست؟

پاسخ کوتاه مصاحبه‌ای

ValueTuple مانند (int Id, string Name) یک Value Type کم‌حجم برای چند خروجی موقت است؛ Tuple<T...> یک Reference Type قدیمی‌تر است؛ type نام‌دار مانند record وقتی معنا، validation یا قرارداد پایدار مهم است انتخاب بهتری است.

مدل ذهنی ساده

Tuple یک بسته موقت از چند value است، نه یک مدل دامنه کامل. اگر caller بلافاصله نتیجه را باز می‌کند و نام‌ها واضح‌اند، (bool Found, User? User) خواناست. اگر داده در چند لایه حرکت می‌کند یا rule دارد، UserLookupResult معنای پایدارتر و قابل‌توسعه‌تری می‌دهد.

توضیح کامل

ValueTuple با assignment کپی می‌شود، mutable است و equality component-wise دارد. نام elementها عمدتاً metadata و کمک Compiler هستند و هویت type را عوض نمی‌کنند؛ (int X, int Y) و (int A, int B) type سازگار دارند. System.Tuple object روی Heap است و propertyهایی مانند Item1 دارد. tuple طولانی، nested یا دارای چند مقدار هم‌type به‌سادگی اشتباه استفاده می‌شود و افزودن behavior یا validation به آن دشوار است.

C#
static (bool Found, User? Value) Find(int id)
    => cache.TryGetValue(id, out var u) ? (true, u) : (false, null);

var (found, user) = Find(42);

رفتار مثال: method با return (bool Success, string? Error) برای نتیجه داخلی ساده قابل‌فهم است و caller می‌تواند آن را deconstruct کند. برای پاسخ API شامل Status، ErrorCode و RetryAfter، record نام‌دار بهتر است چون معنا و evolution را روشن می‌کند. کپی ValueTuple مستقل است، مگر componentهای آن reference به object mutable باشند.

نکات کلیدی

  • ValueTuple یک Value Type و مناسب داده موقت است.
  • نام elementها قرارداد type مستقل ایجاد نمی‌کنند.
  • برای مدل پایدار و دارای behavior از type نام‌دار استفاده کنید.

اشتباهات رایج

  • tuple با شش مقدار نامفهوم
  • فرض سازگاری قراردادی نام عناصر.

جزئیات عمیق‌تر

deconstruction فقط مخصوص tuple نیست و هر type می‌تواند method مناسب Deconstruct داشته باشد. تغییر نام element tuple معمولاً binary identity را تغییر نمی‌دهد، اما روی خوانایی source اثر دارد. در public API، record یا class نام‌دار نسخه‌پذیری و documentation بهتری فراهم می‌کند.
