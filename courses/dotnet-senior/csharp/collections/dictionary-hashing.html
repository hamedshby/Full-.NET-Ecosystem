Dictionary چگونه کار می‌کند و Hash خوب چه ویژگی دارد؟

پاسخ کوتاه مصاحبه‌ای

Dictionary<TKey,TValue> ابتدا با hash کلید محدوده جست‌وجو را به bucket کاهش می‌دهد و سپس با equality کلید دقیق را پیدا می‌کند. هر دو کلید برابر باید hash یکسان داشته باشند و کلید هنگام عضویت نباید از نظر equality تغییر کند.

مدل ذهنی ساده

hash آدرس نهایی نیست؛ یک راهنمای سریع برای رسیدن به گروه کوچکی از candidateهاست. چون چند کلید می‌توانند hash یکسان داشته باشند، Dictionary در پایان equality را بررسی می‌کند. پس hash خوب collision را کم می‌کند، اما درست‌بودن equality تعیین‌کننده هویت کلید است.

توضیح کامل

عملیات معمول lookup میانگین نزدیک O(1) دارد، اما collision زیاد یا comparer بد می‌تواند کار را افزایش دهد. invariant اصلی این است: اگر Equals(a,b) true است، GetHashCode آن‌ها باید برابر باشد؛ عکس آن لازم نیست. comparer انتخاب‌شده هم hash و هم equality را تعریف می‌کند. mutation fieldهای مؤثر در hash پس از insert باعث می‌شود lookup در bucket جدید بگردد درحالی‌که entry در bucket قبلی مانده است.

C#
var users = new Dictionary<string, User>(StringComparer.OrdinalIgnoreCase);
users["Sara"] = new User(1);
Console.WriteLine(users.TryGetValue("sara", out var user));

رفتار مثال: Dictionary با StringComparer.OrdinalIgnoreCase کلیدهای Sara و sara را یکسان می‌بیند چون comparer برای هر دو hash و equality سازگار دارد. TryGetValue lookup را یک بار انجام می‌دهد. اگر یک record mutable به‌عنوان key استفاده و property مؤثر در equality تغییر کند، بازیابی آن ممکن است شکست بخورد.

نکات کلیدی

  • hash bucket candidateها را پیدا می‌کند و equality کلید نهایی را.
  • کلیدهای برابر باید hash یکسان تولید کنند.
  • کلید mutable می‌تواند invariant Dictionary را بشکند.

اشتباهات رایج

  • برابر دانستن hash و identity
  • استفاده از کلید mutable
  • دو بار lookup با ContainsKey و indexer.

جزئیات عمیق‌تر

در string key، comparer را از قرارداد دامنه انتخاب کنید؛ نام کاربری، path و identifier قواعد یکسانی ندارند. hash برای امنیت رمزنگاری نیست. اگر ترتیب لازم است از contract مربوط استفاده کنید و به ترتیب مشاهده‌شده Dictionary به‌عنوان فرض پنهان تکیه نکنید.

در پروژهٔ واقعی

برای username comparer مناسب قرارداد دامنه انتخاب کنید و `TryGetValue` را برای lookup واحد به کار ببرید.

جمع‌بندی برای مصاحبه

bucket، hash، collision، equality و invariant کلید را به ترتیب توضیح دهید.
