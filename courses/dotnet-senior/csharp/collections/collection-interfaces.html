تفاوت IEnumerable، ICollection و IList چیست؟

پاسخ کوتاه مصاحبه‌ای

IEnumerable<T> قرارداد پیمایش است؛ ICollection<T> Count و عملیات افزودن/حذف مجموعه را اضافه می‌کند؛ IList<T> دسترسی و mutation براساس index را نیز تضمین می‌کند. API باید کم‌قدرت‌ترین contract کافی را بپذیرد.

مدل ذهنی ساده

هر interface یک مجوز به function می‌دهد. IEnumerable فقط اجازه دیدن itemها را می‌دهد. ICollection اجازه تغییر اندازه و دانستن Count را اضافه می‌کند. IList علاوه بر آن می‌گوید ترتیب و index معنی دارد. اگر function فقط جمع می‌زند، درخواست IList اختیار اضافی و بی‌دلیل است.

توضیح کامل

IEnumerable می‌تواند lazy، remote، stateful یا یک‌بارمصرف باشد؛ enumeration دوباره الزاماً رایگان یا حتی هم‌نتیجه نیست. ICollection معمولاً materialized collection با Count و mutation را بیان می‌کند، هرچند IsReadOnly می‌تواند عملیات mutation را محدود کند. IList indexer و Insert/RemoveAt دارد و برای sequence مرتب مناسب است. interfaceهای readonly قابلیت mutation را از view مصرف‌کننده حذف می‌کنند، ولی object زیرین را deep immutable نمی‌سازند.

C#
static decimal Total(IEnumerable<Order> orders)
    => orders.Sum(o => o.Amount);

static void Clear(ICollection<Order> orders) => orders.Clear();

رفتار مثال: Total(IEnumerable<Order>) روی Array، List یا query کار می‌کند چون فقط enumeration لازم دارد. methodی که item اضافه می‌کند ICollection<Order> می‌خواهد. UI که drag-and-drop براساس position انجام می‌دهد ممکن است IList<Order> لازم داشته باشد. فراخوانی Count با enumerable.Count() روی query می‌تواند query جدا اجرا کند.

نکات کلیدی

  • IEnumerable فقط پیمایش را قرارداد می‌کند.
  • ICollection Count و mutation مجموعه را اضافه می‌کند.
  • IList semantics مربوط به index و ترتیب را اضافه می‌کند.

اشتباهات رایج

  • پذیرفتن List بدون نیاز
  • چند بار enumerate کردن query گران یا stateful.

جزئیات عمیق‌تر

در خروجی API، IReadOnlyList<T> intent فقط‌خواندن و index را روشن می‌کند، اما برای جلوگیری از mutation خارجی شاید defensive copy یا Immutable Collection لازم باشد. چندبار enumerate کردن ورودی ناشناخته را مستند یا یک‌بار materialize کنید؛ این تصمیم هزینه حافظه و زمان دارد.

در پروژهٔ واقعی

تابع گزارش فقط IEnumerable می‌خواهد؛ UI reorder شاید IList لازم داشته باشد.
