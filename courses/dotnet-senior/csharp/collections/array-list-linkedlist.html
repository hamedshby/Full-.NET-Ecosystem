تفاوت Array، List و LinkedList چیست؟

پاسخ کوتاه مصاحبه‌ای

Array اندازه ثابت و storage پیوسته دارد؛ List<T> یک آرایه رشدپذیر با دسترسی سریع index است؛ LinkedList<T> nodeهای جدا دارد و درج یا حذف O(1) را فقط وقتی node مقصد از قبل در اختیار باشد فراهم می‌کند.

مدل ذهنی ساده

اگر تعداد معلوم و ثابت است Array ساده است. اگر فهرست معمولی با append و index می‌خواهید، List انتخاب پیش‌فرض خوبی است. LinkedList را زمانی بررسی کنید که node پایدار دارید و مرتباً کنار همان node درج یا حذف می‌کنید؛ پیدا کردن node خودش O(n) است.

توضیح کامل

List ظرفیت جدا از Count دارد و هنگام پرشدن، buffer بزرگ‌تری می‌گیرد و elementها را کپی می‌کند؛ append به‌صورت amortized O(1) است. Array و List locality خوبی دارند و cache CPU از traversal آن‌ها سود می‌برد. LinkedList برای هر element node و referenceهای اضافی دارد، allocation و locality ضعیف‌تری ایجاد می‌کند و دسترسی index آن O(n) است. Big-O بدون درنظرگرفتن جست‌وجو، allocation و locality انتخاب کامل نمی‌دهد.

C#
int[] fixedItems = new int[3];
var growing = new List<int> { 1, 2, 3 };
var chain = new LinkedList<int>();
var node = chain.AddFirst(1);
chain.AddAfter(node, 2);

رفتار مثال: افزودن یک میلیون item و پیمایش ترتیبی معمولاً با List مناسب است. اگر marker یک LinkedListNode<T> را نگه می‌دارد و باید دائماً قبل از همان marker item درج شود، LinkedList می‌تواند هزینه جابه‌جایی array را حذف کند. اگر هر بار ابتدا value را جست‌وجو کنیم، مزیت O(1) درج تحت‌الشعاع جست‌وجوی O(n) قرار می‌گیرد.

نکات کلیدی

  • Array fixed-size و دارای locality خوب است.
  • List برای collection عمومی و indexمحور انتخاب رایج است.
  • LinkedList فقط با node موجود درج و حذف O(1) واقعی می‌دهد.

اشتباهات رایج

  • انتخاب LinkedList فقط به‌خاطر O(1) بدون داشتن node
  • فراموشی ظرفیت List.

جزئیات عمیق‌تر

با تعیین capacity اولیه List می‌توان resizeهای قابل‌پیش‌بینی را کم کرد. Span<T> view کم‌هزینه روی storage پیوسته است اما Collection عمومی و قابل‌ذخیره‌سازی روی Heap نیست. انتخاب را با الگوی واقعی access و Benchmark انجام دهید، نه صرفاً جدول Big-O.

در پروژهٔ واقعی

برای buffer اندازه‌ثابت Array، برای فهرست عمومی List، و برای splice با nodeهای پایدار LinkedList را بررسی کنید.

جمع‌بندی برای مصاحبه

اندازه، index، هزینهٔ رشد و locality را کنار پیچیدگی زمانی مقایسه کنید.
