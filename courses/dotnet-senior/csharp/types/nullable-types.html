Nullable Value Type و Nullable Reference Type چه تفاوتی دارند؟

پاسخ کوتاه مصاحبه‌ای

Nullable Value Type مانند int? یک instance از Nullable<int> است و در Runtime حالت «دارای value» یا «بدون value» دارد. Nullable Reference Type مانند string? type جدیدی در CLR نیست؛ annotationای برای تحلیل جریان null توسط Compiler است.

مدل ذهنی ساده

برای int معمولی، null جزو valueهای ممکن نیست. int? یک wrapper می‌سازد که علاوه بر int، وضعیت نبودن value را نگه می‌دارد. اما string از ابتدا می‌تواند در Runtime مقدار null بگیرد؛ علامت ? به Compiler می‌گوید این null در قرارداد برنامه مجاز است تا هشدارها دقیق‌تر شوند.

توضیح کامل

int? score شکل کوتاه Nullable<int> است و propertyهای HasValue و Value دارد. score ?? 0 راه امنی برای fallback است. در مقابل، string? name و string name در metadata Runtime تا حد زیادی همان Reference Type هستند، ولی nullable annotations در metadata ثبت می‌شوند تا ابزارها و Compiler قرارداد را تحلیل کنند. فعال‌بودن Nullable Reference Types مانع ورود null در Runtime نمی‌شود؛ ورودی خارجی همچنان validation لازم دارد.

C#
int? score = null;
if (score.HasValue) Console.WriteLine(score.Value);

string? name = FindName();
Console.WriteLine(name?.Length ?? 0);

رفتار مثال: وقتی score برابر null است، HasValue مقدار false دارد و دسترسی مستقیم به Value exception ایجاد می‌کند. name?.Length ?? 0 اگر name برابر null باشد بدون dereference کردن آن، صفر برمی‌گرداند. این رفتار به‌معنای معتبر بودن business data نیست؛ فقط از NullReferenceException جلوگیری می‌کند.

نکات کلیدی

  • Nullable یک struct واقعی برای Value Typeها است.
  • علامت ? روی Reference Type قرارداد و تحلیل Compiler را تغییر می‌دهد.
  • nullable analysis جای validation در مرزهای سیستم را نمی‌گیرد.

اشتباهات رایج

  • تصور اینکه string? در CLR نوع دیگری است
  • استفادهٔ بی‌رویه از `!` برای خاموش‌کردن هشدار.

جزئیات عمیق‌تر

عملگر null-forgiving یعنی ! فقط هشدار Compiler را خاموش می‌کند و هیچ check در Runtime اضافه نمی‌کند. attributeهایی مانند NotNullWhen و MemberNotNull برای بیان قراردادهای پیچیده‌تر به flow analysis کمک می‌کنند. در API عمومی، annotation باید رفتار واقعی را بیان کند؛ استفادهٔ بی‌رویه از ? یا ! ارزش تحلیل را از بین می‌برد.

در پروژهٔ واقعی

در DTO ورودی، nullability را مطابق قرارداد واقعی بنویسید و در مرز سیستم اعتبارسنجی runtime هم داشته باشید.

جمع‌بندی برای مصاحبه

فرق representation و analysis را روشن کنید: `T?` برای value type ساختار است، برای reference type قرارداد کامپایلری.
