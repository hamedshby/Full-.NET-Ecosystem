Nullable Value Type و Nullable Reference Type چه تفاوتی دارند؟

پاسخ کوتاه مصاحبه‌ای

در C# دو مفهوم متفاوت با علامت ? داریم. برای Value Typeها مثل int?، یک نوع واقعی به نام Nullable<int> ساخته می‌شود تا متغیر بتواند علاوه بر عدد، مقدار null هم داشته باشد. اما برای Reference Typeها مثل string?، نوع جدیدی در Runtime ساخته نمی‌شود؛ علامت ? بیشتر به Compiler می‌گوید که این Reference ممکن است null باشد تا هشدارهای دقیق‌تری بدهد.

مدل ذهنی خیلی ساده

اول فقط این را به خاطر بسپارید: Value Type معمولاً نمی‌تواند null باشد، ولی Reference Type می‌تواند.

مثلاً int باید یک عدد داشته باشد؛ نمی‌توانیم مستقیماً بگوییم:

C#
int age = null; // خطا

اما اگر بنویسیم int?، یعنی «این متغیر یا یک عدد دارد یا هیچ مقداری ندارد».

در مقابل، string از نظر Runtime می‌تواند null باشد. علامت ? در string? بیشتر یک قرارداد برای Compiler و برنامه‌نویس است.

Nullable Value Type چیست؟

Value Typeهایی مثل int، bool، DateTime و بیشتر structها به‌صورت معمول null نمی‌شوند. اگر بخواهیم یک Value Type بتواند null باشد، از ? استفاده می‌کنیم:

C#
int? age = null;
bool? isActive = null;
DateTime? birthDate = null;

کد int? در واقع شکل کوتاه این کد است:

C#
Nullable<int> age = null;

پس Nullable Value Type یک مفهوم واقعی در Type System است.

Nullable<T> چه چیزی نگه می‌دارد؟

به صورت ساده، یک Nullable Value Type باید بتواند دو چیز را مشخص کند:

  1. آیا واقعاً Value دارد یا نه؟
  2. اگر Value دارد، آن مقدار چیست؟

به همین دلیل propertyهای مهمی مثل HasValue و Value داریم.

C#
int? score = 18;

Console.WriteLine(score.HasValue); // True
Console.WriteLine(score.Value);    // 18

اگر مقدار null باشد چه می‌شود؟

C#
int? score = null;

Console.WriteLine(score.HasValue); // False

در این حالت HasValue برابر False است. اگر مستقیم به Value دسترسی بزنیم:

C#
Console.WriteLine(score.Value);

برنامه Exception می‌دهد، چون واقعاً مقداری وجود ندارد. پس بهتر است قبل از استفاده بررسی کنیم.

روش‌های امن استفاده از Nullable Value Type

روش اول: HasValue

C#
int? score = null;

if (score.HasValue)
{
    Console.WriteLine(score.Value);
}

روش دوم: null-coalescing با ??

C#
int? score = null;

int finalScore = score ?? 0;

Console.WriteLine(finalScore); // 0

یعنی اگر score مقدار داشت همان را استفاده کن؛ در غیر این صورت 0 قرار بده.

روش سوم: GetValueOrDefault

C#
int? score = null;

int finalScore = score.GetValueOrDefault();

Console.WriteLine(finalScore); // 0

یک مثال واقعی از Nullable Value Type

فرض کنید تاریخ پایان قرارداد کاربر هنوز مشخص نیست:

C#
public class Employee
{
    public DateTime HireDate { get; set; }

    public DateTime? ContractEndDate { get; set; }
}

HireDate باید حتماً وجود داشته باشد. اما ContractEndDate ممکن است هنوز تعیین نشده باشد، پس Nullable بودن آن منطقی است. اینجا null یک معنی Business واقعی دارد: «هنوز تاریخ پایان نداریم».

Nullable Reference Type چیست؟

Reference Typeهایی مثل string، class، array و List<T> در Runtime از قبل می‌توانند null باشند.

پس تفاوت این دو چیست؟

C#
string name;
string? middleName;

وقتی Nullable Reference Types فعال باشد، مفهوم این است:

  • string name یعنی انتظار داریم این مقدار null نباشد.
  • string? middleName یعنی null بودن این مقدار مجاز و قابل انتظار است.

Compiler چه کمکی می‌کند؟

فرض کنید نوشته‌ایم:

C#
string? name = null;

Console.WriteLine(name.Length);

Compiler هشدار می‌دهد، چون name ممکن است null باشد و دسترسی به Length می‌تواند در Runtime باعث NullReferenceException شود.

روش امن‌تر:

C#
string? name = null;

Console.WriteLine(name?.Length);

یا:

C#
Console.WriteLine(name?.Length ?? 0);

اگر name null باشد، عبارت name?.Length به جای Exception مقدار null تولید می‌کند و بعد ?? 0 مقدار صفر را برمی‌گرداند.

فرق اصلی int? و string?

ویژگی int? string?
نوع اصلی Value Type Reference Type
آیا ? نوع جدید می‌سازد؟ بله، Nullable<int> خیر
کار اصلی ? امکان داشتن null بیان قرارداد Nullability برای Compiler
اثر در Runtime واقعی و بخشی از Type بیشتر برای تحلیل Compiler و metadata

یک نکته خیلی مهم درباره string?

ممکن است فکر کنید چون نوشته‌ایم:

C#
string name = "Hamed";

دیگر Runtime هرگز اجازه نمی‌دهد null وارد name شود. این تصور اشتباه است. Nullable Reference Types بیشتر یک سیستم هشدار و تحلیل در Compile Time هستند و جلوی همه nullهای Runtime را نمی‌گیرند.

مثلاً داده می‌تواند از Database، JSON، API خارجی، Reflection یا کد قدیمی وارد سیستم شود. به همین دلیل همچنان باید ورودی‌های خارجی را Validation کنیم.

Null-forgiving operator یعنی ! چیست؟

گاهی کدی مثل این می‌بینید:

C#
string? name = GetName();

Console.WriteLine(name!.Length);

علامت ! به Compiler می‌گوید: «من مطمئن هستم این مقدار null نیست؛ هشدار نده.»

اما نکته بسیار مهم این است که این علامت هیچ Check جدیدی در Runtime انجام نمی‌دهد. اگر name واقعاً null باشد، هنوز هم NullReferenceException می‌گیریم.

اشتباه خطرناک در استفاده از !

C#
string? name = null;

Console.WriteLine(name!.Length);

Compiler ممکن است دیگر هشدار Nullability ندهد، ولی برنامه در Runtime خطا می‌دهد. پس ! راه‌حل Null نیست؛ فقط هشدار Compiler را خاموش می‌کند.

یک مثال واقعی در DTO

C#
public class CreateCustomerRequest
{
    public string FirstName { get; set; } = null!;

    public string? MiddleName { get; set; }

    public int? Age { get; set; }
}

اینجا سه مفهوم متفاوت داریم:

  • FirstName: انتظار داریم حتماً مقدار داشته باشد.
  • MiddleName: ممکن است کاربر نام میانی نداشته باشد.
  • Age: چون int یک Value Type است و سن ممکن است ارسال نشود، از int? استفاده شده است.

با این حال اگر این DTO از API دریافت می‌شود، همچنان Validation لازم است. Nullability جای FluentValidation، DataAnnotation یا Business Validation را نمی‌گیرد.

چرا Nullable Reference Types مهم شدند؟

یکی از رایج‌ترین خطاهای برنامه‌های C#، NullReferenceException است. Nullable Reference Types کمک می‌کنند خیلی از موقعیت‌های خطرناک قبل از اجرای برنامه توسط Compiler تشخیص داده شوند.

پس هدف اصلی این قابلیت این نیست که null را از C# حذف کند؛ هدف این است که قرارداد null بودن یا نبودن Referenceها واضح‌تر شود.

اشتباهات رایج

  • اشتباه: string? مثل int? یک نوع جدید می‌سازد.
    درست: برای Reference Type علامت ? بیشتر annotation و قرارداد کامپایلری است.
  • اشتباه: string دیگر در Runtime هیچ‌وقت null نمی‌شود.
    درست: Compiler هشدار می‌دهد، ولی null همچنان ممکن است از بعضی مرزها وارد شود.
  • اشتباه: ! از NullReferenceException جلوگیری می‌کند.
    درست: فقط هشدار Compiler را خاموش می‌کند.
  • اشتباه: با فعال کردن Nullable دیگر Validation لازم نیست.
    درست: ورودی API، Database و داده خارجی هنوز باید Validation شوند.

جزئیات عمیق‌تر برای سطح Senior

برای Value Type، عبارت T? در حالت معمول معادل Nullable<T> است و یک Struct واقعی محسوب می‌شود. اما Nullable Reference Type بیشتر به Flow Analysis مربوط است. Compiler با بررسی مسیرهای کد تلاش می‌کند بفهمد یک Reference در نقطه‌ای مشخص ممکن است null باشد یا خیر.

در قراردادهای پیچیده‌تر می‌توان از Attributeهایی مثل NotNullWhen، MaybeNull و MemberNotNull استفاده کرد تا اطلاعات دقیق‌تری به تحلیل Nullability داده شود.

در پروژه واقعی چطور استفاده کنیم؟

Nullability باید معنی واقعی Domain و قرارداد API را نشان دهد. اگر یک فیلد واقعاً Optional است آن را Nullable تعریف کنید؛ اگر وجودش الزامی است بی‌دلیل ? اضافه نکنید. در غیر این صورت Compiler دیگر نمی‌تواند هشدارهای مفیدی بدهد.

همچنین از ! فقط زمانی استفاده کنید که واقعاً دلیل مشخصی دارید که Compiler نمی‌تواند آن را تشخیص دهد. استفاده زیاد از ! معمولاً علامت این است که قرارداد Nullability پروژه درست طراحی نشده است.

اگر مصاحبه‌کننده بپرسد تفاوت اصلی چیست؟

می‌توانید این‌طور جواب دهید:

«برای Value Typeها، مثل int?، علامت ? باعث می‌شود از Nullable<int> استفاده کنیم و Type واقعاً بتواند حالت بدون مقدار داشته باشد. اما برای Reference Typeها، مثل string?، نوع جدیدی در Runtime ساخته نمی‌شود؛ علامت ? قرارداد Nullability را به Compiler اعلام می‌کند تا بتواند احتمال NullReferenceException را بهتر تشخیص دهد.»

جواب پیشنهادی کامل برای مصاحبه

«Nullable Value Type و Nullable Reference Type از نظر مفهوم متفاوت هستند. Value Typeهایی مثل int به‌صورت عادی نمی‌توانند null باشند، بنابراین int? در واقع Nullable<int> است و می‌تواند یا Value داشته باشد یا null باشد. اما Reference Typeها از قبل در Runtime می‌توانند null باشند. در string? علامت ? بیشتر یک Annotation برای Nullable Flow Analysis کامپایلر است و کمک می‌کند مواردی که ممکن است به NullReferenceException منجر شوند زودتر شناسایی شوند. همچنین Nullable Reference Types جای Runtime Validation را نمی‌گیرند و null-forgiving operator یعنی ! فقط هشدار Compiler را خاموش می‌کند.»

چیزی که باید از این سؤال یادت بماند

اگر فقط پنج نکته را حفظ کنید: int? یعنی Nullable<int>، string? نوع Runtime جدیدی نیست، ? روی Reference Type قرارداد Nullability را مشخص می‌کند، ! فقط هشدار Compiler را خاموش می‌کند، و Nullable Reference Types جای Validation داده‌های خارجی را نمی‌گیرند.
