سیستم نوع یکپارچهٔ CLR چگونه C# را پشتیبانی می‌کند؟

پاسخ کوتاه مصاحبه‌ای

C# typeها را در metadata و IL مطابق Common Type System یا CTS توصیف می‌کند. CLR این اطلاعات را برای loading، type safety، Genericها و JIT compilation استفاده می‌کند؛ CLS نیز زیرمجموعه‌ای از قواعد برای interoperability بهتر میان زبان‌ها است.

مدل ذهنی ساده

C# تنها زبان روی .NET نیست. هر زبان syntax خودش را دارد، اما خروجی آن باید بتواند type، member و رابطه‌ها را با قرارداد مشترکی توصیف کند که CLR بفهمد. CTS این واژگان مشترک را فراهم می‌کند و metadata مانند شناسنامهٔ typeها در assembly است.

توضیح کامل

Compiler تعریف class، field، method، Generic Constraint و visibility را در metadata ثبت و body methodها را به IL تبدیل می‌کند. CLR هنگام load کردن assembly سازگاری typeها را بررسی می‌کند و JIT برای methodهای موردنیاز machine code می‌سازد. CTS میان Value Type و Reference Type، inheritance، interface و memberها تمایز می‌گذارد. CLS همهٔ CTS نیست؛ مجموعه‌ای از قواعد است که API عمومی با رعایت آن برای زبان‌های بیشتری قابل مصرف می‌شود.

C#
public sealed class Counter
{
    public int Value { get; }
    public Counter(int value) => Value = value;
}
// metadata نوع، سازنده و property را برای CLR توصیف می‌کند.

رفتار مثال: در مثال Counter، metadata وجود type sealed، constructor، property و type بازگشتی آن را توصیف می‌کند. مصرف‌کنندهٔ نوشته‌شده با زبان .NET دیگر بدون دیدن source C# می‌تواند همین قرارداد را بخواند. implementation method در IL ذخیره شده و CLR/JIT آن را اجرا می‌کند.

نکات کلیدی

  • CTS مدل مشترک typeها در CLR است.
  • metadata قرارداد type و IL رفتار method را حمل می‌کنند.
  • CLS برای interoperability API عمومی است و با CTS یکسان نیست.

اشتباهات رایج

  • برابر دانستن CTS و CLS
  • تصور اینکه CLR فقط کتابخانهٔ C# است.

جزئیات عمیق‌تر

هر type در C# مستقیم یا غیرمستقیم با System.Object مرتبط است؛ Value Typeها از System.ValueType مشتق می‌شوند، ولی System.ValueType خودش یک class است. JIT و Runtime ممکن است implementation را بهینه کنند، بنابراین از نتیجه‌گیری‌های ثابت دربارهٔ layout یا machine code بدون اندازه‌گیری پرهیز کنید.

در پروژهٔ واقعی

برای کتابخانهٔ عمومی که از زبان‌های مختلف مصرف می‌شود، API را CLS-friendly نگه دارید و metadata قرارداد پایدار بسازید.

جمع‌بندی برای مصاحبه

زنجیرهٔ C# → IL/metadata → CLR/JIT را توضیح دهید و نقش CTS و CLS را از هم جدا کنید.
