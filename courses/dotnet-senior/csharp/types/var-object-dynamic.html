تفاوت var، object و dynamic چیست؟

پاسخ کوتاه مصاحبه‌ای

هر سه می‌توانند ظاهر کد را «عمومی‌تر» کنند، اما رفتارشان کاملاً متفاوت است. var فقط به Compiler اجازه می‌دهد Type را از مقدار سمت راست حدس بزند و متغیر همچنان Static Type دارد. object یک Type واقعی و پایه برای همه Typeها است و برای دسترسی به Memberهای اختصاصی معمولاً باید Cast یا Pattern Matching انجام دهیم. dynamic بررسی Memberها را از Compile Time به Runtime منتقل می‌کند؛ بنابراین انعطاف بیشتری دارد، ولی خطاها دیرتر کشف می‌شوند.

مدل ذهنی خیلی ساده

سه متغیر را تصور کنید:

  • var: Compiler همان اول می‌فهمد Type چیست و بعد از آن رفتار کاملاً Type-safe است.
  • object: می‌دانیم متغیر یک Object است، ولی برای استفاده از Memberهای Type واقعی باید آن Type را مشخص کنیم.
  • dynamic: Compiler فعلاً سخت‌گیری نمی‌کند و بررسی می‌گوید «بعداً در Runtime مشخص می‌کنیم».

پس مهم‌ترین تفاوت آن‌ها این است که Type چه زمانی مشخص و عملیات چه زمانی بررسی می‌شود.

var چیست؟

var خودش یک Type نیست. Compiler فقط Type متغیر را از Expression سمت راست تشخیص می‌دهد.

C#
var age = 30;
var name = "Hamed";
var isActive = true;

Compiler این کد را تقریباً مانند این می‌بیند:

C#
int age = 30;
string name = "Hamed";
bool isActive = true;

پس var age = 30 یعنی Type متغیر age دقیقاً int است؛ فقط ما اسم Type را ننوشته‌ایم.

آیا var یعنی متغیر پویا؟

خیر. این یکی از رایج‌ترین اشتباهات است. بعد از اینکه Compiler Type را تشخیص داد، Type متغیر دیگر تغییر نمی‌کند.

C#
var number = 10;

number = 20;      // درست
number = "test";  // Compile Error

چون number در همان خط اول به عنوان int تشخیص داده شده است.

var چه زمانی مفید است؟

وقتی Type از سمت راست کاملاً مشخص است، استفاده از var می‌تواند کد را کوتاه‌تر و خواناتر کند.

C#
var customer = new Customer();
var customers = new List<Customer>();

نوشتن Type دوباره معمولاً اطلاعات جدیدی اضافه نمی‌کند:

C#
Customer customer = new Customer();
List<Customer> customers = new List<Customer>();

object چیست؟

object یک Type واقعی در .NET است. همه Typeهای C# در نهایت می‌توانند به شکل یک object دیده شوند.

C#
object value1 = "Hello";
object value2 = 123;
object value3 = new Customer();

این سه مقدار Type واقعی متفاوت دارند، ولی متغیرهای ما از نظر Compile Time فقط object هستند.

مشکل object چیست؟

وقتی متغیر از نوع object باشد، Compiler فقط Memberهایی را می‌شناسد که روی object وجود دارند. مثلاً:

C#
object value = "dotnet";

Console.WriteLine(value.ToString()); // درست

اما این کد Compile نمی‌شود:

C#
object value = "dotnet";

Console.WriteLine(value.Length); // Compile Error

چرا؟ چون Length متعلق به string است، نه object.

چطور Type واقعی object را استفاده کنیم؟

روش اول: Cast

C#
object value = "dotnet";

string text = (string)value;

Console.WriteLine(text.Length);

روش دوم: Pattern Matching

C#
object value = "dotnet";

if (value is string text)
{
    Console.WriteLine(text.Length);
}

Pattern Matching معمولاً امن‌تر و خواناتر است، چون هم Type را بررسی می‌کند و هم متغیر Typed به ما می‌دهد.

Value Type داخل object چه می‌شود؟

اگر یک Value Type مثل int را داخل object قرار دهیم، Boxing اتفاق می‌افتد:

C#
int number = 10;

object value = number; // Boxing

این همان مفهومی است که در سؤال Boxing و Unboxing دیدیم. پس object می‌تواند Reference Type و Value Type را نگه دارد، اما Value Typeها ممکن است هزینه Boxing داشته باشند.

dynamic چیست؟

dynamic به Compiler می‌گوید: «فعلاً Memberها و Operationها را بررسی نکن؛ در Runtime تصمیم بگیر.»

C#
dynamic value = "dotnet";

Console.WriteLine(value.Length);

این کد Compile می‌شود، چون Compiler بررسی Member Length را عقب می‌اندازد. در Runtime مشخص می‌شود که value یک string است و string واقعاً Length دارد.

خطر dynamic کجاست؟

در dynamic ممکن است کدی Compile شود ولی در Runtime خطا بدهد.

C#
dynamic value = "dotnet";

Console.WriteLine(value.Price);

این کد Compile می‌شود، اما string عضوی به نام Price ندارد. بنابراین در Runtime خطایی مانند RuntimeBinderException رخ می‌دهد.

تفاوت مهم اینجاست: با Static Typing بسیاری از خطاها قبل از اجرای برنامه پیدا می‌شوند؛ با dynamic بخشی از این امنیت را از دست می‌دهیم.

تفاوت var و dynamic با یک مثال

C#
var first = "dotnet";
dynamic second = "dotnet";

Console.WriteLine(first.Length);  // درست
Console.WriteLine(second.Length); // درست

تا اینجا هر دو کار می‌کنند. اما:

C#
Console.WriteLine(first.Price);  // Compile Error
Console.WriteLine(second.Price); // Compile می‌شود، Runtime Error

این مثال تفاوت اصلی را خیلی خوب نشان می‌دهد.

تفاوت object و dynamic با یک مثال

C#
object first = "dotnet";
dynamic second = "dotnet";

Console.WriteLine(first.Length);  // Compile Error
Console.WriteLine(second.Length); // درست

هر دو در Runtime یک string را نگه می‌دارند، ولی رفتار Compiler متفاوت است:

  • برای object، Compiler فقط Memberهای object را اجازه می‌دهد.
  • برای dynamic، بررسی Member تا Runtime عقب می‌افتد.

جدول مقایسه

ویژگی var object dynamic
Type چه زمانی مشخص می‌شود؟ Compile Time خود متغیر object است Operationها در Runtime بررسی می‌شوند
Static Type Safety بله بله کمتر
نیاز به Cast برای Member اختصاصی خیر معمولاً بله خیر
خطای Member ناموجود Compile Time Compile Time Runtime
آیا Type بعداً تغییر می‌کند؟ خیر متغیر همیشه object است مقدار Runtime می‌تواند Typeهای مختلف داشته باشد

یک مثال واقعی با var در LINQ

گاهی استفاده از var فقط برای کوتاه‌تر شدن کد نیست؛ برای Anonymous Type عملاً لازم است.

C#
var result = customers
    .Select(c => new
    {
        c.Id,
        c.Name
    })
    .ToList();

Type ساخته‌شده Anonymous است و اسم مستقیمی برای نوشتن آن نداریم، بنابراین var انتخاب طبیعی است.

dynamic چه زمانی واقعاً مفید است؟

dynamic ابزار بدی نیست؛ مشکل زمانی است که بدون دلیل استفاده شود. در بعضی Boundaryهای واقعاً پویا کاربرد دارد، مثل:

  • Interop با COM
  • کار با بعضی APIهای Legacy
  • داده‌هایی که Shape آن‌ها تا Runtime مشخص نیست
  • بعضی Proxyها یا Frameworkهای Dynamic

اما در Business Logic معمولاً بهتر است داده را هرچه زودتر به یک Model مشخص و Type-safe تبدیل کنیم.

مثال بد از dynamic

C#
dynamic customer = GetCustomer();

decimal total =
    customer.Balance +
    customer.CreditLimit -
    customer.BlockedAmount;

اگر نام یکی از Propertyها تغییر کند یا Type آن متفاوت باشد، ممکن است مشکل فقط در Runtime دیده شود. برای Core Business Logic معمولاً مدل Typed بهتر است:

C#
Customer customer = GetCustomer();

decimal total =
    customer.Balance +
    customer.CreditLimit -
    customer.BlockedAmount;

چرا dynamic روی Refactoring اثر دارد؟

وقتی کد Type-safe باشد، IDE و Compiler اطلاعات زیادی درباره Memberها دارند. مثلاً اگر نام Property را تغییر دهیم، ابزار Refactoring می‌تواند استفاده‌های آن را پیدا کند. اما در کد Dynamic تضمین کمتری وجود دارد، چون بخشی از ارتباط Memberها تا Runtime مشخص نمی‌شود.

اشتباهات رایج

  • اشتباه: var همان dynamic است.
    درست: var کاملاً Static Typed است.
  • اشتباه: var یعنی Type متغیر بعداً می‌تواند عوض شود.
    درست: Type در Compile Time مشخص و ثابت می‌شود.
  • اشتباه: object و dynamic یک رفتار دارند.
    درست: object Memberها را در Compile Time محدود می‌کند، dynamic آن بررسی را به Runtime می‌برد.
  • اشتباه: dynamic راه ساده‌ای برای فرار از Cast است.
    درست: در ازای راحتی، بخشی از Type Safety را از دست می‌دهیم.

جزئیات عمیق‌تر برای سطح Senior

dynamic در سطح CLR یک Type کاملاً مستقل شبیه class جدید نیست؛ بخش مهم رفتار آن توسط Compiler و Runtime Binder مدیریت می‌شود. فراخوانی‌هایی که روی dynamic انجام می‌شوند در Runtime Resolve می‌شوند و همین موضوع می‌تواند هم هزینه بیشتر و هم ریسک خطای دیرهنگام ایجاد کند.

برای APIهای عمومی، استفاده بی‌رویه از dynamic معمولاً Contract را مبهم می‌کند. بهتر است اگر Boundary خارجی پویاست، dynamic را در همان Boundary محدود کنیم و بعد داده را به یک Type مشخص Map کنیم.

در پروژه واقعی چه انتخابی کنیم؟

  • اگر Type مشخص است ولی نوشتنش تکراری یا طولانی است: var.
  • اگر واقعاً نیاز داریم یک API عمومی هر نوع Object را بپذیرد: شاید object.
  • اگر Shape داده واقعاً فقط در Runtime مشخص می‌شود: در Boundary محدود از dynamic.
  • برای Domain و Business Logic تا جای ممکن Typeهای مشخص و Strongly Typed.

اگر مصاحبه‌کننده فقط یک تفاوت بخواهد

می‌توانید بگویید:

«var فقط Type Inference است و Type در Compile Time مشخص می‌شود. object یک Type واقعی است و برای استفاده از Memberهای Type واقعی معمولاً نیاز به Cast یا Pattern Matching داریم. dynamic بررسی Memberها را به Runtime منتقل می‌کند، بنابراین کدی که برای object Compile نمی‌شود ممکن است با dynamic Compile شود ولی در Runtime خطا بدهد.»

جواب پیشنهادی کامل برای مصاحبه

«var، object و dynamic سه مفهوم متفاوت هستند. var فقط باعث Type Inference می‌شود؛ یعنی Compiler از سمت راست Type را تشخیص می‌دهد و متغیر همچنان Static Typed است. object خود یک Type واقعی و پایه است و وقتی مقداری را به شکل object نگه می‌داریم، برای استفاده از Memberهای اختصاصی Type واقعی معمولاً باید Cast یا Pattern Matching انجام دهیم. dynamic برعکس، بررسی Member و Operation را تا Runtime عقب می‌اندازد؛ بنابراین انعطاف بیشتری می‌دهد ولی Type Safety کمتر می‌شود و بعضی خطاها به جای Compile Time در Runtime دیده می‌شوند. من معمولاً از dynamic فقط در Boundaryهای واقعاً پویا استفاده می‌کنم و سریعاً داده را به مدل Typed تبدیل می‌کنم.»

چیزی که باید از این سؤال یادت بماند

اگر فقط سه جمله را حفظ کنید: var = Type Inference در Compile Time، object = Type عمومی با نیاز به Cast/Pattern Matching برای Memberهای اختصاصی، و dynamic = انتقال بررسی Memberها به Runtime.
