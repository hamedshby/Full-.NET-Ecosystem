تفاوت var، object و dynamic چیست؟

پاسخ کوتاه مصاحبه‌ای

var یعنی Compiler type دقیق متغیر را از expression سمت راست استنتاج می‌کند و type همچنان static است. object یک Reference Type عمومی با دسترسی static فقط به اعضای object است. dynamic بررسی member را تا Runtime عقب می‌اندازد.

مدل ذهنی ساده

var را «نام کوتاه type» در نظر بگیرید، نه type پویا. پس از compile، متغیر var یک type مشخص مثل int دارد. object می‌تواند reference یا valueهای boxed را نگه دارد، اما برای اعضای اختصاصی باید type را narrow کنیم. dynamic به Compiler می‌گوید فعلاً بررسی نکن و operation را در Runtime resolve کن.

توضیح کامل

در var total = 12، total دقیقاً int است و بعداً نمی‌توان string در آن قرار داد. در object value = "dotnet"، object واقعی string است ولی type ایستای متغیر object است؛ pattern matching راه امن دسترسی به Length است. در dynamic، فراخوانی payload.Name compile می‌شود حتی اگر member وجود نداشته باشد و خطا ممکن است تازه در Runtime آشکار شود. dynamic برای مرزهای واقعاً پویا مفید است، نه جایگزین طراحی type-safe.

C#
var total = 12; // int
object value = "dotnet";
if (value is string text) Console.WriteLine(text.Length);

dynamic payload = GetLegacyObject();
Console.WriteLine(payload.Name); // بررسی در runtime

رفتار مثال: Compiler برای total تمام خطاهای مربوط به int را در Compile Time پیدا می‌کند. pattern value is string text هم type را بررسی و هم متغیر typed ایجاد می‌کند. اگر object بازگشتی در مثال dynamic فاقد Name باشد، RuntimeBinderException رخ می‌دهد؛ IDE و refactoring نیز تضمین کمتری دارند.

نکات کلیدی

  • var با Static Typing کاملاً سازگار است.
  • object برای استفاده از عضو اختصاصی به cast یا pattern matching نیاز دارد.
  • dynamic انعطاف را با انتقال خطا و بخشی از هزینه به Runtime به دست می‌آورد.

اشتباهات رایج

  • یکی‌دانستن var و dynamic
  • استفاده از dynamic برای فرار از طراحی type-safe.

جزئیات عمیق‌تر

نوع anonymous localها اغلب فقط با var قابل نام‌گذاری عملی است. dynamic در interop با COM، دادهٔ پویا یا برخی proxyها مفید است؛ بهتر است آن را در یک boundary کوچک نگه دارید و سریعاً به model typed تبدیل کنید. هر سه گزینه نوعی ابزارند و انتخاب آن‌ها باید قرارداد API را روشن‌تر کند.

در پروژهٔ واقعی

dynamic را در مرزهای COM یا API پویا محدود کنید و سریعاً داده را به مدل typed تبدیل کنید.
