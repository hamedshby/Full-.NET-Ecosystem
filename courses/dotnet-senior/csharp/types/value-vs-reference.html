تفاوت Value Type و Reference Type چیست؟

پاسخ کوتاه مصاحبه‌ای

Value Type مقدار واقعی داده را نگه می‌دارد و وقتی آن را به متغیر دیگری assign می‌کنیم، یک کپی از مقدار ساخته می‌شود. بنابراین تغییر متغیر دوم روی متغیر اول اثری ندارد. اما Reference Type به یک object اشاره می‌کند؛ در assignment، reference کپی می‌شود و در نتیجه دو متغیر می‌توانند به همان object اشاره کنند. پس تغییر خودِ object از طریق یکی، از طریق دیگری هم دیده می‌شود.

مدل ذهنی ساده

فرض کنید دو نفر به نام‌های Ali و Reza داریم. در Value Type انگار به هرکدام یک برگه داده‌ایم که روی آن عدد 10 نوشته شده است. اگر Reza عدد روی برگه خودش را به 20 تغییر دهد، برگه Ali همچنان 10 است. اما در Reference Type به هر دو نفر «آدرس یک خانه» را داده‌ایم. اگر Reza با آن آدرس وارد خانه شود و رنگ دیوار را عوض کند، Ali هم وقتی به همان خانه می‌رود رنگ جدید را می‌بیند. چون دو خانه نداریم؛ دو آدرس داریم که هر دو به یک خانه می‌رسند.

اول از همه: Value Type یعنی چه؟

در یک Value Type، متغیر مقدار خودش را دارد. نوع‌هایی مثل int، bool، double، decimal، enum و struct در این گروه قرار می‌گیرند.

مهم‌ترین رفتاری که باید برای مصاحبه به خاطر بسپارید این است: در assignment، مقدار کپی می‌شود.

C# - Value Type 
int a = 10;
int b = a;

b = 20;

Console.WriteLine(a); // 10
Console.WriteLine(b); // 20

مرحله‌به‌مرحله: ابتدا a مقدار 10 دارد. در b = a مقدار 10 کپی می‌شود و b نسخه خودش را دارد. بعد که b را 20 می‌کنیم، فقط مقدار b تغییر می‌کند و a همچنان 10 باقی می‌ماند.

Reference Type یعنی چه؟

در Reference Type ما معمولاً با یک object و یک reference به آن object سروکار داریم. نوع‌هایی مثل class، array، string و delegate Reference Type هستند.

وقتی یک متغیر Reference Type را به متغیر دیگری assign می‌کنیم، object جدیدی ساخته نمی‌شود؛ reference کپی می‌شود. بنابراین هر دو متغیر ممکن است به همان object برسند.

C# - Reference Type
public class Person
{
    public string Name { get; set; }
}

var first = new Person { Name = "Sara" };
var second = first;

second.Name = "Mina";

Console.WriteLine(first.Name);  // Mina
Console.WriteLine(second.Name); // Mina

چرا first هم تغییر کرد؟ فقط یک Person با new ساخته شده است. عبارت second = first یک Person جدید نمی‌سازد؛ فقط reference را کپی می‌کند. پس first و second هر دو به همان Person اشاره می‌کنند. وقتی از طریق second مقدار Name را عوض می‌کنیم، property همان object مشترک تغییر می‌کند.

تفاوت را کنار هم ببینیم

  • Value Type: در assignment، خود مقدار کپی می‌شود.
  • Reference Type: در assignment، reference کپی می‌شود؛ نه خود object.
  • Value Type: تغییر نسخه دوم معمولاً روی نسخه اول اثر ندارد.
  • Reference Type: اگر هر دو reference به یک object اشاره کنند، تغییر state آن object از هر دو مسیر دیده می‌شود.

یک نکته خیلی مهم: تغییر object با تغییر reference فرق دارد

این بخش یکی از جاهایی است که Juniorها معمولاً اشتباه می‌کنند. اگر property یک object مشترک را تغییر دهید، هر reference که به آن object اشاره کند تغییر را می‌بیند. اما اگر خود متغیر را به یک object جدید assign کنید، فقط همان متغیر به object جدید اشاره خواهد کرد.

C#
var first = new Person { Name = "Sara" };
var second = first;

// اکنون هر دو به یک object اشاره می‌کنند
second = new Person { Name = "Ali" };

Console.WriteLine(first.Name);  // Sara
Console.WriteLine(second.Name); // Ali

اینجا object اول تغییر نکرده است. فقط second را به یک Person جدید وصل کرده‌ایم. بنابراین بعد از خط second = new Person(...) دیگر first و second به یک object اشاره نمی‌کنند.

پس Stack و Heap چه می‌شوند؟

یک جواب رایج ولی اشتباه در مصاحبه این است: «Value Type روی Stack و Reference Type روی Heap قرار می‌گیرد.» این جمله تعریف دقیقی نیست. تفاوت اصلی این دو نوع، رفتار و semantics آن‌ها است؛ یعنی اینکه مقدار یا reference چگونه نگه‌داری و کپی می‌شود.

برای مثال یک int که field یک class است می‌تواند همراه object آن class روی Managed Heap قرار بگیرد. بنابراین برای پاسخ مصاحبه، تفاوت Value Type و Reference Type را با Stack و Heap تعریف نکنید.

ارسال به Method چطور کار می‌کند؟

پارامترهای C# به‌صورت پیش‌فرض by value ارسال می‌شوند. این قانون برای Reference Type هم برقرار است. تفاوت این است که در Reference Type چیزی که by value کپی می‌شود، خودِ reference است.

C#
static void Rename(Person person)
{
    person.Name = "Mina";
}

var user = new Person { Name = "Sara" };
Rename(user);

Console.WriteLine(user.Name); // Mina

یک کپی از reference وارد method می‌شود، اما reference اصلی و کپی آن هر دو به همان Person اشاره می‌کنند. به همین دلیل تغییر person.Name روی object اصلی دیده می‌شود. این موضوع به معنی ارسال پارامتر با ref نیست.

مثال‌های معروف هر گروه

  • Value Type: int، long، bool، double، decimal، char، enum، struct و DateTime.
  • Reference Type: class، string، array، interface و delegate.

اشتباهات رایج در مصاحبه

  • گفتن «Value Type یعنی Stack و Reference Type یعنی Heap» به‌عنوان تعریف اصلی.
  • فکر کردن second = first برای یک class یک object جدید می‌سازد.
  • فکر کردن هر Reference Type به‌صورت خودکار با ref به method ارسال می‌شود.
  • یکی دانستن «متغیر reference» با «objectی که آن reference به آن اشاره می‌کند».

جزئیات عمیق‌تر برای سطح بالاتر

Value Typeها از System.ValueType مشتق می‌شوند و شامل structها و enumها هستند. Reference Typeها هویت object دارند و چند reference می‌توانند به یک instance واحد اشاره کنند. همچنین Value Type در بعضی شرایط، مثلاً تبدیل به object یا یک interface مناسب، می‌تواند Boxing شود. محل واقعی storage نیز به context و تصمیم‌های runtime/JIT وابسته است؛ پس Stack/Heap را نتیجهٔ نحوه استفاده بدانید، نه تعریف Value/Reference Type.

در پروژه واقعی چرا این تفاوت مهم است؟

این موضوع فقط سؤال مصاحبه نیست. وقتی DTO، Entity یا Value Object طراحی می‌کنید باید بدانید assignment و mutation چه اثری دارد. برای مثال اگر دو بخش برنامه reference یک Entity را داشته باشند، تغییر آن object می‌تواند از هر دو مسیر دیده شود. از طرف دیگر برای مدل‌های کوچکِ value-based مثل Money یا Coordinate ممکن است یک struct یا readonly struct انتخاب مناسبی باشد؛ البته انتخاب نهایی به نیاز مدل و performance بستگی دارد.

جمع‌بندی برای مصاحبه

اگر مصاحبه‌کننده پرسید «تفاوت Value Type و Reference Type چیست؟» می‌توانید بگویید:

Value Type خود مقدار را نگه می‌دارد و assignment یک کپی مستقل از مقدار ایجاد می‌کند. Reference Type به یک object اشاره می‌کند و assignment معمولاً reference را کپی می‌کند، بنابراین چند متغیر می‌توانند به یک object مشترک اشاره کنند. نکته مهم این است که این تفاوت را نباید صرفاً با Stack و Heap تعریف کرد؛ تفاوت اصلی در semantics و رفتار کپی و هویت object است.
