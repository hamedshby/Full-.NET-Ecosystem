تفاوت Value Type و Reference Type چیست؟

پاسخ کوتاه مصاحبه‌ای

متغیر یک Value Type خودِ value را نگه می‌دارد؛ بنابراین assignment معمولاً یک کپی مستقل می‌سازد. متغیر یک Reference Type یک reference به یک object را نگه می‌دارد؛ assignment در این حالت reference را کپی می‌کند، نه خود object را.

مدل ذهنی ساده

دو جعبه با نام a و b تصور کنید. اگر نوع آن‌ها Value Type باشد، هر جعبه نسخهٔ خودش از value را دارد. بعد از assign کردن a به b، تغییر b به a سرایت نمی‌کند. اگر نوع Reference Type باشد، هر جعبه یک نشانی دارد و هر دو نشانی می‌توانند به همان object برسند؛ تغییر object از مسیر b از مسیر a هم دیده می‌شود.

توضیح کامل

در مثال int، ابتدا a مقدار 10 دارد. عبارت b = a مقدار 10 را در متغیر جدید کپی می‌کند؛ پس بعد از b++، مقدار b برابر 11 و a همچنان 10 است. در مثال Person، عبارت second = first یک Person تازه نمی‌سازد. reference موجود در first کپی می‌شود و هر دو متغیر به همان object می‌رسند. به همین دلیل تغییر second.Name، property همان object مشترک را تغییر می‌دهد و first.Name نیز مقدار جدید را می‌بیند. نکتهٔ کلیدی این است که «متغیر» و «object» را یکی ندانیم.

C#
int a = 10;
int b = a;
b++; // a همچنان 10 است

var first = new Person { Name = "Sara" };
var second = first;
second.Name = "Mina"; // first.Name نیز Mina است

رفتار مثال: بعد از اجرای بخش اول، a=10 و b=11 است؛ دو value مستقل داریم. بعد از اجرای بخش دوم فقط یک Person ساخته شده است و first و second هر دو به آن اشاره می‌کنند. برای کپی مستقل یک Reference Type باید خودمان object دیگری بسازیم یا روش cloning متناسب با مدل را تعریف کنیم.

نکات کلیدی

  • Value Type در assignment دادهٔ خودش را کپی می‌کند.
  • Reference Type در assignment یک reference دیگر به همان object می‌سازد.
  • ارسال آرگومان به method به‌صورت پیش‌فرض by value است؛ برای Reference Type یعنی خود reference کپی می‌شود.

اشتباهات رایج

  • گفتن «struct همیشه روی stack است»
  • تصور اینکه پارامتر reference type با ref ارسال می‌شود.

جزئیات عمیق‌تر

این تفاوت را با جملهٔ «Value Type روی Stack و Reference Type روی Heap است» تعریف نکنید. محل storage به context وابسته است: یک field از نوع int می‌تواند داخل object روی Managed Heap قرار بگیرد و JIT نیز دربارهٔ نگه‌داری localها تصمیم می‌گیرد. دسته‌بندی زبان دربارهٔ semantics است، نه یک نقشهٔ ثابت Stack/Heap. struct و enum از Value Typeها هستند؛ class، array، delegate و string از Reference Typeها هستند.

در پروژهٔ واقعی

برای مدل‌های کوچک و بدون هویت مانند Money یک value object مناسب است؛ Entity دارای هویت معمولاً class است.

جمع‌بندی برای مصاحبه

ابتدا رفتار کپی و هویت را بگویید، سپس با مثال انتساب نشان دهید و تأکید کنید stack/heap نتیجهٔ نحوهٔ استفاده است، نه تعریف نوع.
