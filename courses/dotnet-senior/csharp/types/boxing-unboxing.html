Boxing و Unboxing چگونه رخ می‌دهند و چه هزینه‌ای دارند؟

پاسخ کوتاه مصاحبه‌ای

Boxing زمانی رخ می‌دهد که یک Value Type به object یا یک interface سازگار تبدیل شود و CLR یک object شامل کپی value بسازد. Unboxing همان value را با بررسی type دقیق از object بیرون می‌آورد؛ این دو عملیات می‌توانند allocation، کپی و فشار بیشتر بر GC ایجاد کنند.

مدل ذهنی ساده

یک int مستقیماً value عددی را نگه می‌دارد، اما متغیر object باید به یک object اشاره کند. برای قرارگرفتن int در object، CLR یک بستهٔ object می‌سازد و value را داخل آن کپی می‌کند؛ این همان Boxing است. Unboxing بازکردن دلخواه آن بسته نیست و فقط با type دقیق داخل آن معتبر است.

توضیح کامل

در object boxed = count، value فعلی count کپی و boxed می‌شود. تغییر بعدی count محتوای boxed را عوض نمی‌کند. عبارت (int)boxed ابتدا بررسی می‌کند object واقعاً یک boxed int است و سپس value را کپی می‌کند. اگر داخل object یک int باشد، cast مستقیم به long مجاز نیست؛ ابتدا باید int را Unbox و سپس conversion عددی انجام داد. استفاده از List<int> به‌جای collection غیر Generic باعث می‌شود elementها بدون Boxing ذخیره شوند.

C#
int count = 42;
object boxed = count; // boxing
int copy = (int)boxed; // unboxing

var values = new List<int> { 1, 2, 3 }; // بدون boxing برای عناصر

رفتار مثال: boxed یک snapshot از مقدار 42 است، نه اتصال زنده به count. int copy = (int)boxed موفق است؛ اما (long)boxed یک InvalidCastException ایجاد می‌کند، چون type boxed دقیقاً System.Int32 است. long converted = (int)boxed ابتدا Unboxing و سپس numeric conversion انجام می‌دهد.

نکات کلیدی

  • Boxing یک allocation و کپی value ایجاد می‌کند.
  • Unboxing به type دقیق boxed نیاز دارد.
  • Generic APIها معمولاً Boxing ناخواستهٔ Value Typeها را حذف می‌کنند.

اشتباهات رایج

  • اینکه `(long)boxed` برای int boxed کار می‌کند
  • نادیده گرفتن boxing هنگام فراخوانی interface روی struct.

جزئیات عمیق‌تر

هر conversion به object الزاماً مشکل Performance مهمی نیست. اهمیت آن به تعداد تکرار و مسیر اجرا بستگی دارد. در hot pathها با profiler مقدار allocation را اندازه بگیرید. فراخوانی interface روی struct نیز در برخی شکل‌های استفاده می‌تواند Boxing ایجاد کند؛ Generic Constraint مناسب گاهی به JIT امکان فراخوانی بدون Boxing می‌دهد.

در پروژهٔ واقعی

در مسیرهای داغ از collectionهای generic و APIهای generic استفاده کنید و قبل از بهینه‌سازی allocation را با profiler اندازه بگیرید.
