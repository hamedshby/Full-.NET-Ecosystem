Boxing و Unboxing چگونه رخ می‌دهند و چه هزینه‌ای دارند؟

پاسخ کوتاه مصاحبه‌ای

Boxing یعنی تبدیل یک Value Type مثل int یا struct به object یا یک Interface سازگار. در این حالت CLR مقدار Value Type را داخل یک Object قرار می‌دهد. Unboxing برعکس آن است؛ یعنی مقدار اصلی را از Object بیرون می‌آوریم و دوباره به Value Type تبدیل می‌کنیم. Boxing معمولاً باعث Allocation و کپی شدن مقدار می‌شود و اگر زیاد تکرار شود می‌تواند فشار بیشتری به GC وارد کند.

مدل ذهنی خیلی ساده

فرض کنید عدد 42 را روی یک برگه نوشته‌اید. این برگه را می‌توانیم شبیه یک Value Type تصور کنیم. حالا می‌خواهیم آن را داخل یک «جعبه» از نوع object قرار دهیم. CLR یک جعبه می‌سازد و یک کپی از مقدار 42 را داخل آن قرار می‌دهد. این عملیات Boxing است. وقتی بعداً جعبه را باز کنیم و مقدار 42 را دوباره به صورت int بگیریم، عملیات Unboxing انجام شده است.

نکته مهم این است که داخل جعبه یک کپی قرار گرفته است؛ بنابراین جعبه به متغیر اولیه متصل نیست.

اول یک مثال خیلی ساده

C#
int number = 42;

object boxedNumber = number;   // Boxing

int result = (int)boxedNumber; // Unboxing

در خط اول number یک Value Type از نوع int است. در خط دوم می‌خواهیم آن را داخل متغیری از نوع object قرار دهیم؛ بنابراین Boxing اتفاق می‌افتد. در خط سوم مقدار داخل Object را دوباره به int تبدیل می‌کنیم؛ این همان Unboxing است.

در زمان Boxing دقیقاً چه اتفاقی می‌افتد؟

کد زیر را در نظر بگیرید:

C#
int number = 10;
object boxed = number;

به صورت مفهومی CLR این مراحل را انجام می‌دهد:

  1. مقدار فعلی number را می‌خواند؛ یعنی 10.
  2. برای نگهداری مقدار به شکل Object فضای لازم را فراهم می‌کند.
  3. مقدار 10 را داخل آن Object کپی می‌کند.
  4. Reference آن Object را در متغیر boxed قرار می‌دهد.

پس boxed به خود متغیر number اشاره نمی‌کند؛ بلکه Object جداگانه‌ای را در اختیار دارد که مقدار 10 داخل آن قرار گرفته است.

چرا می‌گوییم مقدار کپی می‌شود؟

C#
int number = 10;

object boxed = number;

number = 20;

Console.WriteLine(number); // 20
Console.WriteLine(boxed);  // 10

وقتی Boxing انجام شد، مقدار 10 داخل Object کپی شد. تغییر بعدی number به 20 هیچ تأثیری روی مقدار داخل boxed ندارد. این مثال یکی از بهترین راه‌ها برای فهم Boxing است.

Unboxing دقیقاً چیست؟

حالا فرض کنید یک Object داریم که قبلاً یک int داخل آن Box شده است:

C#
object boxed = 42;

int number = (int)boxed;

در خط دوم از CLR می‌خواهیم مقدار Box شده را به عنوان int دریافت کند. CLR بررسی می‌کند که مقدار داخل Object واقعاً یک System.Int32 است و سپس مقدار آن را برای متغیر number کپی می‌کند.

یک نکته مهم: Unboxing با تبدیل عددی فرق دارد

یکی از سؤال‌های محبوب مصاحبه این است که اگر داخل Object یک int باشد، آیا می‌توان مستقیماً آن را به long تبدیل کرد؟

C#
object boxed = 42;

long value = (long)boxed; // InvalidCastException

این کد در Runtime خطا می‌دهد. دلیلش این است که مقدار داخل Object در اصل یک Int32 است، نه Int64. برای Unboxing باید ابتدا همان Type واقعی را مشخص کنیم:

C#
object boxed = 42;

int number = (int)boxed; // Unboxing
long value = number;     // Numeric conversion

یا به صورت کوتاه:

C#
long value = (int)boxed;

اینجا اول (int)boxed عملیات Unboxing را انجام می‌دهد و بعد مقدار int به long تبدیل می‌شود.

Boxing چه هزینه‌ای دارد؟

Boxing از نظر Performance رایگان نیست. در ساده‌ترین مدل ذهنی، هنگام Boxing باید برای نمایش مقدار به شکل Object فضایی اختصاص داده شود و مقدار Value Type نیز در آن کپی شود. Object ایجادشده بعداً باید توسط Garbage Collector مدیریت شود.

اگر فقط چند بار Boxing داشته باشیم معمولاً مسئله مهمی نیست. مشکل زمانی ایجاد می‌شود که این عملیات در یک Hot Path، Loop بزرگ یا کدی که میلیون‌ها بار اجرا می‌شود اتفاق بیفتد.

مثال از Boxing ناخواسته

C#
int number = 10;
object value = number;

چون number یک Value Type و value از نوع Object است، اینجا Boxing انجام می‌شود. در کدهای واقعی ممکن است چنین تبدیل‌هایی مستقیم نباشند و به همین دلیل تشخیص آن‌ها سخت‌تر شود.

Generics چگونه کمک می‌کنند؟

قبل از Generic Collectionها، Collectionهایی مثل ArrayList مقادیر را به شکل object نگه می‌داشتند. بنابراین قرار دادن Value Typeهایی مثل int در آن‌ها باعث Boxing می‌شد.

C#
var numbers = new ArrayList();

numbers.Add(10); // Boxing
numbers.Add(20); // Boxing
numbers.Add(30); // Boxing

اما با Generic Collection:

C#
var numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

List<int> مشخصاً برای int ساخته شده است و برای نگهداری عناصر لازم نیست آن‌ها ابتدا به object تبدیل شوند. این یکی از مزیت‌های مهم Generics است.

یک مقایسه سریع

عملیات از به اتفاق اصلی
Boxing Value Type object / interface مقدار در نمایش Object قرار می‌گیرد و کپی می‌شود
Unboxing object Value Type Type بررسی و مقدار خارج می‌شود

اشتباهات رایج

  • اشتباه: هر Cast در C# یعنی Boxing یا Unboxing.
    درست: Boxing و Unboxing فقط در سناریوهای مشخص مربوط به Value Type و Object/Interface مطرح هستند.
  • اشتباه: مقدار Box شده به متغیر اولیه متصل است.
    درست: هنگام Boxing مقدار کپی می‌شود.
  • اشتباه: اگر یک int Box شده باشد، می‌توان مستقیماً با (long) آن را Unbox کرد.
    درست: ابتدا باید با Type واقعی یعنی int Unbox شود.
  • اشتباه: هر Boxing الزاماً یک مشکل Performance جدی است.
    درست: اهمیت آن به تعداد تکرار و مسیر اجرای برنامه بستگی دارد.

جزئیات عمیق‌تر برای سطح Senior

Boxing فقط در تبدیل مستقیم به object دیده نمی‌شود. تبدیل یک Struct به Interfaceای که پیاده‌سازی کرده نیز می‌تواند Boxing ایجاد کند. همچنین استفاده از Value Type از طریق Interface در بعضی الگوها می‌تواند هزینه‌ای ایجاد کند که در کد Generic با Constraint مناسب قابل اجتناب باشد.

با این حال نباید صرفاً با دیدن احتمال Boxing شروع به Micro-Optimization کنیم. در پروژه واقعی بهتر است ابتدا با Profiler یا Benchmark مشخص کنیم Allocation واقعاً در Performance برنامه اثر قابل توجهی دارد یا خیر.

در پروژه واقعی کجا مهم می‌شود؟

فرض کنید یک سرویس پرداخت در هر ثانیه تعداد زیادی Transaction پردازش می‌کند و داخل یک Loop پرتکرار دائماً Value Typeها به Object تبدیل می‌شوند. تعداد زیادی Allocation کوچک می‌تواند در مجموع فشار بیشتری روی GC ایجاد کند. در چنین مسیرهایی استفاده از APIهای Generic، Collectionهای Generic و بررسی Allocation با ابزارهای Profiling اهمیت پیدا می‌کند.

اگر مصاحبه‌کننده بپرسد «چطور از Boxing جلوگیری می‌کنی؟»

  • تا جای ممکن از Generic APIها استفاده می‌کنم.
  • برای Collectionها از نوع‌هایی مثل List<T> به جای Collectionهای قدیمی مبتنی بر Object استفاده می‌کنم.
  • در Hot Pathها تبدیل‌های غیرضروری Value Type به Object یا Interface را بررسی می‌کنم.
  • قبل از Optimization با Profiler یا Benchmark مطمئن می‌شوم Boxing واقعاً Bottleneck است.

جواب پیشنهادی برای مصاحبه

«Boxing زمانی اتفاق می‌افتد که یک Value Type مثل int یا struct را به object یا یک Interface سازگار تبدیل کنیم. CLR مقدار Value Type را در یک Object قرار می‌دهد و مقدار در آن کپی می‌شود. Unboxing برعکس این فرآیند است و برای خارج کردن مقدار باید Type واقعی Box شده را بدانیم. Boxing می‌تواند Allocation و در نتیجه فشار بیشتری روی GC ایجاد کند، بنابراین در مسیرهای پرتکرار مهم است. یکی از راه‌های رایج جلوگیری از Boxing غیرضروری استفاده از Genericها، مثلاً List<int> به جای Collectionهای مبتنی بر object است.»

چیزی که باید از این سؤال یادت بماند

اگر فقط چهار نکته را به خاطر بسپارید کافی است: Value Type → Object = Boxing، Object → Value Type = Unboxing، هنگام Boxing مقدار کپی می‌شود، و Boxing زیاد می‌تواند به دلیل Allocation و فشار روی GC روی Performance اثر بگذارد.
