تفاوت عملگرهای && و & چیست؟

پاسخ کوتاه مصاحبه‌ای

برای operandهای bool، && یک Conditional AND با Short-Circuit Evaluation است؛ اگر سمت چپ false باشد سمت راست اجرا نمی‌شود. & روی bool هر دو operand را ارزیابی می‌کند و روی integerها Bitwise AND است.

مدل ذهنی ساده

نتیجهٔ false && هرچیزی از همان سمت چپ مشخص است، پس C# می‌تواند سمت راست را رد کند. این توقف زودهنگام فقط بهینه‌سازی نیست؛ بخشی از semantics && است و برای guard کردن دسترسی‌های خطرناک استفاده می‌شود. & چنین توقفی ندارد.

توضیح کامل

در user is not null && user.IsActive، property فقط وقتی خوانده می‌شود که user null نباشد. جایگزین‌کردن && با & باعث ارزیابی user.IsActive و احتمال NullReferenceException می‌شود. در CheckA() & CheckB() هر دو method اجرا می‌شوند، حتی اگر اولی false دهد؛ این رفتار با side effectها قابل مشاهده است. برای integer، هر bit متناظر مقایسه می‌شود و فقط 1 & 1 نتیجهٔ 1 دارد.

C#
bool safe = user is not null && user.IsActive;
bool bothRun = CheckA() & CheckB();
int mask = flags & 0b_0011;

رفتار مثال: عبارت safe بدون exception مقدار false می‌گیرد اگر user null باشد. در مثال bothRun هر دو log یا side effect اجرا می‌شوند. mask فقط دو bit پایین flags را نگه می‌دارد؛ این کاربرد هیچ ارتباطی با شرط boolean ندارد.

نکات کلیدی

  • && سمت راست را در صورت false بودن سمت چپ اجرا نمی‌کند.
  • & روی bool هر دو طرف را اجرا می‌کند.
  • & روی integer عملیات Bitwise AND انجام می‌دهد.

اشتباهات رایج

  • استفاده از & در null check
  • فراموش‌کردن معنای bitwise برای integerها.

جزئیات عمیق‌تر

operatorهای && و || مستقیماً overload نمی‌شوند، اما type می‌تواند operatorهای true/false و & یا | را تعریف کند تا conditional logic سفارشی ممکن شود. در کد عادی، && انتخاب پیش‌فرض شرط‌ها است؛ & را فقط وقتی semantics eager یا bit mask را واقعاً می‌خواهید به‌کار ببرید.

در پروژهٔ واقعی

در شرط‌های معمولی && را ترجیح دهید؛ فقط وقتی side effect هر دو بررسی واقعاً لازم است & روی bool را انتخاب کنید.

جمع‌بندی برای مصاحبه

سه معنا را جدا کنید: short-circuit boolean، eager boolean و bitwise integer.
