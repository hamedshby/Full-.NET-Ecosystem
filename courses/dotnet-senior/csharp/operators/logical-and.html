تفاوت عملگرهای && و & چیست؟

پاسخ کوتاه مصاحبه‌ای

وقتی با مقادیر bool کار می‌کنیم، هر دو عملگر && و & معنی AND دارند؛ یعنی نتیجه فقط زمانی true می‌شود که هر دو طرف true باشند. تفاوت مهم این است که && از Short-Circuit Evaluation استفاده می‌کند؛ اگر سمت چپ false باشد، سمت راست اصلاً اجرا نمی‌شود. اما & هر دو طرف را ارزیابی می‌کند. علاوه بر این، & برای Typeهای عددی صحیح یک Bitwise AND هم هست.

مدل ذهنی خیلی ساده

فرض کنید برای ورود کاربر دو شرط داریم:

C#
isLoggedIn && hasPermission

اگر isLoggedIn از همان ابتدا false باشد، دیگر بررسی hasPermission برای نتیجه نهایی فایده‌ای ندارد؛ چون false AND هر چیزی = false.

&& از همین موضوع استفاده می‌کند و سمت راست را اجرا نمی‌کند. اما & می‌گوید: «حتی اگر نتیجه را بدانیم، من هر دو طرف را اجرا می‌کنم.»

اول AND منطقی را بفهمیم

در منطق AND، فقط وقتی نتیجه true است که هر دو شرط true باشند:

A B A && B
false false false
false true false
true false false
true true true

از نظر نتیجه منطقی، برای دو مقدار bool، عملگر & نیز همین جدول نتیجه را دارد. تفاوت اصلی در نحوه ارزیابی Expressionها است.

&& چگونه کار می‌کند؟

&& عملگر Conditional Logical AND است. سمت چپ را اول بررسی می‌کند. اگر سمت چپ false باشد، نتیجه کل Expression قطعاً false است؛ بنابراین سمت راست را اجرا نمی‌کند.

C#
bool first = false;

bool result = first && CheckSomething();

چون first برابر false است، CheckSomething() اصلاً فراخوانی نمی‌شود.

Short-Circuit یعنی چه؟

Short-Circuit یعنی وقتی نتیجه Expression از قبل مشخص شده، ادامه Expression ارزیابی نشود.

در عبارت زیر:

C#
false && SomeMethod()

نتیجه بدون توجه به خروجی SomeMethod() همیشه false است. پس C# نیازی ندارد Method را اجرا کند.

این رفتار هم برای Performance مفید است و هم در بسیاری از موارد از اجرای کد ناامن جلوگیری می‌کند.

& روی bool چگونه کار می‌کند؟

وقتی & بین دو Expression از نوع bool قرار بگیرد، نتیجه منطقی AND را تولید می‌کند، اما هر دو طرف را ارزیابی می‌کند.

C#
bool first = false;

bool result = first & CheckSomething();

اینجا با اینکه first false است، CheckSomething() همچنان اجرا می‌شود.

تفاوت را با Console ببینیم

C#
static bool Check()
{
    Console.WriteLine("Check executed");
    return true;
}

bool a = false;

bool result = a && Check();

Console.WriteLine(result);

خروجی:

Output
False

متن Check executed چاپ نمی‌شود، چون Method اجرا نشده است.

حالا فقط && را با & عوض کنیم:

C#
bool result = a & Check();

خروجی:

Output
Check executed
False

نتیجه منطقی هر دو مثال false است، اما در مثال دوم سمت راست هم اجرا شده است. این دقیقاً تفاوت اصلی && و & برای bool است.

یک مثال بسیار مهم: جلوگیری از NullReferenceException

یکی از کاربردهای مهم Short-Circuit این است که قبل از دسترسی به Object، null بودن آن را بررسی کنیم.

C#
Customer? customer = GetCustomer();

if (customer != null && customer.IsActive)
{
    Console.WriteLine("Customer is active");
}

اگر customer برابر null باشد، شرط اول false می‌شود. به دلیل Short-Circuit، عبارت:

C#
customer.IsActive

اصلاً اجرا نمی‌شود. بنابراین به Object null دسترسی نمی‌زنیم.

اگر در مثال قبلی از & استفاده کنیم چه می‌شود؟

C#
Customer? customer = null;

if (customer != null & customer.IsActive)
{
    Console.WriteLine("Customer is active");
}

سمت چپ false است، اما & سمت راست را هم ارزیابی می‌کند. پس برنامه تلاش می‌کند customer.IsActive را روی مقدار null بخواند و NullReferenceException رخ می‌دهد.

به همین دلیل برای ترکیب شرط‌های معمولی در if تقریباً همیشه && انتخاب طبیعی‌تر است.

ترتیب شرط‌ها در && مهم است

چون سمت راست ممکن است اصلاً اجرا نشود، معمولاً شرط ارزان‌تر و ایمن‌تر را سمت چپ قرار می‌دهیم.

C#
if (user != null && user.HasPermission("Payment"))
{
    ProcessPayment();
}

اول بررسی ساده null انجام می‌شود. فقط اگر user وجود داشته باشد، Method دوم اجرا می‌شود.

مثال Performance

فرض کنید بررسی دوم عملیات نسبتاً گرانی است:

C#
if (order.IsActive && HasEnoughBalance(order))
{
    Process(order);
}

اگر Order فعال نباشد، دیگر لازم نیست HasEnoughBalance اجرا شود. این Method ممکن است Query، محاسبه یا کار دیگری انجام دهد.

البته بهتر است Expressionهای شرطی Side Effect پیچیده نداشته باشند و Optimization نیز بر اساس اندازه‌گیری واقعی انجام شود.

پس چرا اصلاً & برای bool وجود دارد؟

گاهی واقعاً می‌خواهیم هر دو Expression اجرا شوند، حتی اگر اولی false باشد.

C#
bool firstCheck = ValidateName();
bool secondCheck = ValidateEmail();

bool isValid = firstCheck & secondCheck;

در این شکل هر دو Validation از قبل اجرا شده‌اند، پس تفاوت Short-Circuit دیگر روی اجرای آن دو Method اثری ندارد. اما اگر مستقیم بنویسیم:

C#
bool isValid = ValidateName() & ValidateEmail();

هر دو Method اجرا می‌شوند. با این حال برای Validation واقعی معمولاً بهتر است طراحی واضحی داشته باشیم و برای اجبار Side Effect به عملگرهای منطقی تکیه نکنیم.

& فقط عملگر منطقی نیست

نکته مهم مصاحبه‌ای این است که & روی Integer Typeها Bitwise AND انجام می‌دهد. یعنی بیت‌های دو عدد را با هم مقایسه می‌کند.

C#
int a = 6;
int b = 3;

int result = a & b;

نمایش باینری:

Binary
6 = 110
3 = 011
    ---
&   010

result = 2

در هر موقعیت فقط وقتی بیت نتیجه 1 می‌شود که بیت هر دو عدد 1 باشد.

آیا می‌توان با int از && استفاده کرد؟

خیر. && برای شرط منطقی است و Operandهای آن باید در قرارداد منطقی مربوط به این عملگر قرار بگیرند؛ در استفاده معمول C# یعنی bool.

C#
int a = 6;
int b = 3;

int result = a && b; // Compile Error

اما این درست است:

C#
int result = a & b;

یک کاربرد واقعی Bitwise AND: Flags

یکی از جاهایی که & واقعاً مفید است، بررسی Flagها است.

C#
[Flags]
public enum Permission
{
    None   = 0,
    Read   = 1,
    Write  = 2,
    Delete = 4
}

Permission permissions =
    Permission.Read | Permission.Write;

bool canWrite =
    (permissions & Permission.Write) != 0;

اینجا & دیگر Logical AND معمولی نیست؛ Bitهای Permission را بررسی می‌کند تا ببینیم Flag مربوط به Write فعال است یا نه.

جدول مقایسه && و &

ویژگی && &
کار با bool بله بله
نتیجه AND منطقی برای bool بله بله
Short-Circuit بله خیر
آیا همیشه سمت راست اجرا می‌شود؟ خیر بله
Bitwise AND روی Integerها خیر بله
کاربرد معمول در if بسیار رایج کمتر رایج

اشتباه رایج: فکر کنیم فقط Performance فرق دارد

تفاوت فقط Performance نیست. این دو کد ممکن است رفتار متفاوتی داشته باشند:

C#
if (customer != null && customer.IsActive)
{
}

و:

C#
if (customer != null & customer.IsActive)
{
}

دومی می‌تواند Exception ایجاد کند. پس Short-Circuit بخشی از Semantics و رفتار برنامه است، نه فقط یک Optimization.

اشتباهات رایج

  • اشتباه: && و & کاملاً یکسان هستند.
    درست: برای bool نتیجه نهایی مشابه است، ولی نحوه ارزیابی Operandها متفاوت است.
  • اشتباه: && همیشه هر دو شرط را اجرا می‌کند.
    درست: اگر سمت چپ false باشد، سمت راست اجرا نمی‌شود.
  • اشتباه: تفاوت فقط در سرعت است.
    درست: اجرا نشدن سمت راست می‌تواند از Exception یا Side Effect جلوگیری کند.
  • اشتباه: & فقط برای bool است.
    درست: روی Integer Typeها Bitwise AND هم انجام می‌دهد.

جزئیات عمیق‌تر برای سطح Senior

در C#، && یک Conditional Logical Operator است و رفتار Short-Circuit دارد. برای Typeهای User-defined نیز C# قواعد Operator Overloading مخصوصی دارد؛ && مستقیماً مثل یک Operator مستقل ساده overload نمی‌شود و رفتار آن با operator & و عملگرهای truth مربوط به Type ارتباط دارد.

در کد Production، نکته مهم‌تر این است که روی Short-Circuit برای کنترل ترتیب اجرای Expressionها آگاه باشید. اگر سمت راست Side Effect دارد، تفاوت && و & می‌تواند رفتار Business را تغییر دهد. بهتر است شرط‌ها تا حد امکان ساده و بدون Side Effect پنهان باشند.

در پروژه واقعی کدام را استفاده کنیم؟

برای شرط‌های معمولی تقریباً همیشه && انتخاب مناسب‌تری است:

C#
if (transaction != null
    && transaction.IsActive
    && transaction.Amount > 0)
{
    ProcessTransaction(transaction);
}

هر شرط فقط زمانی بررسی می‌شود که شرط‌های قبل از آن موفق باشند.

از & معمولاً زمانی استفاده می‌کنیم که:

  • Bitwise operation لازم داریم.
  • با Flags کار می‌کنیم.
  • در یک سناریوی مشخص واقعاً لازم است هر دو Boolean Expression ارزیابی شوند.

اگر مصاحبه‌کننده فقط در ۲۰ ثانیه جواب بخواهد

می‌توانید بگویید:

«هر دو عملگر روی bool عملیات AND انجام می‌دهند، اما && Short-Circuit است؛ اگر Operand سمت چپ false باشد، سمت راست ارزیابی نمی‌شود. & هر دو Operand را ارزیابی می‌کند. همچنین & روی Integerها برای Bitwise AND استفاده می‌شود.»

جواب پیشنهادی کامل برای مصاحبه

«در C# وقتی با bool کار می‌کنیم، هم && و هم & نتیجه AND منطقی می‌دهند، اما تفاوت اصلی در Evaluation است. && از Short-Circuit Evaluation استفاده می‌کند؛ بنابراین اگر شرط سمت چپ false باشد، سمت راست اصلاً اجرا نمی‌شود، چون نتیجه از قبل false است. اما & هر دو طرف را همیشه ارزیابی می‌کند. این تفاوت فقط Performance نیست و می‌تواند روی رفتار برنامه اثر بگذارد؛ مثلاً customer != null && customer.IsActive از دسترسی به null جلوگیری می‌کند. علاوه بر این، & روی Typeهای عددی صحیح Bitwise AND هم انجام می‌دهد و در سناریوهایی مثل Flags کاربرد دارد.»

چیزی که باید از این سؤال یادت بماند

سه نکته را حفظ کنید: && = AND با Short-Circuit، & روی bool = AND بدون Short-Circuit، و & روی عدد = Bitwise AND.
