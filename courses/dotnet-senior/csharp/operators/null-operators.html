تفاوت ??، ??=، ?. و ?[] چیست؟

پاسخ کوتاه مصاحبه‌ای

این چهار Operator همگی برای کار امن‌تر و خواناتر با null استفاده می‌شوند، اما وظیفه‌شان متفاوت است. ?? اگر مقدار سمت چپ null باشد یک مقدار جایگزین برمی‌گرداند. ??= فقط وقتی متغیر null باشد مقدار جدید را داخل آن قرار می‌دهد. ?. Member یک Object را فقط وقتی Object null نیست می‌خواند یا فراخوانی می‌کند. و ?[] همان رفتار Null-Conditional را برای دسترسی با Index یا Indexer فراهم می‌کند.

مدل ذهنی خیلی ساده

برای حفظ کردن این چهار Operator، هرکدام را با یک سؤال به خاطر بسپارید:

  • ?? → «اگر null بود، به جایش چه چیزی استفاده کنم؟»
  • ??= → «اگر null بود، چه چیزی داخلش قرار بدهم؟»
  • ?. → «اگر Object وجود داشت، Member آن را بخوان یا اجرا کن.»
  • ?[] → «اگر Collection/Object وجود داشت، به Index یا Indexer آن دسترسی بزن.»

اول مشکل null را ببینیم

C#
Customer? customer = null;

Console.WriteLine(customer.Name); // NullReferenceException

چون customer هیچ Objectی را Reference نمی‌کند، دسترسی مستقیم به Name خطرناک است. Operatorهای Null در C# کمک می‌کنند این سناریوها را کوتاه‌تر و واضح‌تر مدیریت کنیم.

عملگر ?? چیست؟

?? را Null-Coalescing Operator می‌نامیم. اگر مقدار سمت چپ null نباشد همان مقدار را برمی‌گرداند؛ اگر null باشد، مقدار سمت راست را استفاده می‌کند.

C#
string? name = null;

string displayName = name ?? "Guest";

Console.WriteLine(displayName); // Guest

اگر name مقدار "Hamed" داشته باشد:

C#
string? name = "Hamed";

string displayName = name ?? "Guest";

Console.WriteLine(displayName); // Hamed

?? را می‌توان مثل یک if ساده تصور کرد

C#
string displayName;

if (name != null)
{
    displayName = name;
}
else
{
    displayName = "Guest";
}

نسخه کوتاه‌تر:

C#
string displayName = name ?? "Guest";

وقتی فقط هدف انتخاب مقدار جایگزین برای null است، ?? معمولاً Intent را خیلی واضح نشان می‌دهد.

آیا سمت راست ?? همیشه اجرا می‌شود؟

خیر. اگر سمت چپ null نباشد، Expression سمت راست ارزیابی نمی‌شود.

C#
string? name = "Hamed";

string result = name ?? LoadDefaultName();

چون name مقدار دارد، LoadDefaultName() اجرا نمی‌شود.

عملگر ??= چیست؟

??= را Null-Coalescing Assignment Operator می‌نامیم. یعنی: «فقط اگر متغیر null است، مقدار سمت راست را به آن Assign کن.»

C#
string? name = null;

name ??= "Guest";

Console.WriteLine(name); // Guest

اما اگر از قبل مقدار داشته باشد:

C#
string? name = "Hamed";

name ??= "Guest";

Console.WriteLine(name); // Hamed

تفاوت ?? و ??= دقیقاً چیست؟

Operator کار اصلی آیا متغیر سمت چپ را تغییر می‌دهد؟
?? انتخاب یک مقدار جایگزین خیر
??= Assign کردن مقدار در صورت null بودن بله
C#
string? name = null;

string result = name ?? "Guest";
// name هنوز null است

name ??= "Guest";
// حالا خود name برابر Guest است

یک کاربرد واقعی ??=

فرض کنید یک Collection را فقط زمانی می‌خواهیم بسازیم که واقعاً لازم شده باشد:

C#
List<string>? errors = null;

errors ??= new List<string>();
errors.Add("Invalid amount");

اگر errors قبلاً ساخته شده باشد، List جدیدی ساخته و جایگزین نمی‌شود.

عملگر ?. چیست؟

?. یک Null-Conditional Operator است. Member سمت راست فقط زمانی Access می‌شود که Object سمت چپ null نباشد.

C#
Customer? customer = null;

string? name = customer?.Name;

اگر customer وجود داشته باشد، Name خوانده می‌شود. اگر customer null باشد، به جای Exception نتیجه Expression برابر null می‌شود.

?. فقط برای Property نیست

می‌توانیم Method را نیز به شکل Null-Conditional فراخوانی کنیم:

C#
customer?.Activate();

اگر customer null باشد، Activate() اصلاً اجرا نمی‌شود.

چرا نتیجه ?. گاهی Nullable می‌شود؟

فرض کنید Property ما از نوع int است:

C#
public class Customer
{
    public int Age { get; set; }
}

حالا:

C#
Customer? customer = null;

int? age = customer?.Age;

خود Age از نوع int است، ولی نتیجه customer?.Age باید بتواند حالت «customer وجود نداشت» را هم نشان دهد؛ بنابراین نتیجه می‌تواند int? باشد.

ترکیب ?. و ?? بسیار رایج است

C#
string displayName = customer?.Name ?? "Guest";

این خط را از چپ به راست بخوانید:

  1. اگر customer وجود دارد، Name را بخوان.
  2. اگر نتیجه null شد، مقدار "Guest" را استفاده کن.

این ترکیب در DTO Mapping، Response سازی و نمایش مقادیر Optional بسیار رایج است.

زنجیره Null-Conditional

می‌توانیم چند دسترسی را زنجیره کنیم:

C#
string? city = order?.Customer?.Address?.City;

اگر هرکدام از order، Customer یا Address در مسیر null باشند، ادامه زنجیره متوقف می‌شود و نتیجه null خواهد بود.

?[] چیست؟

?[] نسخه Null-Conditional برای Element Access / Indexer است. مثلاً اگر یک Array یا Collection ممکن است null باشد:

C#
string[]? names = null;

string? first = names?[0];

اگر names null باشد، به Index صفر دسترسی زده نمی‌شود و نتیجه null است.

?[] جلوی IndexOutOfRangeException را می‌گیرد؟

خیر. این نکته مصاحبه‌ای بسیار مهم است.

C#
string[] names = { "Ali" };

string? value = names?[10]; // IndexOutOfRangeException

?[] فقط null بودن خود Collection/Object را مدیریت می‌کند. اگر Collection وجود داشته باشد ولی Index نامعتبر باشد، Exception مربوط به Index همچنان رخ می‌دهد.

?[] فقط برای Array نیست

هر Typeای که Indexer مناسب داشته باشد می‌تواند در چنین Expressionهایی استفاده شود.

C#
Dictionary<string, string>? settings = null;

string? value = settings?["ConnectionString"];

اگر settings null باشد، Indexer اجرا نمی‌شود. اما اگر Dictionary وجود داشته باشد و Key موجود نباشد، رفتار خود Indexer پابرجاست و در این مثال می‌تواند KeyNotFoundException بدهد.

پس ?[] چه چیزی را Safe می‌کند؟

وضعیت collection?[index]
Collection برابر null است دسترسی انجام نمی‌شود و نتیجه null است
Collection وجود دارد و Index معتبر است عنصر برگردانده می‌شود
Collection وجود دارد ولی Index نامعتبر است Exception مربوط به Index همچنان ممکن است رخ دهد

هر چهار Operator در یک مثال

C#
Customer? customer = GetCustomer();

// ?.  دسترسی امن به Member
string? name = customer?.Name;

// ??  مقدار جایگزین
string displayName = name ?? "Guest";

// ??=  مقداردهی فقط در صورت null بودن
customer ??= new Customer();

// ?[]  دسترسی شرطی به Index
string[]? tags = customer.Tags;
string? firstTag = tags?[0];

جدول مقایسه سریع

Operator نام وظیفه مثال
?? Null-Coalescing مقدار جایگزین در صورت null name ?? "Guest"
??= Null-Coalescing Assignment Assign فقط در صورت null name ??= "Guest"
?. Null-Conditional Member Access دسترسی به Member فقط اگر Object null نیست user?.Name
?[] Null-Conditional Element Access دسترسی به Index/Indexer فقط اگر Object null نیست items?[0]

مثال واقعی در یک API

C#
public CustomerResponse Map(Customer? customer)
{
    return new CustomerResponse
    {
        Name = customer?.Name ?? "Unknown",
        City = customer?.Address?.City ?? "Unknown",
        FirstPhone = customer?.Phones?[0]
    };
}

در این مثال با چند Operator کوچک، مسیرهای Optional را واضح کرده‌ایم. البته اگر Index صفر الزاماً وجود ندارد، باید Count یا روش مناسب دیگری را نیز بررسی کنیم؛ ?[] فقط null بودن Phones را پوشش می‌دهد.

تفاوت ?. با ! چیست؟

این دو را با هم اشتباه نکنید:

C#
customer?.Name
customer!.Name
  • ?. واقعاً رفتار Runtime را تغییر می‌دهد و اگر customer null باشد Member را Access نمی‌کند.
  • ! همان Null-Forgiving Operator است و فقط به Compiler می‌گوید هشدار Nullability را نده؛ جلوی NullReferenceException را نمی‌گیرد.

اشتباه رایج: استفاده بیش از حد از ?.

Null-Conditional Operator بسیار مفید است، اما نباید خطای Domain را مخفی کند. اگر طبق Business Rule وجود Customer الزامی است، این کد شاید مشکل را پنهان کند:

C#
var customerId = order?.Customer?.Id;

اگر نبودن Customer یک وضعیت غیرمجاز است، شاید بهتر باشد Validation یا Exception مناسب داشته باشیم تا مشکل سریع‌تر مشخص شود. Null Safety به معنی «همه‌جا null را نادیده بگیر» نیست.

?? با مقدار پیش‌فرض Business چه فرقی دارد؟

مقدار سمت راست ?? باید از نظر Domain معنی داشته باشد.

C#
decimal amount = request.Amount ?? 0;

این کد از نظر Syntax درست است، اما آیا «ارسال نشدن Amount» واقعاً باید معنی صفر بدهد؟ اگر Amount الزامی است، Validation انتخاب درست‌تری است.

اشتباهات رایج

  • اشتباه: ?? مقدار متغیر سمت چپ را تغییر می‌دهد.
    درست: فقط یک مقدار نتیجه انتخاب می‌کند؛ برای Assignment از ??= استفاده می‌شود.
  • اشتباه: ?. تضمین می‌کند نتیجه null نیست.
    درست: برعکس، اگر Object null باشد نتیجه معمولاً null می‌شود.
  • اشتباه: ?[] همه خطاهای Index را مدیریت می‌کند.
    درست: فقط null بودن Receiver را مدیریت می‌کند.
  • اشتباه: ?. و ! یک کاربرد دارند.
    درست: ?. رفتار Runtime دارد؛ ! عمدتاً هشدار Compiler را Suppress می‌کند.
  • اشتباه: هر null را باید با مقدار Default مخفی کرد.
    درست: گاهی null نشان‌دهنده ورودی نامعتبر یا نقض Business Rule است و باید Validation شود.

جزئیات عمیق‌تر برای سطح Senior

Null-Conditional accessها Short-Circuit هستند؛ وقتی Receiver در یک زنجیره null شود، ادامه دسترسی شرطی انجام نمی‌شود. همچنین نوع نتیجه باید بتواند حالت null را نمایش دهد؛ به همین دلیل دسترسی شرطی به یک Value Type غیر Nullable مثل int معمولاً نتیجه‌ای Nullable مانند int? ایجاد می‌کند.

در طراحی Production Code، این Operatorها ابزار بیان Contract هستند، نه جایگزین Validation. در Boundaryهایی مثل API، Database و Message Consumer باید مشخص کنیم null واقعاً یک حالت معتبر Domain است یا داده ناقص و نامعتبر.

در پروژه واقعی کدام را چه زمانی استفاده کنیم؟

  • یک مقدار Optional دارم و Default منطقی می‌خواهم → ??
  • می‌خواهم یک متغیر فقط در صورت null بودن Initialize شود → ??=
  • یک Object Optional است و می‌خواهم Member آن را امن بخوانم/فراخوانی کنم → ?.
  • یک Array/Collection/Indexer Optional است و می‌خواهم Element Access فقط در صورت non-null بودن انجام شود → ?[]

اگر مصاحبه‌کننده فقط در ۲۰ ثانیه جواب بخواهد

«?? در صورت null بودن مقدار سمت چپ یک مقدار جایگزین برمی‌گرداند؛ ??= همان منطق را برای Assignment دارد و فقط وقتی متغیر null است مقداردهی می‌کند؛ ?. Member را فقط اگر Object null نباشد Access می‌کند؛ و ?[] همین Null-Conditional behavior را برای Indexer یا Element Access دارد. نکته مهم این است که ?[] جلوی IndexOutOfRangeException را نمی‌گیرد.»

جواب پیشنهادی کامل برای مصاحبه

«این چهار Operator برای مدیریت Null هستند ولی کاربرد متفاوتی دارند. ?? یا Null-Coalescing Operator مقدار سمت چپ را در صورت non-null بودن برمی‌گرداند و در غیر این صورت مقدار سمت راست را انتخاب می‌کند. ??= فقط زمانی مقدار سمت راست را به متغیر Assign می‌کند که مقدار فعلی null باشد. ?. یک Null-Conditional Member Access است و Property یا Method را فقط وقتی Receiver null نیست Access می‌کند؛ در غیر این صورت نتیجه null می‌شود. ?[] همین رفتار را برای Element Access یا Indexer دارد. این Operatorها کد Null Handling را کوتاه‌تر و خواناتر می‌کنند، ولی جای Validation Business را نمی‌گیرند و ?[] نیز فقط null بودن Collection را کنترل می‌کند، نه معتبر بودن Index یا Key.»

چیزی که باید از این سؤال یادت بماند

چهار جمله را حفظ کنید: ?? = اگر null بود، مقدار جایگزین بده، ??= = اگر null بود، مقداردهی کن، ?. = اگر Object وجود داشت، Member را Access کن، و ?[] = اگر Object وجود داشت، Index/Indexer را Access کن.
