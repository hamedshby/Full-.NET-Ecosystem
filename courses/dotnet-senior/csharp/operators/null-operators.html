تفاوت ??، ??=، ?. و ?[] چیست؟

پاسخ کوتاه مصاحبه‌ای

?? در صورت null بودن operand چپ fallback می‌دهد؛ ??= فقط در همان حالت assignment می‌کند؛ ?. و ?[] دسترسی member یا index را متوقف کرده و نتیجهٔ null می‌دهند اگر receiver null باشد.

مدل ذهنی ساده

این operatorها یک مسیر امن برای «نبودن value» می‌سازند. ?? میان value موجود و fallback انتخاب می‌کند. ?. پیش از دسترسی می‌پرسد آیا object وجود دارد؛ اگر نه، ادامهٔ زنجیره را اجرا نمی‌کند. این رفتار exceptionهای دیگر را پنهان نمی‌کند.

توضیح کامل

در customer?.Address?.City ?? "نامشخص" هر access فقط وقتی ادامه پیدا می‌کند که نتیجهٔ قبلی null نباشد. سمت راست ?? lazy است، بنابراین fallback گران فقط در صورت نیاز ساخته می‌شود. cache ??= new Dictionary... initialization را انجام می‌دهد اگر cache null باشد، اما به‌تنهایی primitive همگام‌سازی threadها نیست. ?[] همان conditional access برای indexer است.

C#
var city = customer?.Address?.City ?? "نامشخص";
cache ??= new Dictionary<string, Item>();
var first = items?[0];

رفتار مثال: اگر customer یا Address null باشد، city برابر «نامشخص» می‌شود. اگر getter مربوط به City exception دیگری پرتاب کند، ?. آن را catch نمی‌کند. اگر cache از قبل ساخته شده باشد، constructor سمت راست ??= اجرا نمی‌شود.

نکات کلیدی

  • ?? و ??= سمت راست را فقط هنگام نیاز ارزیابی می‌کنند.
  • ?. و ?[] فقط null receiver را مدیریت می‌کنند.
  • fallback نباید نبودن دادهٔ الزامی را بی‌صدا پنهان کند.

اشتباهات رایج

  • پنهان‌کردن دادهٔ الزامی با fallback
  • تصور اینکه `?.` تمام exceptionها را می‌گیرد.

جزئیات عمیق‌تر

چند operator را می‌توان ترکیب کرد، ولی زنجیرهٔ طولانی ممکن است معلوم نکند کدام داده غایب بوده است. در domain invariant یا ورودی الزامی، validation و خطای صریح بهتر است. throw expression نیز می‌تواند سمت راست ?? قرار گیرد تا قرارداد non-null enforce شود.

در پروژهٔ واقعی

برای دادهٔ اختیاری و lazy initialization مناسب‌اند؛ در ورودی الزامی، خطای صریح بهتر است.
