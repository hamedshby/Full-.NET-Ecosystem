Conditional Operator ?: چه زمانی از if مناسب‌تر است؟

پاسخ کوتاه مصاحبه‌ای

Conditional Operator یعنی condition ? whenTrue : whenFalse یک expression است که یکی از دو value را تولید می‌کند. برای انتخاب کوتاه یک value مناسب است؛ اگر هر branch چند کار انجام می‌دهد یا خوانایی افت می‌کند، if روشن‌تر است.

مدل ذهنی ساده

if مسیر اجرای statementها را کنترل می‌کند، ولی Conditional Operator خودش یک value دارد. به همین دلیل می‌توان آن را در assignment، return یا argument قرار داد. تنها یکی از دو branch ارزیابی می‌شود، پس branch انتخاب‌نشده side effect یا exception ایجاد نمی‌کند.

توضیح کامل

در var label = score >= 10 ? "قبول" : "نیازمند تلاش" هدف فقط انتخاب یک string است و شکل expression خواناست. اگر branchها نیاز به log، validation و چند statement داشته باشند، فشرده‌کردن آن‌ها در expression فهم کد را سخت می‌کند. Conditional Operator می‌تواند target-typed باشد؛ context مقصد به Compiler کمک می‌کند type مشترک branchها را تعیین کند.

C#
string label = score >= 10 ? "قبول" : "نیازمند تلاش";
return user is null ? Result.NotFound() : Result.Ok(user);

رفتار مثال: برای score برابر 12 فقط expression نخست اجرا و label برابر «قبول» می‌شود. در return دوم، اگر user null باشد Result.NotFound ساخته می‌شود و Result.Ok اصلاً فراخوانی نمی‌شود. این lazy branch selection با فراخوانی هر دو method و انتخاب نتیجه متفاوت است.

نکات کلیدی

  • Conditional Operator یک value تولید می‌کند.
  • فقط branch انتخاب‌شده ارزیابی می‌شود.
  • خوانایی مهم‌تر از کوتاه‌کردن ظاهری کد است.

اشتباهات رایج

  • استفاده برای چند دستور
  • nesting پیچیده فقط برای کوتاه‌شدن کد.

جزئیات عمیق‌تر

زنجیرهٔ nested از ?: از نظر syntax ممکن است، اما ترتیب association و scan کردن آن دشوار می‌شود. برای mappingهای کوچک مناسب است؛ برای business rule چندشاخه، switch expression یا method نام‌دار معمولاً intent را بهتر منتقل می‌کند.

در پروژهٔ واقعی

در mapping کوتاه یا تعیین label استفاده کنید؛ منطق کسب‌وکار چندشاخه را واضح نگه دارید.
