checked و unchecked چگونه Overflow عددی را کنترل می‌کنند؟

پاسخ کوتاه مصاحبه‌ای

در C#، checked باعث می‌شود Overflow در عملیات عددی Integral در Runtime بررسی شود و در صورت خارج شدن نتیجه از محدوده Type، معمولاً OverflowException رخ دهد. unchecked این بررسی را غیرفعال می‌کند و Overflow می‌تواند با Wrap شدن بیت‌ها ادامه پیدا کند. این موضوع بیشتر برای Typeهای صحیح مثل int، long و تبدیل‌های عددی مهم است؛ رفتار Floating Point مثل double متفاوت است.

مدل ذهنی خیلی ساده

فرض کنید یک ظرف فقط می‌تواند اعداد بین یک حداقل و حداکثر مشخص را نگه دارد. اگر عدد از ظرفیت ظرف بزرگ‌تر شود، دو رفتار ممکن داریم:

  • checked → می‌گوید: «عدد از محدوده خارج شد؛ خطا بده.»
  • unchecked → می‌گوید: «خطا نده و طبق نمایش بیتی Type ادامه بده.»

Overflow اصلاً چیست؟

هر Type عددی Integral محدوده مشخصی دارد. مثلاً int نمی‌تواند هر عدد دلخواهی را نگه دارد.

C#
Console.WriteLine(int.MaxValue);
// 2147483647

حالا اگر یک واحد به این مقدار اضافه کنیم، نتیجه واقعی ریاضی برابر 2147483648 است؛ اما این عدد دیگر داخل int جا نمی‌شود. به این وضعیت Overflow می‌گوییم.

مثال ساده با int.MaxValue

C#
int number = int.MaxValue;

number = number + 1;

Console.WriteLine(number);

در یک Context unchecked، نتیجه به جای عدد مورد انتظار می‌تواند Wrap شود و به مقدار دیگری در محدوده int برسد. برای int دو مکمل، بعد از عبور از بیشینه معمولاً به سمت مقدار کمینه Wrap می‌شود.

checked چه کاری می‌کند؟

اگر همان عملیات را داخل checked قرار دهیم، Runtime Overflow را بررسی می‌کند:

C#
int number = int.MaxValue;

checked
{
    number = number + 1;
}

اینجا نتیجه خارج از محدوده int است، بنابراین OverflowException رخ می‌دهد.

checked به صورت Expression

لازم نیست همیشه یک Block کامل داشته باشیم:

C#
int number = int.MaxValue;

int result = checked(number + 1);

این فرم زمانی خوب است که فقط یک Expression خاص باید Overflow-checked باشد.

unchecked چه کاری می‌کند؟

unchecked مشخص می‌کند Overflow برای عملیات Integral بررسی نشود:

C#
int number = int.MaxValue;

unchecked
{
    number = number + 1;
}

Console.WriteLine(number);

در این حالت Exception مربوط به Overflow رخ نمی‌دهد و نتیجه طبق رفتار unchecked محاسبه می‌شود.

Wrap شدن یعنی چه؟

برای درک ساده، محدوده int را مثل یک دایره تصور کنید:

Concept
... 2147483645
    2147483646
    2147483647
        ↓ overflow
   -2147483648
   -2147483647
   ...

این تصویر برای درک رفتار معمول unchecked روی int مناسب است: بیت‌های نتیجه در همان اندازه Type باقی می‌مانند.

مثال مهم با cast

checked فقط برای جمع و ضرب نیست؛ در تبدیل‌های عددی هم مهم است.

C#
long value = 3_000_000_000;

int result = checked((int)value);

چون مقدار long داخل int جا نمی‌شود، این Cast در Context checked باعث OverflowException می‌شود.

همین cast با unchecked

C#
long value = 3_000_000_000;

int result = unchecked((int)value);

اینجا Exception مربوط به Overflow رخ نمی‌دهد و فقط بیت‌های قابل نگهداری در int باقی می‌مانند؛ بنابراین مقدار نهایی ممکن است کاملاً با عدد اولیه متفاوت باشد.

کدام عملیات‌ها معمولاً تحت تأثیر checked هستند؟

در سناریوهای Integral، عملیات‌هایی مثل این‌ها می‌توانند Overflow داشته باشند:

  • جمع
  • تفریق
  • ضرب
  • Increment و Decrement
  • تبدیل Explicit بین Typeهای عددی
C#
checked
{
    int a = int.MaxValue;
    a++;

    int b = 100_000;
    int c = b * b;
}

آیا division هم Overflow دارد؟

یک مورد خاص و معروف وجود دارد:

C#
int value = int.MinValue;

int result = value / -1;

نتیجه ریاضی برابر 2147483648 است و داخل int جا نمی‌شود. این مورد خاص می‌تواند OverflowException ایجاد کند.

checked با double و float چطور رفتار می‌کند؟

این نکته مهم است: checked برای Overflow مربوط به Floating Point مثل double همان رفتار Integralها را ایجاد نمی‌کند. Floating Point طبق استاندارد خودش می‌تواند مقادیری مثل Infinity داشته باشد.

C#
double value = double.MaxValue;

double result = value * 2;

Console.WriteLine(result); // Infinity

پس checked را نباید به صورت «کنترل همه نوع Overflow عددی در C#» تعریف کنیم. تمرکز اصلی آن روی Integral Arithmetic و Conversionهای مربوط است.

decimal چطور؟

decimal رفتار متفاوتی دارد و در بسیاری از عملیات خارج از محدوده خودش به صورت ذاتی Exception می‌دهد. برای سناریوهای مالی، decimal به دلیل ماهیت ده‌دهی و رفتار دقیق‌تر برای مقادیر پولی معمولاً مناسب‌تر از float/double است.

Compile Time و Runtime چه فرقی دارند؟

اگر Compiler بتواند Overflow یک Constant Expression را همان موقع تشخیص دهد، ممکن است اصلاً اجازه Compile ندهد.

C#
int x = 2147483647 + 1;

چون هر دو مقدار Constant هستند، Compiler می‌تواند محاسبه را همان Compile Time انجام دهد و Overflow را تشخیص دهد.

ولی اگر مقدار در Runtime مشخص شود...

C#
int x = GetNumber();
int y = x + 1;

Compiler مقدار واقعی x را نمی‌داند؛ بنابراین رفتار checked یا unchecked Runtime اهمیت پیدا می‌کند.

checked block یا checked expression؟

حالت نمونه کاربرد
Checked Block checked { ... } چند Operation پشت سر هم
Checked Expression checked(a + b) فقط یک Expression خاص
Unchecked Block unchecked { ... } غیرفعال کردن بررسی در یک بخش
Unchecked Expression unchecked((int)value) یک Conversion یا Expression خاص

مثال واقعی در سیستم مالی

فرض کنید Amountها را جمع می‌کنیم:

C#
long total = 0;

foreach (var transaction in transactions)
{
    total = checked(total + transaction.Amount);
}

اگر Amountها به شکلی برسند که از محدوده long عبور کنند، بهتر است سیستم خطا را آشکار کند تا اینکه یک مقدار Wrap شده و اشتباه مالی تولید شود.

در Domainهای حساس مثل مالی، Silent Overflow می‌تواند بسیار خطرناک‌تر از Exception باشد.

مثال واقعی برای unchecked

گاهی Wrap شدن عمدی است، مثلاً در بعضی الگوریتم‌های Low-level، Hashing یا کار مستقیم با بیت‌ها.

C#
int hash = unchecked(seed * 31 + value);

در چنین الگوریتمی Overflow ممکن است بخشی از رفتار مورد انتظار باشد، نه Bug.

آیا checked را باید همه‌جا روشن کنیم؟

نه لزوماً. این تصمیم به Domain و نوع محاسبات بستگی دارد. اگر Overflow نشانه خطای مهم Business است، checked می‌تواند ارزشمند باشد. اگر الگوریتم عمداً روی Wraparound تکیه دارد، unchecked مناسب‌تر است.

هدف این است که رفتار Overflow آگاهانه و صریح باشد.

اشتباه رایج: فکر کنیم checked مقدار را بزرگ‌تر می‌کند

checked ظرفیت Type را بیشتر نمی‌کند.

C#
checked
{
    int x = int.MaxValue;
    x++;
}

int همچنان همان محدوده قبلی را دارد؛ checked فقط تشخیص Overflow و Exception را فعال می‌کند.

اشتباه رایج: unchecked یعنی داده درست باقی می‌ماند

نه. unchecked فقط می‌گوید Overflow را Exception نکن. عدد نهایی ممکن است از نظر Business کاملاً غلط باشد.

C#
int balance = int.MaxValue;

balance = unchecked(balance + 100);

اینکه برنامه Crash نکرده به این معنی نیست که balance هنوز مقدار منطقی و معتبری دارد.

فرق Overflow با DivideByZeroException

این دو را با هم اشتباه نکنید.

C#
int x = 10;
int y = 0;

int result = x / y; // DivideByZeroException

checked برای جلوگیری از تقسیم بر صفر نیست. Divide by zero یک خطای مستقل است.

جدول مقایسه سریع

ویژگی checked unchecked
بررسی Overflow Integral بله خیر
OverflowException ممکن است رخ دهد معمولاً برای Overflow معمول Integral رخ نمی‌دهد
Wraparound اجازه نمی‌دهد Overflow بی‌صدا ادامه پیدا کند می‌تواند رخ دهد
کاربرد مناسب محاسبات حساس و نیازمند تشخیص Overflow الگوریتم‌های عمدی با Wraparound

Overflow با Underflow فرق دارد؟

برای Integerها وقتی از پایین‌ترین یا بالاترین محدوده عبور می‌کنیم، معمولاً در بحث checked/unchecked هر دو را در قالب Overflow عددی بررسی می‌کنیم. برای Floating Point، اصطلاح Underflow معمولاً به کوچک شدن بیش از حد مقدار و از دست رفتن Precision یا رسیدن به صفر/مقادیر Subnormal مربوط می‌شود و داستان متفاوتی دارد.

تنظیم پروژه هم می‌تواند مهم باشد

در C# علاوه بر استفاده موضعی از checked و unchecked، تنظیمات Compiler نیز می‌توانند روی Context پیش‌فرض Overflow Checking برای Integer Arithmetic اثر بگذارند. اما حتی در چنین پروژه‌ای می‌توان با checked/unchecked در یک بخش مشخص، Intent را صریح کرد.

اشتباهات رایج

  • اشتباه: checked محدوده int را بزرگ‌تر می‌کند.
    درست: فقط Overflow را تشخیص می‌دهد.
  • اشتباه: unchecked یعنی نتیجه هنوز از نظر Business صحیح است.
    درست: فقط Exception مربوط به Overflow را حذف می‌کند و Wraparound ممکن است داده را خراب کند.
  • اشتباه: checked روی double هم مثل int OverflowException می‌دهد.
    درست: Floating Point رفتار متفاوتی دارد و می‌تواند Infinity تولید کند.
  • اشتباه: checked فقط برای جمع است.
    درست: روی چندین عملیات Integral و Conversionهای عددی اثر دارد.
  • اشتباه: checked جلوی DivideByZeroException را می‌گیرد.
    درست: تقسیم بر صفر مسئله جداگانه‌ای است.

جزئیات عمیق‌تر برای سطح Senior

Compiler برای عملیات Integral در Context checked می‌تواند IL متفاوتی تولید کند؛ برای مثال برخی دستورهای Overflow-checking در IL وجود دارند که اگر نتیجه از محدوده خارج شود Exception ایجاد می‌کنند. در Context unchecked، عملیات بدون آن بررسی Overflow انجام می‌شود.

همچنین Constant Expressionها می‌توانند در Compile Time بررسی شوند، بنابراین تفاوت بین Overflow زمان Compile و Runtime مهم است. برای Domainهای حساس بهتر است Type مناسب را هم انتخاب کنید؛ checked جای انتخاب Type درست را نمی‌گیرد. اگر محدوده int ذاتاً برای داده کوچک است، شاید long یا Type مناسب‌تری لازم باشد.

در پروژه واقعی چه قاعده‌ای داشته باشیم؟

  • اگر Overflow نشانه Bug یا فساد داده است → checked.
  • اگر Wraparound عمداً بخشی از الگوریتم است → unchecked.
  • اگر Type انتخاب‌شده ظرفیت کافی ندارد → Type بزرگ‌تر یا مناسب‌تر انتخاب کنید.
  • در محاسبات مالی، Silent Overflow را بسیار جدی بگیرید.
  • برای کد Performance-sensitive، اول صحت و سپس Benchmark واقعی را در نظر بگیرید.

اگر مصاحبه‌کننده فقط در ۲۰ ثانیه جواب بخواهد

«checked باعث می‌شود Overflow در عملیات Integral و Conversionهای مربوط بررسی شود و اگر نتیجه از محدوده Type خارج شد OverflowException بگیریم. unchecked این بررسی را غیرفعال می‌کند و Overflow می‌تواند به صورت Wraparound ادامه پیدا کند. این رفتار عمدتاً برای Integerها مهم است؛ Floating Pointهایی مثل double رفتار متفاوتی دارند.»

جواب پیشنهادی کامل برای مصاحبه

«در C# checked و unchecked Context نحوه برخورد با Overflow در محاسبات Integral را کنترل می‌کنند. در checked، اگر نتیجه یک Operation یا Conversion از محدوده Type خارج شود، Runtime معمولاً OverflowException ایجاد می‌کند. در unchecked، همان Overflow بدون Exception ادامه پیدا می‌کند و بیت‌های نتیجه در محدوده Type Wrap می‌شوند. این موضوع در محاسبات حساس مثل مالی مهم است، چون Silent Overflow می‌تواند داده اشتباه تولید کند. checked ظرفیت Type را تغییر نمی‌دهد و روی Floating Point مثل double هم رفتار مشابه int ندارد. من از checked زمانی استفاده می‌کنم که Overflow باید به عنوان خطا دیده شود و از unchecked فقط وقتی Wraparound بخشی عمدی از الگوریتم باشد.»

چیزی که باید از این سؤال یادت بماند

سه جمله را حفظ کنید: checked = Overflow را بررسی کن و در صورت خروج از محدوده خطا بده، unchecked = Overflow را بدون Exception ادامه بده، و این موضوع عمدتاً برای Integral Arithmetic و Conversionهاست، نه Floating Point معمول.
