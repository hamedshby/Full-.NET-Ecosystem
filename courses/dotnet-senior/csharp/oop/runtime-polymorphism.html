Runtime Polymorphism در C# چگونه کار می‌کند؟

پاسخ کوتاه مصاحبه‌ای

Runtime Polymorphism یعنی call یک member مجازی از طریق reference پایه یا interface، implementation متناسب با Runtime Type واقعی object را اجرا کند. این رفتار با virtual/override، abstract/override یا interface dispatch شکل می‌گیرد.

مدل ذهنی ساده

متغیر دو type مرتبط دارد: Static Type مشخص می‌کند چه memberهایی قابل فراخوانی‌اند؛ Runtime Type مشخص می‌کند کدام override اجرا شود. در Shape shape = new Circle()، Compiler فقط قرارداد Shape را می‌بیند، اما هنگام shape.Area()، Runtime پیاده‌سازی Circle را انتخاب می‌کند.

توضیح کامل

Compiler برای call مجازی instruction و metadata لازم را تولید می‌کند و CLR slot مناسب Runtime Type را dispatch می‌کند. شرط آن است که member واقعاً virtual باشد؛ method عادی یا member static از این مسیر استفاده نمی‌کند. interface dispatch نیز implementation type واقعی را پیدا می‌کند. Runtime Polymorphism به مصرف‌کننده اجازه می‌دهد بدون if روی typeهای مشخص، با قرارداد پایه کار کند؛ افزودن implementation جدید معمولاً مصرف‌کننده را تغییر نمی‌دهد.

C#
abstract class Shape { public abstract double Area(); }
sealed class Circle(double r) : Shape
{ public override double Area() => Math.PI * r * r; }
Shape s = new Circle(2);
Console.WriteLine(s.Area());

رفتار مثال: حلقه روی IEnumerable<Shape> فقط Area() را فراخوانی می‌کند. برای Circle فرمول دایره و برای Rectangle فرمول مستطیل اجرا می‌شود، با اینکه type متغیر حلقه Shape است. اگر Area در base virtual نباشد و فقط در derived هم‌نام تعریف شود، این نتیجه به‌دست نمی‌آید.

نکات کلیدی

  • Static Type سطح قرارداد قابل‌مشاهده را تعیین می‌کند.
  • Runtime Type override واقعی را برای call مجازی انتخاب می‌کند.
  • Polymorphism شرط‌گذاری روی typeهای concrete را کاهش می‌دهد.

اشتباهات رایج

  • تصور اینکه هر متد instance polymorphic است
  • فراخوانی virtual از constructor.

جزئیات عمیق‌تر

constructorها virtual نیستند و فراخوانی member مجازی از constructor پایه خطرناک است، چون state بخش مشتق شاید هنوز کامل نشده باشد. CLR ممکن است call را devirtualize و inline کند بدون تغییر semantics. برای correctness روی قرارداد تکیه کنید و برای Performance خروجی Benchmark و JIT را بررسی کنید.

مجموعه‌ای از handlerهای یک interface می‌تواند بدون switch بر type رفتار مناسب را اجرا کند.
