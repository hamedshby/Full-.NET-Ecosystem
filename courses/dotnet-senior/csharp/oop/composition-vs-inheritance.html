چرا Composition معمولاً بر Inheritance ترجیح داده می‌شود؟

پاسخ کوتاه مصاحبه‌ای

Inheritance رابطه پایدار «is-a» و substitutability می‌سازد؛ Composition رفتار را با نگه‌داشتن و واگذاری کار به objectهای دیگر ترکیب می‌کند. وقتی فقط reuse رفتار لازم است، Composition معمولاً انعطاف و coupling بهتری دارد.

مدل ذهنی ساده

اگر هرجا Base پذیرفته می‌شود Derived بدون شکستن انتظارها قابل استفاده است، Inheritance ممکن است درست باشد. اگر object فقط به یک رفتار نیاز دارد، آن رفتار را به‌صورت dependency نگه دارید. Car یک Engine «دارد»، پس Composition طبیعی است؛ Circle یک Shape «است»، پس Inheritance یا interface می‌تواند طبیعی باشد.

توضیح کامل

Inheritance implementation و lifecycle را به base گره می‌زند و تغییر protected behavior می‌تواند derived typeها را بشکند. طبق Liskov Substitution Principle، derived type نباید precondition را سخت‌تر، postcondition را ضعیف‌تر یا invariant base را نقض کند. Composition این رابطه را به همکاری objectها تبدیل می‌کند؛ strategy در Runtime قابل تعویض، مستقل قابل test و جدا قابل توسعه است. هزینه آن تعداد object و wiring بیشتر است.

C#
sealed class ReportService(IRenderer renderer)
{
    public string Build(Report r) => renderer.Render(r);
}
interface IRenderer { string Render(Report report); }

رفتار مثال: ReportService یک IFormatter دریافت می‌کند. برای PDF یا JSON فقط formatter دیگری inject می‌شود و خود سرویس تغییر نمی‌کند. اگر ReportService از PdfFormatter ارث می‌برد، تبدیل رفتار به JSON رابطه «is-a» جعلی می‌ساخت و reuse را به hierarchy وابسته می‌کرد.

نکات کلیدی

  • Inheritance باید substitutability واقعی داشته باشد.
  • Composition رفتار را از طریق dependency و delegation می‌سازد.
  • reuse کد به‌تنهایی دلیل کافی برای Inheritance نیست.

اشتباهات رایج

  • Inheritance فقط برای reuse
  • تبدیل هر dependency به strategy بی‌دلیل.

جزئیات عمیق‌تر

Inheritance برای framework hook یا hierarchy دامنه پایدار می‌تواند عالی باشد. Composition نیز اگر interfaceهای بی‌معنا و delegationهای طولانی بسازد، بیش‌طراحی است. معیار عملی این است: آیا تغییر مستقل رفتار و testing جدا ارزش دارد، و آیا مصرف‌کننده واقعاً باید type مشتق را همان base بداند؟

در پروژهٔ واقعی

فرمت PDF و HTML را به‌صورت IRenderer تزریق کنید، به‌جای ساخت زیرکلاس برای هر ترکیب رفتار.

جمع‌بندی برای مصاحبه

Composition را پیش‌فرض انعطاف‌پذیر بدانید؛ Inheritance را برای taxonomy پایدار و substitutable نگه دارید.
