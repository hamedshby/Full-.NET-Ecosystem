Interface و Abstract Class را چه زمانی انتخاب می‌کنیم؟

پاسخ کوتاه مصاحبه‌ای

interface قرارداد یک capability را تعریف می‌کند و یک type می‌تواند چند interface را پیاده کند. abstract class علاوه بر قرارداد، state، constructor، protected member و implementation مشترک برای یک خانواده نزدیک از typeها فراهم می‌کند.

مدل ذهنی ساده

interface می‌گوید «این object چه کاری می‌تواند انجام دهد؟»؛ مانند IPrintable. abstract class می‌گوید «این object عضو چه خانواده‌ای است و چه state و invariant مشترکی دارد؟»؛ مانند Document. اگر فقط مصرف‌کننده به یک قابلیت نیاز دارد، interface coupling کمتری ایجاد می‌کند. اگر lifecycle و state مشترک داریم، base class می‌تواند مناسب‌تر باشد.

توضیح کامل

یک class تنها از یک class ارث می‌برد ولی می‌تواند چند interface داشته باشد، بنابراین interface برای مرزهای قابل‌تعویض، testing و ترکیب capabilityها مناسب است. interfaceهای جدید می‌توانند Default Interface Member داشته باشند، اما جایگزین state instance، constructor و protected workflow یک abstract class نیستند. abstract class می‌تواند template method بسازد و invariantها را در یک مسیر کنترل کند؛ در عوض coupling وراثتی ایجاد می‌کند و evolution آن بر تمام derived typeها اثر دارد.

C#
public interface IClock { DateTimeOffset Now { get; } }
public abstract class Entity
{
    public Guid Id { get; protected init; }
}

رفتار مثال: EmailSender و SmsSender هر دو INotifier را پیاده می‌کنند و سرویس مصرف‌کننده فقط Send را می‌بیند. اگر همه notificationها retry count، validation مقصد و یک workflow مشترک داشته باشند، NotificationBase می‌تواند این state و sequence را نگه دارد. ممکن است class هم از base استفاده کند و هم چند interface ارائه دهد.

نکات کلیدی

  • interface قرارداد capability و چندپیاده‌سازی را ممکن می‌کند.
  • abstract class برای state و invariant مشترک مناسب است.
  • انتخاب به رابطه دامنه و نیاز مصرف‌کننده وابسته است، نه تعداد memberها.

اشتباهات رایج

  • ساخت interface برای هر class بدون مصرف
  • قراردادن state مشترک در interface.

جزئیات عمیق‌تر

interface بسیار بزرگ به God Interface تبدیل می‌شود؛ قراردادها را حول نیاز مصرف‌کننده کوچک نگه دارید. base class شکننده نیز derived classها را به جزئیات داخلی وابسته می‌کند. قبل از Inheritance، Composition را بررسی کنید: گاهی inject کردن یک strategy هم reuse می‌دهد و هم coupling کمتری دارد.

در پروژهٔ واقعی

IClock وابستگی قابل‌تعویض است؛ Entity invariant و identity مشترک را نگه می‌دارد.

جمع‌بندی برای مصاحبه
