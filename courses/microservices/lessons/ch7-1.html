🚍 MassTransit

Introduction to MassTransit

📅 به‌روزرسانی: 1405/08/29
⏱️ زمان مطالعه: ۸ دقیقه
👤 آکادمی مهندسی نرم‌افزار

MassTransit یک فریم‌ورک متن‌باز برای ساخت برنامه‌های توزیع‌شده و Message-Based در محیط .NET است. این فریم‌ورک به ما کمک می‌کند سرویس‌ها را از طریق پیام‌ها و به‌صورت Asynchronous با یکدیگر ارتباط دهیم.

به‌جای اینکه هر سرویس مستقیماً به سرویس دیگر وابسته باشد، می‌توانیم پیام ارسال کنیم، پیام‌ها را منتشر کنیم و سرویس‌های دیگر آن‌ها را دریافت و پردازش کنند. MassTransit بخش زیادی از زیرساخت Messaging را در قالب APIهای ساده و یکپارچه فراهم می‌کند.

🎯
MassTransit خودِ Message Broker نیست. یک Framework و Abstraction برای برنامه‌های .NET است که روی Transportهایی مانند RabbitMQ یا Azure Service Bus کار می‌کند.

چرا MassTransit به وجود آمده است؟

تصور کنید چند Microservice داریم. برای ارتباط آن‌ها ممکن است از RabbitMQ استفاده کنیم. بدون یک Framework مناسب، باید بخش زیادی از کدهای اتصال، ارسال و دریافت پیام، مدیریت Consumerها، خطاها، Retry، Serialization و Lifecycle را خودمان پیاده‌سازی و مدیریت کنیم.

MassTransit یک Programming Model یکپارچه ارائه می‌دهد تا بتوانیم به‌جای درگیرشدن با جزئیات Transport، بیشتر روی منطق برنامه و قرارداد پیام‌ها تمرکز کنیم.

  • تعریف Message Contractها
  • ساخت Producer برای ارسال یا Publish پیام
  • ساخت Consumer برای دریافت و پردازش پیام
  • مدیریت ارتباط با Transport
  • پشتیبانی از Retry، Redelivery و Fault Handling
  • امکانات Outbox، Scheduling و Workflowها
  • قابلیت تست Consumerها و جریان پیام‌ها

MassTransit در معماری چه جایگاهی دارد؟

MassTransit بین کد برنامه و Message Transport قرار می‌گیرد. برنامه ما با APIهای MassTransit کار می‌کند و MassTransit از Transport انتخاب‌شده برای انتقال واقعی پیام استفاده می‌کند.

💡
Transport مسئول انتقال واقعی پیام‌هاست. MassTransit API و رفتارهای Messaging را برای برنامه .NET فراهم می‌کند و جزئیات هر Transport را تا حد زیادی پشت یک مدل مشترک قرار می‌دهد.

Message چیست؟

Message یک قرارداد داده‌ای است که اطلاعات موردنیاز برای ارتباط بین بخش‌های مختلف سیستم را حمل می‌کند. در MassTransit پیام‌ها معمولاً به شکل Class، Record یا Interface در C# تعریف می‌شوند.

C# — Message Contract

public record OrderCreated
{
    public Guid OrderId { get; init; }
    public DateTime CreatedAt { get; init; }
    public decimal TotalPrice { get; init; }
}

این پیام بیان می‌کند که یک سفارش ایجاد شده و سرویس‌های دیگر می‌توانند با دریافت آن، کارهای مرتبط را انجام دهند؛ مثلاً ارسال ایمیل، رزرو موجودی یا ثبت اطلاعات تحلیلی.

⚠️
Message Contract را یک قرارداد بین سرویس‌ها در نظر بگیرید. تغییر ناسازگار در ساختار پیام ممکن است Consumerهای دیگر را خراب کند؛ بنابراین طراحی و Versioning پیام‌ها اهمیت دارد.

Producer و Consumer

مفهوموظیفه
Producerپیام را ایجاد کرده و Send یا Publish می‌کند.
Consumerپیام را دریافت کرده و منطق مرتبط با آن را اجرا می‌کند.
Messageقرارداد و داده‌ای که بین اجزای سیستم منتقل می‌شود.
Transportزیرساخت انتقال پیام؛ برای مثال RabbitMQ یا Azure Service Bus.

Producer و Consumer لازم نیست در یک Process یا حتی در یک سرویس باشند. ممکن است Producer در Order Service و Consumer در Notification Service قرار داشته باشد.

یک مثال واقعی: ثبت سفارش

فرض کنید کاربر سفارشی ثبت می‌کند. Order Service سفارش را در دیتابیس ذخیره کرده و پیام OrderCreated را منتشر می‌کند. سرویس‌های دیگر می‌توانند مستقل از Order Service به این رویداد واکنش نشان دهند.

  • Inventory Service: موجودی محصول را بررسی یا رزرو می‌کند.
  • Email Service: ایمیل تأیید سفارش را ارسال می‌کند.
  • Analytics Service: اطلاعات سفارش را برای گزارش‌گیری ثبت می‌کند.

Order Service لازم نیست بداند کدام سرویس‌ها به پیام واکنش نشان می‌دهند یا چگونه عملیاتشان را انجام می‌دهند. این موضوع باعث کاهش Coupling می‌شود.

Send و Publish چه تفاوتی دارند؟

در MassTransit دو الگوی مهم برای ارسال پیام وجود دارد:

روشمفهومکاربرد معمول
Send ارسال پیام به مقصد مشخص؛ معمولاً برای یک Consumer یا Endpoint مشخص Command مانند ProcessPayment
Publish انتشار پیام به‌صورت رویداد؛ هر Consumer دارای Subscription مناسب می‌تواند آن را دریافت کند Event مانند OrderCreated
📌
به‌عنوان یک قاعده ذهنی: Command معمولاً با Send و Event معمولاً با Publish استفاده می‌شود. این قاعده کمک‌کننده است، اما انتخاب نهایی باید با طراحی پیام و Routing سیستم هماهنگ باشد.

MassTransit از چه Transportهایی پشتیبانی می‌کند؟

MassTransit می‌تواند با Transportهای مختلفی کار کند. API اصلی تا حد زیادی یکسان است، اما هر Transport قابلیت‌ها، محدودیت‌ها و رفتارهای عملیاتی خاص خود را دارد.

Transportتوضیح کوتاه
RabbitMQMessage Broker محبوب برای Queue، Exchange و Routing
Azure Service Busسرویس Messaging مدیریت‌شده در Azure
Amazon SQSQueue service مدیریت‌شده در AWS
ActiveMQMessage Broker با قابلیت‌های Messaging
SQL TransportTransport مبتنی بر دیتابیس‌های پشتیبانی‌شده
⚠️
یکسان‌بودن API به معنی یکسان‌بودن تمام قابلیت‌ها، هزینه‌ها، ترتیب پیام‌ها یا رفتارهای Brokerها نیست. هنگام طراحی Production باید ویژگی‌های Transport انتخاب‌شده را بررسی کنیم.

MassTransit چه امکاناتی فراتر از ارسال پیام دارد؟

MassTransit امکانات و الگوهای متعددی برای ساخت سیستم‌های قابل‌اعتمادتر فراهم می‌کند:

  • Retry: تلاش مجدد برای پردازش پیام پس از خطای موقت
  • Delayed Redelivery: دریافت مجدد پیام پس از یک بازه زمانی
  • Fault Handling: مدیریت پیام‌هایی که پردازششان شکست خورده است
  • Outbox: هماهنگ‌کردن ذخیره تغییرات و پیام‌های خروجی برای کاهش مشکل Dual Write
  • Saga State Machine: مدیریت فرآیندهای Business چندمرحله‌ای و طولانی
  • Scheduling: زمان‌بندی ارسال یا پردازش پیام
  • Testing: ابزارهایی برای تست Consumerها و رفتار Message Flow

در فصل‌های بعدی این دوره، هرکدام از این مفاهیم را جداگانه و با مثال‌های عملی بررسی خواهیم کرد.

MassTransit جای RabbitMQ را نمی‌گیرد؛ اگر RabbitMQ را انتخاب کنیم، MassTransit می‌تواند لایه برنامه‌نویسی ما برای کار با آن باشد.

⚠️
MassTransit جایگزین کامل REST یا gRPC نیست. در معماری واقعی ممکن است برای APIهای فوری از HTTP و برای پردازش‌های پس‌زمینه و Eventها از Messaging استفاده کنیم.

نکته مصاحبه

🎓
سؤال: MassTransit چیست و چه تفاوتی با RabbitMQ دارد؟

پاسخ پیشنهادی: MassTransit یک Framework برای ساخت برنامه‌های Message-Based و Distributed در .NET است. این فریم‌ورک APIهایی برای تعریف Message Contract، ارسال و Publish پیام، Consumerها و الگوهایی مانند Retry و Outbox ارائه می‌دهد. RabbitMQ یک Message Broker یا Transport است که پیام‌ها را در زیرساخت خود انتقال می‌دهد و نگهداری می‌کند. MassTransit می‌تواند به RabbitMQ متصل شود و توسعه Messaging را در برنامه .NET ساده‌تر کند.

جمع‌بندی

MassTransit یک Framework برای پیاده‌سازی ارتباط Message-Based در برنامه‌های .NET است. ما Message Contract تعریف می‌کنیم، پیام‌ها را Send یا Publish می‌کنیم و Consumerها آن‌ها را پردازش می‌کنند. MassTransit با Transportهایی مانند RabbitMQ و Azure Service Bus کار می‌کند و ابزارهایی برای مدیریت خطا، Retry، Outbox، Scheduling و Workflow در اختیارمان می‌گذارد.
