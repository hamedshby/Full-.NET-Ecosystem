Lesson 01 · Introducing Yourself

01 معرفی خود

در این درس یاد می‌گیری در یک گفت‌وگوی دوستانه یا شروع مصاحبه شغلی خودت را معرفی کنی.

مکالمه نمونه

Hello! My name is Hamed.
I'm from Iran, but I live in Turkey.
I'm a software developer.

سلام! اسم من حامد است. اهل ایران هستم، اما در ترکیه زندگی می‌کنم. من توسعه‌دهنده نرم‌افزار هستم.

گرامر: I am / I have / I want to

I am + noun/adjective برای معرفی و ویژگی‌ها: I am a developer.

I have + noun برای بیان داشتن یا تجربه: I have experience in C#.

I want to + base verb برای هدف و خواسته: I want to improve my English.

I want to become a confident English speaker.

می‌خواهم به فردی تبدیل شوم که با اعتمادبه‌نفس انگلیسی صحبت می‌کند.

Lesson 03 · Work Experience

03 معرفی تجربه کاری

I'm a software developer. I have seven years of experience in software development. I work with C#, ASP.NET Core, SQL Server, and Entity Framework.

من توسعه‌دهنده نرم‌افزار هستم. هفت سال سابقه توسعه نرم‌افزار دارم و با C#، ASP.NET Core، SQL Server و Entity Framework کار می‌کنم.

نسخه طبیعی‌تر برای مصاحبه

I have seven years of experience working with C#, ASP.NET Core, SQL Server, and Entity Framework.

گرامر: Present Simple و Present Perfect

Present Simple: برای شغل و کارهای معمول: I work with C#.

Present Perfect: برای تجربه تا زمان حال: I have worked with SQL Server.

have/has + past participle

For مدت زمان است: for seven years. Since زمان شروع مشخص است: since 2019.

Work with در برابر Work on

  • Work with: کار کردن با ابزار یا فناوری — I work with RabbitMQ.
  • Work on: کار کردن روی پروژه یا مسئله — I work on a payment system.

Lesson 04 · Describing a Project

04 توضیح پروژه پرداخت و معماری

نسخه اصلاح‌شده پاسخ تو

I worked on a payment system based on microservices architecture.

We used ASP.NET Core, SQL Server, gRPC for synchronous communication, and RabbitMQ for asynchronous communication.

We implemented CQRS to separate command and query operations.

We had two SQL Server databases: a primary database and a secondary database. The primary database was used for write operations, while the secondary database was used for read operations.

We used Entity Framework Core as our ORM.

این متن درباره سیستم پرداخت مبتنی بر میکروسرویس، ارتباط هم‌زمان و غیرهم‌زمان، CQRS، جداسازی خواندن و نوشتن و استفاده از EF Core است.

اشتباهات پرتکرار

  • on payment system → on a payment system
  • architeture → architecture
  • sync communication → synchronous communication
  • async communication → asynchronous communication
  • command and query segregation → separation of command and query operations
  • ORM → an ORM

گرامر: Passive Voice

Subject + was/were + past participle

Active: We used RabbitMQ.

Passive: RabbitMQ was used for asynchronous communication.

مثال: CQRS was implemented in our system.

Lesson 05 · gRPC & RabbitMQ

05 توضیح ارتباط هم‌زمان و غیرهم‌زمان

We used gRPC for synchronous communication between the API Gateway and microservices.

We used RabbitMQ for asynchronous communication. For example, after a transaction was completed, we used RabbitMQ to send SMS messages and notifications to clients.

از gRPC برای ارتباط هم‌زمان بین API Gateway و میکروسرویس‌ها استفاده کردیم. از RabbitMQ برای ارتباط غیرهم‌زمان، مثلاً ارسال پیامک و اعلان پس از تکمیل تراکنش، استفاده کردیم.

عبارت‌های حرفه‌ای

Background processingپردازش پس‌زمینه

RabbitMQ helped us decouple services and handle background tasks asynchronously.

RabbitMQ کمک کرد وابستگی بین سرویس‌ها را کاهش دهیم و وظایف پس‌زمینه را غیرهم‌زمان پردازش کنیم.

Lesson 06 · RabbitMQ Reliability

06 پیام، Consumer، ACK و Idempotency

توضیح اصلاح‌شده

The message stays in the queue until the consumer becomes available and consumes it.

If a consumer processes a message but crashes before sending an ACK, RabbitMQ can redeliver the message, provided manual acknowledgments are used.

The consumer checks the idempotency key to determine whether the message has already been processed. If it is a duplicate, the consumer skips the business operation and acknowledges the message.

پیام تا زمان در دسترس قرار گرفتن Consumer در صف باقی می‌ماند. اگر Consumer بعد از پردازش و قبل از ACK متوقف شود، با فعال بودن تأیید دستی، RabbitMQ می‌تواند پیام را دوباره تحویل دهد. Consumer با بررسی کلید Idempotency از اجرای دوباره عملیات جلوگیری می‌کند.

واژگان فنی

Producerتولیدکننده پیام
Consumerمصرف‌کننده پیام
Queueصف
Acknowledge (ACK)تأیید پیام
Redeliverتحویل مجدد
Duplicateپیام تکراری
Retryتلاش مجدد
Idempotent processingپردازش تکرارپذیرِ امن
نکته فنی: تحویل مجدد به تنظیمات ACK و وضعیت صف وابسته است. برای جلوگیری مطمئن از اجرای دوباره، ثبت Idempotency Key باید به‌شکل پایدار و هماهنگ با عملیات کسب‌وکار انجام شود. ACK را فقط پس از اتمام موفق یا مدیریت قطعی پیام ارسال کن.

گرامر: Until

until + present simple

The message stays in the queue until the consumer becomes available.

بعد از until برای اشاره به آینده معمولاً از حال ساده استفاده می‌کنیم.

Lesson 07 · Authentication & JWT

07 Authentication، Authorization و JWT

تفاوت دو مفهوم

Authentication determines who the user is.
Authorization checks whether the user has permission to access a specific resource.

Authentication هویت کاربر را مشخص می‌کند. Authorization بررسی می‌کند کاربر اجازه دسترسی به منبع مشخصی را دارد یا خیر.

توضیح JWT به انگلیسی

A JWT contains claims that provide information about the user, such as their identity and roles.

When the client sends a JWT with a request, the server validates the token's signature using the configured signing key.

If the signature is valid and the token passes all validation checks, authentication is successful.

JWT شامل Claimهایی درباره کاربر، مانند هویت و نقش‌هاست. وقتی کلاینت توکن را همراه درخواست می‌فرستد، سرور امضای آن را با کلید پیکربندی‌شده بررسی می‌کند. اگر امضا و سایر بررسی‌های اعتبارسنجی موفق باشند، احراز هویت موفق است.

ساختار JWT

Header — token type and signing algorithm
Payload — claims such as subject, roles, issuer, and expiration
Signature — helps verify token integrity and authenticity

واژگان

Identityهویت
Permissionمجوز
Validateاعتبارسنجی کردن
Signing keyکلید امضا
Expirationزمان انقضا
Credentialاطلاعات ورود
Claimادعای هویتی / داده توکن
نکته فنی: اعتبارسنجی JWT فقط بررسی Signature نیست. مواردی مانند انقضا (exp)، صادرکننده (iss)، مخاطب (aud) و الگوریتم مجاز نیز باید بررسی شوند. Claimهای JWT رمزگذاری‌شده نیستند مگر از سازوکار رمزگذاری جداگانه استفاده شود؛ بنابراین اطلاعات محرمانه را در Payload قرار نده.

سؤال مصاحبه

Can you explain how JWT authentication works in ASP.NET Core?

یک پاسخ نمونه ببین
The user sends their login credentials to the server. The server validates the credentials and issues a JWT. The client includes the token in the Authorization header of subsequent requests. The JWT bearer middleware validates the token, and the application uses the claims to establish the user's identity and apply authorization policies.
