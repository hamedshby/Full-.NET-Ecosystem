# طراحی دورهٔ «آموزش یک‌روزه CI/CD در GitLab»

## هدف

یک دورهٔ جدید به آکادمی دات‌نت اضافه می‌شود که در صفحهٔ اصلی، کنار دوره‌های .NET، Microservices و سایر مسیرهای آموزشی نمایش داده شود. این مرحله فقط ساختار دوره و صفحه‌های درس را آماده می‌کند و محتوای تفصیلی درس‌ها در محدودهٔ این تغییر نیست.

## محدودهٔ تغییر

- افزودن یک کارت جدید به بخش «دوره‌ها و مسیرهای رشد» در صفحهٔ اصلی.
- ساخت صفحهٔ اصلی دوره با عنوان «آموزش یک‌روزه CI/CD در GitLab».
- نمایش برنامهٔ یک‌روزه و فهرست ۱۰ بخش دوره در صفحهٔ اصلی دوره.
- ساخت یک فایل HTML مستقل برای هر بخش.
- خالی نگه‌داشتن محتوای آموزشی صفحه‌های درس، به‌جز پوستهٔ مشترک، عنوان درس و ناوبری.
- استفاده از الگوهای ظاهری، دسترس‌پذیری و Theme موجود در دوره‌های فعلی سایت.

## ساختار فایل‌ها

دوره در مسیر `courses/gitlab-cicd/` قرار می‌گیرد:

- `index.html`: معرفی و فهرست بخش‌های دوره.
- `course.css`: ظاهر مشترک صفحهٔ فهرست و درس‌ها.
- `course-navigation.js`: داده‌ها و رفتار ناوبری مشترک درس‌ها.
- `lessons/ch1-1.html` تا `lessons/ch1-10.html`: صفحه‌های خالی درس‌ها.

در صورت هماهنگی بیشتر با الگوهای موجود پروژه، نام فایل‌های درس می‌تواند معنادار باشد؛ بااین‌حال نام‌گذاری ترتیبی برای نگهداری ترتیب دوره و سازگاری با ساختار فعلی ترجیح داده می‌شود.

## کارت صفحهٔ اصلی

کارت جدید در `index.html` و داخل `course-grid`، کنار سایر دوره‌ها قرار می‌گیرد و شامل این موارد است:

- نشان بصری متنی `CI/CD`.
- وضعیت «سرفصل‌ها آماده».
- عنوان «آموزش یک‌روزه CI/CD در GitLab».
- توضیح کوتاه دربارهٔ مسیر عملی از Build پروژهٔ .NET تا Deploy در Kubernetes.
- خلاصه‌ای از GitLab Pipeline، Docker Registry و Environmentها.
- پیوند «مشاهدهٔ سرفصل‌ها» به `courses/gitlab-cicd/`.

## سرفصل‌ها

۱. مفاهیم CI/CD، Pipeline، Stage، Job و Runner

۲. Build و Restore پروژهٔ .NET

۳. اجرای Unit Test در Pipeline

۴. ساخت Docker Image

۵. Push کردن Image به Docker Registry

۶. Environmentهای Dev، Stage و Production

۷. Deploy خودکار

۹. ساخت Pipeline واقعی برای .NET

۱۰. Deploy در Kubernetes و مرور مصاحبه‌ای

## صفحهٔ فهرست دوره

صفحهٔ `index.html` دوره شامل Header، مسیر بازگشت به دوره‌ها، عنوان، توضیح کوتاه، مشخصات دوره و یک فهرست مرتب از ۱۰ بخش خواهد بود. هر بخش به صفحهٔ HTML مربوط به خود پیوند دارد. صفحه باید RTL، Responsive و قابل استفاده با Keyboard باشد و از اصطلاحات رسمی فنی به شکل انگلیسی استفاده کند.

## صفحه‌های درس

هر صفحهٔ درس شامل موارد زیر است:

- عنوان دقیق درس در `title` و `h1`.
- پیوند بازگشت به فهرست دوره.
- فهرست مشترک درس‌ها در Sidebar یا Navigation.
- پیوند درس قبلی و بعدی.
- یک ناحیهٔ `main` خالی برای محتوای آینده؛ هیچ متن آموزشی ساختگی یا Placeholder نمایشی در آن قرار نمی‌گیرد.

صفحه‌ها باید حتی بدون JavaScript نیز عنوان، مسیر بازگشت و ناحیهٔ اصلی قابل استفاده داشته باشند. JavaScript فقط برای بهبود ناوبری و رفتارهای اختیاری استفاده می‌شود.

## ظاهر و تجربهٔ کاربری

- طراحی از زبان بصری دوره‌های فعلی آکادمی پیروی می‌کند.
- کنتراست، Focus state، ساختار Headingها و Landmarkها با الزامات دسترس‌پذیری هماهنگ می‌شوند.
- صفحه‌ها در نمایشگرهای کوچک بدون Scroll افقی و با ناوبری قابل دسترس نمایش داده می‌شوند.
- Theme روشن و تیره، در صورت استفاده در الگوی انتخاب‌شدهٔ دوره‌های فعلی، حفظ می‌شود.
- برای این دورهٔ فنی و ساختاریافته، تصویر تزئینی جدید لازم نیست و نشان متنی کارت کافی است.

## رفتار و جریان کاربر

کاربر از کارت صفحهٔ اصلی وارد صفحهٔ فهرست دوره می‌شود، یکی از ۱۰ بخش را انتخاب می‌کند و سپس می‌تواند با پیوندهای قبلی و بعدی میان صفحه‌های درس حرکت کند یا به فهرست دوره بازگردد.

## مدیریت خطا و سازگاری

- تمام پیوندهای داخلی باید به فایل موجود اشاره کنند.
- مسیر Assetها از صفحهٔ فهرست و پوشهٔ `lessons` به‌درستی محاسبه می‌شود.
- نبود JavaScript نباید دسترسی به صفحه‌ها یا جابه‌جایی اصلی را مختل کند.
- تغییر، ساختار یا محتوای دوره‌های موجود را بازنویسی نمی‌کند.

## Verification

- اجرای آزمون‌های موجود پروژه برای اطمینان از ایجاد نشدن Regression.
- افزودن آزمون ساختاری برای وجود کارت دوره، صفحهٔ فهرست و هر ۱۰ صفحهٔ درس.
- بررسی اینکه تمام پیوندهای دوره به فایل موجود ختم می‌شوند.
- بررسی عنوان، جهت RTL و Landmark اصلی در صفحه‌ها.
- اجرای Smoke test پروژه.
- بازبینی صفحهٔ اصلی دوره و یک صفحهٔ درس در اندازهٔ Desktop و Mobile.

## خارج از محدوده

- نوشتن محتوای آموزشی کامل درس‌ها.
- ساخت Pipeline واقعی یا فایل `.gitlab-ci.yml` برای پروژه.
- افزودن Backend، ثبت پیشرفت کاربر یا سیستم آزمون.
- انتشار یا Deploy سایت.
